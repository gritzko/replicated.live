Context

Ordered by gritzko 2026-07-19. why: (WHY-001 landed) is file-only: whyOne steps ONE file's weave and emits the WHOLE body, tokens bg-washed by ORIGIN commit with commit ?<hashlet> O-targets; a dir operand has no path today (be/views/why/why.js:267 comment: "the file-vs-dir distinction lives HERE, not in the pager" — the hook exists, unused).

  • diff: already owns the dir machinery: views/diff/diff.js diffWtTree (:254, wt-vs-base changed files only), diffTreeRefs (:205), readTreeRecursive leaves, sub-mount recursion via core/recurse.js + prefixingSink; DIFF-014 f168d856 made the recursion nice.
  • why.js already FILTERS by range (?a..b → rangeIds, deletes via rms) but never WINDOWS: it has no only-the-changed-hunks emission; WHY-001 deliberately avoids diff's emitDiff/emitFull.

Goals

why <dir> renders like a diff run — per changed file, ONLY the changed hunks (context-windowed, hunk per sink.feed with the file's why: banner) — but every token inside a hunk is hili'd the why way: origin-commit bg wash + commit ?<hashlet> click, NOT diff's add/rm colouring.

  • Bare why <dir> selects wt-vs-base changes (what diff <dir> would show); ?<rev> / ?<a>..<b> reuse the diff ref convention for both file selection and the changed-token set.
  • Unchanged files emit nothing; file args keep today's whole-body behavior.
  • Sub mounts recurse like diff (core/recurse.js emit-prefix discipline).

Constraints

  • Reuse, don't fork: diff.js's tree-walk/recursion for file selection, shared/weave.js stepping + why's existing rangeIds/O-token wash for the body; the new piece is ONLY the hunk-windowing over weave steps.
  • Dir detection in the VERB (why.js), pager stays arg-blind; paths through discover resolve/wtpath (BE-030), refs through the shared ?rev parse — no manual URI parsing.
  • meta/work.mkd budgets: commit 1 line, comments ≤2 lines.
