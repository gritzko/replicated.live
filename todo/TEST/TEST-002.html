TEST-002 done: be/ stale CTest config inverted bro WILL_FAIL flags

The be/build generated CTestTestfile.cmake was out of date with the source test/CMakeLists.txt _BE_WILL_FAIL xfail list: it marked be-js-bro-color and be-js-bro-view as WILL_FAIL (so their clean exit 0 counted as failures) and did NOT mark be-js-bro-universal (so its tracked divergence failed). Three false failures with no code cause — the build was never re-cmaked after the list edit. Method: Issues.

Input

Context

  • be/build uses Unix Makefiles + a CONFIGURE_DEPENDS glob; ctest does not trigger a reconfigure, so an edit to _BE_WILL_FAIL left the generated config stale.
  • Source test/CMakeLists.txt:20-31: only be-js-bro-universal is xfail (comment "JS bro universal-pager checks differ"). color/view are expected to PASS.
  • Generated build/test/CTestTestfile.cmake (stale): WILL_FAIL on color+view, none on universal — the exact inverse. color/view print PASS and exit 0, so WILL_FAIL flips them to FAILED; universal exits nonzero with no WILL_FAIL.
  • Reproduce: ctest --test-dir be/build -R be-js-bro- → 3 failed before the fix.

Goals

  • be/ suite 58/58 green; generated CTest config matches source intent.

Constraints

  • No source or product change — purely a build-config refresh.

WIP

  • cmake -S be -B be/build to regenerate CTestTestfile.cmake from current source.
