Tarjan over all 481 require edges of be/ (102 modules; top-level AND in-body, since an in-body require defers the LOAD, not the DEPENDENCY) finds 5 strongly-connected components, every one of them a PAIR, and no self-loops. Each is ONE misplaced symbol: a primitive split across two files, or a library embedded in a view. core/registry.js's runtime req(f) verb dispatch is the one legitimate upward edge and is excluded — folding it in collapses ~50 modules into a single SCC and says nothing. Four of the five cures are leaf extractions of low risk; the fifth touches the pager's spell path and is the only dangerous one.

Input

Context

Analysed 2026-08-04 on ///be/#014aa381, re-verified independently at the same tip; every closing edge below was read at the cited line.

  • core/discover.js ↔ core/resolve_hash.js — discover.js:151,179,182-185 in-body, resolve_hash.js:28 top.
  • shared/cache.js ↔ shared/classify.js — cache.js:159 in-body, classify.js:81 in-body, `libDir()`.
  • core/loop.js ↔ views/bro/bro.js — loop.js:590 in-body, `_here`, bro.js:108,176 in-body, bareword.
  • views/todo/todo.js ↔ views/work/work.js — todo.js:572 in-body, work.js:43 top.
  • verbs/get/get.js ↔ verbs/patch/fetchleg.js — get.js:513 in-body, fetchleg.js:12 top.
  • Object.assign(module.exports, …) makes a cycle load-order-SAFE; it does not remove it. All five count as cycles.

Goals

Zero SCCs of size >1 in the require graph, with registry's dynamic dispatch the only upward edge.

  • Each cure is a SYMBOL MOVE plus a re-export, so call sites do not change and the diff stays readable.
  • A test asserts the graph is acyclic, so the property is enforced rather than remembered.
  • Behaviour, output bytes and module identity unchanged throughout — this is structure, not function.

Constraints

Pure refactor; the pager and the .be climb are the two places to tread carefully.

  • The .be climb stays in core/resolve_hash.js — resolve-hash-mandatory is a standing rule; take the cure DIRECTION that preserves it (see Design decisions).
  • Do not reintroduce in-body require() to hide an edge — a hidden cycle is still a cycle (CODE-028's ruling).
  • views/bro/pager.js is a render-layer module misfiled under views/; moving it is right but 35 test files name the path. OUT OF SCOPE, recorded only.
  • No test edited to pass. The loop/bro cure needs a pty-click repro, not a unit probe (verify-through-real-ui-path).

WIP

Design decisions

  • 1. cache ↔ classify: wtWalk belongs to neither — its own header says "two callers, wtScan and cache.js". Move it into cache.js (where the rev keying its memo lives), takeWalk becomes internal, classify.wtWalk stays a one-line re-export. 2 files.
  • 2. get ↔ fetchleg: parseRemote + resolveLocalSource are URI classification, not verb behaviour — extract to a leaf verbs/get/remote.js, get.js re-exports. 3 files.
  • 3. discover ↔ resolve_hash: the .be CLIMB and the ANCHOR READER are two halves of one primitive. Fold discover.resolve/beRoot/resolveAnchor INTO resolve_hash.js and leave discover.js a forwarding facade — this direction keeps the climb where the standing rule says it lives. 3 files.
  • 3b. REJECTED unless gritzko rules otherwise: the mirror, extracting both halves into a new core/anchor.js. Same 3 files and same acyclic result, but it relocates the climb.
  • 4. todo ↔ work: two disjoint libraries each embedded in the other's view. Extract the ticket-page family to shared/ticketpage.js; work.js then needs no todo at all and views/ticket/ticket.js becomes a direct consumer. 4 files.
  • 5. loop ↔ bro: driveSpell is a dispatch function living in a view. Move driveSpell/spellCall/_openPager into loop.js; bro.js calls loop.openPager(). The snag is driveSpell's bare-path branch calling bro's buildHunks — pass it in, or extract it. 2-3 files, HIGH risk: ~14 pty/driver tests wire this path.
