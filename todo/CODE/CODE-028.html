54 call sites across 24 be/ files call require() from inside a function body, so the spec is re-RESOLVED on every invocation: jab/require.cpp load() runs resolve() BEFORE it consults cache[abs], and resolution is normalize() plus an io.stat per candidate. The module body still evals once — what repeats is the path work. One be todo render pays this 80,342 times on core/resolve_hash.js alone. RULING (gritzko 2026-08-04): the idiom is wrong; these become regular top-level requires. The loader-side memo is JAB-010's, in ///jab — a separate repo and a separate ticket; this one does not wait on it.

Input

Context

Profiled be todo 2026-08-04 (strace + a jab microbench, warm cache).

  • be --color todo = 4.37s vs be --plain todo = 0.084s; the colour board scans 137 work/ clones.
  • stat("…/jsrc/core/resolve_hash.js") 80,342 times, open once — one stat per re-resolve.
  • Microbench: 80,342 repeat require(abs) = 231ms, of which io.stat is 190ms (~5% of the run).
  • The hot chain is per classified PATH: classify → discover.wtpath → discover.resolve → workRoot() → _rh() → require.
  • shared/project.js:17 justifies its lazy require with "resolve_hash pulls in discover, and a top-level require risks a cycle" — TRUE for core/discover.js, FALSE for project.js, which resolve_hash never requires.

Goals

Every require() in be/ sits at the top of its file; a call site names a module handle, never a require().

  • All 54 in-body sites hoisted, or deleted where the handle already exists at top level.
  • 52 of the 54 hoist with NO cycle: verified by building the top-level require graph and re-running cycle detection with every in-body edge added.
  • The 2 that DO close a cycle get the cycle BROKEN, not a lazy require left behind (see Design decisions).
  • be todo resolve_hash.js stat count drops from 80,342 to 1; no behaviour change anywhere.

Constraints

Pure refactor: no verb behaviour, no output bytes, no module identity changes.

  • libDir()-built and __dirname-built specs (shared/classify.js, shared/subs.js, shared/patchscope.js) become plain relative specs.
  • core/loop.js's _here + "/…" sites are the ENTRY shim's own resolution — check each before hoisting, _here is argv-derived.
  • Do NOT touch ///jab — the loader memo is JAB-010's ground.
  • Existing tests must pass untouched; no test edits without gritzko's word.

WIP

Design decisions

  • The two real cycles: core/discover.js ↔ core/resolve_hash.js, and verbs/patch/fetchleg.js ↔ verbs/get/get.js.
  • core/resolve_hash.js assigns module.exports = { … } at the END, so a cycle partner that hoists captures a frozen {} — that is WHY the lazy requires exist.
  • Cure: make the exports object exist EARLY and be filled by mutation (const API = module.exports = {}; … API.treeAt = treeAt;), the standard CommonJS cycle-safe shape; then both partners may hoist.
  • resolve_hash.js uses only discover.beRoot, discover.resolveAnchor, discover.resolve — a leaf split is the alternative cure if the mutation shape is refused.
  • verbs/get/get.js needs ONE symbol from fetchleg (landTip); fetchleg top-level requires get back — same two cures apply.
