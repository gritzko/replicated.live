Context

index/kv.js:91:9B-98 NORM.Due guards NaN only: ron.of() throws for any date outside the ron60 2000-2099 window and the exception escapes lex -> sweep -> sweepRepo, so a ticket carrying Due: 1999-01-01 kills the whole bee index run (rc 1, ron._ofMs: out of range); bee todo survives only because view/todo.js:271:i4 swallows it and silently drops that repo's lane. And Date.UTC rolls invalid dates over: Due: 2026-13-45 indexes as 2027-02-14, 2026-02-30 as 2026-03-02, so a typo answers a Due~ range under a plausible wrong date. Found in the 2026-09-18 index review.

Goals

Wrap ron.of and fall through to the HASH payload exactly as a regex miss does; round-trip the parsed fields (getUTCMonth()+1 === +m[2] etc.) and return null otherwise.

WIP

Design decisions

  • The round-trip is new Date(t) against the three captured fields, not a calendar table: it catches the roll and the impossible day in one test.
  • ron.of stays wrapped as well — the window is the runtime's, not this regex's, so a guard on the year alone would rot.
  • Due is the ONLY entry in NORM, and the only unguarded throw in packValue; ron.decode/ron.encode there were already in a try, view/log.js:29:Uf guards its own ron.of.
