URI-010 HIGH: relative URI paths (path-rooted or .//../) must resolve against the wt root via cwd

A URI with a RELATIVE path — path-rooted (no scheme/authority: .?, dir/file?) or opening .//../ — MUST resolve its path against the current cwd, then re-express it relative to the WORKTREE ROOT. Example: from the be/test submodule dir, jab post .? resolves . → be/test, so the effective URI is be/test? and the be/test submodule posts onto its trunk. Today be/ does the opposite: the ./-strip pattern (verbs/put/put.js:46, verbs/delete/delete.js:55, and DIS-054's new makeNarrow verbs/post/fold-decide.js:90) drops the ./ and matches wt-ROOT-relative leaves with NO cwd rebasing — cwd is read only by core/discover.js:find() to locate the .be anchor — so .?/./foo from a subdir silently hit the wrong path. First consumer: be/ post/put/delete narrowing (DIS-054); the pure URI parser stays cwd-agnostic. Method Issues.

Input

Context

  • jab post .? in be/test MUST mean "post the be/test submodule onto its trunk" — resolved URI be/test?; the ? is the bare-trunk (present-empty) query, the . is the cwd path. Not "post . at the wt root".
  • Confirmed cwd is never consulted for the path: no io.cwd() in the post→narrow flow; makeNarrow (fold-decide.js:90) n.slice(2) then underNarrow matches root-relative leaves; cwd serves only core/discover.js:find() (walk UP to the .be shard anchor).
  • Same root-relative-not-cwd assumption in the sibling verbs: verbs/put/put.js:46, verbs/delete/delete.js:55, views/log/log.js all ./-strip without rebasing on cwd.
  • Diverges from git: git commit -- ./foo is cwd-relative; Beagle's be post ./foo is silently wt-root-relative. POST.mkd's Path slot ("narrow to that path/submodule") never pins cwd semantics — this ticket pins it.

Goals

  • A relative URI path resolves as: (1) join with cwd, (2) normalize dot-segments, (3) re-express relative to the wt root; verbs consume that wt-root-relative path. .→cwd, ./foo→cwd/foo, ../x→parent/x.
  • jab post .? from be/test → be/test? (submodule onto trunk); jab post ./foo? from be/test → be/test/foo?.
  • ABSOLUTE paths (/abs) and scheme/authority URIs (ssh://…, be://…, file:/…) are NOT cwd-rebased — left as-is.
  • A ../ that climbs ABOVE the wt root is an error, not a silent clamp.

Constraints

  • Resolve in the layer that owns cwd+wtRoot (be/ side: at/after core/discover.js:find()); the pure parser (abc/URI.h) stays cwd-agnostic — context can't live in the grammar (CLAUDE).
  • No hand-rolled path surgery beyond shared/util/path.js/PATH helpers (CLAUDE no manual parsing).
  • be/ post/put/delete/log narrowing first; native be CLI should honor the same rule — cross-check, split a beagle/ ticket if it diverges.
  • Repro-first: a SUBDIR-invocation test asserting the resolved wt-root-relative path, before the fix.

WIP

Design decisions

  • One shared resolveWtPath(uriPath, cwdRelRoot) in shared/util/path.js, applied once per command before verbs read u.path; verbs stop ./-stripping ad hoc.
  • Trigger = relative path: path-rooted URI (no scheme && no authority) OR path opens .//../. Absolute /… and scheme/authority URIs bypass.
  • Orthogonal to URI-009 but both feed DIS-054 slot detection: URI-009 tells a bare . path from an absent one, this ticket then anchors it to cwd.
