URI-017: trailing slash must survive path handling — JS+C audit, violations

Now:
OPEN

Input

Context

Ordered by gritzko 2026-07-19: fleet audit of all path/URI handling in be/ (JS), beagle/ (C), jab/ (C++) and libdog for trailing-slash preservation. The invariant: a trailing slash is semantic — ///sub is the parent's de-jure pin, ///sub/ the sub's de-facto live tip (URI); track paths same. Precedent URI-005 (PATHu8sBase returns EMPTY on …/.be/, fixed narrowly d09bd197); the wtdir collapse surfaced during WORK-007.

  • Canonical layers verified CLEAN: JS resolve_hash.js reads entered/pin off the RAW path before normalizing; the URI class keeps .path verbatim; C URIMake (abc/URI.c:77) and DOGCanonURIFeed (DOG.c:531) round-trip the slash; jab uri.cpp parse/make faithful.
  • jab/dog/ is a vendored copy of libdog dog/+abc/ — libdog findings apply verbatim there.

Goals

Fix the live JS violations; harden the latent C root helpers so one careless caller cannot reintroduce the URI-005 class.

Constraints

  • All resolution stays routed through the canonical layers (URI class, be/core/resolve_hash.js, URIMake/DOGCanonURIFeed) — no parallel slash logic.
  • An fs dir cannot encode pin-vs-live: consumers must read the slash off the RAW URI before resolve (the resolve_hash entered / discover argRel / put.js:531 idiom), never off wtdir's output.
