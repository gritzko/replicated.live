URI-015: git scp-form remotes violate the URI grammar — rewrite to ssh:// at remote intake

Now
DONE

The github remote shape git@github.com:gritzko/jab.git (git's scp form) is NOT a URI — the native URI class refuses it (uri.parse: malformed, verified on jab), and per URI-013 the URI class is the ONLY parser/composer, so no code may hand-lex it. Yet it is the wild's dominant remote spelling: this journal's own .gitmodules carries git@github.com:gritzko/beagle-ext.git. Every be/ remote intake lexes via new URI() (wire.classify wire.js:33, get parseRemote get.js:69, head.js:68), so a scp remote throws or degrades to prose. Fix: a fromGit(s) heuristic in shared/uri.js — DETECT the git scp grammar (colon before any slash, user@ head, no scheme) with plain index checks on the non-URI string, then COMPOSE strictly via URI.make("ssh", "//user@host", "/path") and relex-guard the result; non-matches and make-rejects fall through verbatim. Applied at remote intake only, never inside the total uri.parse arg classifier (prose like me@10:30 must stay prose). Scope: be/ JS (beagle-ext); the C WIRECLI.c wcli_spawn shares the gap — own linked ticket. Method Issues.

Goals

  • be get git@github.com:gritzko/jab.git routes as ssh://git@github.com/gritzko/jab.git → spawn ssh git@github.com git-upload-pack 'gritzko/jab.git' (byte-identical to git's scp handling).
  • jab post git@github.com:gritzko/beagle-ext.git classifies as a Host-slot PUSH (post.js parseSlots), never as message prose; put wire forms likewise; the stored remote (get's wtlog anchor) records the recomposed ssh:// URI, never the raw scp string.
  • A beagle branch selector rides the scp tail: git@host:o/r.git?br#sha — the tail after the git-colon relexes as a RELATIVE URI (path+query+fragment via the URI class), so ?br/#sha land in their slots.
  • Non-remote args are untouched: be:/store, keeper:local, host:port, //host, prose messages with @+: never rewrite.

Constraints

  • URI class is the only URI parser/composer (URI-013): detection = index checks on the non-URI scp string (git grammar, not URI grammar); composition = URI.make + relex guard. No regex, no string-concat URIs.
  • Repro test FIRST: new unit test/uri.js (registered be-js-unit-uri in test/CMakeLists.txt foreach) — hermetic, classify is pure, no network. No other tests edited.
  • Heuristic lives in shared/uri.js (the JAB-005 module) as exported fromGit; call sites are the three intake lexes only.

WIP

Design decisions

  • Require the @ in the head (and no whitespace): bare host:path is ambiguous with scheme:path (be:/store, DIS-058) — github/gitlab scp remotes always carry user@; whitespace anywhere = prose, never a remote.
  • Tail handling stays in the URI class: split ONLY at the git-grammar colon, lex the tail as a relative URI (new URI(tail) — path/query/fragment), compose URI.make("ssh", "//"+head, "/"+path, query, frag), relex-guard the result; any lex/make refusal falls back to the original string.
  • Rewrite at INTAKE — wire.classify, get parseRemote, head lex, and post parseSlots' per-arg loop (before its uri.parse) — never inside the total uri.parse itself: it serves prose args (messages) too.
