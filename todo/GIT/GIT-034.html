bee http on pg-journal answered 404 "refs/heads/main names no readable commit" for the tip git had just committed (2026-09-24 10:25), while a fresh bee http served it. GIT-031 keeps one git.open handle per store for the process's life, and the store rescans its listings ONCE per handle (ODB.c::'o->rescanned || round == 1'): the first miss spends it, and every commit that opens a new objects/xx dir after that is invisible until restart. The per-epoch have.freshen() (index.js::'have.freshen()') is a call to a method the binding never had; its throw is swallowed.

Input

Context

  • Repro: fresh repo, bee http, GET 200; commit; GET 200 (the one rescan); commit again into a new fan-out dir; GET 404, and every later commit too (scratch run, 2026-09-24).
  • odb_loose gates on the fan-out BIT (ODB.c::'u1At(fan'), so the file is never stat'ed; the hashlet half lists the dir and finds the name, then ODBFetch misses on the bit anyway.
  • A loose object born in a fan-out dir the handle already knows is found: only NEW dirs and NEW packs go stale.
  • BEE-048:26:E9 left objects/ unwatched and named this gap as its own ticket; GIT-031 has no page (GIT-033:74:0_).

Goals

  • A miss rescans whenever <objects> or <objects>/pack moved since the last scan (two stats), for the handle's whole life.
  • ODBFreshen(o) + git.freshen(h): the epoch catch-up bee already calls, so a page starts on git's current listings.
  • Repro test in quickjab/test/gitodb.js: fan-out dirs born under an open handle are read, by sha and by hashlet.

Constraints

  • A miss storm must not readdir per miss: an mtime witness gates the rescan; a listing stamped in the scan's own ms is racy and counts as moved.
  • Read-only store, no malloc (GIT-030); no new watcher in bee.
  • Fix in the main trees quickjab/dog, quickjab; bee unchanged.

WIP

Design decisions

  • rescanned -> seen_obj, seen_pack, seen_at (ron60 ms, RONNow); odb_moved compares, odb_rescan stamps first.
  • ODBHex retries a hashlet miss once after a moved rescan.
