GIT-031 keeps every git.open handle for the process's life (HANDLES, bee/index/index.js:796), keyed by the realpath'd worktree. But linked worktrees of one repo are ONE object store: each open re-maps the same packs via commondir (ODB.c:116) and burns one of quickjab's GIT_MAX_OPEN slots (git.c:25). A resident bee http board stats every $SRC_ROOT worktree, so the 17th distinct repo threw ODBFULL — "index: Error: git.open: too many open repositories" — on the todo view (2026-08-21).

Input

The ODB is objects-only (GIT-030: four calls, READ-ONLY); refs are read per worktree in JS (bee/index/refs.js). So the handle is shareable across all worktrees of a repo — the dedup key just has to be the store's identity, not the worktree's path.

Context

  • Have: refs.commonDir(gitdir) (refs.js:29) and idx.gitdirOf(root) — the store key is computable in JS.
  • Have: handleOf memoizes per realpath'd path only; ~18 bee-* worktrees = 18 slots over one bee store.
  • Trap: openRepo takes gitdir from h.dir and derives root from it; a shared handle reports the FIRST opener's gitdir, so both must come from the arg path instead.
  • Interim relief: GIT_MAX_OPEN bumped 16 -> 100 in quickjab/git.c:25 (2026-08-21, uncommitted).

Goals

  • Key HANDLES/FRESHAT by realpath'd commondir, so N worktrees of one repo hold ONE slot between them.
  • ctx.gitdir/ctx.root stay the worktree's own, JS-derived; TIPS/LANES/refs behavior unchanged (BEE-048 bars hold).
  • A repro test: open the main tree and a linked worktree, assert the one shared handle and both cxts' own gitdirs.

Constraints

  • epoch()/freshen() become per store — one rescan per epoch, not one per worktree alias of the same store.
  • closeRepo stays a no-op for shared handles (index.js:927); hook.js openUnborn keeps owning its own.
  • Submodules are real separate stores (own commondir): they must keep their own handles, no false sharing.
  • Repro-first per work; no path string surgery where a realpath answers.

WIP

Design decisions

  • Store key = io.realpath(refs.commonDir(gitdir)), with the gitdir from idx.gitdirOf (fallback: today's climb).
