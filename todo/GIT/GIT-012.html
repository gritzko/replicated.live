GIT-012 JS: smart-fetch transports — keep SSH, add HTTPS via curl spawn

The JS wire (be/shared/wire.js) speaks git's smart protocol but only over a spawned ssh/local keeper; classify() has no HTTP(S) branch, so an https:// (or git://) URL wrongly routes to ssh host git-upload-pack (wire.js:28,76). jab has no TLS and we will NOT add one, so HTTPS rides a spawned curl; the pkt-line negotiation (advert → want/have/done → NAK → pack) is transport-independent and reused as-is. Transport I/O moves to the non-blocking pol loop. SSH stays exactly as it is; git:// (daemon, TCP 9418) is OPTIONAL — net.connect already yields the socket and the core is shared. Method: Issues.

Input

Context

  • be/shared/wire.js fetch() runs ALL transports through io.spawn + blocking io._read/io.writeAll; the negotiation core is transport-agnostic (wire.js:142-201).
  • classify() has NO http(s) branch: //host, git://, ssh:// all map to ssh host git-upload-pack, so an HTTPS remote silently mis-routes to ssh (wire.js:24-78).
  • The C keeper has no smart-HTTP either (keeper/WIRECLI.c only local-exec or ssh), so smart-HTTP is net-new and lives in JS — no C reference to mirror.
  • jab exposes non-blocking TCP (net.connect over pol, js/net.cpp:55-64,323-331) but NO TLS/HTTP/curl binding; pol is the loop the runtime drains after the script (js/main.cpp:159,319).
  • Motivating case: a real fetch of Beagle's own //origin (replicated.live) and jab get https://… need an actual HTTPS path, not an ssh misfire.

Goals

  • Add an HTTPS smart-fetch transport to the JS wire (fetch first; push a follow-up), keeping the ssh:// and local-keeper paths behaviour-identical.
  • Drive all transport I/O non-blocking over the pol loop, replacing the synchronous io._read loops with pol-fed incremental reads.
  • Reuse the shared pkt negotiation (pkt.js, parseAdvLine, pickWant) verbatim across ssh / https / (optional) git://.
  • OPTIONAL: a git:// daemon adapter (net.connect :9418 + one request pkt-line), included only because the core is shared and it needs no new binding.

Constraints

  • HTTPS = spawned curl (curl owns TLS+HTTP); NO native HTTPS/TLS — jab has none and we will not add one.
  • No new JABC bindings: git:// rides existing net.connect, HTTPS rides io.spawn(curl), ssh/local unchanged.
  • Non-blocking only: every transport fd is a pol.watch registration; the wire awaits via the loop, never a blocking read.
  • ABC/wiki norms: reuse before adding, ≤2-line comments, greppable no-wrap lines, ticket-coded commits.
  • Do not vandalize the working ssh/local path — parity must hold (meta/work.mkd).

WIP

Design decisions

  • Split wire.js into a transport-agnostic negotiation core + per-transport adapters: local/ssh (spawn, have), https (curl spawn, new), git (net.connect, optional).
  • Make the core async: feed pkt.Reader from pol-driven 'data' chunks (net socket or watched spawn fd), resolving on advert-flush and on pack-EOF — no synchronous io._read.
  • Smart-HTTP is two stateless requests: GET <base>/info/refs?service=git-upload-pack then POST <base>/git-upload-pack, types application/x-git-upload-pack-{advertisement,request,result}.
  • The HTTP advert carries a # service=git-upload-pack\n + flush preamble before the refs; the advert drainer skips it, while ssh/git go straight to the ref lines.
  • Keep the demux-free path: request want <sha> ofs-delta WITHOUT side-band-64k, so the server streams the raw pack after NAK — exactly what wire.js already assumes (wire.js:174-193).
  • curl shape: GET advert curl -sSf --get <base>/info/refs --data-urlencode service=git-upload-pack; POST curl -sSf -H 'Content-Type: …request' --data-binary @- <base>/git-upload-pack; stdout is the pkt stream.
  • git:// (optional): one request pkt-line git-upload-pack <path>\0host=<host>\0 (v0, port 9418), then the identical core; the daemon serves upload-pack only.
  • Push is OUT of scope here: receive-pack will be ssh + smart-HTTP POST git-receive-pack (own ticket); the git:// daemon refuses receive-pack by default (anonymous-push unsafe).
