GIT-027: stock-git push into a Beagle store — thin-pack land + git-receive-pack entry parity

Now:
OPEN

The be:// receive-pack serves the JAB client only (POST-028 serve.js receivePack: v0 advert, raw NON-thin pack, bare-path selector). A stock git push differs on two counts: send-pack ships a THIN pack by default (REF_DELTA against objects only the server holds — ingest.js defers exactly that: "OFS re-encode + REF-base resolve, a follow-up"), and ssh spawns git-receive-pack '<path>', a name jab does not answer to. Close both and a git-only colleague pushes into a .be store with no jab on their side — the highest-leverage wire-compat direction.

Input

Context

  • serve.js receivePack 124: v0, caps report-status ofs-delta, cmd parse strips caps after \0 (tolerates agent=), drain → ingest.land → per-ref CAS + FF gate → report-status. Entry: core/loop.js 315.
  • ingest.js header: a verbatim full-clone pack lands as an OFS-only log; thin packs (REF_DELTA) are explicitly a follow-up — no REF-base resolve.
  • Stock git: send-pack pushes --thin by default; only --no-thin avoids REF_DELTA. Deletes arrive as zero-sha new; tags as refs/tags/*.
  • refUpdate (POST-028) serves refs/heads only, refuses deletion, FF-only with CAS — the policy stays; only the wording is user-facing.
  • The jab-client direction (jab → git remote) already works: GIT-013 push, GIT-012 transports. This ticket is the reverse arrow.

Goals

  • git push into a .be store lands green over local exec and ssh: the initial (full) push AND the incremental (thin) push; report-status ok.
  • Refused moves (non-FF, delete, refs/tags/*) come back as plain-words report-status lines, not bare error codes.
  • A stock client reaches the serve loop without jab-specific flags on the remote: a git-receive-pack spawn form (PATH shim or documented remote.<name>.receivepack=jab receive-pack config), path arg mapped.

Constraints

  • Reuse ingest.js/pkt.js/serve.js; NO second pack or framing impl.
  • The store invariant holds: OFS-only logs — REF_DELTA is re-encoded on land, never stored (GIT-002 format law, GIT-003 is the native shape).
  • Protocol v0, no side-band (current contract); jab-client parity must not regress (test/serve/* stays green).

WIP

Design decisions

  • Thin-fix on land: extend ingest.land — index the incoming pack, resolve each REF_DELTA base via the store reader, re-encode the object OFS/full into the log (the GIT-003 ingest re-encoder, done in JS).
  • Entry naming: keep ONE serve loop; git-receive-pack is a spawn-name alias resolving to jab receive-pack with the git-style quoted path mapped by the POST-028 bare-path contract.

Blockers and bummers

  • git push --no-thin is a workable interim for demos, but the default path MUST land thin packs or the compat claim is hollow.
  • Zero-sha in a command line must not hit the sha-resolve path — it is a delete marker, not an object.
