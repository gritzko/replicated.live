GIT-028: git porcelain shim — a separate jsrc repo of git-named verbs delegating to the be basis

Now
OPEN

The muscle-memory layer of the git compat story: a SEPARATE repo (not be/) carrying its own jsrc/verbs/, one bareword verb per everyday git command — clone checkout switch add commit push fetch pull merge rebase cherry-pick branch tag stash — each parsing only the handful of flags people actually type and delegating to the existing be verbs exactly per the Verbs cheat sheet. jab already scans every planted jsrc/, so the shim needs ZERO core changes; git command names do not collide with the verb basis, and status/log/diff already exist as views.

Input

Context

  • Verbs §"git → be cheat sheet" is the dictionary: add→PUT, commit→POST, checkout ?br→GET, merge→PATCH+POST, push→PUT ssh://, branch -d→DELETE, stash→sub-branch idiom.
  • jab verb discovery scans <dir>/jsrc/ shards; multiple planted shards compose, so a compat repo rides alongside be/ unmodified.
  • Sibling layers: GIT-029 plumbing (same repo), GIT-027 wire compat — the shim serves humans, those serve software.

Goals

  • jab clone URL, jab add f, jab commit -m msg, jab push, jab merge trunk behave as the cheat-sheet composition end to end.
  • Unmappable idioms answer with the Beagle idiom in plain words (stash → eager sub-branch, reflog → the ulog), never a half-emulation.
  • The flag subset stays tiny and documented; anything else errors with the be-verb equivalent spelled out — teaching, not emulating.

Constraints

  • Pure translation: shims compose existing verb/view invocations through the registry — no store, wire, or weave logic of their own.
  • Shim verbs take (context, arg) and resolve through the standard resolve path like any verb; no private URI parsing.
  • No flag sprawl re-import: the git surface is capped per command (the ~3-5 everyday flags); rejected flags name the be way in the error.

WIP

Design decisions

  • One file per command under the compat repo's jsrc/verbs/<name>/; each maps flags → a be verb call sequence, then delegates output.
  • Collision policy: git names that shadow existing views (status, log, diff) alias the view rather than re-render.
  • Multi-step rows (commit -am = PUT . + POST; merge = PATCH + POST) run as a sequence with fail-fast between steps.
