GIT-011: ZINFInflate wraps output on fill, never signals NOROOM

Now
OPEN
Sev
MED

ZINFInflate (dog/git/ZINF.c) mishandles a too-small into slice: when avail_out hits 0 it WRAPS next_out back to into[0] and keeps inflating (corrupting already-produced bytes), then the trailing u8sFed(into, total_out) — all-or-nothing — no-ops because total_out exceeds capacity, so the head never advances and the call returns OK with produced 0. A genuine empty result also yields 0, so overflow is undetectable by the caller. Surfaced by JS-035 (zip.inflate grow-and-retry), which had to add an XOR head-sentinel hack to guess at overflow. Method: Issues.

Input

Context

  • Bug is the avail_out == 0 reset block, dog/git/ZINF.c:31-34, inside the inflate loop (lines 27-35); resets next_out/avail_out instead of erroring.
  • Native callers pre-size into to the object's known uncompressed length (keeper/UNPK.c:336,618, dog/git/PACK.c:177), so the wrap is LATENT there; it only bites a caller that doesn't know the size up front.
  • JS-035 js/zip.cpp works around it with a head sentinel (into[0][0] ^= 0xa5, re-checked after the call) — that hack is deletable once this lands.
  • Audit 24Jul26 review: wrap intact. The pre-sized callers are NOT fully latent — a record whose stream inflates PAST its declared size wraps and corrupts; PACKInflate (dog/git/PACK.c:171-182) never cross-checks total_out == size, and UNPK.c:618 CONSUMES the inflated delta bytes. Related: GIT-025 (PACKRecordEnd's measure-by-inflate needs the fix).

Goals

  • On a stream needing more room than into holds, return a NOROOM-style error (new ZINFROOM) so the caller can grow and retry — never wrap or corrupt.
  • On OK, total_out equals the bytes actually present in into; the success path stays byte-identical for the pre-sized native callers.

Constraints

  • dog/git libdog, ABC style; new code RON60-encoded, ZINF-prefixed (abc/ok64), declared in ZINF.h beside ZINFFAIL/ZINFINIT/ZINFTOOBIG.
  • Must not regress the native callers (they must still receive OK).

WIP

Design decisions

  • Replace the wrap block: when inflate returns Z_OK with avail_out == 0 (stream not ended, no room left) → inflateEnd(&zs); return ZINFROOM;.
  • Run u8csUsed/u8sFed only on the Z_STREAM_END success path.
