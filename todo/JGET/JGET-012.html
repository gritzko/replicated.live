JGET-012: relative submodule url (../sub) not resolved against the parent source

Now
OPEN
Sev
MED

jab get of a git parent whose .gitmodules declares a RELATIVE submodule url (url = ../sub) passes it to the sub fetch without resolving it against the parent SOURCE URI, so the fetch targets a nonexistent project (HOMENOPROJ / "peer advertised no usable ref"), the sub is absent and the get exits 1. Native resolves ../sub against the parent URI (the SUBS-020 rule). Part of JGET-001; method Issues.

Input

Context

  • Native beagle/test/get/50-file-subs-git-relative (SUBS-020, relative ../sub).
  • Repro: git parent with .gitmodules url=../sub; jab get <parent> → HOMENOPROJ / no usable ref, sub absent. Evidence ~/todo/JSGET-cases/c50/wk/c3a.err.
  • Root: the sub-mount candidate builder takes the declared url verbatim; no relative-to-parent-source resolution (be/shared/submount.js).

Goals

  • A relative .gitmodules url is resolved against the parent source locator before fetch (matching native SUBS-020); absolute urls unchanged.

Constraints

  • Use the URI binding's path-merge, not string concat. Repro-first. Sequence after JGET-006/JGET-007 (sub mount must work for non-relative first).

WIP

Design decisions

  • Resolve the declared url: if relative, merge against the parent source URI (scheme/host/path) to form the sub locator; keep absolute urls as-is. Slot it as a candidate before the raw declared-url fallback.
