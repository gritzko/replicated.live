JGET-013: jab get --force leaves a tracked-but-out-of-tree orphan on disk (no orphan sweep)

Now:
OPEN
Sev:
MED

jab get --force ?feat does not delete a tracked file that is absent from BOTH the baseline and the target trees but still present on disk (a leftover from a prior aborted unlink). When baseline==target the reconcile walks only the empty delta and has no orphan sweep, so the stale file survives; native unlinks it (the GET-016 force-full-reset invariant). Not destructive — the surviving file is stale clutter and the in-tree bytes are correct — but the case-49 invariant fails. Part of JGET-001; method Issues.

Input

Context

  • Native beagle/test/get/49-force-full-reset (GET-016 Part 2, the deletion side).
  • Repro: baseline==target==feat with a tracked-but-out-of-tree sub/b.txt on disk; jab get --force ?feat → sub/b.txt survives; native unlinks it. Evidence /tmp/claude-1000/jabprobe/c49-jab.
  • Root: the --force reconcile only diffs baseline↔target; no pass that removes tracked paths present on disk yet in neither tree.

Goals

  • jab get --force drives the wt to EXACTLY the target tree, including removing tracked on-disk paths absent from the target (matching native GET-016); untracked files are governed by --prune, not this sweep.

Constraints

  • Distinguish tracked-orphan (sweep) from untracked clutter (leave unless --prune). Repro-first.

WIP

Design decisions

  • Add a force-mode orphan sweep: enumerate tracked paths (from the wtlog/baseline stamp-set) and unlink any not present in the target tree. Gate on --force.
