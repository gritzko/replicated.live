JGET-004 DONT: dirty cross-branch jab get ?feat writes conflict markers into the uncommitted file (no up-front dirty refusal)

Now: DONT Sev: CRIT

jab get ?feat against a worktree with a DIRTY tracked file (locally edited, uncommitted) does not refuse: its only dirty guard fires solely for NEW-in-target paths that lack a baseline, so a tracked file present in both trees falls straight into the leaf 3-way weave. The on-disk dirty bytes vs base vs target collide, jab WRITES <<<<dirty||||-feat>>>> into the file and grows the wtlog, then errors GETCONF. The user's uncommitted bytes are mangled and the refusal-atomicity invariant is violated. Native refuses up front (SNIFFDRTY), leaving the file and wtlog untouched. Part of JGET-001; method Issues.

Input

Context

  • Native beagle/test/get/09-refuse-no-commit (cross-branch-dirty refusal, SNIFFDRTY, must run BEFORE the commit point).
  • Repro: two-branch repo, edit tracked x.txt dirty, jab get ?feat → x.txt becomes <<<<dirty||||-feat>>>>, wtlog 7→8 rows, then rc=1 (GETCONF). VERIFIED marker in evidence /tmp/claude-1000/jabprobe/r09/wt/x.txt. Native: rc≠0, x.txt still dirty, wtlog unchanged.
  • Root: dirtyOverlapCheck (get.js:328) only inspects paths with NO baseline (new-in-target); a tracked file in both base+target skips it and reaches the leaf weave-merge (~get.js:651/748).

Goals

  • A switch/restore that would overwrite a DIRTY tracked file refuses up front (before any wt write or wtlog append), wt + wtlog byte-identical, nonzero exit with a native-style dirty diagnostic.
  • A clean wt still switches/weaves as today.

Constraints

  • The refusal must be a PRE-PASS barrier (before the fan-out commit point), like native SNIFFDRTY / the existing SNIFFOVRL pre-pass. Repro-first.

WIP

Design decisions

  • Broaden the pre-pass: refuse if ANY tracked path that the target changes is dirty on disk (baseline≠wt), not only un-baselined overlays. Keep the existing no-baseline overlay arm. Decide whether --force/weave is the opt-in to merge.
