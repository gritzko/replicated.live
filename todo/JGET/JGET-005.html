JGET-005: jab get ?<branch> fetches the WRONG branch (trunk) for any non-main/master name

Now:
OPEN
Sev:
HIGH

jab get ?feat (or ?/proj/feat) over the wire silently checks out TRUNK instead of feat: the want-ref builder prefixes the bare branch with refs/ (→ refs/feat) instead of refs/heads/, so it never matches the peer's advertised refs/heads/feat and falls through to the HEAD/main/master fallback, returning the trunk tip. ?master/?main only work by the coincidence of those fallback lines. No error — the user gets the wrong content. Part of JGET-001; method Issues.

Input

Context

  • Native beagle/test/get/{24-uri-refs, 38-remote-main-branch} (ref-shape resolution).
  • Repro: seed a be peer with trunk+feat; jab get "be://localhost/<U>?/proj/feat" → jab checks out hello.c=TRUNK; native checks out FEAT. Evidence ~/todo/JS096-probe1/c24/{j2,n2,j3}.
  • Root: pickWant (be/shared/wire.js:107): const full = wantRef.indexOf("refs/")===0 ? wantRef : ("refs/"+wantRef); builds refs/feat, never matching the advertised refs/heads/feat.

Goals

  • A bare ?<branch> resolves the peer's literal refs/heads/<branch>, exactly like native; full refs/... refs pass through unchanged; trunk/empty still resolves HEAD/default.

Constraints
