Ruled 2026-09-18 (gritzko): a URI scheme can have no dots. RFC 3986 §3.1 allows them, so abc/URI.lex:34 reads the bare link x.c:12 as scheme x.c plus path 12, and a link that reaches the URI parser loses its file. No scheme we use is dotted; the registered ones (soap.beep, iris.beep, z39.50r) are dead weight. The grammar sits in the abc/ submodule (libabc) and serves every runtime.

Input

Context

  • abc/URI.lex:34 Scheme = (alpha ( alpha | digit | "+" | "-" | "." )*) ':'; its ragel twin is abc/URI.c.rl:240.
  • abc/URI.lex:30 PathNoscheme = segment_nz_nc …: a relative ref's first segment takes no colon (RFC 3986 §4.2).
  • Verified 2026-09-18 on quickjab: uri._parse("x.c:name") gives {scheme:"x.c", path:"name"}, x.c:12 the same shape.
  • ./x.c:12 and dir/x.c:12 parse as plain paths already: only a bare name.ext:anchor collides.
  • Found in BEE-074: an explicit Markdown dest [t](x.c:12) goes through uri._parse and comes out verbatim, a dead href.

Goals

  • Scheme loses the ".": x.c:12, HUNK.c:HUNKu8sMakeURI and a.b.c:'x' carry no scheme.
  • Those inputs parse as a PATH holding the whole text; none of them becomes malformed, which dropping the dot alone would do.
  • foo:bar, mailto:x@y.z, spot:.c#body, be://host/x?ref and http://h:80/p parse exactly as today.
  • Repro first (work 3) in abc/test/URI.c: the dotted cases red, the undotted ones pinned green before the change.
  • abc/URI.md and the INDEX entry say the scheme is dotless and why; the twin is regenerated, never hand-edited.

Constraints

  • Ragel only (abc); URI.lex stays the one source of the grammar, whatever generates URI.c.rl from it is rerun.
  • The change lands in libabc and is bumped through libdog, quickjab and jab; the existing URI tests stay green and unedited.
  • Grep every consumer for a dotted scheme before landing (be, bee, beagle-ext, jab): none is expected, a hit is a finding.

WIP

Design decisions

  • A deliberate break with RFC 3986 §3.1, as the link grammar is one (BEE-073): our own text is links first, URIs second.
  • The rule: abc/URI.lex:28 segment_nz_dc = (path_char - (":"|"."))* "." (path_char - ":")* ":" path_char*.
  • A first segment holding a . before its first :, and a : after it; PathNoscheme (:31) takes it beside segment_nz_nc.
  • Disjoint by construction: a scheme has no dot before its colon, segment_nz_dc demands one, segment_nz_nc takes no colon.
  • So no scanner ordering and no new callback: the path still lands via URIonPathNoscheme (abc/URI.c:10).
  • a.b://host/p is a PATH holding the whole text: with no scheme there is no authority, and //host/p is plain segments.
  • Links do not need this to resolve (BEE-074 feeds F tokens to tok.link); it is for text that reaches the URI parser anyway.
