gritzko 2026-08-15: we need a .rst tokenizer in libdog. Today .rst falls to the plain-text TXTT (dog/tok/TOK.c:211), and the RST name is TAKEN — dog/tok/RST.c.rl is the Rust machine (.rs + T: /// doc comments, r#"…"# raw strings, lifetimes). The new machine follows the ext+T convention as RSTT, a prose machine in the MDT/MKDT family: reST markup emits 'G', code inners tokenize formatting-blind, LINK is included so path/ticket refs fuse to 'F'. Tokens for paint + nav only — no AST, no directive semantics.

Input

Context

  • MDT.c.rl (Markdown) is the nearest model: prose machine, include LINK "LINK.rl";, markup as 'G', DOG-025 code-inner rule.
  • reST inventory worth 'G': section under/overlines (====, ----), transitions, directives .. name::, comments .. text, hyperlink targets .. _name: url, substitutions |sub|, field lists :field:, literal-block :: opener, inline `literal, emph, *strong*, :role:text , ref_ / ref__, footnotes [1]_`.
  • DOG-025 ruling carries over: literal/code inners tokenize at word granularity, but NO nested formatting and no 'F' fuses inside.
  • DOG-037 wires LINK into TXTT first, so .rst refs fuse even before this machine lands; this ticket adds the markup layer.

Goals

RSTT.c.rl + generated twin land in dog/tok, the dispatch row E("rst", …) moves from TXTTLexer to RSTTLexer, and a .rst page paints like a page in lite/bro.

  • Markup delimiters 'G', prose words through the LINK-bearing word layer ('F' fuses), literal bodies verbatim-tokenized 'H'-style per DOG-025.
  • TOK01-style fixtures covering each inventory row plus the DOG-036 link table inside reST prose.

Constraints

  • Ragel machine only; never ever manual parsing in C.
  • Scope cut: tokenizer, not parser — no directive execution, no reference resolution, no include files; grid/simple tables tokenize as plain rows for now.
  • Repro-first; ragel -C RSTT.c.rl -o RSTT.rl.c -L; ctest -j16 clean.

WIP

Design decisions

  • Name RSTT (ext+T; RST is Rust) — CONFIRMED by gritzko before code.
  • THREE machines in RSTT.c.rl, no hand-cut bytes anywhere: RSTT (the inline scanner, include LINK "LINK.rl"; + the same five nav bindings MKDT/MDT/FREE carry), rsttb (the block grammar — one line -> kind + indent/mark/rest, the MKDTB pattern), rsttl (the one-bit "does this line end in ::" inquiry that opens a literal block). RSTT.c holds the callbacks and the line driver only.
  • IN v1, one 'G' markup run each: section under/overlines and transitions (>=3 of one adornment char, whole line), directives .. name:: (substitution definitions .. |x| replace:: included), comment openers .., hyperlink targets .. _name:, footnote/citation DEFINITIONS .. [1], field lists :field:, the literal-block :: opener, inline `literal, emph / *strong*, :role:text, ref_ / ref__, footnote refs [1]_, substitutions |sub|`.
  • Tag policy: markup 'G'; prose through the LINK-bearing word layer, so refs fuse to 'F' identically to .mkd/.md/comments; a literal block's and an inline literal's inners tokenize at word granularity as 'H' with NO nested formatting and NO 'F' (DOG-025); an emphasis body re-lexes one level down (DOG-024's reading), so a ref inside *...* still fuses; a comment body goes through FREEu8sFeed('D',…), the established comment path — 'D' with refs sticky 'F' (DOG-006).
  • A literal block runs from the :: opener to the first non-blank line NOT indented past the opener; indent is compared by byte length (a tab counts one) — v1 simplification.
  • PUNTED, deliberately: grid/simple tables are plain rows (no table machinery); a role's inner text does not tokenize (one 'G' for the whole ` :role:text ); a directive body is prose unless the directive line itself ends in :: (no per-directive literal semantics); the postfix role form text:role: ; doctest blocks, line blocks, option lists, bullet/enumerated markers (all plain punct + prose); . and : are NOT adornment chars here (they head comments and field lists), and an adornment run needs >=3 chars so --/**` never reach the block layer.
  • Found by the eyeball leg, not by the fixtures: TOKLexer dispatches through a TOKstate, which has no depth field, so the block layer must never read state->depth — RSTTEmitInline opens every line at depth 0 (dog/tok/RSTT.c:113). Through the CLI a whole *emph* was collapsing into one token before the fix.
