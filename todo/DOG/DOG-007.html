DOG-007: split dog/ out of beagle into a libdog submodule (the libabc pattern)

Now:
DONE

The beagle tree grew too big; today it splits into subprojects. abc/ already lives as the libabc submodule; dog/ is next. dog/CMakeLists.txt already declares project(libdog C), and the dog target links only abc-core + ZLIB, so the layer is submodule-shaped as-is. Every consumer (bro, spot, sniff, keeper, graf, beagle, woof, mark, js) links dog abc-core and includes "dog/..." via the beagle-root include path, so mounting the new submodule at the same dog path means ZERO consumer churn. Sibling ticket: JAB-005 (jabc split) depends on this one. Method: Issues.

Input

Context

  • Precedent: beagle/.gitmodules maps abc -> https://github.com/gritzko/libabc.git; abc/CMakeLists.txt doubles as a standalone root (own project(libabc), options, DOG_BIN_DIR, dep discovery) and as an add_subdirectory child of beagle.
  • dog/ is already self-contained on disk: own test/, fuzz/, tok/ (~60 ragel tokenizers + gen_tok.sh), vendored git/ + sha1dc/, version.cmake, INDEX.md, README.md.
  • dog/CMakeLists.txt has include_directories(.. . tok git): the .. resolves "abc/..." headers against the beagle root today; standalone it must resolve against the libdog root, which therefore carries its OWN abc submodule.
  • In-tree, dog inherits root-CMake state: DOG_BIN_DIR, DOG_TEST_TMP_BASE/DOG_TEST_TMP_ROOT, TEST_CXX_FLAGS, WITH_FUZZ/WITH_ASAN, find_package(ZLIB); abc/CMakeLists shows the re-default pattern for a dual-mode child.
  • dog/version.cmake already falls back from git describe to the beagle tip hashlet when the tree is a .be store, so it survives the split in both homes.

Goals

  • libdog builds and its full ctest (dog/test + dog/fuzz) runs green STANDALONE from its own repo root, with libabc as its submodule.
  • beagle builds and tests EXACTLY as before with dog as a submodule: same mount path dog, same target names dog/dogtok, same include spellings.
  • No double-build of abc when nested: libdog guards its abc with if(NOT TARGET abc-core) add_subdirectory(abc), so in-beagle it uses beagle's abc/ checkout.
  • The public repo carries LICENSE plus the vendored sha1dc/ and git/ license notices.

Constraints

  • ZERO consumer churn: no include-path or target-name changes in bro/spot/sniff/keeper/graf/beagle/woof/mark/js.
  • abc version skew: beagle's abc/ pin wins in-tree (the NOT-TARGET guard); libdog's own abc pin exists for standalone dev and is kept in lockstep manually.
  • The GitHub repo is created by the USER (T2 below); no agent pushes anything to GitHub without an explicit go-ahead.
  • Work in an own worktree per Issues; the beagle main tree is not touched until the cut-over is approved.
