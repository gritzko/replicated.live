Every code grammar in dog/tok ends its rule list with a per-BYTE punctuation catch-all ((any8 - idalpha - dgt - ws - …) => on_punct, e.g. tok/JST.c.rl:128:r5), and spells identifiers ASCII-only. A non-ASCII codepoint that lands outside a string or comment — an em dash, an NBSP, a π — is therefore emitted as two to four one-byte tokens, and any consumer that decodes token spans one at a time (bee render/html.js:108:9F dec()) throws utf8.Decode(): malformed UTF-8. DOG-042 gave the prose machines (MDT, MKDT, FREE, TXTT) the shared UTF8.rl sequences and a whole-codepoint fallback rule; the ~55 code grammars never got either. This ticket sweeps them all: identifiers in any alphabet, and ONE token per refused codepoint.

Input

Context

Found 2026-08-17 on http://localhost:8888/bee/commit/b3b14e13d9d2b75 — the page 500s with bee http: utf8.Decode(): malformed UTF-8.

  • Repro (a probe over view/commit.js hunks): only hunk 93, test/land/pty.js#L31, has token ends inside a UTF-8 sequence — tokens 211..213 are \xe2, \x80, \x94, each tagged P, side 2.
  • How it got there: the diff emit joins the removed tail of a comment ( 20, col 7 — INSIDE it) to the inserted code on one merged line; the re-lex under js sees the — in CODE context, where the JS grammar has only the byte-wide catch-all.
  • The comment sub-tokenizer is not at fault: tok/TOK.c TOKSplitText walks continuation bytes, so an em dash inside // … is one D token (hunk lines 16/25/30 of the same diff are clean).
  • Scan (2026-08-17): of 60 grammars, only MDT MKDT FREE TXTT RSTT TOKL MKDTB (the LINK.rl includers) and AGDT (idalpha = … | (0x80..0xff), per byte but never split) know hi bytes at all; HTMT's text run (any8 - …)+ swallows a sequence whole; JSONT and MLT have NO catch-all and fail the lex outright. Every other grammar splits.
  • The grammars that split include the four that carry most of the tree: JST, CT, PYT, GOT; also TST CPPT CST JAT KTT SCLT SWFT DARTT ZIGT DT RBT PHPT PRLT RT SHT FSHT PWST YMLT TOMLT SQLT GQLT HCLT NIXT NIMT LUAT LLT LAXT CLJT CMKT DKFT MAKT ELXT ERLT FORT GLMT GLST ODNT SOLT TYST VIMT VERT HST JLT CSST SCSST PRTT.

Goals

A code grammar never emits a token boundary inside a UTF-8 sequence, and a word spelled in any alphabet is ONE token.

  • a — b under js is SWPWS; naïve is S; π = 3 is SWPWL; x<NBSP>y is SPS (a gap codepoint is punctuation, not a letter — DOG-042's utf8gap); a 4-byte codepoint is one token.
  • The same holds under EVERY ext TOKExtAt enumerates: a property test feeds each lexer a handful of non-ASCII probes and asserts every emitted token starts and ends on a codepoint boundary.
  • Every existing TOK01.c case unchanged; ctest green in the dog build and in a quickjab build.

Constraints

  • Worktrees ~/src/dog-DOG044 (of ~/src/quickjab/dog, branch DOG-044) and ~/src/quickjab-DOG044 (dog symlinked in); no main-tree edit, no VC ops.
  • Ragel only: the fix is grammar (include UTF8 "UTF8.rl", utf8ch in the word classes, a (0x80..0xff) (0x80..0xbf)* fallback ahead of the byte catch-all); regenerate each twin with ragel -C X.c.rl -o X.rl.c -L; no C byte-walking added anywhere.
  • RED first: the property test and the JST/CT/PYT/GOT pins fail on the base build before any grammar moves.

WIP

Design decisions

  • ONE fallback shape for all code grammars, the same rule MDT.c.rl:237 already carries, but bound to on_punct: a codepoint the word rule refused is a gap (NBSP, U+2000..206F, …) or malformed, and in code that reads as punctuation, not as a word. The prose machines keep their on_word binding — a gap between two words there is still prose.
  • Identifiers take utf8ch (start AND continue) in every grammar, whether or not the language formally allows Unicode identifiers: the alternative is a per-language table nobody maintains, and a π painted as a word in C is harmless where a split sequence is a crash. Gaps stay out of words by utf8ch's own definition, so x<NBSP>y is three tokens.
  • JSONT and MLT are left STRICT: neither has a catch-all today, so a stray symbol fails the lex (and the caller falls back to plain) rather than splits; the property test checks boundaries only, so a refusal passes as long as whatever WAS emitted is whole.
  • AGDT moves from (0x80..0xff) per byte to utf8ch, so NBSP stops gluing words; HTMT gets utf8ch in idalpha so a Cyrillic word is one text token, not a run.
  • The include goes into each grammar directly (include UTF8 "UTF8.rl";); none of these includes LINK.rl, so ragel sees the definitions once.
