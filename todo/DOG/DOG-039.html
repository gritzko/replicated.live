WIP

Design decisions

One character added to one define — seg = [A-Za-z_] [A-Za-z0-9_\-]* — and nothing else in the grammar moves. seg feeds dirs, relknown, relanch, rooted, extany and keyvoid, so the dash reaches dir segs and basenames together, in all five machines that include LINK.rl.

  • TRAILING and DOUBLE dash FUSE (foo-.c -> F, a--b.c -> F). The only guard is that a dash never STARTS a seg, which is what keeps --flag and -v out; past that a dash is an ordinary name byte, because both shapes are legal filenames and it is the EVIDENCE gate — known ext, or anchor past a slash — that keeps hyphenated prose from fusing, not the dash's position. A foo-bar or well-known with no evidence stays prose exactly as before, so a shape guard would buy nothing and cost a rule.
  • Codes-are-paths (gritzko 2026-08-15) is written into the LINK.rl header beside the spec table: a code is a valid seg by design, and where both could match the rule listed FIRST wins by scanner order — ticket before the path rules. No tie guard was built and none was needed: DOG-036, DOG-036:18, DOG-036/README.mkd:18, DOG-036/repro all lex exactly as DOG-036 pinned them, and keyvoid goes on voiding GPL-2.0 / ISO-8859-1 / AB12-34CD.
  • feed-icon.png CANNOT fuse and is pinned as crumbs instead: png is not in the KNOWN dictionary (TOK_TABLE is the lexer table, and this ticket does not touch it), so the name carries no evidence — same answer src/weird.xyz gets. The dash was never its obstacle. feed-icon.js is pinned in its place as the kebab + known-ext positive; add png to the dictionary and feed-icon.png fuses with no further grammar work.
  • The includer rule lists were NOT touched — the five rules bind the same components — and neither was the TOKPathRefKnown gate. Five includers, not three: DOG-037 wired RSTT.c.rl and TXTT.c.rl to the same include, so their twins are regenerated too and their existing DOG-036/037 case lists re-verify every pin under the new seg.
