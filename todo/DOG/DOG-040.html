Two StrictMark verbatim sites hand their body out as ONE flat token and never run the link recognizer over it, so a reference written there fuses no F and clicks nowhere: an inline code span (MKDT.c:47 MKDTonCode, body 'H', DOG-024) and a meta-pair value (MKDT.c:238 MKDTEmitValue, value 'S', DOG-026). Backticking a path is the house style (index, todo) and the meta keys See: Sub: Dup: On1: Rev: Rep: exist to point at other tickets, so the two documents whose job is to point at things are exactly the ones whose pointers are dead — in the pager, in bee http and in bee lindex alike.

Input

Context

Found 2026-08-16 reading bee http pages of JAB-036 and JAB-032 off bee-journal: the same JAB-035 links five times in prose and not once on line 5, and no backticked path on JAB-032 links at all.

  • Repro A — /bee-journal/todo/JAB/JAB-036.mkd, line 5 See: JAB-035: paints tok-T See: + one tok-S JAB-035, no F; the same code in prose from line 7 links fine.
  • Repro B — /bee-journal/cat/todo/JAB/JAB-032.mkd, line 52 ` test/fsw.js : paints tok-G backtick + one tok-H body + tok-G backtick; fTokens yields 16 F` on that page and not one of them is a backticked name.
  • Every NEIGHBOURING verbatim context already fuses, so these two are the outliers, not the precedent: *test/fsw.js* -> F, a `` `-fenced ` block -> F, a 4-space indented block -> F, test/fsw.js -> nothing, See: test/fsw.js` -> nothing.
  • FREE.rl.c:47..59 mirrors MKDTonCode deliberately (DOG-024: "a comment and a .mkd page tokenize their markup identically"), so a comment's code span is dark the same way.
  • Consumers see only what the lexer emits — bee's index/hook.js fTokens is the ONE recognizer by the 2026-08-15 ruling, and index/lindex.js mints its LINK rows off the same call — so a ticket named ONLY from a meta pair gets no backlink row either.

Goals

A nav target written inside a code span or a meta value fuses one F, exactly as the same bytes do in prose; nothing else about either body changes.

  • Positives to pin: ` test/fsw.js , JAB-035 , dog/tok/LINK.rl:70 , See: JAB-035, Rep: ///jab, On1: DOG-024`.
  • Negatives to pin: ` GPL-2.0 , ISO-8859-1 , .. , foo (no evidence), a bare --flag ` — every DOG-036 non-ref stays dark inside a span too.
  • Unchanged: the delimiters stay 'G', non-ref body text keeps its own tag ('H' in a span, 'S' in a value), and NO inline layer opens — no emphasis, no nested span, no punctuation splitting.
  • Repro A and B click through end to end under bee http, and bee lindex mints rows for a code named only from a meta pair.

Constraints

  • MAIN TREE quickjab/dog — explicit permission for this ticket only, the DOG-039 precedent; dog/tok + fixtures (dog/test/TOK01.c) only; NO VC ops of any kind.
  • Ragel only, never a hand-written byte scanner; regenerate every touched twin with ragel -C <X>.c.rl -o <X>.rl.c -L.
  • bee needs NO edit: it already resolves whatever F it is handed. A fix that touches bee2 is the wrong fix.
  • ctest green in quickjab/build-bee2; test/refline, test/perma and test/click identical to baseline.

WIP

Design decisions

ONE new primitive, two call sites, no grammar change and no precedence change. TOKLinkText(u8 tag, u8cs text, TOKcb cb, void *ctx) sits beside TOK.h:77 TOKSplitText — the existing "re-grain a verbatim blob under a caller-chosen tag" primitive — and is backed by a LINK-only ragel machine over the already-shared LINK.rl definitions: each fused nav target emits 'F', every run between emits tag.

  • MKDTonCode (MKDT.c:59) swaps cb('H', body) for TOKLinkText('H', body, ...); MKDTEmitValue (MKDT.c:246) swaps cb('S', val) for TOKLinkText('S', val, ...); FREE.rl.c:52,59 takes the identical edit so a comment span matches a page span, as DOG-024 requires.
  • DOG-024's "never re-lexed" and DOG-026's "the inline layer never runs in a value" both HOLD in the sense that matters: only nav targets fuse, so the body still paints as literal. What those rulings guarded against was markup opening inside a verbatim run, not a path staying findable.
  • MDT.c.rl's scanner is NOT touched, so its ruling that "a decorated ref stays in its span" — the code rule outranking relknown by length — remains exactly true; this ticket only changes what the span HANDLER does with a body it has already isolated.
  • keyvoid and dotdot come along free from LINK.rl, so ` GPL-2.0 and .. ` stay dark inside a span with no guard of their own.
  • Fenced and 4-space-indented blocks already fuse and are NOT touched: they are the consistency argument for the change, not a risk it introduces.

Outcome

Done in the MAIN TREE quickjab/dog (edited, nothing staged, no VC op run). A code span's body and a meta pair's value keep their verbatim tag and now fuse the nav targets written in them.

  • dog/tok/TOKL.c.rl (new) — the LINK-only scanner. It binds LINK.rl's components and NOTHING else, in the includers' own order: a fused ACCEPT emits 'F', every run between refs emits the caller's tag in ONE token, and code keyvoid / dotdot / the catch-all any8 emit nothing but grow the pending run. TOKLFuse flushes that run, fuses the ref and reopens past it; a TOKUNCUT-trimmed anchor or an ext-gate miss simply stays run.
