DOG-006: StrictMark inline markup inside code comments

Run the StrictMark inline grammar over comment BODIES in every language at the one shared seam — FREEu8sFeed('D', …), which each *onComment already calls — so ` code , strong, emph, del, link light up uniformly with no per-grammar edits. First split the comment DELIMITER (//, /* /, #, --, ( *), %, ;) into its own token, kept as plain comment and NEVER fed to the inline parser. Inline spans only (block markup is line-anchored); mirrors the existing sticky-F` issue-key overlay.

Input

Context

  • Every lang's onComment funnels the WHOLE comment (delimiter included)

    through FREEu8sFeed('D', tok, cb, ctx) → S/L/P/W split under a D overlay, with only the F issue-key (ABC-123) staying sticky (dog/tok/FREE.c, dog/tok/CPPT.c:CPPTonComment).

  • StrictMark's inline layer is a regular language of regex-matched brackets —

    stateless, line-local, total (any8 catch-all) — so it is safe run on an isolated comment span (wiki/StrictMark.mkd; MKDTInlineLexer in dog/tok/MKDT.c.rl, same TOKcb protocol FREE already uses).

  • Feeding delimiters in mis-fires: C's /*strong*/ parses / + *strong*

    as a strong span (the ragel * opener has no whitespace lookbehind) — the concrete reason the delimiter must be split off before the inline parse.

Goals

  • One seam lights up all ~40 langs: FREEu8sFeed gains a StrictMark mode (or

    a sibling MKDTu8sFeed) that runs MKDTInlineLexer over the comment body.

  • The comment delimiter is a SEPARATE token (kept D), passed straight

    through, never entering the inline parse — the explicit ask of this ticket.

  • Inline spans only: ` code /strong/emph/del/link`; block

    shapes (##, - , fences) stay out of scope — a comment is a fragment, the block layer is line-anchored (MKDTBlock/MKDTLexer).

Constraints

  • Ragel only, no hand-scanning (ABC §"never manual parse"); reuse

    MKDTInlineLexer, do not re-derive the grammar.

  • No per-language grammar edits — the value is the single FREE seam; the

    delimiter split must be centralized too (see design), not smeared over 40 onComment sites.

  • Table-driven: extend dog/test/TOK01.c ({"// *x*\n", …}-style expected

    tag strings), keep the existing plain-comment cases ("// comment\n" → DDDDW) green.

WIP

Design decisions

  • Chosen seam: EXTEND FREE (its ragel machine) with StrictMark inline

    bracket rules, not a separate MKDT pass — FREE is the sole comment-body scanner (all 55 langs) and already detects issue keys, so one machine keeps F AND adds markup in a single pass. Code span → H, emphasis/strike/link → G. No backslash-escape rule (comments must not eat \n/\t).

  • Tag policy RULED: markup pops. FREE_overlay_cb keeps F, G, H sticky

    through the D overlay (mirrors the existing sticky-F precedent).

  • Delimiter split lives in each grammar (ragel), not a central C classifier

    (would be manual parsing in C — forbidden). Spine helper FREECommentFeedN(tok, olen, clen) carves delimiter+body with a_head/ a_tail/a_part and feeds only the body; FREECommentFeed(open,body,close) for variable-width delimiters. Single-form langs = one-line .c change; multi-form = split grammar actions by width + regen (CPPT is the exemplar).
