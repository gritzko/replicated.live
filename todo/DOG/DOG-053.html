StrictMark has no tables: a GFM pipe table on a .mkd page (impII/ai/algo/Battle.mkd, 9 such tables over the impII wiki) lexes as paragraphs and renders as one run-on paragraph. Ruled 2026-09-28 (gritzko): a table row is a block leaf like any other, its markup is ONE 4-char quad — the pipe padded in any column (| , | , | , |) — and the delimiter row has its own full quads, |--- and |:--, as the ruler has ----. The cells are the leaf's content; the | between them is inline markup, escapable. This ticket is the block grammar and the tokens; MARK-019 builds the <table> off them.

Input

Context

  • MKDTB.c.rl main := prefix ( list | heading | fence | hrule | refdef | meta )? has no row shape, so | 0 | pike | leaves mark empty (a paragraph).
  • mark/strict.js (bee) reads the 'R' quads MKDT cuts and classifies the marker by its chars (strict.js::markList), so a new quad is visible to JS once it is an 'R' token.
  • The cell dividers must reach JS as tokens of their own, so the parser splits cells without rescanning bytes (strict.js:1); \| and a | inside a code span must not split.

Goals

  • Row quad: | + 3 spaces in any of the four columns, after any (INDENT|QUOTE)* prefix, cut as the line's marker quad ('R').
  • Delimiter quad: |--- and |:-- (a full quad, no padding), the rest of the delimiter row being its content.
  • MKDTmarkRow(mark) / MKDTmarkDelim(mark) inquiries in MKDT.h, beside MKDTmarkHRule.
  • In a row's (and delimiter row's) rest, every unescaped | outside a code span is a token of its own; \| stays an escape, ` a|b ` one code token.
  • Off-grammar stays a paragraph: | 0 | pike | (first quad | 0 ), |-- short, |---- long? — decide and test.

WIP

Design decisions

  • The pipe quad is a prefix-free LEAF, not a container: a row holds no child blocks, and a table ends at a blank, another marker or a dedent (the one continuation law).
  • Only the first column's alignment rides the quad (|:--); the rest of the delimiter row (|:---:|---:|) is content MARK-019 reads.
  • Spec: wiki/StrictMark.mkd gets a row line in the block-element table and a Tables section — drafted into this ticket's Outcome for gritzko to apply.
  • Off-grammar: |-- (short) is a paragraph; |---- is a delimiter row — the quad |---, the 5th dash its content (|------|--|).
  • The cell | is tagged 'G', the inline-delimiter tag; \| stays 'P' (its token span \|), a code span's | stays in its 'H'.
  • MKDTRowLexer (Ragel mkdtr) cuts the rest at each cell | first, then lexes each cell inline, so no span crosses a cell.
  • A row obeys the one continuation law: a line one quad deeper continues its cells, through the same row lexer.

Tables

A table row is a leaf whose marker is one | padded with spaces in any column (| , | ); the delimiter row has full quads of its own, |--- or |:--, as the ruler has ----. The cells are the leaf's content: every | between them is inline markup that binds tighter than any span, escapable as \|, inert inside a code span.

  • Only the first column's alignment rides the quad; the rest of the delimiter row (|:--:|--:|) is content.
  • | 0 | (a 3-char pad) and |-- (short) are off-grammar, so the line stays a paragraph.
  • A table ends at a blank line, another marker or a dedent; a row's cells continue one quad deeper.
