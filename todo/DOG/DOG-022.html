DOG-022: promote spot/RXLITS into dog/tok + jab tok._rx_lits binding

Now:
OPEN

Input

Context

RXLITS (regex → literal runs, the Russ Cox trigram-filter feed) sits in beagle/spot/RXLITS.c.rl but is another grammar for dog/tok by nature: a self-contained ragel machine over pattern bytes, depending on abc/INT.h only. /todo/SPOT/SPOT-003's JS regex filter needs it, and jab links only the dog submodule + abc-core — spot's C is out of reach from JS land; hand-parsing regex in JS is banned.

  • Interface today: RXLITSu8sDrain(pattern, cb, ctx) — cb gets each literal byte, flush=YES at meta-boundaries, final flush always.
  • jab's tok surface is one leaf (tok._tok_parse_into, tok.cpp); the binding follows that pattern.

Goals

Move the machine into the dog submodule and expose it to JS.

  • Relocate RXLITS.c.rl/RXLITS.h from beagle/spot/ to dog/tok/ (DOG-002 relocation model); spot's C includes update.
  • EXTEND the grammar to a structural token stream (gritzko 2026-07-18): nesting like ((a|b)c|d) makes flush-only insufficient — emit group open/close, alternation bar, quantifier, literal-run events; the ragel machine stays the ONLY regex reader.
  • jab binding tok._rx_lits(pattern) → the event/token stream; JS folds it: concat = AND, | = OR, ?/*-quantified subtree = contributes nothing → an AND-of-OR trigram filter (CNF), consumed by /todo/SPOT/SPOT-003 candidates.
  • Update dog/INDEX.md + spot includes; both trees build; C consumer (GREP.c regexlits) migrates or keeps a compat shim.

Constraints

  • VERIFY the C consumer's alternation semantics while relocating: flat-flush foo|bar yields two intersectable runs → over-filtering, silently dropped matches (GREP.c regexlits may carry this today; check, ticket separately if real). The structural stream is the fix; the fold's truth table is the repro.
  • The ragel grammar is the truth — no JS reimplementation, the binding is a thin leaf.
