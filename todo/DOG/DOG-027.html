DOG-027: Pup becomes the LSM — memtable in libdog, jab binds only, idxmaint retires

Now
DONE

The run-stack machinery exists four times: HIT* merges (abc), DOGPup* does fs housekeeping (dog), idxmaint.js drives a ladder in JS, and abc.index's JS body in jab/cont.cpp re-implements scan, mmap, naming, sort and a min-heap of its own. Collapse it: Pup absorbs the memtable and becomes the LSM, HIT* keeps the merge, jab does marshalling only, and the ladder policy becomes C defines. Rulings 2026-08-02 (gritzko): memtable goes to the pup layer; jab must only do the bindings; policy is C defines — 64 files max, 1/8 ladder; idxmaint likely retires wholesale.

Input

Context

  • Puppies already ARE runs: <10-RON64 seqno><ext> files of fixed-size sorted records, one stack per dog under .be/, covering keeper's pack indexes, graf's DAG runs and spot's postings (jab/dog/DOG.h :611-632).
  • Pup deliberately stops at fs level — "the typed merge during compaction stays caller-side (HIT*Compact); this API only does fs-level housekeeping" (DOG.h:625).
  • The overlap: the run-stack fs layer exists THREE times (Pup, idxmaint, cont.cpp), seqno allocation three times in TWO formats, and the 1/8 ladder twice (HIT*Compact implements it, isCompact re-derives it from io.stat).
  • cont.cpp:654 names runs String(seq).padStart(8,"0") — off the store convention (DOG_PUP_SEQNO_W is 10 RON64 chars) and sorting BEFORE ron60 names, so a freshly compacted run reads as the oldest and newest-wins inverts.
  • idx.compact() hands the whole stack to a leaf that throws above 64 runs (index.hpp:88,145), so it cannot repair the very shard it exists for; idxmaint works around that with a youngest-64 window.
  • abc.index.compact() has NO production caller: three sites, all jab/test/index.js; the only on-disk .flush() in be/ is a test fixture (be/test/store.js:137).
  • shared/graf.js compacts *.graf.idx runs the native C keeper wrote — one shared code path removes that class of hazard entirely.
  • abc carries TWO heap-merge twins: HIT is live (instantiated in jab/hit.hpp, bound as the _seekrange_/_compact_ leaves, reused by BOXx.h) and MSET has no production caller yet is still built/tested/fuzzed (open /todo/ABC/ABC-022).
  • LSM.h/LSM.c is NOT a third twin and stays: it is a byte-stream merger over u8xs/u8ys slicer callbacks with live callers — abc/FILE.c:1268 (FILEScanSorted → LSMSort) and dog/ULOG.c:16,1065,1080 (LSM_MAX_INPUTS, documented at ULOG.h:306,328).
  • The ladder therefore exists THREE times: MSETIsCompact/Compact, HITIsCompact/Compact, and idxmaint.isCompact/compactStep (plus cont.cpp's JS compact driving the same leaf).
  • HITx.h:329 carries the verdict verbatim — "ABC-015: near-duplicate of MSETIsCompact/Compact (different NOROOM codes); unifying the LSM-ladder logic into one home is a follow-up" — so HIT's ladder was copied from MSET's in the 2026-07-07 review and unification was deferred, not done.
  • The equal-key group primitive (MSETTopZ/MSETAdvZ, with the ABC-015 caller-supplied z) sits on the DEAD side; HITTops/HITAdvanceTops (HITx.h:83-119) is its live twin.

Goals

Pup owns the LSM; jab owns nothing but the crossing; the policy numbers live in C.

  • Pup gains the memtable: put, sort, flush into a fresh pup, thin-tail, close — the whole write path beside its existing scan/mmap/create/close.
  • Ladder and caps as C defines (64 files max, 1/8 size-tiered), driving HIT*Compact; above the cap the leaf simply THROWS (ruling 2026-08-02) — no windowing, no repair cascade.
  • A stack past 64 runs is damaged or foreign, not a state a ladder-enforcing writer can reach; the cure is to drop the runs and re-derive, exactly as for an unmarked run.
  • One naming scheme: the 10-char RON64 pup_key from a monotonic allocator (keep_next_pup_key shape), never stat-and-bump.
  • abc.index(lane, {dir, ext}) reduced to a handle: no runs array, no _seq, no naming, no mem.sort(), no JS min-heap cursor (cont.cpp:807-861 is a hand-rolled twin of what HIT* IS).
  • shared/idxmaint.js retires; its only non-duplicated part is keeper's 0xF PACK coverage probe and tail rebuild.

Constraints

  • This INVERTS rule #4 for the subsystem: state moves to C and JS holds a handle, where API.md today says all state is JS and native leaves marshal only — say so explicitly or every binding author re-derives the JS machinery.
  • No on-disk format change: runs stay raw fixed-size element arrays; only the NAMES of new runs change. Legacy 8-wide padStart runs are DELETED on open and the family recomputes (ruling 2026-08-02) — no dual-width name parsing.
  • Callers keep the abc.index(lane, {dir, ext}) surface — store.js, graf.js and TODO-003's metaidx.js must not notice the move.
  • Lane stays a per-family property, never a global switch; the meta.idx family of /todo/TODO/TODO-003 joins as a pup stack like the rest.
  • store.js:222 sits under EVERY read verb: a read-only or EROFS store must still open, so the best-effort posture survives the retirement of the module that holds it today.

WIP

Design decisions

  • 64 is a backstop, the ladder is the policy: a strict 1/8 stack never approaches 64 runs, and C already throws above it — the JS side stops having an opinion instead of inventing a stricter one.
  • OPEN_CAP = 32 dies: it compensated for the ladder not being maintained on write, which stops being possible once one layer owns both.
  • Layer split after the collapse: HIT* = merge, Pup = fs + memtable + ladder, jab = marshalling, be = which shard and which family. No third implementation anywhere.
  • Memtable shape (ruling 2026-08-02): ONE 4 KB buffer, PAST holds the sorted part, DATA the appended tail; on each query or op, sort DATA alone when it is under 512 bytes (two sorted slices) else sort both and collapse DATA into PAST (one sorted slice).
  • Puts just APPEND — duplicate keys are the merge's and the read's problem, since both see multiple slices; the PAST+DATA collapse should dedup.
  • DATA is sorted with INSERTION sort — QSORT*InSort(), made public for this (ruling 2026-08-02): 32 rows max costs <=496 compares over 8 hot cache lines, beats the introsort path at that size, and is STABLE, so equal keys keep arrival order.
  • Dedup keeps the LAST of an equal run (ruling 2026-08-02): after a stable sort a duplicate group reads oldest->newest, so keep-last IS arrival-newest. sDedup keeps the FIRST today and must change.
  • sSort must NOT be used for DATA: it is an introsort, stable only below QS_ISORT_THRESH 24 (QSORTx.h:22-58, QSCore partitions above that), and a 512-byte DATA window is 32 rows — just past the cutoff.
  • With DATA deduped, the collapse is a uniform merge: ties between PAST and DATA go to DATA, the younger side — the same younger-wins rule HIT applies across runs.
  • The memtable enters a query as one or two more HIT runs, never a special-cased path.
  • 512 bytes is a C define beside the 64-file cap and the 1/8 ladder.
  • Buffer full => flush: mmap a tmp file, trim, remap, add it as a pup with a timestamp key; the rename is atomic, so a torn flush leaves a dot-file and nothing else.
  • Unflushed puts die with the process and that is fine — every index is re-derivable (keeper.idx from packs, meta.idx from files); flush timing is performance, not correctness.
  • Crash safety is a PUP concern (ruling 2026-08-02), not a caller's: no consumer hand-rolls tmp/rename/unlink ordering, and ingest.js-style direct writers stop existing by construction.
  • Every run carries a MARKER entry (ruling 2026-08-02): a run without its marker is incomplete, so its family drops it and re-derives — the rebuildability of every index is what buys this.
  • Flush protocol (ruling 2026-08-02): the caller finishes indexing, writes the marker, then tells Pup to COMMIT — which force-flushes the remaining incomplete page, trims and renames. The marker lands on that same tail page, so its presence after a commit is exactly the evidence the page went out.
  • ALL marker handling is caller-side (ruling 2026-08-02): Pup does fs housekeeping and does not know what is being indexed, so each index family writes its own marker entry in its own entry vocabulary and checks it on open.
  • Pup's side of the contract is only commit — force-flush the incomplete tail page, trim, rename — plus the fd/mmap lifecycle; deciding a run is incomplete and dropping it is the family's call.
  • The memtable is a dict entry like any pup, keyed ALL-ONES (ruling 2026-08-02): it sorts last, which is its true age (youngest), and it leaves 0 alone as DOGPupSeqno's not-found answer.
  • The memtable's file stays dot-named until commit renames it into <10-RON64><ext>, so a crashed memtable can never be re-scanned by DOGPupOpenAll as an oldest run of unsorted bytes; the missing marker is the second line of defence.
  • Dict invariant: every entry below the reserved key is an immutable, marked, sorted run, and at most one entry above it is the live memtable.
  • Keyed-winner resolution (ruling 2026-08-02): X(HIT,Step) and the heap ops go INTERNAL and take X(,csps) — a slice of POINTERS to slices. The X(,cs) entries sit in a contiguous on-stack array built oldest-first and never move; the heap permutes only the csp pointers, so comparing two csp values IS comparing age. Ties resolve to the highest csp (youngest).
  • Age is then true by construction, not by kernel behaviour: no PROT_NONE arena, no MAP_FIXED sequential mapping, no exhaustion or re-pack policy, no rule about where the memtable maps.
  • X(,csSwap) stops being an instantiation prerequisite (HIT.md calls it "HIT's one prerequisite"; jab/hit.hpp:35 exists only to supply it for kv32/kv64/wh64) — pointer swaps are builtin, 8 bytes instead of 16, at one deref per compare. wh128cscp (WHIFF.h:77) is the precedent for the pointer-to-slice type.
  • The winner rule must hold identically in Merge, Seek, SeekRange's drain and Compact: if a query and a compaction disagree, the value visibly changes the moment a merge runs.
  • Merge must EMIT the winner rather than an arbitrary tie member — today ties are only identical full elements so any will do; a keyed lane makes the choice load-bearing.
  • Intra-run duplicates stay uncovered: two rows with one key inside one run share a cs, so csp order says nothing about them. The memtable's PAST+DATA collapse dedup is what keeps them out of a committed run, which makes that dedup correctness-critical and obliges it to keep the arrival-newest.
  • Pup stacks are lane-TYPED ON CREATE (ruling 2026-08-02), the same machinery as every jab container: the .lane tag picks per-lane _pup_<lane>_* leaves; the earlier "dogpupsync bound once via the reserved key" wording is dead — sort/dedup/collapse is a per-lane C instantiation selected by the lane, no stored hook, no per-call type.
  • Handle split (ruling 2026-08-02): dir and ext hang on the JS object as plain JS strings; the C-land object is the kv64b dict, 64 cells, malloced, behind the handle.
  • rw opens hold the memtable as the LAST dict entry, one of the 64 cells; ro opens have none. At query time the memtable is 1 or 2 more runs (PAST, plus DATA when non-empty).
  • Compaction is triggered by commit/flush IN C LAND (ruling 2026-08-02): Pup runs the ladder after seal; the JS user knows NOTHING about the state of the ladder.
  • Lanes to instantiate: kv64, wh128, u64; spot's trigram lane is u64.
  • Marker row is the CALLER's concern end to end (ruling 2026-08-02): the family puts it in its own vocabulary (it lands as the sealed run's tail), checks it on open via per-run views, drops failures.
  • JS API (ruling 2026-08-02), the whole surface — today's runs, _seq, mem, flush, compact all die:
const idx = abc.index(lane, {dir, ext});  // scans <dir>/*<ext>, oldest-first
idx.put(k, v);          // pair lanes; idx.put(v) scalar BigInt for u64
idx.commit();           // family put its marker first; C collapses, seals, compacts
idx.get(k);             // point lookup -> val | undefined (newest wins)
idx.range(lo, hi, cb);  // ordered [lo,hi) scan, cb may return "enough"
idx.seek(k);            // cursor at first el >= k; .next() pulls merged rows
idx.count;              // committed runs      (open-time marker audit only)
idx.run(i);             // read-only lane-typed view of run i, oldest-first
idx.drop(i);            // unlink a markerless run; idx.drop() = all, re-derive
idx.close();            // munmap runs + memtable, free the dict
  • OPEN: whether keeper's coverage probe and tail rebuild (coverage/listLogs/maintain) follow Pup into C or stay in shared/ingest.js — gritzko's call.
