BEE-019 shortens the permalink to path:LINE:HASHLET — decimal line, then 2..10 ron64 chars, odd lengths allowed. dog/tok/LINK.rl:94 commit = ":" ron64{1,4} ":" (ron64 ron64){2,5} fuses only the old :OFF:HASH4+even shape, so a :58:mJ anchor is cut off the F token and the door never sees it. One rule changes; the six lexers that include LINK.rl are regenerated.

Input

Context

  • LINK.rl:93 line = ":" [0-9]{1,10} (":" [0-9]{1,10})? and :94 commit are the two anchor branches (anchor = line | commit); the JS side (door.js splitRef) tells them apart by segment 2 carrying a non-digit.
  • Includers: FREE.c.rl:93, MKDT.c.rl:50, MDT.c.rl:43, TOKL.c.rl:37, RSTT.c.rl:49, TXTT.c.rl:27; the generated *.rl.c are checked in (ragel -C X.c.rl -o X.rl.c -L, dog/INDEX.md:239).
  • DOG-034 caps an anchor at 10 chars and trims an over-long tail; :58:mJ is 6.

Goals

  • commit = ":" [0-9]{1,10} ":" ron64{2,10}; the header comment at LINK.rl:20 follows.
  • x.mkd:58:mJ, x.mkd:58:m7Q, BEE-005:58:mJ each fuse as ONE F token in every includer; x.mkd:58:20 still fuses (via line, unchanged bytes); the 10-char cap still trims.
  • ninja && ctest in the quickjab build green; the TOK tests amended only where they pin the old even-length rule.

Constraints

  • A git worktree of ~/src/quickjab/dog (and of ~/src/quickjab, dog/ symlinked in), built as BEE-019's build-bee3; no main-tree edit, no VC ops.
  • RED first: a tok probe showing :58:mJ cut short on the base.

WIP

Design decisions

  • Segment 1 goes digits-only in the grammar (it IS a line now); the JS keeps deciding old-vs-new nothing — the old form is migrated, not read (BEE-019 ruling 5).
  • oldcommit — BEE-019 TEMPORARY, gritzko 2026-08-16: the grammar CARRIES the retired ":" ron64{1,4} ":" (ron64 ron64){2,5} alongside the new rule for the length of the migration. Without it a SLASHED old permalink (index/hook.js:1cG:xoo4) fuses no F token at all — the half-eaten anchor makes the whole ref retreat to crumbs — so bee reperma cannot see it and would need a hand-rolled byte walk, which is exactly what "no manual parsing" forbids. The JS never reads it: door.js splitRef stays digits-only, so an old link still lands on the file and nothing follows it.
