dog/tok/LINK.rl knows two evidence sources — a KNOWN extension (relknown) and an anchor past a slash (relanch/rooted) — and a wiki shortcut link carries NEITHER by design: wiki rules that a page is linked "with a bare [Page] or [/pocket/Page]", ext-less and anchor-less. So the one link form the wiki spec mandates is the one form the grammar cannot see, and every [/wiki/Bro], [Plan], [README], [/meta/todo] in the tree paints as loose prose crumbs between two 'G' brackets. The BRACKETS are the evidence here, exactly as an ext or an anchor is elsewhere — a source the DOG-036 spec table simply lacks, so admitting them loosens nothing: a bare /wiki/Bro outside brackets must stay prose, and does.

  • The gap is EVIDENCE-LESS forms only — [claude-code/main.js] (known ext) and [/wiki/Bro:12:Yl] (anchor) already fuse whole, so the brackets were never the obstacle; the missing rule is the one that lets the brackets BE the evidence.
  • rooted = ("/" | "./") relanch is what refuses /wiki/Bro: DOG-036 makes the anchor mandatory after a / head precisely so a URL path (https://foo.io/bar.c) stays prose, and a bracketed page name is collateral.

Goals

A bracketed shortcut link fuses ONE F over its inner path, in every machine that includes LINK.rl; the brackets stay 'G' and nothing outside brackets moves.

  • Positives to pin: [Plan], [README], [/wiki/Bro], [/meta/todo], [/todo/GET/GET-041] (the PATH fusing, not just the code), [claude-code/main.js], [/wiki/Bro:12:Yl].
  • Negatives to pin: bare /wiki/Bro and [https://foo.io/bar.c] stay prose, [] and [ ] fuse nothing, and every DOG-036 non-ref stays dark inside brackets too ([GPL-2.0], [ISO-8859-1], [..], [--flag]).
  • Unchanged: a StrictMark reference-definition line and the [text](url) inline form get a Design-decisions ruling and a fixture either way.

WIP

Design decisions

The brackets are a THIRD evidence source beside the known ext and the anchor, and wikied spans them, so it outranks every inner rule by length and needs no tie guard. Where the brackets end is the MACHINE's to say: wikied references three marks an includer defines (wiki_open wiki_close wiki_end), so the emitter paints boundaries the grammar set and no C counts a bracket byte (gritzko's ruling 2026-08-16, StrictMark and Markdown alike).

  • THE MARKS, not pointer arithmetic. A first cut sliced tok[0]+1 / tok[1]-1 in TOK.c; that is the manual parsing the house rules forbid, and it also hard-codes a one-byte delimiter. wikibody = (wikipath - (code keyvoid)) >wiki_open %wiki_close and wikied = "[" wikibody "]" %wiki_end stash p at each boundary instead, and TOKLinkBracket takes the three finished slices. Ragel resolves action names AT INCLUDE TIME, so the three action blocks stand ABOVE include LINK "LINK.rl"; in every includer.
  • A LABEL IS NOT A PAGE. [text](url), [x][1] and [OPEN]: are the same bracket shape, so wikied ("(" | "[" | ":") matches one byte longer, wins, fholds the follower back and emits the span exactly as before. The : arm earns its place twice: it keeps a ticket header's [OPEN]: status marker dark AND a StrictMark reference DEFINITION's key dark, while the definition's target past the : fuses on its own evidence — which is the reading both want.
  • - (code keyvoid) is the ONLY guard inside the brackets. seg admits digits and dashes (DOG-039), so [ISO-8859-1] would otherwise fuse; the difference voids exactly the shapes DOG-036 already voids bare, and [GPL-2.0] never matched wikipath at all (.0 is no extany — a seg cannot start with a digit).
  • THREE machines, not six. RSTT is left alone because reST spells its citation [x]_ and a bare [x] is literal text, so a StrictMark reading would be wrong there; TXTT has no markup tag to give the brackets; TOKL is DOG-040's verbatim re-grainer, whose contract is that NO inline layer opens in a code span. FREE, MKDT and MDT are exactly the machines that read StrictMark.
  • [Page] in FREEInlineMarkupTest was pinned GDG by DOG-006 and is now GFG — amended on gritzko's say-so 2026-08-16. The same suite already pinned [ABC-123] -> GFG, so bracketed nav targets fusing was established; [Page] was the outlier, and DOG-006's own claim (delimiters stay 'G') is untouched.
