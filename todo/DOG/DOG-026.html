DOG-026: MKDT meta-pair leaf block Key: value

Now:
DONE

Tickets now carry meta (assignee, due date, milestone) as Key: value lines under the header, per todo; the leaf is specced in StrictMark §"Meta pairs". The tokenizer must emit it as its own block type so renderers and view verbs stop reading meta as paragraph prose.

Input

Context

  • Spec: KEY ':' GAP VALUE, KEY := [A-Z][a-z][a-z] at line start; value verbatim to EOL, no inline layer.
  • Registered ticket keys (todo): Who: Due: For: Ask: Env: Rev: Dup: Sub:; the grammar is key-agnostic.
  • Today such a line lexes as paragraph text: greps work, but rendering and the :todo view (BE-038) see prose.
  • Ticket status moves from the header into a meta pair (ruling 2026-08-02), so this leaf carries the board's primary query, not just decoration.
  • The meta-pair index TODO-003 extracts by line regex until these tokens land, then swaps over; its row carries a 4-bit kind, so the lexer's kinds are what it can index.

Goals

  • MKDTLexer (dog/tok/MKDT.c) emits a distinct meta-pair leaf token for ^[A-Z][a-z][a-z]: lines.
  • A line-start escape (Due\:) keeps a paragraph a paragraph; StrictMark-wins otherwise.
  • Repro-first: fixture with a ticket header + meta block + prose-with-colon lines, asserting token kinds.
  • Each indexable leaf carries a distinct kind nibble — meta pair now, -[ ] todo marker next for the board badge (TODO-002) — one shape the index can key on.

Constraints

  • New alternative in the line-start scan before the paragraph fallback; ragel/regex, no hand-rolled byte scanner.
  • Marker is exactly 4 chars (Who: + gap), consistent with the DOG-024 quad discipline.
  • Renderer support (key–value row in mark) is a separate MARK ticket once tokens land.

WIP

Design decisions

  • Shape-only recognition: key vocabulary lives in todo, never in the lexer.
