libdog hands out two segmentations of the same source. HUNKu32bTokenize emits the lexer's tokens verbatim, so a whitespace run glues a \n to the next line's indent ("\n " as ONE token); the CRDT fold then re-splits every token at each newline (CFOLD.c:832 atok_emit, "so the diff's line anchors work"). Both are libdog's, and they disagree by exactly one boundary per indented line — which is where a permalink's byte falls, so the byte an anchor names is a token start on one side and mid-token on the other (BEE-053). Mint the split once, in the lexer callback, and the two agree by construction.

Input

Context

Found from the http side: index/index.js:879:cn emitted #b41999, a byte no painted span began at.

  • HUNKTokCB (HUNK.c:1561) packs one tok32 per lexer callback; over . \n if the W token is "\n ", spanning two lines.
  • atok_emit (CFOLD.c:832) cuts each token at every \n, the newline staying the tail of the line it ends, so a weave atom never straddles a line.
  • The same split is re-implemented a third time in JS, mark/strict.js tokLines, for the same reason — a page is read as lines.
  • A token that straddles a line has no reader: every consumer — the row index, the painter, the weave, the StrictMark blocks — asks about lines.

Goals

One stream, line-coherent at the source.

  • HUNKTokCB cuts its token at each \n, the newline the tail of the line it ends — atok_emit's rule, moved to where the tokens are minted.
  • Tags are untouched: both halves of a split token carry the tag the lexer gave it, so nothing repaints.
  • Ends still tile the source, strictly increasing (dog/test/HUNK.c:954).
  • The JS re-implementations go: mark/strict.js tokLines reads lines off the stream instead of cutting them.

Constraints

  • No lexer rule changes — this is a segmentation of what the lexer already emitted, downstream of every grammar.
  • atok_emit stays: its own split becomes a no-op for lexer tokens but still covers the unknown-ext 'S' tail, which is not lexer output.
  • Token counts grow by one per line-crossing token; a painted index/index.js page went 962 KB -> 995 KB of html (+3.4%).

WIP

Design decisions

  • In the CALLBACK, not in HUNKu32bTokenize's loop: the callback is the one place every dialect's tokens pass through, so no lexer needs to know.

Outcome
