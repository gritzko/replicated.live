Context

A pup run is a plain array of fixed-width sorted records, so every read binary-searches the WHOLE file: jpup_##L##_get calls L##sFindGE per source (pup.c:344) and HIT##L##Seek/SeekRange binary-search inside each entry. On a cold mapping that is log2(N) random page faults per run per lookup, and a linux-sized index is 14.5M rows (DOG-032). A sparse first-record-per-page ToC turns it into two searches: a hot contiguous one over ~1/256 of the bytes, then one page.

Goals

Runs may carry an optional ToC block; readers that ignore it keep working, and no reader ever mistakes ToC cells for records.

  • Layout [data][toc][len:5]["TC"] — the ToC is appended at seal, so the write path stays one pass and the rename stays atomic.
  • Point lookup and seek narrow to one page before the record search; a run without a ToC falls back to today's whole-range search.
  • Optional at BOTH ends: a lane opts in, and presence is decided per FILE, so a stack holds ToC'd and plain runs side by side with no migration.
  • Measure: cold-cache _get page faults and wall time on a linux-sized index, before and after.

Constraints

  • Pup stays generic over bytes: the row width comes from the lane on every call, nothing about it is ever dicted (DOG-027).
  • Crash contract UNCHANGED: seal is still tmp+rename, a kill leaves a dot-file or a complete run.
  • jab/ is read-only and the JS binding must keep compiling; existing goldens pass UNMODIFIED (no test edits without a report).
  • No new search machinery: reuse L##sFindGE and the lane's Z comparator, per abc "reuse, no parallel impls".

WIP

Design decisions

The ToC is a pure accelerator — derived, droppable, never load-bearing — and its cells are records, so both search steps share one comparator.

  • ToC cell = that page's FIRST RECORD verbatim; cell i covers page i, so no page number and no byte offset is stored.
  • Trailer is 7 bytes: 5-byte little-endian length + magic "TC"; 7 is ODD, so the residue check works for every row width but 1 and 7.
  • The length counts BYTES of the ToC block, not cells: pup then clips with zero knowledge of the row width, and only the SEARCH is lane-typed.
  • Alignment falls out: data a·w + toc b·w + 7 means the ToC starts at a·w, so cells stay naturally aligned and need no padding.
  • Presence is CHECKED, not inferred: last two bytes "TC", toc_bytes + 7 <= size, and (size - 7 - toc_bytes) % row == 0, all three.
  • Opt-in is one new dogpuplane field row (0 = none): raw byte stacks (.keeper packs) and unsorted runs never build a ToC and are never probed.
  • A seal builds one only when FILESysPage() % row == 0 (no record straddles a page) and the run is >= 2 pages; a 1-page run keeps today's shape.
  • Clipping happens in ONE place — DOGPupData / DOGPupDataAll / DOGPupAllData / DOGPupAllRuns return data only, so merge, ladder and dedup never see ToC cells.
  • That clip is the correctness core: ToC cells carry REAL keys, so an unclipped source would feed the keep-last dedup duplicate rows and silently eat data.
  • The ToC narrows the START only: _get searches the ToC then that one page; SeekRange narrows the lower bound and leaves the entry's end untouched.
  • Seal path: build the ToC off the collapsed DATA, FILETrimMap, append ToC+trailer through the fd, optional fsync (DOG-032 durable), then the rename.
  • Compaction reuses it: dog_pup_collapse appends the same block into its heap scratch before DOGPupCreate, so merged runs are ToC'd too.
