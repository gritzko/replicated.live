Input

Context

After DOG-030/031 the linux first index is 10 min, and the LSM seal cadence is a top remaining cost: the pup memtable is ONE 4KB page, so lite seals every 200 rows — git.git measured 3,847 commit() calls at 9ms each (35s of 344s pre-DOG-030); a linux-sized run is 50k seals. Each seal sorts+dedups DATA, writes a run, and climbs the 1/8 ladder — fewer, fatter pages cut all three.

Goals

Memtable size becomes an open-time parameter; the bulk indexer opts into 1MB (ruling 2026-08-13: "sort and flush e.g. 1MB, not 4KB each time").

  • abc.index(lane, {dir, ext, mem}) -> the pup open leaves -> the dog memtable; DEFAULT stays 4KB.
  • The requested size rounds UP to a multiple of getpagesize() at open — never a hardcoded 4096; sub-OS-page memtables (16KB pages on a mac) pay a full page per flush anyway, a multiple sidesteps it.
  • lite IDX_BATCH stops being a magic 200: it scales with (or reads) the page size off the handle — the discipline is "rows put between two commits fit ONE page".
  • Crash contract UNTOUCHED: seal persists a prefix, run rename stays atomic; a kill redoes up to one page's worth of commits, which the lazy contract absorbs (INDEXES.mkd).
  • Measure: git.git seal time before/after; the linux first index total (currently ~10 min) re-timed.

Constraints

  • DOG-027 stays the shape: memtable in dog, quickjab pup.c binds only; DOG-029's writer lock semantics unchanged.
  • jab/ is read-only — its binding keeps working at the 4KB default; no jab edits.
  • The lite resume/fault goldens (mid-commit seal, crash-before-mark) must still pass with a big page — they encode the contract, not the page size; no test edits without a report.

WIP

Design decisions

The size is a plain parameter riding down every put, like dir/ext — nothing about it is ever dicted; sorting reuses the templated abc/QSORTx.h sorts already instantiated for the lanes (a prior from-scratch attempt was rm -rf'd, abc: reuse, no hand-rolled algos).

  • Units are RECORDS and PAGES, never bytes (ruling 2026-08-13): mem counts lane rows; C converts rows to whole getpagesize() pages, rounding UP; 0/absent -> one page, the default.
  • New sized entry DOGPupPutMem(pups, dir, ext, rec, lane, mem_pages) — dog is generic over bytes and knows no row size, so its unit is PAGES; pup.c converts rows -> pages (round UP). DOGPupPut stays and wraps it at the one-page default, so jab's binding compiles and behaves untouched.
  • Seal/commit/reopen never need stored size: they measure the live mapping (FILETrimMap path unchanged); after a seal the next put's lazy open gets mem_rows again from the parameter.
  • Sort dispatch in jpup_sync_##L: small DATA keeps QSORT##L##InSort (stable insertion, the one-page path); big DATA calls L##sSort, the QSORTx.h public introsort, instantiated as kv64sSort (KV.h, in use at DOG.c:682), u64sSort (INT.h), wh128sSort (pup.c QSORTx include). NO new sort code.
  • Introsort is legal for wh128/u64 whose Z totally orders the full row (wh128Z key-then-val, u64Z), so equal rows are identical and sDedup semantics survive an unstable sort.
  • kv64Z is key-only: newest-wins-per-key needs the STABLE sort, so the kv64 lane keeps InSort at any size; kv64 users stay at the one-page default (jab), noted in the lane table.
  • The collapse scratch carve in jpup_sync_##L is sized from the live mapping, not the constant.
  • DOG_PUP_COLLAPSE stays as is (ruling 2026-08-13): the initial indexing never reads, so the read-path fold never fires there.
  • abc.index(lane, {dir, ext, mem}): opts.mem (rows) -> _pup_<lane>_open(dir, ext, mode, mem); the page-rounded row capacity lands on the pupslot, read back via one shared abc._pup_mem(h) leaf, exposed as idx.mem (rows).
  • lite: the INITIAL bulk index alone opens big — 64Ki rows (1MB of wh128); the incremental path keeps the default. Batch discipline stays "rows put between two commits fit the memtable": IDX_BATCH = ix.mem rows, the magic 200 dies.
  • Optional lazy fsync (ruling 2026-08-13: only fsync when done): a DOGPupCommit sized sibling takes durable; the bulk path commits with durable=NO, then ONE final durable commit/close fsyncs the live runs + dir. DOGPupCommit itself stays durable=YES — jab and the incremental path untouched. Crash mid-bulk = a partial index, re-derive; the lazy contract (INDEXES.mkd) already absorbs it.
