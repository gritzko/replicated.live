POST-034: sub gitlink bump flips the parent to selective, dropping its own dirty files

Now:
OPEN
Sev:
HIGH

A commit-all post '#msg' in a tree with a dirty MOUNTED sub commits the sub and the gitlink but SILENTLY DROPS every dirty file of the parent. postSubs records the bump by appending a real put <sub>#<newtip> row to the PARENT wtlog (post.js:740), then postOne → fold-decide.decide re-derives anyPd from that just-mutated wtlog, reads "something is staged", and switches the whole parent commit to SELECTIVE — so each dirty tracked file takes the if (anyPd) keep(...) baseline arm (fold-decide.js:158) instead of add. Data loss is silent: the post reports success. Same class as the bug POST-026 fixed one layer up (mode decided ONCE into ctx._selective, post.js:611-617), which postOne never consults. Contradicts POST (wiki/POST.mkd:64): commit-all is "nothing staged ANYWHERE ⇒ auto-stage all changes, dirty subs bottom-up, the parent last".

Input

Context

  • Live incident (gritzko, 2026-07-29, work/BRO-041/be): a bare jab post from the wt root with view/bro.js modified AND the test sub carrying a modified 13-color-word-wash/run.sh.
  • Result: commit 861d2ee2 holds ONLY the test gitlink bump (+ the sub's own 2c927d8a); jab status still shows ...v view/bro.js, uncommitted, no warning.
  • post.js:733-741 synthesises ulog.append(info.bePath, [{verb:"put", uri:<sub>#<newtip>}]) — its own comment says "postOne re-opens the wtlog, so it sees this just-appended bump row".
  • postOne (post.js:873) calls decideM.decide(info, wtl, reader, narrow); decide reads m.anyPd from the classifier (fold-decide.js:107), NOT from ctx._selective.
  • fold-decide.js:158: mod (tracked + content-modified) → if (anyPd) keep(...) — the file's change is left in the wt, out of the commit.

Goals

  • A commit-all post with a dirty sub commits the parent's OWN dirty files too, in the SAME commit as the gitlink bump (POST.mkd's "dirty subs bottom-up, the parent last").
  • The global mode decided once by POST-026 (ctx._selective) is the authority for postOne/fold-decide; no level re-derives it from a wtlog that the run itself has written to.
  • Genuinely selective posts are unaffected: a real user put anywhere still commits exactly the staged set, sub bumps included.

Constraints

  • Do NOT stop synthesising the bump row (the gitlink-add path in fold-decide reads it); the mode derivation is what must change, not the record.
  • Thread the decided mode in, e.g. decide(info, wtl, reader, narrow, selective) with anyPd overridden when the caller passes one — keep the classifier's own anyPd for every other consumer (status, put, delete).
  • Nested subs (dog/abc) must behave the same at every level — the mode is computed at the OUTERMOST level only.
  • JS ///be/ only; no C twin for this one.

WIP

Design decisions

  • ctx._selective already exists and is already threaded through the whole fan-out — this is a plumbing fix, not a new mode.
