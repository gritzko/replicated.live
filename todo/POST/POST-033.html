POST-033 LONG: migrate PUT's reflog editing into forceful post! — PUT/DELETE go wt-only

Input

Context

Proposal (gritzko, 2026-07-24): PUT/DELETE become wtlog-only editors (stage, unstage, move, base-set as in PUT-014); PUT's reflog-edit forms migrate into a forceful post!. RULING 2026-07-24 backs the split: ulog edits with no wt effect are PUT/DELETE.

  • Falls off PUT/DELETE: non-FF ref reset (put ?br#sha, ?#sha, ?<40hex>), branch tombstone (delete ?feat, -r), remote force-push (put ssh://origin), remote ref delete, the DIS-011 log-only URL row.
  • Survives: put ?./fix create is subsumed by post ?./fix (FF-from-nothing lands at the same sha).

Goals

Settle the verb scoping: either land the migration with answers to every concern below, or reject and keep a narrower explicit ref-editor verb.

  • Decide the shape of forceful ref writes, ref removal, and force push.
  • Update Verbs.mkd + PUT.mkd + POST.mkd + DELETE.mkd once ruled.

Constraints

  • Slot law (Verbs.mkd): the same four slots combine the same way across every verb — a bang must not re-type a slot.
  • GIT-016 RULING: post's non-FF refusal is honest, no force hint.
  • Errors in plain words; no URI bangs (retired 2026-07).

WIP

Design decisions

Concerns to resolve before any code moves; each is a blocker on its own.

  • Fragment collision: POST's # is the commit message (post ?other#msg); reset shapes need #sha. post! ?br#abc1234 is ambiguous; hex-sniffing messages is a footgun; a bang re-typing # breaks the slot law.
  • Direction breach: POST is wt→repo; ref-to-arbitrary-sha (tag an old commit, repair a ref) has no wt in it. Confining post! to cur.tip targets forces checkout round-trips just to write a label.
  • Bang overload: post! already overrides the conflict-marker gate (post.js:881); one bang would arm BOTH "commit conflict markers" and "non-FF clobber" at once. Fragment bangs (#msg! squash, #!) stack on top: post! '#msg!'.
  • Removal homeless: POST writes values, never removes; tombstones either stay in DELETE (breaking the wt-only symmetry that motivates the migration) or need a contrived empty-value post! shape.
  • Safety gradient inverts: force moves from a deliberately-chosen verb (PUT, unconstrained by charter) to a habitual bang on the everyday commit verb; "refused → add !" turns honest FF refusals into silent history clobbers.
  • Strays: the DIS-011 log-only URL row fits neither wt-only PUT nor post!; wire force-push + ingest remote-tracking bookkeeping migrate verbs (churn, harmless).
  • Alternative on the table: keep ONE explicitly-forceful ref editor scoped to ?ref shapes only (a narrower PUT successor), instead of merging force into POST.
