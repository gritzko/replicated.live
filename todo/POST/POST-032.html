Goals

post (and its get leg) treat a pending-edit conflict as a NORMAL merge outcome, per the ruling below: complete the weave, leave the fences, write the con wtlog row, report conflict status — and never exit through the GETCONF hard-error path.

  • One attempt = one con row; a repeated post over an unresolved conflict must not stack duplicate rows.
  • Exit status/report says "merged with conflicts" as a STATE, not an error; the rest of the op (unconflicted files, log rows) completes.

Constraints

  • RULING (gritzko, chat 2026-07-18): "Conflicts for pending edits are not any special. Must merge, mark conflict, make wtlog record. Erring out is not correct." Matches the bare-track post spec (weave uncommitted + FF base, conflict status); the dirty-refusal/hard-err gate contradicts it.
  • get is likely affected the same way (GETCONF originates in the get path; bare get over dirty edits should mark+record too) — fix the shared leg, not a post-only wrapper.
  • User-facing text in plain words; no bare C codes like GETCONF in the error line.
