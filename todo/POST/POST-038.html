be post ///be/ from a wt one commit ahead must advance the main tree's be sub (POST row 4: merge the files into the target, then FF the target's base) — instead it throws JS exception: no changes since base. The routing hole: parseSlots (post.js:148) recognizes a LOCAL WORKTREE target by u.host being truthy, but the canonical main-tree-sub URI ///be/ parses to {authority: "//", host: "", path: "/be/"} — empty host. The target arg falls through to the narrow PATH slot (narrow = "/be/"), post takes the committing leg over a clean wt, and dies on post.js:919 with an error that describes the wrong operation entirely.
