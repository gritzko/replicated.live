Port be's POST (POST) to bee over plain git as the worktree→repo verb that ONLY fast-forwards: every tip it moves is an ancestor of HEAD, a non-linear move is refused. Bare post is today's push (sync.js:124:5f), post 'msg' commits; the new shapes name a branch, a worktree or a remote. Args are git-style refs and paths (RULING gritzko 2026-09-19, GET-065).

Input

Context

  • sync.js:124:5f push has two legs: git push -q to a remote @{u}, and the BEE-045 land on a LOCAL upstream.
  • The land is the PARENT tree's own merge -q --ff-only --autostash at landSite (sync.js:109:5f), then follow there (BEE-064).
  • be's two motions map onto a fork: commit moves the ticket branch (be's wt base), post FFs the track; never coupled.
  • RULING (gritzko 2026-09-19): post 'msg' commits, reversing BEE-037:8:KH's two-verb split; sync.js:85:5f commit is the machinery.
  • sync.js:58:5f descend already commits staged subs depth-first under one message, gitlinks staged in the parent (BEE-056).
  • git refuses to move a checked-out ref from outside; that is why a land is a merge run AT the site, files first.

Goals

  • RULING (gritzko 2026-09-19): post 'msg' commits ALL added and changed-tracked files (commit -a reach); untracked stay out.
  • The commit moves the worktree's branch only; the track moves by a bare post, the two never couple (POST).
  • RULING: a bee-made commit checks .git/be/patch.log for the state of the merge — in-scope parent rows become parents (PATCH-026).
  • RULING: a CRDT conflict row is INFORMATIVE ("this file is suspicious"), never a refusal — the user posting means it is OK.
  • bare post: push's exact behaviour and report line under the new word; detached or no upstream refuses in words.
  • post <branch>: FF-move that local ref to HEAD, no commit, HEAD untouched; an absent branch is created.
  • A branch checked out in some worktree goes the landSite way — files merged first, a conflict refuses BEFORE the ref moves.
  • post <worktree> (a registry //name or a path): the same land, the site named outright instead of found via @{u}.
  • post <remote> [<branch>]: git push <remote> HEAD:<branch>, ff-only as git has it, the rejection verbatim on stderr.
  • RULING (gritzko 2026-09-19): every shape recurses into submodules by default — subs commit, push and land FIRST, the parent last.
  • Behind or diverged refuses in one line naming get / the merge verb; equal tips say so and exit 0.
  • RULING (gritzko 2026-09-21): the report is the status QUAD summary (view/status.js:363:vX) of the rows this run moved.
  • The post <target> <sha> line plus the tally sub counts (sync.js:182) closes the summary; the exit status is honest.

Constraints

  • RULING (gritzko 2026-09-19): never write git's upstream or any other git setting, that is intrusive; @{u} is only READ.
  • So a created branch gets no upstream and a remote push runs without -u.
  • Never --force, never a +refspec: there is no forceful post! in this ticket.
  • git via argv spawn only (stage.js:31); no porcelain text parsing; the ff test is merge-base --is-ancestor (sync.js:132:5f).
  • RED first over an origin+clones+worktrees fixture (a new test/post/run.sh); no existing case edited.
  • RULING (gritzko 2026-09-21): the verb lives in its OWN file verb/post.js; verb/ is the writers, view/ the read-only views.
  • Shared helpers (sync.js, stage.js, the shapeOf arg pick of verb/get.js) are required, never copied or forked.
  • RULING (gritzko 2026-09-21): worked in the MAIN tree, in sequence GET → POST → PATCH; no commit (work).
  • POST lands BEFORE patch: the patch.log parents and new-file rows are PATCH-026's last TODO, not this ticket's.
  • Comments per comment, POST-040 on the change.
