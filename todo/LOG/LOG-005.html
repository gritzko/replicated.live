Context

Profiled 2026-08-06 on the main tree be/: jab log = 0.85-1.06s wall for 287-289 rows, ~3ms/row, all user CPU (syscall time is noise). Instrumented clone work/PROF-log (phase timers in views/log/log.js, call timers in shared/ticket.js, JABPROF=1), main tree untouched.

  • Phase split (ms): appendRow loop 1015, of which ticket.ticketUri 954 (246 calls); history walk 62 (spine 31 + ts sort 30); store.open/resolveTip/pack/feed 3; process start 50.
  • The 954ms is ONE call: be.navCwd(root) — 224 calls x 4.2ms — reached per row via appendRow -> summarySpans -> ticket.ticketUri (shared/ticket.js:86), which asks for the same project root every time.
  • be.navCwd(<explicit dir>) -> be.treeAt(dir) re-reads and re-PARSES the whole .be per call, no memo; cost is linear in .be size: 96890B (///journal) 5.13ms, 12644B (//be) 0.57ms, 114B (a worktree) 0.03ms. Arg-less be.navCwd() (cwd tree) is 0.05ms — only the explicit-dir form pays.
  • Secondary: dag.commitTs (shared/dag.js:283) re-parseCommits per call — 1469 calls, 2039 parseCommit for 287 commits; the newest-first sort in branchHistory alone re-parses n log n times.
  • Measured in the clone: memoising the navCwd(root) result per root -> 1.06s -> 0.15s; + a sha-keyed commitTs memo -> 0.12s (8.8x), parseCommit 2039 -> 855, sort 30ms -> 8ms. Output byte-identical both times (md5 e6e3629b4e516c4b60e23d5a15f1e609 vs the main tree).
  • BE-050 owns the same root cause from the status/work side (its TODO "per-drive anchor-dir memo around treeAt"); this ticket is the log: view's per-row instance of it, fixable in JS today.

Goals

jab log on a 287-commit history renders in ~0.15s or less, byte-identical output, with the per-row .be re-parse gone.

  • A red-first repro that COUNTS work, not wall time: a log drive over N commits with ticket codes must cost O(1) treeAt/navCwd climbs, not O(N) — red today.
  • dag.commitTs costs one parseCommit per distinct sha per drive.

Constraints

  • Memoize AROUND the canonical calls — ALL URI/hash resolution stays on be/core/resolve_hash.js and the be.* bindings; never reimplement, fork or bypass them, never hand-compose a URI.
  • JS only (///be); the native treeAt memo is BE-050/native ground — do not touch beagle/.
  • Memo lifetime: per drive / per process, keyed by the dir; a mutating verb must not see a stale tree (BRO-024: pager context changes only by navigation).
  • No edits to unrelated tests; the full suite must stay green; jab log output must stay byte-identical (md5 above).
  • No commits, no post, no VC ops without an explicit order.

WIP

Design decisions

  • ticket.js navCtx memo is keyed by (ambient.now(), dir) — be.now is the RUN's start ts (loop.js:488 mints it per verb invocation), so the memo dies at every drive start and no mutating verb can read the previous run's tree.
  • dag.js commitTs memo is a WeakMap keeper -> {sha: ron60} — commits are immutable, a non-object keeper falls through uncached, and one keeper never reads another's memo (asserted in the test).
  • Both memos wrap the CANONICAL calls (be.navCwd, keeper.parseCommit); no URI/hash resolution was reimplemented, forked or bypassed.
