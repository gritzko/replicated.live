LIST-001: a github-style list: view — fs ⊕ tree ⊕ per-entry last commit

Now
DONE

list:<path> VIEW (be/views/list/list.js) renders a dir github-style: per entry <wt-marker> <name> <pale-grey last-commit summary> <short rel-age>, files AND dirs. It FUSES the wt listing (ls classifyDir — name + change bucket) with each entry's LAST COMMIT (message + age) from a BOUNDED backward history walk, so a user sees uncommitted state AND commit context in ONE view. list owns the expensive per-entry-commit fuse; ls/tree stay untouched and cheap. jab+libdog bindings + JS ONLY, NO dog binary. Method: Issues.

Input

Context

  • ls: (views/ls/ls.js) is the O(dir) wt lister: a file row is <7date> <verb> <name>, verb = wt bucket, date = the file MTIME (classify.js:53, io.lstat ron60), NOT a commit time; dirs get a BLANK date. libabc+libdog only, no log.
  • tree: (views/tree/tree.js) is the raw committed tree <mode6> <type6> <sha40>\t<name> — no message, no age, byte-parity with native. Too technical for a friendly listing (gritzko ruling 2026-07-05: add a NEW word, not overload).
  • Commit reads already exist as JS bindings: store.js readTree / commitTree / commitParents / parseCommit / descendPath (store.js:468-531), + shared/ changedpaths.js (changedTrees/changedCommits) — the per-commit changed-path diff.
  • views/log/log.js already extracts a commit SUMMARY (first msg line) + author and paints a grey tail (log.js:362-402, TAG_D/TAG_Q) — the message-render model.
  • No short RELATIVE-time helper exists in JS; render.dateCol(ts) (render.js:16, ron.date) is the short ABSOLUTE date ls uses. Ruling: a JS relAge reimpl is fine.

Goals

  • A list:<path> view (be/views/list/list.js): one row per entry (files AND dirs), <wt-marker> <name> left, a PALE-GREY last-commit summary on the far side, a short rel-age at the right; name carries the U click-target.
  • Each entry's LAST COMMIT via a BOUNDED backward walk from the tip: diff each commit vs parent (changedpaths), attribute an unseen entry its FIRST-touch commit, halt when all entries attributed or a walk ceiling hits. ONE walk.
  • A dir's last commit = the newest commit touching ANYTHING under it (attribute a dir the first time any path beneath it changes); the dir gets an age too.
  • Short rel-age (3h/2d/1y) via a JS relAge(ts, now) sibling of dateCol; optionally the message run opens commit ?<sha> on click.
  • list:<path>?<rev> lists AS OF a rev (walk from <rev>); bare/no query = cur tip with the wt overlay (so uncommitted edits show), reusing the diff/tree ref-parse.
  • Register the scheme (help SCHEMES row + views/list/) so :list <path> dispatches as a view, not degrading to ls (cf DIS-060).
  • A DIR entry's marker ROLLS UP wt-dirtiness: if any file beneath it is non-eq (mod/new/del/unk), the dir shows a DIRTY marker (coloured), not a plain "dir".
  • The wt markers (files AND dirs) render in COLOUR using the SAME palette as the status view (theme.VERB_SLOT) in BOTH the piped --color AND the pager paths.

Constraints

  • jab + libdog bindings + JS ONLY; NO dog binary spawn. A primitive absent from the bindings goes to libdog FIRST (a jab binding), then consumed gritzko2026-07-05 2026-07-05. The walk fits existing bindings; relAge is a permitted JS helper.
  • Keep ls:/tree: UNCHANGED and cheap — list is additive, its own word, its O(history) cost isolated in its own view.
  • Reuse, do not fork: ls classifyDir, tree readTree/descendPath, changedpaths changedTrees, log's summary/author extract, the theme grey slot, the pager U-tag.
  • meta/work.mkd budgets: commit 1 line, comments ≤2 lines; no manual URI parse (uri._parse); greppable no-wrap lines.

WIP

Design decisions

  • Producer = bounded walk: tip→parents, per commit changedpaths.changedTrees vs parent ∩ the scope's entries; first-touch attribution; ceiling cap (cf log.js:186 LOG_MAX_WALK). Unattributed-within-ceiling entries render blank.
  • Merges: attribute age along first-parent (github-like) unless a ruling says otherwise; note the ambiguity in the repro.
  • Layout: <marker> <name> left, pale summary mid/right, rel-age far right; column widths settled in the repro; the wt-marker reuses ls's verb-slot colour.
  • relAge lives in view/render.js (sibling of dateCol) so log/commit can reuse it; coordinate the home with COMMIT-007 (also wants human dates).

Blockers and bummers

  • The one real cost is the walk on deep histories; the ceiling caps it but a big dir with old entries may show blanks — acceptable first cut, revisit via graf.
  • Rename-follow (git --follow) is OUT of scope: the walk sees a path appear / disappear only; note it, do not build it here.
  • relAge home overlaps COMMIT-007/log; coordinate so it is single-sourced.
