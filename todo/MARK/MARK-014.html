MARK-013

Two renderer defects, both in verbs/mark/render.js, neither in libdog. First: the todo marker is the ONLY 4-char quad that does not tolerate a leading space, so the house form -[ ] (one space, what todo prescribes and what every ticket uses) is not recognised as BLOCK markup at all — the whole ### TODOs section collapses into one <p> and the inline lexer then eats each [ ] as a shortcut link to ./ .html. Block markup must never reach the inline layer. Second: a link to a FAT ticket (TOPIC/KEY/README.mkd) resolves to a bare directory path, not a page. Reported by gritzko 2026-08-06.

Input

Context

Probed on this tree, one page, four marker forms:

  • -[ ] at column 0 → correct: <ul class="todo"><li class="open"><input type="checkbox" disabled>.
  • -[ ] at column 1 and -[ ] at column 2 → NOT a marker: the lines join into one <p> and each [ ] renders <a href="./ .html"> </a>.
  • - (ulist) and # (heading) at column 1 → both correct. So the todo quad alone is column-sensitive, and that asymmetry is the bug.
  • render.js:440 tests /^-\[[ vVxX-]\]/ against rest — the line after whole 4-space INDENT units are stripped. Its neighbours test slot, the 4-char quad, and tolerate padding: heading render.js:438 is /^ *(#{1,4}) *$/, quote and ulist likewise. So a todo quad at any column but 0 falls through to paragraph text.
  • This is the DOG-024 self-delimiting-quad rule that render.js:438 already implements for headings ("a full quad self-delimits, so #### needs no gap space and # is h1") and that line 440 does not. MARK-013 is the umbrella for adopting that grammar; this is the concrete unimplemented case, filed on gritzko's instruction.
  • Blast radius is the whole ticket corpus: html/todo/TODO/TODO-012.html renders 7 ./ .html links and its entire TODOs section as a single paragraph.
  • Fat-ticket half: pageExists (render.js:191-194) probes only <stem>.mkd / <stem>.md, never <stem>/README.mkd, so emitPathLink (:198-206) leaves [/todo/BRO/BRO-046] as /todo/BRO/BRO-046 while the thin [/todo/BRO/BRO-043] becomes /todo/BRO/BRO-043.html. 16 fat tickets are affected.
  • That bare path only resolves because the Makefile's indexes target copies README.html to index.html and the server does directory indexing — mark emits a link it cannot itself satisfy, and it dies under file:// or any server without index resolution.

Goals

Block markup is settled by the block layer and never reaches the inline lexer; a link to a ticket reaches that ticket whether it is thin or fat.

  • Red-first: a fixture page with the todo quad at columns 0, 1 and 2 — all three render as <ul class="todo"> items, and no ./ .html link is emitted anywhere. Red today at columns 1 and 2.
  • A [/todo/TOPIC/KEY] shortcut to a fat ticket emits a link that resolves to that ticket's page without depending on the indexes Makefile target.
  • Re-rendering the existing corpus produces zero href="./ .html".

Constraints

mark is JS ONLY — the generator is verbs/mark/mark.js + verbs/mark/render.js (MARK-013 ruling, gritzko 2026-07-29).

  • beagle/mark/MARK.c is NOT the site generator and is out of scope; do not read or touch beagle/.
  • Fix the todo quad to match its NEIGHBOURS (test the slot), not by special-casing a leading space — the quad rule is one rule for all five markers.
  • Do not change the -[ ] / -[v] / -[x] / -[-] vocabulary, only where it is recognised.
  • Do not widen into MARK-006's .md policy or MARK-013's other DOG-024/025 items.
  • Clone ///be/ per work; on any clone failure stop and report.
