MARK-011: rendered pages carry no OG meta and a filename <title> — Bluesky link cards come up blank

Now
OPEN
Sev
MED

A Bluesky link to https://replicated.live/blog/worktree.html shows no title and no preview image: the page head has no Open Graph annotations at all, and OG-family scrapers (Bluesky, Slack, Mastodon...) read nothing else. renderDoc (verbs/mark/render.js:426-442) emits only charset, viewport and <title>; the injected html/head.html is just the stylesheet link; BOTH callers pass the filename stem as the title (verbs/mark/mark.js:74, verbs/rss/rss.js:137) — so the page ships <title>worktree</title> and nothing else. Compounding: metaOf (verbs/rss/rss.js:53-69) matches only H1 openers (/^#\s+/) while blog posts open with ## — the title loop runs its index to EOF, so the intro loop starts at EOF and collects nothing. One regex miss, two symptoms: filename titles AND an empty <description> in html/feed.rss (verified live for the worktree item, 2026-07-20). No code path extracts a post image, though siteBase() (verbs/rss/rss.js:83-86, reads html/CNAME) already yields the absolute base an og:image needs. Orchestrator-verified diagnosis, 2026-07-20. Method Issues.

Input

Context

  • Live evidence: html/blog/worktree.html head = charset + viewport + <title>worktree</title> + stylesheet; feed item for it has <title>worktree</title> and <description></description>.
  • The first image of that post is reference-style with a layout fragment: ![alt][1] ... [1]: ./img/darwin.jpg#rightw30 — image extraction must resolve through refdefs, strip the fragment, and resolve the page-relative path against the page's directory (/blog/img/darwin.jpg).
  • mark and rss share renderDoc but only rss has metaOf; mark passes no meta at all — both verbs must emit the same head.

Goals (gritzko's order, 2026-07-20)

  1. The post's opening heading (# or ##) becomes the HTML <title>, in both mark and rss renders. The feed item <title> follows.
  2. The first image of the post is the preview: og:image with an ABSOLUTE url (siteBase() + resolved page-relative path), refdef-resolved, #fragment stripped.
  3. Add the annotation block to the head: og:title, og:description (the intro paragraph, markup stripped), og:type = article, og:url.
  4. Fix metaOf: accept #/## openers; intro extraction must not depend on a matched heading (fixes the empty feed <description>).

Constraints

  • Minimal fix. ONE shared meta extractor used by both verbs (lift into render.js or shared/ — implementer's call, keep it small).
  • No html/CNAME → no absolute base: OMIT og:url/og:image (OG requires absolute urls) but still emit <title>/og:title/og:description.
  • RULING (gritzko, 2026-07-20): verifying against the REAL journal tree is sanctioned — html/ and feed.rss are generated artifacts. projectRoot() climbs to the topmost .be, so a render run from the worktree anchors at the journal root and rewrites the live output; that is fine, no BE_ROOT fixture pinning required.
  • End-to-end verify on the real post: run the MODIFIED verbs (worktree jsrc) on blog/worktree.mkd; assert in html/blog/worktree.html the <title> equals the heading text, og:image is absolute and fragment-free (https://replicated.live/blog/img/darwin.jpg), og:description is the intro; assert the feed item <description> is non-empty. A test/ regression case (run.sh pattern, BE_ROOT-pinned fixture — test/bro/ticket/run.sh:69) is welcome if cheap, not required.
  • Regenerating the real posts and re-posting is NOT part of this ticket (Bluesky snapshots cards at compose time; old skeets stay bare).

WIP

Design decisions

  • The ONE shared extractor lives in verbs/mark/render.js (both verbs already require it): pageMeta(src, fallback) -> {title, intro, image}, all pure (no fs). title = the FIRST heading opener at ANY level (#{1,6} — so # and ## both work; the old H1-only regex was the bug); intro = the first prose paragraph scanned INDEPENDENTLY of a matched heading (skips blank / heading / image-only / refdef lines), so a missed opener no longer runs the index to EOF; image = the first ![alt][label]/![alt](url), label resolved through the same [key]: url refdefs, #fragment stripped, kept page-relative. plain() moved from rss.js into render.js (single copy).
  • Absolute-url + head assembly is ALSO pure and in render.js: absImage(site, pageRel, rel) resolves the page-relative image against the page's dir via the existing normPath; headMeta(meta, site, outRel) builds the head values (title/intro/url/image) and drops url+image when site==="". Only siteBase() (reads html/CNAME) does fs, so it stays in the verbs — render.js keeps its pure-JS charter. mark.js gained a siteBase() copy (4 lines) matching rss.js's.
  • renderDoc now takes opts.meta (the headMeta result): <title> = the heading (filename stem only as fallback), then an OG block — og:title, og:description (when intro non-empty), og:type=article, then og:url and og:image ONLY when an absolute base exists.
  • Both verbs call render.pageMeta once; rss reuses the same meta for the feed item <title>/<description>, so page head and feed never diverge.
