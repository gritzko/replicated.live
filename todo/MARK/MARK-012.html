MARK-012: explicit-link text and figure captions render inline markup flat

Now: OPEN Sev: LOW

StrictMark :42 gives an explicit [text text][l] "any display text", but both renderers escape that text verbatim instead of running the inline pass on it, so [a *bold* word][1] shows literal asterisks in the anchor. Same for a captioned figure: emitFigure (render.js:209) escapes the bracket text into <figcaption>, which is flow content and could carry the markup. No grammar work is involved — the inline bracket rules already admit *_~ and backticks in their bodies ([^\]\n]+), so the span reaches the renderer whole and MKDTDecomposeSpan hands back the raw inner text; only the emit side chose escf. Scope is explicit links and captions ONLY.

Input

Context

  • emitLink (render.js:194) and mark_emit_link (MARK.c:252) emit display text through escf / MARKu8bFeedEsc; inline (render.js:214) is never re-entered.
  • Recursion already exists for <strong>/<em>/<del> (render.js:225, mark_inline_wrap MARK.c:306), so the machinery is in place and depth-capped (MARK_MAX_DEPTH 64, MARK.c:361).
  • Probe (2026-07-28, renderDoc): [link with *strong* text] → <a href="…">link with *strong* text</a>.

Goals

  • An explicit [text][l] renders its display text through the inline pass — *strong*, _emph_, ~~del~~, ` code become tags inside the <a>`.
  • A figure caption renders through the inline pass, while the alt= attribute of the same image stays plain text.
  • C and JS stay in step for the link half (render.js:5 still claims byte-parity with the C renderer).

Constraints

  • Shortcut [page] links are OUT of scope: the bracket text is also the ref key and the implicit-link filename, so decorating it would break lookup — leave them escaped.
  • Image alt= is an HTML attribute and can never hold tags; strip with the existing plain (render.js:239), do not write a second stripper.
  • No change to MKDT.c.rl or MKDTB.c.rl — the grammar already covers this.
  • <figure> exists only in the JS renderer (C emits a bare inline <img>), so the caption half is JS-only.

WIP

Design decisions

  • "Explicit" is exactly label != text — the discriminator decompose already sets (render.js:85 vs :87), matching the C shortcut test at MARK.c:273.
  • emitFigure splits its one argument into two emits: esc(plain(text)) into alt=, this.inline(text) into <figcaption>.
