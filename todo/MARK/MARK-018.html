A ``` `c `` fence renders as <pre><code class="language-c">a = 1;</code></pre> (mark/html.js:189:vz) — the info string reaches the class attribute and stops there, so the body is one unpainted slab on a site that ships no highlighter. The bytes are already lexable: tok.parse(bytes, ext) is the JS face of dog/tok's whole dispatch table (quickjab/tok.c:76), the same core that paints every source file bee serves, and mark/strict.js already hands the emitter the fence's info and literal. This ticket runs that lexer over the fence body at the RENDERER, emitting the tok-X spans render/html.js emits for source, inside the <pre><code> that everyone else in the world uses. Doing the same nesting one layer down, in MKDTLexer itself, is the bigger prize (the pager would paint fences too) and is NOT this ticket: it breaks the fence-tracking mark/strict.js:322:Tx` infers from the absence of quads, and wants its own change.

Input

Context

  • bee mark todo/MARK/MARK-018.mkd on any fenced page: the C, JS or shell body comes out one colour, while the SAME bytes in a .c file served by bee http come out fully painted.
  • MKDTLexer (dog/tok/MKDT.c:167) tags every fence body line 'H' verbatim; the block grammar keeps the info string (MKDTB.c.rl:41 sets content past the backtick run), so the lower layer has what it needs whenever someone takes that on.
  • mark/html.js is bee's own emitter, not vendored (mark/vendor.sh copies only node/common/blocks/inlines), so the change lands in a file this repo owns.

Goals

  • A fence whose info names a known lexer paints: <pre><code class="language-c"> unchanged on the outside, <span class="tok-R"> and friends inside, escaped exactly as today.
  • An info string naming nothing (text, mkd, none at all) renders byte-identically to today — no empty spans, no class churn.
  • One dialect-neutral path: .md, .mkd and .rst fences all take it, since they all reach the same code_block case.
  • The painted bytes are the fence body's own: concatenating the spans' text must reproduce node.literal exactly, newlines and indentation included.

Constraints

  • Worktree ~/src/bee-MARK-018 (branch MARK-018); no main-tree edit, no commit (work).
  • JS only — no dog/tok C change, no ragel, no rebuild of the runtime.
  • RED first: the repro test fails on the base tree; no existing test case edited.
  • Comments per comment, MARK-018 on the change; 2 lines each.

WIP

Design decisions

  • <pre><code class="language-c"> STAYS, spans go inside — that is what every renderer does: highlight.js nests hljs-keyword, Prism token keyword, GitHub/Chroma pl-k, Shiki one span per line with inline styles. Nobody replaces the <pre>.
  • The class vocabulary is bee's OWN tok-X (render/html.js:99:BN), not hljs-*: bee http already serves a stylesheet with those rules, so a fence and a source file paint from one palette.
  • Paintability is decided by the RESULT, not by a table: tok.parse falls back to plain text for an unknown ext, so a run that yields only S/W tags emits no spans at all — the fallback needs no ext list on the JS side.
  • Nesting at dog/tok instead was weighed and deferred: it would make fence bodies come back tagged R, which mark/strict.js:322:Tx reads as a block quad and ends the fence on. That fix belongs with the lexer work, not here.

Outcome

  • mark/html.js +32: paintCode(literal, lang) beside esc, and the code_block case painting through it — the <pre><code class="language-c"> wrapper, the escaping and the plain fallback all unchanged.
  • test/hifence/ +150 (run.sh), a new suite: 14 checks over the paint, the byte round-trip (tags off = the fence body, escaping included) and the three no-paint cases. RED first — 5 of 13 failed on the unmodified tree, every paint check among them.
  • PUNCTUATION ALONE IS NOT HIGHLIGHTING is the fallback rule, and it earned its keep: tok.parse answers an unknown ext with the plain-text lexer, which still cuts = 42 ; into S/P, so "the ext is known" is no test — a run carrying no D G L H R N C F T tag hands the plain body back.
  • One span per RUN of a tag, not per token: TOKSplitText hands a comment over word by word, and ten spans painted what one does.
  • ctest -j16 164/164 in build-bee-MARK-018, the new suite included; not one existing case edited. test/strict/run.sh:79:Ov's fenced-body check survives untouched — its js body is punctuation only, so it does not paint.
