LITE-035

A rendered page's ![](logo.png) currently resolves to /cat/logo.png — a painted HTML page, not the image (LITE-035 open question) — so no image ever displays in the browser. Serve needs one route that answers a file's OWN bytes with an image content type, and the render-time resolver (LITE-034 door, one resolver rule) must send image destinations there. Bytes stay read-only reads of what cat/blob already reach; no thumbnailing, no uploads, no generic download service.

Input

Context

Serve's views are all HTML today: /cat/ paints (or renders .md), /raw/ paints source, /blob/<hexlet> paints too. The <img> tag needs 200 + image/* + the verbatim bytes.

  • mdHref (index/serve.js) resolves destinations through the door with an isImage flag already in the emitter's hook signature (opts.href(destination, isImage)) — the seam exists.
  • The verbs already read blob/worktree bytes (index/cat.js, index/blob.js, index/read.js path gate); binary detection exists for the painter's refusal path.
  • SVG is text that can carry script: serving it as image/svg+xml executes it in the page's origin — the LITE-035 safety stance (never serve attacker-authored script) applies.

Goals

An image referenced from a rendered .md displays in the browser; nothing else about the routes changes.

  • A bytes route, e.g. /bytes/<path>[?<rev>]: 200, the file's verbatim bytes, correct Content-Type, X-Content-Type-Options: nosniff; 404 through the same door misses everywhere else.
  • Content type from a small extension allowlist (png, jpg/jpeg, gif, webp, ico, bmp); anything off the list answers application/octet-stream — the browser downloads, never interprets.
  • SVG is NOT on the image allowlist: it ships as application/octet-stream (or paints as source via /cat/), never image/svg+xml.
  • mdHref: an image destination resolves to /bytes/<resolved path>; a non-image link to an image file keeps linking to its painted /cat/ view.
  • ?<rev> rides like cat's: an old page revision shows its own era's image.
  • Test leg: wire checks for content type, nosniff, byte-identity with the worktree file, the SVG refusal, the 404, and a rendered page whose <img src> points at /bytes/.

Constraints

  • Read-only, localhost, same as the rest of serve; no directory forms, no listing under /bytes/.
  • One resolver: the door names the file, the route only ships bytes — no second path logic, no fs reads outside index/read.js's gate.
  • Extension map lives in one table next to ROUTE; no content sniffing of the bytes.
  • ZERO quickjab edits; vendored mark/ untouched (the opts.href hook is the only image seam).
  • Tests under test/serve/, dash, $LITEJAB, fixtures in $HOME/tmp; existing legs untouched and green.

WIP

Design decisions

  • Route name (/bytes/ vs widening /blob/) is gritzko's call; the table makes it a one-line rename.
  • A size cap mirroring the painter's over-cap refusal (413 in plain words) rather than streaming — serve pages are whole-buffer today.

Blockers and bummers

Outcome

/bytes/<path>[?<rev>] ships a file's own bytes. The ROUTE row maps bytes onto the SAME cat verb /raw/ already reuses, so the door does all the path work: the gate, the ?<rev> blob read and the plain-words refusal are cat's, and the responder only types and writes what came back. hunks[0].text IS the verbatim bytes, so nothing re-reads the file and no fs call was added.

  • index/serve.js 347 -> 428 lines: MIME table + mimeOf next to ROUTE; refResolve split into seatRel (the door -> file) + refResolve/ imgResolve, refUrl/imgUrl over a shared memoUrl (one REF_CAP budget, per-spelling cache key); mdHref(pg, dir, dest, isImage); pg.rev off the page's own arg; respond(..., extra) for the nosniff header; sendBytes.
  • Content types, the one table: png image/png, jpg/jpeg image/jpeg, gif image/gif, webp image/webp, ico image/x-icon, bmp image/bmp; everything else — .svg included — application/octet-stream. The name types it; no byte is ever sniffed. X-Content-Type-Options: nosniff rides every answer. Over weave.MAX_SOURCE_SIZE (4 MB): 413 in plain words.
  • test/serve/bytes.sh, 225 lines, 59 checks, all green: the seven types, nosniff, svg-is-octet-stream (and never image/svg+xml), byte-identity with the worktree png, ?<rev> serving C0's png and not the tip's, HEAD length, 404 on a miss / a dir / the root / a climb out, 413 over the cap, and a rendered .md whose <img src="/bytes/logo.png"> sits beside an ordinary link still on /cat/logo.png — with the rev carried at /cat/page.md?<rev>.
  • Suite: test/serve/run.sh 174 checks unchanged, every other leg at its baseline (known env fails only: lite/diff 1/34, lite/pager 1/33).
  • README.mkd: one line under the lite serve entry.
  • NOTE for whoever runs the tests: the packed binary's own jsrc WINS over the jsrc symlink the legs plant, so ninja quickjab must be re-run after every tree edit or the leg tests the old code.
