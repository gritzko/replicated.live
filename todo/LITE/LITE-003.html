Replace the lite/main.js scaffolding stub with the real entry: each CLI arg is a file/dir path; at a terminal the args open in the interactive pager, piped or --plain they dump as plain hunks. This is be's views/bro/bro.js broRun flow with the spell/loop layer removed.

Input

Context

The original flow to mirror (READ-ONLY): be/views/bro/bro.js broRun — tty(1) → pager, else plain dump with the BE-002 exit discipline. The current stub proves both runtimes resolve lite/main.js from a cwd inside lite/ (jab x and quickjab x both print the stub line today).

  • process.argv[1] is the entry path; args = process.argv.slice(2).
  • LITE-001 gives buildFileHunk/buildDirHunk/fsPath/plainHunk; LITE-002 gives Pager.
  • An uncaught top-level throw is the non-zero exit path (there is no loop edge in lite; the runtime maps it).

Goals

Rewrite lite/main.js.

  • Flags: --plain (strip from args). Everything else is a path.
  • openPath(path): io.stat the fsPath; dir → buildDirHunk, file → buildFileHunk; ENOENT/throw → null. The ONE fs-open, shared by both modes and handed to the pager as opts.open.
  • tty path (io.isatty(1) && !--plain): build hunks for every arg (a miss → stderr cannot open <p> + continue), new Pager(fd, {color:true, open:openPath}), setHunks, run(). fd = /dev/tty like be's loop edge — or fd 0/1 if that is what the bindings give; match what the pty probe can drive. No args → an empty viewport is FINE (:-type a path).
  • plain path: no args → usage line on stderr + throw "BROUSAGE"; per arg stat/build/plainHunk, miss → stderr + continue; concat and ONE write to stdout; none opened → throw "BRONONE" (non-zero exit).
  • Keep the module-require guard (only self-run when argv[1] is .../main.js) so tests can require it.

Constraints

  • Touch ONLY lite/main.js (and lite/README.mkd MAY gain one usage line). No VC ops, no commits.
  • require only view/bro.js and view/pager.js. No uri/URI, no be globals.
  • Verify from a cwd inside lite/ under BOTH jab and quickjab: <rt> --plain main.js | cat shows hunk main.js + the source; <rt> --plain nosuch; echo $? non-zero; the pager leg via a ~/tmp openpty probe (drive Pager exactly as LITE-002's probe, but constructed through main.js's openPath).

WIP

Design decisions

  • openPath(path) returns a HUNK LIST ([hunk]) or null — LITE-002's door is open(path) -> hunks|null and _openPush/_refresh test hunks.length, so a bare hunk object would slip past their guard and break indexing. The list keeps open: openPath LITERAL (no adapter at the call site, as this ticket's Goals ask); the plain leg loops the 0..1 elements.
  • The hunk URI is the arg VERBATIM (view/ keeps its slash); only the fs ops see bro.fsPath(arg) — be's banner discipline.
  • An EMPTY dir is indistinguishable from a miss through openPath's null (buildDirHunk returns null for it, LITE-001), so it prints cannot open <p> and does not count as opened. be printed no banner and still exited 0. Corner case (git cannot even hold an empty dir); flagged rather than papered over with a second stat.
  • Pager fd = be's loop edge verbatim: /dev/tty rw, else a tty fd 0, else fd 1 — closed in a finally only when we opened it.
  • require("view/pager.js") is LAZY (inside the tty leg), so the whole plain leg works with pager.js absent.
  • The error line is plain words — cannot open <p> — no FILENONE code (be's spelling carried the C code).
  • Usage string is Usage: lite [--plain] <path>....

Blockers and bummers

  • lite/view/pager.js (LITE-002) landed MID-RUN. Before it did, the tty leg was verifiable only to the branch (a clean require: cannot find 'jsrc/view/pager.js', exit 1 — the lazy require); after it landed the leg was driven end to end under a pty and is green, so no caveat remains. The one adjustment it forced is the hunk-LIST return (see Design decisions).
  • <rt> main.js cannot dump main.js itself: both runtimes take an existing .js first word as the SCRIPT, so it runs the entry with zero args (usage + exit 1). The no---plain piped leg was verified with a non-.js first word (<rt> README.mkd | cat) and with <rt> main.js README.mkd. Not a main.js bug — the runtime's entry-resolution convention.

Outcome

lite/main.js rewritten (97 lines), plus ONE usage line in lite/README.mkd. Nothing else touched, no VC op run.

  • openPath(path): io.stat(bro.fsPath(path)), dir → buildDirHunk, file → buildFileHunk, any throw → null; the hunk rides a one-elem list. THE single fs open, exported.
  • tty leg (io.isatty(1) && !--plain): lazy require("view/pager.js"), one hunk per arg (miss → stderr + continue), /dev/tty→0→1 fd, new Pager(fd, {color:true, open:openPath}), setHunks, run(); no args → an empty viewport, not a usage error.
  • plain leg: no args → usage + throw "BROUSAGE"; per arg plainHunk, miss → stderr + continue; ONE concatenated io.writeAll(1, …); none opened → throw "BRONONE". Both throws exit 1 under both runtimes.
  • Module guard kept: module.exports = {main, openPath} and self-run only when process.argv[1] ends /main.js.

Verdicts (cwd lite/), IDENTICAL under jab and quickjab/build-lite/bin/quickjab:

  • --plain main.js | cat — byte-identical to printf 'hunk main.js\n'; cat main.js (cmp OK).
  • --plain main.js README.mkd | cat — both hunks, in arg order, cmp OK against the concatenated expectation.
  • --plain . | cat — hunk . + the dir listing (.github/, main.js, view/, README.mkd, jsrc); --plain view/ keeps the slash in the banner and lists the dir.
  • --plain nosuch.txt — stderr cannot open nosuch.txt, exit 1.
  • --plain (no args) — stderr usage line, exit 1. Bare <rt> </dev/null likewise.
  • piped without --plain (<rt> README.mkd | cat) — the plain dump, byte-identical to the --plain run (isatty(1) false), exit 0.
  • mixed --plain nosuch README.mkd — stderr line, README dumped, exit 0.
  • ~/tmp/lite-probe/entry.js (require main.js as a module): exports present, no self-run, file/dir/trailing-slash hunk lists, miss → null — 6/6 OK.
  • pty probes (~/tmp/lite-probe/ptyrun.py, ptykeys.py), tty on fd 1: --plain still dumps plain (the flag wins, exit 0); WITHOUT the flag the pager runs — banner band + syntax-painted body + inverse status bar README.mkd#L1 … TOP h: help, q exits 0 restoring the main screen. . + j + Enter follows into .github (its own banner + listing), :view/bro.js + Enter pushes the painted file view, :nosuch shows cannot open nosuch in the bar, and a miss-only arg list gives the stderr line + an EMPTY viewport (not a usage error). Byte-identical output under both runtimes (992 / 5730 / 6760 / 245 bytes per drive).
