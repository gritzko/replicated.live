LITE-003

Pager work is verified through the real UI path or not at all: a pty-driven repro that flips, not unit probes. This ticket adds the lite test leg — plain-dump byte checks plus an interactive openpty cycle over the real Pager — runnable standalone against either runtime.

Input

Context

The pattern to follow (READ-ONLY): be/test/bro/pager/{run.sh,pty.js} — a tty.openpty slave fd, tty.setSize, step render/drain/send cycles (a self-pty needs draining between frames or the master buffer deadlocks; ONE blocking read per drain).

  • Tests run with cwd inside lite/ so bareword requires resolve via the lite jsrc scan; the runtime binary comes from $LITEJAB (default jab, quickjab build works the same).
  • Skip-guard when the tty binding is absent (the be run.sh ttyprobe pattern).

Goals

Create lite/test/pager/ with run.sh, pty.js, and a plain leg.

  • plain leg: $LITEJAB --plain <file> | cat = hunk <file>\n + the file bytes (+ trailing NL iff missing); a dir arg lists entries; a missing arg → stderr line + non-zero when NONE opened.
  • colour leg: buildFileHunk on a .js/.c fixture yields nonempty toks; a painted row carries SGR (ESC[…m) and resets; a .txt yields no toks and no paint.
  • pty leg (the real UI path): openpty 10x40; new Pager on the slave with a real open() over a fixture dir; frame 0 shows the body text, the banner band (48;5;230 + width fill + ESC[0m close), the inverse status bar with #L1 and TOP; j scrolls (frame shows line 2 at top... assert a body shift); G/g bottom/top; a dir view + Enter follows an entry (the file's text appears); - backs to the dir; q sets quit; termios restored after run()'s finally (cook check where drivable — else assert _saved cleared).
  • run.sh: sh, standalone (sh lite/test/pager/run.sh), cwd-independent (cd's itself), fixtures in a mktemp under ~/tmp, every FAIL prints the frame bytes escaped.

Constraints

  • Touch ONLY lite/test/pager/*. No edits to view/ or main.js — a found bug becomes its OWN ticket (todo/LITE/), linked both ways, and the test stays red-guarded (skip with a pointer) rather than bent to pass.
  • No VC ops, no commits. Scratch/fixtures under ~/tmp.
  • Must pass under BOTH jab and quickjab/build-lite/bin/quickjab via $LITEJAB.

WIP

Design decisions

  • THREE files, three legs: run.sh carries the PLAIN leg itself (byte compares with cmp, exit codes, stderr greps — shell is the natural driver for a process-level dump), and shells out to color.js (headless render lib) and pty.js (the openpty UI cycle). Each JS leg prints ok/FAIL/skip lines and a final DONE <n> checks; run.sh fails the suite on any FAIL line, a missing DONE, or a non-zero exit, and adds the leg's ok count to its own.
  • CWD differs PER LEG, on purpose. The plain leg must run with cwd lite/ — the runtimes resolve the entry main.js by scanning UP FROM THE CWD, so a fixture-dir cwd would find $HOME/jsrc -> be instead — hence its fixture args are ABSOLUTE. The two JS legs run with cwd = the fixture dir and are invoked with the script's absolute path: the jsrc pin is MAIN-SCRIPT-dir relative, so lite/test/pager/*.js climbs to lite/jsrc -> . and resolves view/bro.js / view/pager.js / main.js from ANY cwd (verified first thing, from /tmp as well — no extra symlink needed beside the tests).
  • Short uris in the pty leg are a REQUIREMENT, not cosmetics: at 40 cols the status bar truncates the left field to cols - len("<pos> h: help") - 1 = 27 cells, so an absolute ~/tmp/… fixture path would push #L1 off the bar and the doc.txt#L1 assert would be untestable. cwd = fixture dir → the uris are doc.txt / ..
  • The pty leg opens through require("main.js").openPath — the SHIPPED entry door, not a mock opener — so the LITE-003 → LITE-002 wiring is what is under test. Requiring main.js does not self-run (its guard tests argv[1]).
  • A master read hands back ONE slave write at a time (they coalesce only sometimes — measured 205+42 vs 38+167 on the same code). Every render() is a single io.writeAll, so a frame = one drain; run() emits THREE writes (enter bracket, frame, restore bracket), so its drain is a bounded loop of at most 3 reads that stops the moment ?1049l is in. A 4th read would block for ever — the loop never reads past the last expected write.
  • run() is ended from a RENDER HOOK (render wrapped to set quit), never a pre-queued key: tty.raw's TCSAFLUSH drops queued slave input (LITE-002). Everything else is stepped: raw is entered ONCE up front, pump() reads the slave FIRST and tests its condition AFTER (so no send leaks into the next pager object), and each check renders + drains explicitly.
  • Cook-check: the tty binding exposes only raw/cook/size/openpty/setSize — no getattr — so termios restoration is asserted the ticket's fallback way (_saved cleared) plus the observable escape bracket: ?1049h…?1049l, ?1000h/l, ?2004h/l, ?25l/h, and ALT_OFF emitted LAST (BRO-027).
  • Fixtures: a mktemp dir under ~/tmp, removed on a green run, KEPT with the path printed when anything fails (the be $WORK habit). Dir-listing asserts sort the entry run — io.readdir order is filesystem order, not sorted.
  • Empty-dir behaviour is NOT asserted (LITE-003 records cannot open for it as a known corner); an EMPTY FILE is asserted instead — banner only, exit 0.

Blockers and bummers

  • The ticket's colour-leg expectation "a .txt yields no toks and no paint" does not hold and is SKIP-GUARDED, not bent to pass (see Outcome, proposed LITE-005): tok.parse has a GENERIC lexer for every unknown extension, so note.txt yields 19 toks and its punctuation paints grey. Only an EXT-LESS file is tok-free (buildFileHunk's ext ? … : new Uint32Array(0)), and that is what the leg asserts positively instead.
  • Flaky-then-fixed: the run() leg failed ~3 runs in 4 until the drain was made write-chunk aware (see Design decisions). The frame legs were never flaky — one write per render.
  • A master read with nothing pending BLOCKS (the fd is not non-blocking and there is no poll binding), so every drain in the suite is placed where bytes are guaranteed to be pending. A probe that read one time too many hung.

Outcome

lite/test/pager/ created — run.sh (executable, 203 lines), color.js (110), pty.js (199). Nothing else touched: no edit to lite/view/*, lite/main.js, be/, jab/ or quickjab/, and no VC op run.

  • sh lite/test/pager/run.sh from ANY cwd; $LITEJAB picks the runtime (default jab). POSIX sh — green under busybox ash AND bash.
  • *76 checks, PASS under BOTH runtimes, output byte-identical* (modulo the runtime name + the mktemp path): jab and quickjab/build-lite/bin/quickjab, 5 consecutive runs each, no flake.

Leg 1 — plain (10 checks, cwd lite/, absolute fixture args): banner + verbatim bytes (cmp against printf 'hunk %s\n'; cat), a no-trailing-NL file gets exactly one NL, an EMPTY file is banner-only + exit 0, two args concatenate in arg order, a dir arg lists its entries (sorted compare — readdir order is fs order) and a trailing / survives into the banner, a miss = cannot open <p> on stderr + EMPTY stdout + non-zero, no args = the usage line + non-zero, a mixed batch dumps the hit and still exits 0, and a piped run WITHOUT --plain (first arg deliberately not a .js — LITE-003 Blockers) equals the --plain bytes.

Leg 2 — colour (21 checks, color.js): buildFileHunk toks nonempty on .js and .c, hunk shape, pathExt; a painted row carries ESC[ and CLOSES with ESC[0m, the comment row opens ESC[90m (tag D) on both .js and .c, a code row paints a different opener, the row text survives the paint; color:false emits no ESC at all, plainHunk is ESC-free with its hunk <uri> head; the banner band (48;5;230, filled to 40, closed ESC[0m) both via bro.bannerColor and theme.DEFAULT.bannerOpen/Close; a dir hunk is F-tagged and its row paints. 2 SKIPPED (below).

Leg 3 — pty (43 checks, pty.js, openpty 10x40, opener = main.js's openPath): frame 0 shows the body (AAAA…HHHH) and stops at the viewport, the banner band (bg + 40-cell fill + close + text) with a body row unbanded, the inverse bar (ESC[7m, exactly 40 cells) carrying doc.txt#L1, TOP and h: help; a real j through the pty scrolls and the frame SHIFTS (IIII enters, the band leaves, TOP goes); G clamps to the last row and paints BOT, g returns to TOP; a dir view lists, its doc.txt row is located through _uriAt, Enter FOLLOWS it (stack 1, uri doc.txt, the file's text painted), - pops back (stack 0, row cache dropped, scroll kept, listing repainted), Enter on the banner says (nothing to follow); q sets quit; and run() paints one real frame with the raw + ALT lifecycle — _saved cleared by the finally, ?1049h…?1049l, ?1000h/l, ?2004h/l, ?25l/h, ALT_OFF emitted LAST.

FAIL output is escaped: the JS legs print got: … with ESC→\e, CR/LF→\r\n; the shell leg dumps every relevant file through od -c. The pty leg is SKIP-guarded on the tty binding (the be ttyprobe pattern).

SKIP-GUARDED FINDING — proposed *LITE-005: buildFileHunk has no KnownExt gate, so plain text gets the generic lexer's paint* (NOT filed: this run may only touch lite/test/pager/ + this ticket; file it and link both ways):

lite/view/bro.js buildFileHunk comments that "an unknown ext yields no toks, exactly like BROTokenize's KnownExt gate", and LITE-004's colour leg was specified on that basis. It does not hold: tok.parse(bytes, ext) never throws for an unknown extension — it falls back to a GENERIC lexer that tags punctuation P and words S. Measured under both runtimes: the same prose yields 19 toks for ext txt, xyz, dat, log; only ext === "" (a file with no extension) short-circuits to no toks. Effect: a .txt in the pager is painted — plain prose\e[90m,\e[39m no lexer… — grey commas and dots, where C bro leaves plain text unpainted. Cosmetic, no crash. DECIDE: gate the ext against a known-lexer list (C parity), or accept the generic lexer and correct the comment + the LITE-004 spec line. The two asserts are parked as skip lines in lite/test/pager/color.js (txt-toks-empty, txt-row-no-paint), each carrying a pointer — flip them to check when this lands.

Deviations from the ticket: none in scope. The one spec line that could not be asserted as written is the .txt = no-toks/no-paint pair above (skip-guarded, with an ext-less fixture asserting the honest "no toks → no paint" case instead).

Amended for QJAB-001 (packed quickjab renders a .js argv instead of running it): the ttyprobe/colour/pty legs now go through the sanctioned door --eval "require('<abs>')", a $WORK/jsrc -> lite symlink at the fixture PARENT serves the cwd-climb jsrc pin for unpacked runtimes ($FIX stays listable for P5), and a relative $LITEJAB is absolutized (the legs cd). PASS 76 under jab, unpacked qjab, packed qjab and build-lite.
