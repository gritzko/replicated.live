Beagle-lite can list a history (LITE-007 log) but cannot show a CHANGE. be has that view already — be/views/diff/diff.js folds a 2-layer CFOLD weave per file pair and emits diff hunks — so this is a PORT: the fold, the emit and the hunk render are the same machinery lite already links (abc.ram("CFOLD"…), abc.ram("HUNK"…), view/bro.js, view/pager.js), while the store access differs completely (be's shared/store.js + wtlog baseline + sub recursion vs lite's git.tree/git.getHex over a plain git repo). The port is mostly SUBTRACTION: be's diff.js is 45 KB because of ulog, patch, subs and EXPECTED layers that lite has none of.

Input

Context

be/views/diff/diff.js is the source; lite/index/log.js is the shape a lite view takes; the C twin is graf/DIFFREF.c, which we do not read (beagle/ is off limits).

  • The core of be's diff is diffFile(name, fromBytes, toBytes, full, …): skip if equal, skip if binary (a NUL in the first 8000 bytes), skip over MAX_SOURCE_SIZE, else fold both sides into one CFOLD weave and emit.
  • fold2 folds a LINEAR chain — base layer = the from-content under ID_FROM, second layer = the to-content under ID_TO listing ID_FROM as its ancestor — then emitDiff (windowed) or emitFull (whole file) writes 'H' records.
  • An empty FROM side is the one special case: the pair collapses, so be folds in the OTHER order (content first, empty second) and INVERTS the from/to revs.
  • quickjab exposes the whole thing: abc._cfold_* (cfold.c, incl. emitdiff/emitfull) and abc._hunk_* (hunk.c), reached as abc.ram("CFOLD", n) / abc.ram("HUNK", n) containers.
  • be reaches those through shared/weave.js (fold, MAX_SOURCE_SIZE 4 MB, MAX_SOURCE_MARKED_UP 4x) — a small file worth porting nearly verbatim.
  • What be's diff.js drags in that lite has NO equivalent of: shared/wtlog.js, shared/classify.js, shared/expected.js (DIFF-016 patch provenance), core/recurse.js subs, shared/nav.js re-baking, core/discover.js context confinement.

Goals

lite diff shows the change as be shows it — coloured hunks in the pager at a terminal, plain hunk bytes when piped or under --plain.

  • Forms (the worker proposes the final set in Design decisions and REPORTS before building): bare = the worktree against HEAD, <path> = that path only, <hex> = that commit against its FIRST parent.
  • Plain output is the bro --plain hunk shape lite already writes: a hunk <uri> line then the bytes, one hunk per changed file.
  • The change SET must match git diff / git diff <hex>^ <hex> on real repos: same files, same added/removed lines; the presentation is be's, not git's +/- unified text.
  • A play loop like LITE-007's: run in $HOME/src repos small to large, diff the file set and the per-file line counts against git, fix what deviates or record it as a genuine model difference.

WIP

Design decisions

Leads, not rulings — the worker confirms each one against the code before building on it.

  • The from/to BYTES come from the ODB (git.tree walk + git.getHex for a blob) and from io.mmap for a worktree file — NOT from the LITE-006 lane.
  • Why not the lane: it stores path_hl only, a one-way 40-bit hash, so it can never ENUMERATE the paths a commit touched, and a deletion is not a rev at all (LITE-007 model difference 1).
  • Consequence: lite diff needs no index and no bringUp at all — it is ODB + fs, which also means it works in a repo whose .git/be was never built.
  • Emit into an abc.ram("HUNK", n) container, then walk the HUNK cursor into lite's own {uri, verb:"hunk", text, toks} hunks so view/pager.js and plainHunk take them unchanged.
  • Port shared/weave.js's fold + the two size constants into lite rather than importing be's file — lite has no shared/ and no stats.js.
  • A tree-vs-tree walk yields four cases: added (empty from), deleted (empty to), modified, and equal-sha (skipped early, which is what makes a big-repo diff cheap).
