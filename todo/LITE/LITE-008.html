Ruling (gritzko 2026-08-13): the packer must respect the jsrc tree's .gitignore, if present. Field evidence: an in-tree lite/build cmake dir got packed wholesale — 472 of 488 files in a 15.5 MB jsrc.pack were build/** (incl. quickjab_boot and libdog.a, 53 MB raw) against ~200 KB of actual JS, and the pack's content hash churns on every rebuild.

Input

Context

quickjab/jsrcpack.js (JAB-035) walks the whole -DJAB_JSRC tree: io.readdir(root, {recursive: true}), every regular file goes into the ustar. It already skips dotfiles, nothing else. quickjab already binds the per-FILE .gitignore leaves: dog._igno_* in quickjab/igno.c (STATUS-020, over dog/git/IGNO) — JS walks, C matches, per the JAB-038 split.

  • The CMake side (quickjab/CMakeLists.txt:92 GLOB_RECURSE) has the same blind spot in its dependency list; a build-dir filter was applied there already — this ticket is the packer's own walk.
  • Pack determinism must survive: same tree, same .gitignore → byte-identical pack, same sha (JAB-035 contract).

Goals

A .gitignore at the jsrc root (and in subdirs, standard git semantics as IGNO implements them) excludes matching files from the pack.

  • jsrcpack.js: on the walk, consult dog._igno_* per directory's .gitignore; no .gitignore anywhere → today's behaviour byte-for-byte.
  • The .gitignore files themselves stay packable only if not self-ignored; do not invent extra hardcoded excludes beyond what IGNO matches.
  • Repro-first test in quickjab's test suite: fixture tree with .gitignore ignoring build/, junk in build/, pack it, assert the junk is out, the JS is in, and the pack of an ignore-free tree is unchanged vs today.

Constraints

  • NO manual .gitignore parsing in JS or C — the IGNO leaves only (the JS walks, C matches split is a standing ruling; a reimplementation is the known cardinal sin).
  • ABC house rules for any C edit (meta/abc.mkd); comments max 2 lines, tagged LITE-008.
  • Work in a worktree off ///quickjab; scratch and builds in ~/tmp; put+report, no VC ops.

WIP

Design decisions

  • RULING (gritzko 2026-08-13): ONE .gitignore, the pack root's, nothing else — no per-directory chain, no scanning for deeper files. JS-only change: one dog._igno_open(root + "/.gitignore") handle for the whole walk. The worker's per-directory chain was cut on that ruling. No C edits.
  • The walk moved to io.readdir's CALLBACK form of the same native scan: an ignored directory returns "skip" (pruned whole), which is also git's no-re-include-under-an-excluded-dir rule; names are collected then sorted as before, so an ignore-free tree packs byte-identical (verified on two trees, same sha).
  • Chain starts at the pack root: a .gitignore above the tree, .git/info/exclude and core.excludesFile are not consulted.
  • .gitignore files themselves are dotfiles and the walk already skips dotfiles — they were never packable, unchanged.
