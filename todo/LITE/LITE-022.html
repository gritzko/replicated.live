gritzko's ruling 2026-08-14: lite chat's output names are UUIDs ("we are not Anthropic") — compress each to a COLLISION-RESISTANT 10-char ron60 string derived from the original UUID. 10 ron60 chars = 60 bits; the derivation is the weaveId-style move: hash the UUID (never truncate the string raw — the version/variant nibbles are constant, ~6 bits dead), take the hi 60 bits, render in the RON60 alphabet. So d12979f3-336b-4666-88b1-d7e6765c817e.jsonl → <10 ron60 chars>.mkd. The name is a pure function of the source basename, so the verb's REENTRANCY (pages update on every run — the [log]: byte-count append) keeps landing on the same page with no state anywhere.

Input

Context

lite chat (LITE-016, lite/index/chat.js) converts every *.jsonl in the mangled log dir to <outdir>/<basename>.mkd, 1:1 by basename; a rerun reads the trailing [log]: file:/<abs jsonl> "<bytes>" ref def and appends only the gap.

  • The 1:1 map is currently the identity on the basename — the ONLY change is that map; render, append, sanitizer, reporting stay untouched.
  • The ron60 alphabet is dog/RON's base64 (index/log.js:52 already decodes ron60 dates — the alphabet/binding lead); a hash source: quickjab links sha1 via its git machinery — worker finds the cheapest existing binding, no new C.
  • Pages carry their provenance in the [log]: ref def (abs jsonl path), so a name clash between two DIFFERENT sessions is detectable at write time: the ref def names another jsonl → refuse loudly, never silently merge two sessions into one page.
  • Reruns must not duplicate: existing <uuid>.mkd pages from pre-LITE-022 runs map to the new name — migrate (rename, then extend as usual) instead of writing a second page for the same session.

Goals

Same behavior, shorter names: lite chat writes <ron60x10>.mkd, reruns append to the same pages, old UUID-named pages migrate on first contact, sessions never collide silently.

  • Name = ron60(hi60(hash(uuid-basename bytes))), 10 chars, stable across runs and machines.
  • Rerun on an already-converted dir: 0 rewrites when logs unchanged (the watermark behavior, unchanged), appends land on the ron60-named page.
  • Migration: <uuid>.mkd present + <ron60>.mkd absent → rename and continue reentrant as usual; both present → the ron60 page wins if its ref def matches, else refuse loudly.
  • Clash of two different sessions on one ron60 name: loud plain-words refusal naming both jsonls (60-bit birthday odds make this ~never; the check makes it safe anyway).
  • Tests: the LITE-016 legs keep passing with only expected-name edits; new legs pin the name function (known UUID → known ron60 string), migration, and the clash refusal (forced via a stubbed short hash or two crafted names — worker picks the honest way).

WIP

Design decisions

Confirmed against the code; the leads held, with one simplification (no shared encoder was needed).

  • NAME = ron.encode(sha1(basename)[0..7] big-endian >> 4).padStart(10, "0") — index/chat.js pageName(), 5 lines, no require. The digest is dog/WHIFF.h's hashlet60 (top 60 bits of the sha1), the very one index/index.js hlOfText names paths with; sha1 and ron are quickjab globals already, so ZERO new C and no new JS module.
  • No shared ron60 encoder was written: ron.encode IS the encoder (quickjab/codec.c → RONutf8sFeed), and it walks the value msb-first over RON64_CHARS = 0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqrstuvwxyz~ (dog/abc/RON.c, read — not assumed). It DROPS leading zeros, and RON64's zero digit is 0, so a left pad to 10 restores them exactly (main.js ron60Text does the same for lite now; main.js was NOT touched).
  • Worked example: d12979f3-336b-4666-88b1-d7e6765c817e → sha1 59ab785a31b12dd1… → top 60 bits 0x59ab785a31b12dd → MQitMZ6mBT.mkd. Independently recomputed with python3 hashlib + the alphabet table before the code was ever run; the two agree on all 12 pinned names.
  • claim(src, old, dst) runs before convert(): it reads the target's [log]: ref def (which now yields src as well as the offset), refuses when that names a DIFFERENT jsonl, and otherwise renames <uuid>.mkd → <ron60>.mkd when the target is absent. Exactly ONE extra stat per file on the steady-state path (the old name is gone after the first run); the ref-def read is the same page convert reads anyway.
  • Both names present: the ron60 page wins when its ref def names this jsonl (the uuid page is reported as superseded, never deleted behind the user's back); with no cursor to tell them apart, the run refuses in plain words naming both files.
  • Non-UUID basenames go through the same hash — the map is total, sess-one and a UUID are named the same way.
