Found on a real page, lite serve over a kernel tree, /cat/Documentation/security/lsm.rst (gritzko, 2026-08-15; fix ordered straight into the main lite/ tree). Two defects against LITE-037's own rules: (1) a two-part Sphinx role ` :c:type:struct cred <cred> leaks the :c:type: prefix as text and the backticked body falls to the citation rule (<em>) instead of the ruled <code> degrade — the role regex knows single-name roles only; (2) LSM Capabilities Module_ shows verbatim although the emitter already slugs every heading (<h2 id="lsm-capabilities-module"> is on the same page) — reST's implicit section targets were punted on the false premise that nodes can't carry an id. The RSTT paint twin of (1) ( and :c:type: fuses into one G token on the /raw/ side) is ///quickjab` ground and stays outside this ticket.

Input

Goals

  • :dom:part:text` (any colon-joined role name) degrades to <code>text</code>`, same as a one-part role.
  • A section title is an implicit hyperlink target: ` Title_ and Title_ resolve to #slug` where the slug matches the emitter's heading id (same text, same document order, same dedup numbering); an explicit target of the same name wins, and a truly unresolved reference stays source-text plain as pinned by test/rst/run.sh.

Constraints

  • Repro checks land in test/rst/run.sh first; no other test edited.
  • mark/rst.js only; the emitter, the vendored files and serve stay untouched (pageHref already passes a bare #anchor through, index/serve.js:257).
