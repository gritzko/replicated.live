gritzko's ruling 2026-08-14: a text-file permalink is file.c:k4:d8K3 — segment 1 a ron64 BYTE OFFSET into the named blob, segment 2 the BLOB's ron64 hashlet, ONLY ever a blob hash (commit-id tier overruled same day). Nav: resolve the file name (may hit several files — chooser), find that blob in the path's history, count to byte k4 there, find the same place in the current/required version, open, set the cursor. Blob offset, never a weave/insertion offset: the fold's ranges are tokenizer-dependent, a weave rebuild would re-point every link; blob bytes are canonical git ground. The DOG-034 lexer already fuses both segments (pathanchor, ron64{1,10} twice), so the grammar is DONE — this ticket is the door/resolution/mint half, extending the LITE-024 :line:col landing.

Input

Context

LITE-024 lands file.c:12:24 on the line via the door's splitRef (the ONE split point in openTarget) and the LITE-023 cursor; both anchor segments are lexed into the fused F token since DOG-034. CFOLD (DIS-082, quickjab/dog/CFOLD.h) stores per-commit 'C' records: canonical id (hi64 sha1), body range, P_c view length; CFOLDBlame maps a body offset to its inserting commit; CFOLDIterNext walks any rev's view.

  • Anchor forms, decided by segment 2: :123 line; :123:45 line:col, current version only (both all-digit); :k4:d8K3 permalink (segment 2 carries a non-digit).
  • Hashlet = BLOB id prefix, nothing else: min 4 chars, EVEN length (12-bit chunks, 3 hexes per 2 chars), extended by 2 until unique in scope AND holding one non-digit.
  • Scope is ONE file — the path's own blob history plus its staged/working blob, never repo-wide; that keeps the space tiny and hashlets short.
  • Later collisions resolve to the EARLIEST match in the path's history order — a later blob's own links were minted longer, so old links never break.
  • Blob-only also serves commit-time minting: the commit id cannot be known while the link bytes are part of the commit, blob hashes of staged files exist; a same-file self-link stays :line:col or pins the pre-edit blob.
  • Offset segment needs no rules: the form is decided by segment 2, and the 16 MiB cap bounds it at 4 ron chars.

Goals

Door leg + resolution walk + mint gesture; line:col behavior unchanged.

  • Door (lite/main.js): splitRef learns the permalink form — segment 2 non-digit routes to resolution instead of the line:col shed; miss stays the quiet plain-words bar message.
  • Resolve: path -> file (chooser on several); hashlet -> the path's blob (earliest in history order; index/worktree-only blob = the working version); byte k4 in that blob -> forward-map to the current/required version -> open, cursor on the row:col via LITE-023.
  • Tombed target: land on the nearest alive neighbor, bar says deleted in ⟨commit⟩ in plain words (Verbs error tone, no bare codes).
  • Mint: copy-permalink on the active token — hashlet of the VIEWED version's blob, offset = the cursor's byte position in it; no blame, no tokenizer, no commit needed (staged blobs mint fine).
  • Chooser leg keeps the anchor through ambiguity, as LITE-024 does for :line:col.

Constraints

  • Repo split as LITE-024: CFOLD-side helpers in a ///quickjab worktree (its dog sub carries DOG-034; ///jab/dog and installed jab are STALE — run pty probes with LITEJAB=<quickjab build>); door/pager/tests in ///lite. No VC ops.
  • All anchor parsing rides the lexed F token bytes; no regex, no URI machinery, no new grammar.
  • Verify through the real UI path: pty probe follows a minted permalink to the moved line after later edits, plus the tombed leg.
