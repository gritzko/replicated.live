Ruling (gritzko 2026-08-14): lite now with no argument prints the CURRENT ron60 timestamp; lite now <ron60> converts the given ron60 word to the ISO date format. Pure JS over the existing ron bindings (quickjab codec.c, JS-021: ron.now(), ron.encode/ron.decode) — no C changes, no new bindings; the digit unpack is BigInt shifts.

Input

Context

ron60 timestamps stamp every ULOG row and log view, but there is no CLI way to mint one or to read one back as a calendar date. The encoding is ten 6-bit RON Base64 digits, calendar-field packed (abc/RON.c RONOfTime): [y/10][y%10][mon][dd/10][dd%10][hh][mm][ss][ms/64][ms%64], years 2000-2099, so a JS unpack is shift-and-mask on the BigInt.

  • ron.now() (RONNow, localtime-aligned) and ron.encode/ron.decode (RON64 text ↔ value — verify the direction in codec.c) already ship in the runtime.
  • ms spellings above 999 occur in real rows and are VALID; RONToTime clamps on conversion — the JS unpack mirrors that, never errors on them.

Goals

Two legs of one verb, CLI-only (no pager view, not in the VERBS door).

  • lite now — the current ron60 as RON64 text, all 10 digits (no DeNorm strip: the tail digits are the ms), one line.
  • lite now <word> — <word> is 1..10 RON64 chars; a short word is LEFT-ALIGNED (ron60Norm semantics: a1 reads as a100000000); output 20YY-MM-DDThh:mm:ss.mmm, one line.
  • A word with a non-RON64 char or an out-of-range field errors in plain words (e.g. not a ron60 timestamp: <word>), non-zero exit.
  • Dispatch in main.js alongside index/log/commit/diff; --plain is a no-op here (the output is already plain).
  • Test test/now/: lite now output is 10 RON64 chars that survive a decode/encode roundtrip; a FIXED fixture word yields its exact ISO string; the short-word alignment case; the error case.

Constraints

  • JS only, lite/main.js + the new test/now/ files — nothing else moves; the uncommitted index/index.js edit in the tree is NOT yours, leave it.
  • No new C bindings; reuse the ron object; no hand-rolled base64 tables if ron.encode/ron.decode can carry the text leg.
  • MAIN-TREE edit by explicit order (this ticket only); NO version-control operations there, not even put.
