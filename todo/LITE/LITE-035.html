lite serve (LITE-034) ships every file as syntax-painted source; this follow-up makes .md pages read like pages. The parser is already in the tree: LITE-030 vendored the commonmark.js 0.31.2 parse half, LITE-031 (merged) added the four GFM extensions — what is missing is only the HTML emitter, because upstream's render/ was deliberately dropped in vendoring. This ticket writes that walk: mark/ AST in, HTML out, ours in style and ours in safety. StrictMark .mkd rendering (the be/verbs/mark/render.js port) is NOT this ticket — .mkd keeps serving as painted source until that follow-up.

Input

Context

The vendored parser (lite/mark/, entry mark/gfm.js) yields the full node inventory: blocks, inlines, and the GFM four — strikethrough, task lists (checked state on the node, LITE-031), extended autolinks, tables.

  • Upstream's HTML renderer was dropped with render/ (LITE-030); the emitter must be a fresh walk, not a re-vendor.
  • LITE-030 pinned two parser divergences the emitter inherits: normalizeURI is identity (source URL bytes pass through), and the interim entity table decodes numeric + ~90 named refs.
  • The HTML oracle for tests is the cmark-gfm binary (LITE-031 rule: never a second JS parser).
  • LITE-034 gives the router, the response path and the theme-derived stylesheet the rendered page plugs into.

Goals

A .md URL in lite serve answers with rendered HTML; the source stays one click away.

  • An AST→HTML walk over the vendored parser's node types, GFM four included: <del>, real checkboxes (disabled), <table> with alignment, autolinked <a>.
  • SAFE BY DEFAULT: raw HTML blocks/inlines in the source are escaped and shown as text, cmark's --safe stance; a served page must never carry attacker-authored script. javascript: and data: link/image destinations are dropped the same way.
  • Relative links rewrite into serve URLs (.md targets stay rendered pages, other paths go to their painted view); headings get stable anchors.
  • Rendered is the default view for .md; a raw/source toggle links to the painted-source view LITE-034 already serves.
  • Tests: ported spec examples through parse+emit, cmark-gfm agreeing on the HTML; plus the safety legs (raw HTML, bad URL schemes), which cmark confirms under --safe.

Constraints

  • ZERO edits inside the five vendored files and the gfm-* layer; the emitter is a separate mark/html.js (or similar) reading the AST only.
  • Ported tests 500 lines MAX (gritzko's LITE-030 cap); embedded spec examples carry the CC-BY-SA attribution, same as the LITE-030/031 legs.
  • NO StrictMark logic: .mkd is out of scope, no be/verbs/mark code copied in.
  • ZERO quickjab edits; pure JS over the existing runtime.

WIP

Design decisions

  • Emitter output is a body fragment; LITE-034's page shell (head, stylesheet, nav) wraps it — one chrome for painted and rendered views alike.
  • Table nodes render as real tables here even though LITE-032 cannot lift them into StrictMark; the two consumers of the AST stay independent.

Files

  • mark/html.js — 214 lines, NEW. The whole emitter: one node.walker() pass, put/cr mirroring cmark's own line breaking, so the output is cmark-gfm's byte for byte. render(doc, opts) gives a BODY FRAGMENT; toHtml(src, opts) is parse+emit for a caller that has bytes. opts.href is the ONE hook — (destination, isImage) -> url | "", "" meaning the link paints as plain text. The GFM four: <del>, <input type="checkbox" disabled> off item.taskChecked, <table>/<thead>/<tbody> with align=, and autolink <a> (a plain link node by then).
  • index/serve.js — +54 lines. ROUTE gains raw: "cat"; a .md under /cat/ RENDERS, /raw/<path> is the same bytes painted, and each view banners a link to the other. mdHref resolves a destination WHILE THE PAGE IS RENDERED, through the same door LITE-034's refUrl uses: absolute urls and bare #anchors ride as typed, a relative one is joined onto the document's own directory and handed to pg.door.seatOf — a .md target lands on its rendered page, another path on its painted view, a directory on /list/, and a miss or an ambiguity comes back "" and paints plain. No second resolver, one cache and one REF_CAP budget per page.
  • view/html.js — +25 lines: viewBar (the banner band with the toggle) and markBody (the fragment in the same .hunk chrome), plus six geometry-only .mark rules in the generated sheet — currentColor throughout, so the theme still owns every colour.
  • README.mkd — +2 lines under the serve entry.

Safety, as shipped

Raw HTML blocks and inlines are ESCAPED to visible text (cmark drops them for a comment — ours is the stricter of the two), and a javascript:/vbscript:/ data:/file: destination renders as PLAIN TEXT, no <a> at all (cmark keeps <a href="">). The scheme gate strips whitespace and control characters before it reads, so \tJAVASCRIPT: and java\nscript: are caught; entity-encoded schemes are already decoded by the parser. Titles and alts are attribute-safe.

Tests

test/mark/html/run.sh — 416 lines (cap 500), NEW, six legs. *PASS html 128 checks* with the oracle, 80 without it ($CMARK absent → the agreement checks skip, ours still run). 38 ported spec examples: each is checked against an embedded expectation AND, on the spot, against cmark-gfm -e strikethrough -e table -e tasklist -e autolink (0.29.0.gfm.13) — CC-BY-SA attribution for both specs in the header. Nine safety cases assert our output whole and assert that cmark refuses the same danger under its own safe default. The wire leg starts lite serve on a git fixture and pins: a .md URL answers rendered HTML, no painted spans on it, the checkbox and the aligned table present, sub/x.txt → /cat/sub/x.txt, sub/other.md → /cat/sub/other.md, sub → /list/sub/, a miss with NO href, no javascript: and no <script anywhere, the source toggle → /raw/doc.md (painted, with a rendered link back), a link inside sub/other.md resolved against ITS directory, and .mkd still painted.

Whole suite re-run on this box: 23 of 25 PASS, lite/diff (1 of 34) and lite/pager (1 of 33) failing identically before and after (the known environment artefacts); test/serve unchanged at 174 checks, test/mark at 66, test/mark/gfm at 49.

Oracle sweep outside the test (652 CommonMark 0.31.2 spec examples through parse+emit vs cmark-gfm, heading ids stripped): *568 identical. Of the 84 that differ, 72 carry raw HTML (the deliberate safety divergence above) and 12 are PARSER ground, inherited and not touched here — 2 the interim entity table (LITE-030), 10 the 0.29-vs-0.31 base gap (nested `**strong***` runs, the unicode-punctuation flanking rule). No emitter-level disagreement was left.

Divergences pinned in the test header

Ours: raw HTML as text, dropped schemes as plain text, and a slug id on every heading (cmark emits none — leg 2 strips id="…" before comparing, leg 5 asserts the ids). Inherited: identity normalizeURI, which the emitter cures at RENDER time by escaping the destination houdini's way (so </my uri> agrees with cmark again), the interim entity table, and the 0.29/0.31 base gap.
