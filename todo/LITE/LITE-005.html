Ruling (gritzko 2026-08-13): the pager must use the EXT of the file to decide on the tokenizer. Today buildFileHunk passes any ext to tok.parse, and dog's TOKLexer falls back to the GENERIC TXTTLexer for an unresolved ext — so .txt prose gets its punctuation painted grey where C bro leaves plain text unpainted (LITE-004's skip-guarded finding). An unknown ext must yield NO toks.

Input

Context

The C truth already exists and must not be mirrored in JS (no parallel ext lists): dog/tok/TOK.c TOKKnownExt(u8csc ext) = TOKResolve(ext) != NULL over TOK_TABLE (name, then dotted-ext). It is not exposed to JS — quickjab/tok.c installs only tok.parse/TokStream.

  • The generic fallback lives in TOKLexer (fn == NULL → TXTTLexer), reached through HUNKu32bTokenize; dog/CFOLD.c:608 shows the house pattern — the CALLER gates on TOKKnownExt before tokenizing.
  • Measured (LITE-004): txt, xyz, dat, log → 19 toks on the same prose; only ext === "" short-circuits today.
  • lite/test/pager/color.js carries the two skip-guarded asserts (txt-toks-empty, txt-row-no-paint) written for exactly this gate — flip them to real checks.
  • jab (JSC, dev runtime) has no such binding and jab/ is READ-ONLY: under jab the gate cannot fire. quickjab is lite's product runtime; the dev divergence is accepted and the tests must branch on the binding's presence.

Goals

Two small edits + the test flip.

  • quickjab/tok.c: expose tok.known(ext) — a thin JABC_API_FN over TOKKnownExt (same u8 arg plumbing parse uses; string in, boolean out). No behavior change to parse.
  • lite/view/bro.js buildFileHunk: tokenize iff ext is non-empty AND (tok.known is absent OR tok.known(ext)); else new Uint32Array(0). Correct the misleading KnownExt comment. NO JS ext list.
  • lite/test/pager/color.js: txt-toks-empty + txt-row-no-paint become real checks when tok.known exists, and keep a one-line skip (pointer: jab lacks tok.known) when it does not.
  • Verify: under a rebuilt quickjab (unpacked ~/tmp + refreshed build-lite) a .txt/.xyz hunk has 0 toks and paints nothing while .js/.c still paint; the full pager suite passes under all four runtimes (under jab the two checks skip); packed quickjab <a .txt> in a pty shows unpainted prose.

Constraints

  • Touch ONLY quickjab/tok.c, lite/view/bro.js, lite/test/pager/color.js (+ run.sh only if a leg needs the branch). be/, jab/ untouched; never read beagle/.
  • Dev builds in ~/tmp; only quickjab/build-lite refreshed in place. No VC ops.
  • ABC house rules for the C edit (meta/abc.mkd); comments max 2 lines tagged LITE-005.
