lite/ has three output modes — plain, color (tty), html — over one good hunk model, but the axes are tangled: color exists only inside the pager (no ANSI-to-pipe), the plain leg is five hand-rolled copies in main.js (runPlain/runLog/runCommit/runDiff/runView), verbs return four different shapes (rows, text+hunks, hunks, hunks+plain/bytes), and bro.js mixes hunk building, row geometry, the ANSI painter and the plain sink in one file, with TOK_TAG and banner chrome mirrored again in html.js. Target: N views x 3 renderers with no pairwise code, a new renderer = one file in render/.

Input

Context

The current seams, mapped 2026-08-15 on the main tree lite/:

  • One view contract almost exists: a hunk is {uri, kind, text, toks}; all three sinks already consume it without re-reading a byte (plainHunk bro.js:334, cellAnsi bro.js:122, hunkHtml html.js:119); theme.js single-sources every colour number.
  • The door is already shared: openTarget/seatOf/VERBS in main.js serve CLI args, pager clicks and serve links alike.
  • The plain escape hatch sits at two levels: per-hunk hunk.plain (diff weave) vs per-view out.plain (list/tree rows).

Goals

Views and renderers become orthogonal axes; the tree says which is which.

  • Tree: index/ lane+ODB readers only; view/ one module per verb -> {hunks}; render/ = theme.js wrap.js plain.js ansi.js html.js, each render(hunks, opts) -> bytes, verb-blind; door.js the one openTarget/seatOf/VERBS table; pager.js and serve.js top-level apps pinned to ansi/html.
  • One view shape: every verb returns {hunks}, hunk = {uri, kind, text, toks, plain?, land?}; log rows, commit meta text and list/tree out.plain become ordinary hunks; per-hunk plain stays as the ONE escape hatch.
  • One mode pick in main.js: tty -> pager, --plain, --color (the missing ANSI-to-pipe leg, falls out free), --html; the five bespoke plain legs collapse into one runVerb(verb, arg, renderer).
  • bro.js dissolves: build* hunk makers -> view/fs.js, geometry (indexRows/rowEnd/landAt/tokSpanAt) -> render/wrap.js, painter -> render/ansi.js, plain sink -> render/plain.js; the html.js TOK_TAG/banner mirror dies.
  • Apps stay renderer-pinned, not renderer-owning: the pager paints per visible row via ansi.paintRow(hunk, span); serve calls html.render with its link resolver; both navigate through the door only.

Constraints

  • Worktree //LITE-045 (clone ///lite/ per /meta/work); no VC ops; suites green under a fresh quickjab (LITEJAB=, stale ~/bin/jab lacks git.getTreeDiff).
  • Byte parity pins the reorg: every existing plain leg and every serve page must emit identical bytes before/after each step (capture goldens FIRST); pager pty smokes unchanged.
  • Pure moves and the contract change land as SEPARATE steps, never mixed in one edit; no behaviour change except the new --color/--html legs.
  • No require shims: each step updates every require path it breaks; the tree never holds two copies of a function.

WIP

Design decisions

The reorg is stepwise, cheapest-risk first; every step ends with all suites green and the golden bytes identical. Steps:

  1. Goldens: script captures plain output of every verb x fixture and a served page set; this is the parity oracle for all later steps.
  2. Contract: all verbs return {hunks} (log/commit/list/tree reshaped, out.plain/out.bytes retired into per-hunk plain); main.js's five plain legs collapse into one runVerb; goldens byte-identical.
  3. Carve render/: move theme.js; split bro.js into render/plain.js, render/ansi.js, render/wrap.js and view/fs.js; update requires; bro.js deleted.
  4. html.js -> render/html.js consuming the same painter tables (its TOK_TAG/chrome mirror deleted); mark/ embeds unchanged.
  5. door.js: openTarget/seatOf/splitRef/VERBS move out of main.js; pager.js and serve.js re-point; main.js is dispatch + mode pick only.
  6. Verb modules move index/ -> view/; index/ keeps the readers (index.js, read.js, resolve.js, weave.js, perma.js, hook.js).
  7. New legs: --color (ansi.render to a pipe) and --html, one flag scan in main.js; new tests pin both.
