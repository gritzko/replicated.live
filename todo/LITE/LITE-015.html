Ruling (gritzko 2026-08-14): a file reference in any viewed file (/* refers to diff/color.js */) is a click target that opens the file it names — test/diff/color.js in the lite repo. Detection is DOG-033's fused F token, resolution is LITE-011's FSEG descent at HEAD; the pager stays arg-blind and hands the token bytes to the door verbatim. Paint is unconditional and the CLICK verifies, exactly like ticket codes: a non-resolving reference is a quiet plain-words bar message.

Input

Context

lite's click path today (view/pager.js _mouse/_followRow): a hidden U span opens verbatim (a log row's commit <hexlet>), an F dir-listing entry follows via _follow; an F token inside a FILE hunk falls through to nothing. The door openTarget (main.js) reads a <verb> <arg> line or stats a path; a partial like diff/color.js stat-misses into "cannot open", though index/resolve.js can already name test/diff/color.js from it.

Goals

Click a path reference → the file opens; several candidates → a chooser view; none → a bar message.

  • Pager: after the U-target check, an F token in a FILE hunk hands its BYTES to the door — no resolution, no path math in the pager (dir listings keep _follow).
  • Door: a stat miss falls back to resolve.resolveAt(ctx, ix, HEAD, partial) on the cwd repo; ONE hit opens the recovered full path. The : bar gains the same fallback for free (same door).
  • SEVERAL hits: the list IS the answer — push a CHOOSER hunk, one row per candidate full path: the visible path text plus a hidden U span carrying it (the log-row precedent), banner = the partial as typed. Enter/click on a row opens that file, - backs out. Zero new pager machinery — _targetAt already opens U spans.
  • NONE: "cannot open diff/color.js" on the bar, quiet — the pager already spells this.
  • pty click repro (test/click precedent): a fixture whose comment names another file uniquely AND ambiguously; assert the pushed view for the unique hit and the chooser rows + second click for the ambiguous one.

Constraints

  • Resolution is per-commit (HEAD trees): an uncommitted/untracked file does not resolve; no worktree scan here — that is its own ticket if wanted.
  • The chooser is a plain hunk {uri, text, toks} built like index/log.js rows — U target bytes ride the text, invisible at paint, --plain never sees a chooser (non-tty has no clicks).
  • No hand-composed URIs, no second descent: index/resolve.js is the ONE resolver; the door reuses it, never reimplements.
  • A ticket-code F (ABC-123) in a lite view stat-misses and FSEG-misses into the same quiet message — lite has no todo/ resolver and grows none here.
