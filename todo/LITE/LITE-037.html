Input

Context

  • No JS reST parser exists in-tree; docutils is Python and out of the question; vendoring rules are LITE-030's (zero npm deps, CommonJS under require.c).
  • serve emits final hrefs at render time, door code shared with the pager (path→FSEG→perma), unresolved refs stay plain text — the ruling of 2026-08-15; an rst renderer inherits it.
  • LITE-032 set the normalize-to-StrictMark pattern for GitHub Markdown; .mkd rendered pages are themselves still pending in serve.

Goals

.rst files serve as rendered pages with resolved links, at parity with the .md treatment.

Constraints

  • Zero npm deps; whatever parses reST is small, vendorable or hand-written JS in lite/.
  • Subset over completeness: sections, paragraphs, lists, literal blocks, inline emph/strong/literal, targets+references first; directives/tables can degrade to literal text.

WIP

Design decisions

  • BUILT AS (a), BY DEFAULT — *subject to gritzko's override*, which would rm -rf the worktree and cost nothing else. (b) waits on a .mkd renderer that is not in the tree, so it could not be built at all; (c) forfeits the rendered page the goal asks for. (a) also turned out to be the CHEAP one: mark/html.js walks a plain mark/node.js tree, so the reST parser builds THE SAME commonmark nodes and the LITE-035 emitter, the LITE-034 page shell and the serve link door are all reused BYTE FOR BYTE — one new file, no second emitter, no second resolver, zero edits on the Markdown side.
  • The two rendered dialects meet in ONE table, index/serve.js RENDER ({md, rst}): the parser is all that differs, and a third dialect is a row.
  • The subset, and what every other construct degrades to — nothing is dropped silently except the comment, which reST itself drops:

section titles (over/underline) -> <h1>..<h6>, style ranked first-seen paragraph -> <p>, source line breaks kept bullet / enumerated list -> <ul> / <ol start=>; marker style

change opens a new list

literal block :: -> <pre><code>, reST's colon rule block quote (indented run) -> <blockquote> transition -> <hr /> emph *strong `literal -> <em> <strong> <code> hyperlink target + reference -> <a>, named / phrase / anonymous / (t <uri>_, name_, p_, __) embedded-uri, unresolved -> PLAIN standalone http(s)/mailto uri -> <a>, trailing punctuation left out title` (single backticks) -> <em>, the citation role

degrade ---------------------------------------------------------- directive (.. x:: incl. image, -> LITERAL: its own source in <pre> raw, substitution defs) footnote / citation definition -> LITERAL grid table (+---+) -> LITERAL, the ASCII art intact :role:text -> <code>text</code> comment (.. text) -> DROPPED, as reST drops it field list, line block, simple -> PLAIN paragraph text table, |sub|, [1]_

  • Links follow the serve ruling verbatim: a destination is resolved WHILE THE PAGE IS RENDERED through pageHref — the same door .md uses, so an .rst target lands on its rendered page, another path on its painted view, a directory on /list/, and a miss or an ambiguity paints PLAIN TEXT. A path/ticket ref in reST PROSE links exactly as much as it does in .md prose, i.e. only where the document writes a reference — bare prose refs stay the painted-source side's job (DOG-038), and adding prose autolinking to .rst alone would put the two dialects out of step.
  • SAFE BY CONSTRUCTION: the parser emits no html_block/html_inline node at all, so a document's own markup is always text; the emitter's scheme gate then drops a javascript:/data: destination to plain text as before.

Files

  • mark/rst.js — *405 lines, NEW*. The whole parser, two layers. The BLOCK layer (blocks(), //LITE-037/mark/rst.js:68) is one line-index loop over the seven openers in order — indent, section title, transition, explicit markup, grid table, list, paragraph — each returning the index past what it took, so an unrecognised line always falls through to a paragraph and the loop always advances. A list item is its marker line with the marker taken off plus everything indented past the marker column, handed BACK to blocks() (:163), so a nested list, a second paragraph or a literal block inside an item all work with no per-case code. The INLINE layer runs after the whole document is read (parse(), :393), which is why a reference resolves against a target defined ANYWHERE — before it, after it, or in another section. markupAt() (:301) tries the seven inline forms at one offset and returns the index past the winner or the offset itself; phraseAt() (:365) is the backtick fork (embedded uri / named / anonymous / citation). Exports parse(src) -> a commonmark document node and toHtml(src, opts) -> the body fragment.
  • index/serve.js — *+14 lines* (428 -> 442). RENDER = {md, rst} (:227) is the dialect table and renderOf(path) (:230) the lookup that replaced isMd; mdPage/mdHref became pageBody/pageHref and pageBody now takes the dialect's toHtml (:269). extOf(path) (:72) is the one extension split, shared with LITE-036's mimeOf. The dispatch is one line (:359). Nothing else in the file moved: the same route table, the same door, the same cache and the same REF_CAP budget per page.
  • README.mkd — +1 line under the serve entry.

Punts, all deliberate and all pinned by a check

  • Alphabetic and roman enumerators (a., iv.) are paragraphs — only \d+ and # open an ordered list, so a sentence starting A. is not silently eaten. Simple tables (==== ====) are paragraphs for the same reason: a run with a gap is not an adornment line.
  • A tab counts ONE column, as in the DOG-038 machine.
  • An INTERNAL target (.. _name: with no url) records an empty destination, so name_ paints plain — the emitter has no way to put an id on a node, so there would be nothing to jump to.
  • .. image:: degrades to literal, so LITE-036's /bytes/ route is not reached from an .rst page. A real <img> would need the directive read rather than degraded — one branch in explicitAt, if it is wanted.
  • Adornment chars exclude . and : (DOG-038's cut), and an adornment run needs three characters, so --/** never reach the block layer.

Open question for gritzko

Besides the (a)/(b)/(c) ruling itself: section levels are ranked by FIRST-SEEN adornment style, per reST, so a document that overlines its title and underlines the rest gives h1 to the overlined style and h2 to the first underlined one — see Install above landing on h2. That is docutils' behaviour; if serve should instead pin .rst headings to a fixed depth, it is one line in headingAt.
