gritzko's ruling 2026-08-14: the lite pager gets a notion of an ACTIVE line and an ACTIVE token, rendered as a colour wash (bg lightness shift for the line, a stronger second wash for the token — composes over the diff/why washes, never a hue that drowns them). Keyboard then navigates the cursor, not just the scroll: Enter follows the ACTIVE token's U target when there is one, falling back to the active row's entry (today Enter only fires on the TOP row, _followRow(v.scroll)). A mouse click sets the cursor before following. lite/ pager ONLY for now — be's pager and C bro follow later, on their own tickets.

Input

Context

lite/view/pager.js (LITE-002) has scroll-only state: view = {hunks, path, rows, scroll, cols, wrap}; Enter/click follow via _followRow/_uriAt (hidden U toks), _screenToByte maps a click to a byte. lite/view/bro.js paints rows with attr composition (aOr, the LITE-010 diff wash slots) — the wash machinery the active line/token rendering rides on.

  • Current keys (SHORTCUTS/_keyScroll): q, j/k scroll, space/b page, g/G, m mouse, : bar, Enter, -/BS back, R/r, w wrap, h help.
  • A row knows its hunk + byte range ({hunk, off, end}); tokens per row come from the hunk's tok32 stream, same walk _screenToByte does.
  • The cursor is render-side state; hunks/toks stay untouched — no new tok tags.

Goals

Cursor state + wash rendering + keys, in lite/view/pager.js (+ a paint hook in lite/view/bro.js if the row painter needs an "extra attr" arg).

  • view.cur = {row, tok}: active display row, active token index within it (tok optional — a line with no tokens is still an active line).
  • Active line: a subtle bg LIGHTNESS wash OR'd over every cell of the row at paint time; active token: a stronger wash on its span. Both compose with existing washes (diff in/rm, why blame) — pick shifts, not hues.
  • Token hops land only on FOLLOWABLE tokens — a visible token with a hidden U follower, or an F nav-target tok (ticket codes / file refs, the LITE-015 click path) — skipping plain text; a line with none has no active token.
  • Enter follows the active token exactly as a click on it would (U target, F door hand-off), else the active row (the _followRow fallback); click = set cursor to the hit cell, then follow as today.
  • Cursor moves scroll the viewport when it walks off-screen; scroll alone never moves the cursor (the two are independent, vim-window style).
  • Status line may show the active target's name/path (the _uriAt string) instead of the top-row #L.
  • Help hunk (h) regenerates from the ONE SHORTCUTS table, per BRO-007.

Constraints

  • lite/ ONLY: lite/view/pager.js, lite/view/bro.js, lite/test/. No jsrc/, no jab/, no C. No VC ops.
  • Verify through the real UI path: pty probe (LITE-004 style) showing the wash moving under the keys and Enter following the active token — not unit probes alone.

WIP

Design decisions

  • KEY SCHEME RULED (gritzko 2026-08-14): scheme B — vim keys drive the cursor, asdw scrolls + back/fwd. j/k = active line down/up, h/l = active token prev/next; w/s = scroll up/down; a/d = back/forward through the view stack (back stays on -/BS too; FORWARD is NEW — a fwd stack popView currently drops, in scope). Displaced keys: help h → ?, wrap w → W.
  • Wash values: reuse the LITE-010 wash-slot shape — one WASH_CUR_LINE + one WASH_CUR_TOK attr const in bro.js, OR'd in the row paint when the pager passes the cursor down; theme decides light/dark-safe shifts.
