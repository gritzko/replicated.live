LITE-001

Port be's raw-mode alt-screen hunk pager to beagle-lite as the plain FILE pager: scrollable viewport, syntax colours, status bar, mouse — with the whole be-verb layer removed. The pager displays files and dir listings; navigation is fs-only (follow a dir entry, back, refresh).

Input

Context

The original: be/views/bro/pager.js (READ-ONLY). Most of it is be-specific and must NOT come along: spell composer/argline/glob, tab completion, per-repo cache, CI badge/runner, viewmark ticks, discover/context invite (BRO-024), ticket resolver, mutation/editor gating, be.* ambient globals, URI machinery.

  • The TUI boilerplate to keep is proven: raw/cook via try/finally, ALT screen (BRO-027), SGR mouse (JAB-030/BRO-005), bracketed paste, straddling-escape carry, 100ms key spin, resize repaint (BRO-045), one-write frames (BRO-011 byte discipline).
  • LITE-001 provides lite/view/bro.js + theme.js with be-identical export names; hunks are {uri, verb, text, toks, kind}.
  • The pty harness pattern (be/test/bro/pager/pty.js) drives a Pager against tty.openpty step by step — keep the object headless-drivable: new Pager(fd, opts), setHunks, pushView/popView, render, key, _feed.

Goals

Create lite/view/pager.js exporting {Pager, indexAll, paintRow, SHORTCUTS}.

  • Pager(fd, opts); opts: {color, open} where open(path) -> hunks|null replaces driveSpell — the entry (LITE-003) supplies the fs open; the pager NEVER touches the fs itself except via open.
  • KEEP: run() raw+ALT lifecycle with finally-restore; render() one-write frame (banner band via theme, emitBody byte sink, CRLF); indexAll; scroll keys q/j/k/space/b/g/G; m mouse toggle; w wrap toggle (per-view only — no be.wrap defaults, drop W); Enter/click follow; -/BS back-stack (popView re-indexes); R/r refresh (re-open the view's path, keep scroll); h help; : bar with Esc/Backspace editing and bracketed paste capture.
  • Status bar: inverse video; left <path>#L<line> of the top row's hunk (bro.statusURI), right <TOP/NN%/BOT> h: help; command mode shows : <buffer>. No context invite, no CI badge, no loading band.
  • Follow (Enter on a row / left click): a dir-hunk row's F-token name joins the hunk's OWN path (dir listing → open the entry); a file row does nothing ("(nothing to follow)"). uriAt reduces to the F-token read; screenToByte keeps the cell walk (no els).
  • Mouse: wheel = scroll 3; plain left press = follow that row's entry. Same SGR ESC[<b;c;rM/m parse + straddle carry.
  • h builds an inline help hunk from SHORTCUTS (plain text; no views/help).
  • : bar accepts: q/quit to exit; anything else is a PATH — resolve ./x ../x against the current view's dir, absolute as-is, bare name against the view's dir — then open() and push. No verbs, no spells.
  • Relative-path join: a small local resolve (split on "/", collapse ./.., never climb above "/"); lite has no shared/util.

Constraints

  • require ONLY "view/bro.js" and "view/theme.js". No core/, no shared/, no be.*, no uri/URI, no abc, no CACHE/CI/VIEWMARK/TICKET/SPELL.
  • Touch ONLY lite/view/pager.js. No VC ops, no commits.
  • Verify headless from a cwd inside lite/ under jab AND quickjab: a ~/tmp probe that openpty's, renders a synthetic hunk, sends j/q, checks the frame bytes (body, inverse bar, band) — the be pty.js pattern.
  • Size target: under 600 lines (the original is 1622; the drop list is most of it).

WIP

Design decisions

  • A View carries a path — the string open() was called with. be tracked view.uri/view.call (a spell + its context); lite has neither, and the hunk's own uri is a DISPLAY string, so refresh and the : bar's relative resolve need the opened path recorded. setHunks(hunks, path) takes it, defaulting to hunk 0's uri so a one-arg headless driver still works.
  • open(path) gets the path VERBATIM — the pager never splits arg from fs path. bro's buildFileHunk(arg, path) two-arg shape means the entry (LITE-003) can keep a short display uri and resolve the fs path itself; the pager only ever hands back what it composed from the view's own path.
  • BACK does NOT re-drive. be's - pops AND refreshes (a mutation verb could have changed the tree under it); lite's views are pure fs reads and R/r is one keystroke away, so popView just re-indexes for the live width and the saved hunks stand — no second open() per back press.
  • _uriAt reduces to "is the token covering this byte tagged F?". There is no U/O click-target layer in lite (buildDirHunk emits F + P + W only), so a dir entry's own name IS the nav target and a file row has none. A click that lands on the P slash falls through to _followRow, which re-reads the row at its start offset — so the slash is not a dead cell.
  • The . / # ? sigil keys are DROPPED, not re-purposed. In be they open the bar pre-filled for a URI SLOT edit (?ref, #frag); lite has no slots, and the ticket's key list stops at :. : opens an empty bar, nothing else.
  • Wrap defaults to true per view and only w changes it (W/be.wrap and wrapFor are gone). The rows() cache key stays (cols, wrap) so the toggle re-indexes and a scroll does not — the BRO-014 mechanism, minus the session table it read from.
  • emitBody/paintRow keep be's pass parameter (always PASS_NORMAL here) and the U/O hidden-cell skips, so the walks stay byte-identical to the originals and to lite/view/bro.js's rowEnd column accounting.
  • _statusLine shows the message + <path>#L<n> LEFT and <pos> h: help RIGHT, no invite/context prefix: with no context to name, be's //WT/dir/: would be a bare : on every frame. Command mode still prints : <buffer>.
  • Errors are plain words on the bar — cannot open <path> for a null/empty open() result or a throw, (nothing to follow) / (nothing to refresh) / (no prev view) for a gesture with nothing behind it. Nothing escapes to the key loop and kills the session.

Blockers and bummers

  • run() cannot be smoke-tested with a PRE-QUEUED key: ANSIRaw (dog abc/ANSI.c) installs the raw termios with TCSAFLUSH, which DROPS input already sitting in the slave's queue. Under jab the queued q vanished and the loop spun forever; under quickjab the same probe passed by luck (the write had not landed yet when tcsetattr ran) — a race, not a runtime difference. The probe now ends the loop from a render hook instead, which still exercises raw + ALT + one real frame + the finally-restore.
  • The pty harness's pump() originally tested its done-condition BEFORE reading, so a send whose condition was already true left its bytes in the slave queue for the NEXT pager object to swallow (a stray ESC cancelled a later : bar). Read first, test after.

Outcome

lite/view/pager.js created — 576 lines (target: under 600; the be original is 1622). Nothing else touched, no VC op run.

Exports {Pager, indexAll, paintRow, SHORTCUTS}; requires ONLY view/bro.js and view/theme.js.

  • KEPT: run() raw+ALT lifecycle with the finally-restore (BRO-027), the one-write byte frame (BRO-011: enc for SGR/ASCII, raw(lo,hi) for verbatim text) with the theme banner band and CRLF rows, indexAll, rows() cached on (cols, wrap) (BRO-014), scroll keys q/j/k/space/b/g/G, m mouse toggle, w wrap toggle, Enter/click follow, -/BS back-stack, R/r refresh keeping the scroll pos, h inline help off SHORTCUTS (BRO-007), the : bar with Esc/Backspace editing, the SGR mouse parse + bracketed paste + straddle carry in _feed (JAB-030/BRO-005), the 100ms key spin and the resize repaint (BRO-045), _screenToByte's cell walk.
  • DROPPED: spells/argline/glob/tab-completion, CACHE/CI/VIEWMARK/TICKET/ SPELL/discover, the context invite (BRO-024) and ctxWt, mutation/editor gating and _suspend/_resume, be.* globals, all uri/URI machinery, the loading band, W, the . / # ? sigils, hunksFromTlv/hunksFromLog, the diff/why/elastic-B render branches and els throughout.

Probe: ~/tmp/lite-pager/pty.js (fixture ~/tmp/lite-pager/fix/, a jsrc symlink beside it; cwd lite/), after be/test/bro/pager/pty.js — openpty, setSize(slave, 10, 40), new Pager(slave, {color:true, open}) where open is the LITE-003-shaped io.stat + buildDirHunk/buildFileHunk opener. *65 checks, ALL OK, byte-identical output under jab and under quickjab/build-lite/bin/quickjab:*

  • frame 0: body text, the banner band (48;5;230, _banner fills exactly 40 cells and closes ESC[0m, a body row is unbanded), the inverse bar (ESC[7m open, 40 cells, ESC[0m close) carrying doc.txt#L1, TOP and h: help.
  • j scrolls (scroll==1 and the body shifts — row IIII enters the frame); G clamps to the last row and paints BOT, g returns to TOP.
  • a dir view (open(".")): the F-token entry row is found, Enter opens doc.txt (file hunk, pushed on the stack, painted), - restores the dir view with rows === null and an empty stack.
  • : bar over the pty: other.txt, ./sub/deep.txt, ../other.txt (the .. collapse) and an ABSOLUTE path all open; Esc cancels; bracketed paste captures sub/deep.txt with the pasted \r NOT submitting, and a 3-byte-truncated ESC[200~ is carried (feed consumes 0); :q sets quit.
  • mouse: a truncated wheel report consumes 0 bytes (straddle carry), a real ESC[<65;5;5M scrolls +3 and ESC[<64;5;5M back, a left press ESC[<0;2;2M on a dir row opens that entry.
  • w: a 300-char line indexes to 1+8 rows wrapped, 1+1 no-wrap, and back.
  • h pushes the help hunk and - backs out; R re-opens keeping scroll 5; Enter on a file row says (nothing to follow); a missing path says cannot open <path>; m toggles both ways.
  • run(): one frame painted, quit set, _saved nulled, and the master saw ?1049h … ?1049l, ?1000h, ?2004h and ?25h.

Deviations from the ticket: none in scope. The judgement calls (view path, back not re-driving, the sigil keys dropped) are recorded under Design decisions. A bug found while probing — resolvePath read its absolute flag off rel instead of the JOINED path, so every follow under an absolute base lost its leading / — was caught by the probe and fixed before the green run.
