LITE-026

The LITE-026 mint iterates to a bounded fixpoint (4 rounds): rewriting carrier B changes the blob a link in A names, so hashlets are re-minted until the images stop moving. On a DAG that converges — it is a lazy topological sort. On a LINK CYCLE (A links B, B links A — the same-file self-link generalized: a hash naming content that contains the hash) it cannot converge, and the current bail "still moving = nothing written" abandons EVERY upgrade in the commit. The right grain: an explicit topo sort mints the acyclic part and leaves only the refs sitting ON the cycle as line:col — exactly how self-links are already treated.

Input

Context

index/hook.js: the pass collects fresh refs per staged file, mints against target blobs, then loops rewrite rounds; the round cap doubles as the cycle detector. Carrier->target edges form a file-level graph; hashlet dependence flows target-first.

  • Fixpoint failure today is all-or-nothing per COMMIT, not per ref.
  • A cycle is unmintable by construction, not a transient: no round count helps.

Goals

Deterministic one-pass mint, cycle members degraded per-ref.

  • Build the file-level link graph from the collected refs; topo-sort; mint carriers in dependency order (targets final before any hashlet that names them).
  • Cycle members: their refs onto the cycle stay line:col, said in plain words; refs from cycle members to acyclic targets still mint.
  • Round cap and "nothing written" bail retired; behavior on a DAG byte-identical to today.

Constraints

  • ///lite worktree, index/hook.js (+ tests) only; no VC ops.
  • RED first: a two-file link cycle plus an innocent third file — today the third file's ref is abandoned, after the fix it mints.
  • Full-suite failure counts identical to the pristine baseline; existing test/hook legs stay green unamended unless reported.

WIP

Design decisions

  • The order and the cycle set come from ONE primitive: Tarjan over the carrier graph emits strongly connected components SINK FIRST, which is exactly "every target settled before anything naming it". A ref is unmintable iff carrier and target land in the SAME component — and that single test also IS the self-link rule, since a file linking itself is its own component with an edge to itself. No separate self-link branch left.
  • Edges only to CARRIERS: a target this commit does not rewrite is already final, so it is no edge at all and can never make a cycle.
  • The plain-words note names the REAL cycles only. A self-link is documented and expected (LITE-025), so it stays silent — the old code said nothing about it either, and a line on every commit carrying one would be noise.

Spec/code note for gritzko, not improvised around:

  • The edges are STRUCTURAL — a ref that resolves to a carrier is an edge even if it would not have minted anyway (say, a line past the end of the target). So two files whose back-ref merely resolves read as a cycle and both refs degrade, where the old fixpoint would have settled. Making the edge depend on mintability makes mintability depend on the edge, so it was left honest.
