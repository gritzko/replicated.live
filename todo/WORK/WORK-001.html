Goals

Bare work renders three blocks — ASCII tree in plain mode, HUNK spans + hidden U nav in the pager:

  1. the TREE: the top wt as root, mounts recursed in .gitmodules order; each line <date5> #<hashlet8> <subject> off that line's cur tip; a work wt tracking a wt pin hangs under the tracked wt.
  2. BRANCHES: store → shard → branch (nested by name segments) → the wts tracking that branch, named by authority path (e.g. //WORK-123/test).
  3. FOREIGN: refs/anchors outside the project's stores, with the wts tracking them.
  • Every wt row carries ahead/behind counts vs its TRACKED ref (ruling below), rendered compactly after the subject.
  • Siblings name-sorted everywhere; a work wt is ONE row — no descent into its own mounts.
  • DAG cost batched per shard: keeper opened ONCE per (store,project), ancestor closures memoized per distinct tip — hundreds of wts share a handful of tips.

Constraints

  • Read-only view; discovery = readdir of work/ (the BE-043 .be-file gate) + the context tree's mounts; NOTHING hardcoded.
  • ALL URI/track/anchor parsing via the wtlog reader / uri / core resolve — no regexes, no string surgery (work §NOT TO DO).
  • Date column: the existing ron.date / render.dateCol 7-col utility (the 5-char 18Jul form) — no new formatter.
  • Keep BE-043's machinery (workDir, buttons, tests) — the forest is the BARE form; the flat board's chrome rides the wt rows.
