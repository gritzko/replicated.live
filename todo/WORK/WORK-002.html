Goals

An O-invite mutation runs IN the invite's recorded context, full stop: [get] on //bro-why appends to bro-why's wtlog and touches nothing else; a run whose context cannot be anchored refuses loudly (no fallback to cwd/launch tree).

  • Red-first repro: fixture forest, press [get] on a row whose context ≠ launch tree; assert the row's wt got the get row and the launch tree's .be is byte-identical.
  • Root-cause where the context is dropped: _actSpell(spell, ctxOverride) → driveSpell(s, ctx) — does driveSpell's ctx only scope ARG resolution (nav) while the verb's TARGET wt stays the process cwd? The BRO-025 spec is chdir/serialize/restore — the recorded-call path — the verb must run AS IF cwd were the context.
  • Fix in the shared drive path, not per-button.

Constraints

  • Rulings in force: verbs resolve args via resolve(context,base,rel) — the pager is arg-blind (BE-030 family); //authority is consumed from arg0 ONLY (authorityRepo); context changes ONLY by navigation (BRO-024).
  • Distinct from the day's OTHER wrong-tree writes: the be/.be hijack rows (26718KcF3v/KhW83) were a poisoned-code cascade (pre-DIS-062 code) — THIS misfire ran current WORK-001 code, so it is a live tip bug in the O-context execution path.
