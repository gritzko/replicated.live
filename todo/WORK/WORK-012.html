WORK-012: work view pin-form tracker ahbeh reads the parent's TIP, not its gitlink pin

Now
OPEN

A wt tracking a slashless pin-form URI (get ///be#43a754a0… — //WHY) renders [+99][-1]: placeWt (views/work/work.js:257) hangs it under the mount's PARENT and computes counts(wt.repo, wt.sha, nodeTip(parent)) — the parent repo's own tip sha, fed into the WT's shard keeper. Input

Context

  • Repro live in the forest: //WHY (work/WHY) tracks ///be pinned #43a754a0…; journal root tip is #4d8da412… (journal repo), its de-jure be pin IS 43a754a0… — correct ahbeh is 0/0, row shows [+99][-1].
  • resolveTrack (work.js:221-244): slashless track → { node: m.parent } — returns ONLY the parent node, DROPPING which mount/subpath the pin names; placeWt then has nothing to look the pin up by.
  • The mount repo rows already do it right: nodePins(node, reg)[c.subpath] (work.js:601) per the R2 ruling "a mount reads vs the PARENT's de-jure gitlink pin" (dejure-vs-defacto, work.js:20-22).
  • Same wrong-tip shape wherever the parent is a DIFFERENT repo; a same-repo parent merely yields wrong-but-plausible counts.

Goals

  • A pin-form tracker wt's ahbeh reads its cur tip vs the PARENT's de-jure gitlink pin of the tracked mount (nodePins(parent)[subpath]); //WHY renders no counters (0/0).
  • A dir-form track (///be/) keeps reading vs the mount's own live tip — unchanged.
  • No cross-repo sha ever enters a shard keeper's ancestor walk.

Constraints

  • Fix inside resolveTrack/placeWt: return the mount node + pin/base bit (or the subpath) instead of pre-collapsing to the parent; hanging position (under the parent) stays as ruled by WORK-007.
  • Unpinned mount (no gitlink in the parent's base tree) → no counts, like the repo rows' mc = pin ? … : null.
  • WORK-011 rewires counts() onto the graf index — coordinate; this ticket is about WHICH shas compare, not how.
