WORK-008: work view post mints the ticket's status mark into the message

Now
OPEN
Sev
LOW

Input

Context

Reported by gritzko 2026-07-19. The [post] button mints post '<ticket title>' where title = the ticket page's RAW first header line (views/work/work.js:338 → views/todo/todo.js:116 pageTitle, #+padding stripped only), so the status mark leaks into the commit message: post 'WORK-004 [OPEN]: work view — …'.

  • Mint site: work.js:429 SPELL.mintOspell(ctx, "post '" + title + "'").
  • todo.js:127 headerMark already parses the mark grammar — an UPPERCASE […] word either side of the colon (KEY [MARK]: title and KEY: [MARK] title both live on the board).

Goals

Regex the [OPEN]/[HIGH]/[MED]/[LOW]/[DONE]/[DONT]/[STALE] status token out of the minted title — everything before the first ':' loses the mark, so the message is WORK-004: work view — … (the meta/work.mkd commit convention).

Constraints

  • Fix at the work-view title consumer, not inside pageTitle (the todo board reads the mark separately via headerMark); reuse/share the todo.js mark grammar rather than a second regex if cheap.
  • Handle both mark placements around the colon; a markless title passes through unchanged.

WIP

Design decisions

- Shared grammar: refactored todo.headerMark to a markSpan() helper; added todo.stripMark(key,title) beside it, exported for work.js. - Strip at ticketTitle() (the work.js pageTitle consumer), NOT in pageTitle; board still marks via headerMark. Both placements + colon-space normalized; markless title passes through unchanged.

Blockers and bummers

Outcome

Fixed. work.js ticketTitle now calls todo.stripMark; grammar shared via markSpan (headerMark + stripMark). Red-then-green verified. Files: views/todo/todo.js, views/work/work.js, test/work/view/{check.js,run.sh}. Suggested commit: WORK-008: strip status mark from work post title
