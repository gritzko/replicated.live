WORK-017: work view stats 88 .be files per render — cache tracked ref + base in a root .be-ref ulog

Now:
OPEN

Every work render walks work/ and be.treeAt(dir)-opens each wt's .be to read its tracked ref and base commit — 88 wts in this tree today, plus a .be per mount. The read is pure re-derivation: a wt's .be is append-only, so an unchanged size+mtime means last render's answer still holds. Cache the resolved (ref, base) per wt in ONE append-only ulog at the project root, .be-ref, validated by stat(); only stat-mismatched wts get opened. Complements WORK-011 (ahbeh via graf, not a DAG walk) — same render, the other half of its cost.

Input

Context

  • Scan today: listWork (work.js:71-86) stats <wt>/.be per name, then be.treeAt(dir) opens+parses it (work.js:179, again work.js:762).
  • isMount (work.js:88-95) stats a .be per gitmodules path per wt — the per-mount multiplier on top of 88.
  • ls -d work/*/ = 88 wts in //journal as of 2026-07-20; the WORK-001 survey counted ~65.
  • Per-render memos exist (keeper/ancestors/metas per shardKey, work.js:99-150) but die with the process — nothing survives to the next render.

Goals

  • A render whose wts are all unchanged opens ZERO .be files: one .be-ref read + 88 stat()s.
  • A render after N wts changed opens exactly those N.
  • Rendered ref/base values are byte-identical to the uncached path on the same tree state.

Constraints

  • .be-ref is PURE CACHE: absent, truncated, or garbage tail ⇒ every key is a miss and the view rebuilds. The work view must never fail on it.
  • Ref/base resolution stays in be/core/resolve_hash.js — the cache stores its OUTPUT, never a second resolver.
  • Rows name trees by URI (//WT/), not prose paths.
  • Cache lives at the project root, beside .be, and is never committed.

WIP

Design decisions

  • One append-only ulog .be-ref at projectRoot, keyed by the wt URI, latest row wins on replay.
  • Row = //WT/ <tracked-ref-uri> #<base-hash> <size> <mtime> — size/mtime of THAT wt's .be.
  • Validator is size+mtime of <wt>/.be: append-only, so size alone nearly suffices; mtime catches replace.
  • Vanished wt = tombstone row (empty ref), so it is not a permanent miss on every later render.
  • Compact (replay → temp → rename) when rows exceed 4x live wts; never in the read path.
