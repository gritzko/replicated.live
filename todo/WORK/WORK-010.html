Work-view row chrome, split from the WORK-001 forest work. A worktree named after a ticket (//WORK-004) or a ticket topic (//WORK) should carry a [?] button linking to that ticket page — todo:TKT-123 for a ticket name, todo:TKT for a bare topic — so the ticket is one click from its wt row. Independently, the [diff] button compacts to [±], shrinking the fixed button region.

Input

Context

  • The view already resolves ticket-named wts: [post] takes its commit title via todo.pageTitle (views/work/work.js:333-339), and the WORK-001 [done]/[dont] ruling flips a ticket-named wt's ticket header status.
  • Button slots today (work.js:379-393, reshaped by WORK-004): [diff] mints diff //KEY; [+N]/[-N] mint bare post/get; no ticket-page link anywhere in the row.
  • The row's key/URI click navigates to the wt's STATUS (WORK-001 ruling), so the ticket page needs its own click target.

Goals

  • A wt whose name is a ticket code gets [?] minting the todo:TKT-123 link; a wt named for a bare topic (e.g. //WORK) gets todo:TKT (the topic's ticket dir).
  • [diff] renders as [±] — same verb minted (diff //KEY), just the compact face; slot widths and the aligned button column shrink accordingly.
  • RULING (gritzko, chat 2026-07-19): [?] and [±] are the FIRST TWO buttons of the row, in that order, ahead of the rest of the button run.
  • Non-ticket-named wts show no [?] (padded per the WORK-006 absent-button ┄-pad).

Constraints

  • Ticket-name detection reuses the shared ticket lookup (the todo.pageTitle path) — no new name parsing; ticket/topic resolution through the standard resolvers only.
  • Overlaps the unlanded WORK-001/003/004 cuts of views/work/work.js and the be/test/work/view/ layout test; build on be tip, expect weaves.
  • Plain (no-pager) output: no buttons today, so no [?]/[±] there.
