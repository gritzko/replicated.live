A board page resolves ~512 ticket codes per request and re-derives every one from zero: per code x per mount the door reopens the lane, re-reads the tip and re-runs the FSEG resolve (door.js:332 inMount), and the mount order asks git/linux/quickjab before bee-journal ever answers. GIT-031 cached only the ODB handle; the rest of the resolution layer still lives by the CLI's open-read-close hygiene, which a resident server pays per reference. RULING (gritzko 2026-08-20): cache FULLY, per repo, for the process life; staleness is witnessed by fsw and never by a TTL — an event on a repo drops that repo's entries and nothing else.

Input

Context

  • The resolution layer per (ref, mount): laneUp = openIndex + bringUp watermark (door.js:301), tip = refs.head + readCommit (door.js:334), FSEG resolve per spelling (door.js:344); all reopened per call.
  • pg.refs memoizes per PAGE only (http.js:229 memoUrl); the next request pays all 512 again, warm = cold.
  • The BEE-027 rev tree (index/cache.js) is the fsw witness and http already runs it — but it deliberately skips .git (object churn), so lane and tip moves are invisible to it today.
  • wtstat.js:40 MEMO is the house pattern: memoize only under a live watcher, one-shot CLI runs compute and remember nothing.
  • The board already holds every row's resolved file (view/todo.js gather t.file) yet paints the key as a plain reference token, so http re-resolves what the view knew.

Goals

  • Per-repo door cache, process-life: resolved ref -> seat/href, the open lane handle, the tip {head sha, commit, tree} — one map keyed by repo root, entries shared by CLI-door, pager and http alike.
  • fsw drops it, PER REPO: an event under a repo's worktree or gitdir invalidates that repo's cache entries only; no TTL, no epoch guessing where a witness can stand.
  • A narrow gitdir watch joins the rev tree: HEAD, refs/ and .git/be (the lane) — the dirs are few and quiet; objects/ stays unwatched (GIT-031's freshen gap is its own ticket).
  • Mount order stops hurting: a ref born on a board row resolves in the row's OWN repo first (BEE-008 spirit); the fan-out runs only on a local miss.
  • Bar: the second /todo/Now:* request must not reopen a single lane or re-read a single tip; page bytes byte-identical to today.

Constraints

  • No door variant per frontend (LITE-045:27): the cache lives inside door.js / index, not in http.js.
  • Cache only under a live watcher (wtstat.js law); a one-shot CLI run behaves exactly as today.
  • A dropped repo recomputes lazily on the next query, never eagerly.
  • A write through BEE-047's act endpoint or the pager must land in the same witness path (bumpRoot already misses every memo).
  • Tests: warm-request lane/tip open counts (zero), a touch under todo/ dropping ONE repo's entries, a ref move under refs/ dropping tip+lane; no other tests edited.

WIP

Design decisions

  • Ref->seat entries key on (repo, ref string); the fan-out's negative answers may cache too, dropped by the same per-repo witness as the positives.
  • The gitdir watch rides index/cache.js as extra armed dirs attributed to the repo's root spot, so one rev(root) compare still answers "did anything move".

Blockers and bummers

  • Own-repo-first is NOT done: resolvePartial already tries the ambient repo first, so the only win left is making a board page's ambient ROW-aware — the row's home would have to ride the painted token through view/todo.js into http.js's one-ambient-per-request link closure. That is the view surgery this ticket ruled out; it wants a ticket of its own.
  • Only the readers that bring the lane UP share the cached handle (door.js laneUp, view/todo.js dateRows). view/status.js, view/log.js, view/list.js, view/diff.js and every writer (index.js, hook.js, mint.js, perma.js, lindex.js foreign) still own theirs: a lane cached without a bring-up would hand the door stale rows, and a read-only one is a different handle.
  • A gitdir whose refs/ fans past 64 dirs BLINDS its root — cache.rev hands out fresh tokens there, so that repo recomputes every query rather than trusting a witness that cannot see a ref move.
  • openRepo now arms the whole worktree of every repo the fan-out touches, so the FIRST query after startup pays one tree walk per registered repo; wtstat paid it for board repos only.
