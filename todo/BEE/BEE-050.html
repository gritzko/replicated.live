A permalink is a place the reader has to go to. BEE-017 gave the CLI one way back — bee see <ref> — but one ref at a time, retyped by hand, so reading pager.js or a ticket still means leaving the page at every link. bee cite <path> is the other half: the file as it stands, tokenized once, with every F token that carries a line anchor resolved and its target quoted directly under the line that named it — one line of context above, two below. Source or markdown, anything the lexer takes.

Input

Context

The three halves of this already exist and nothing joins them over a whole file.

  • index/hook.js:24:_m fTokens fuses a ref into ONE F token; link recognition is the tokenizer's alone (LITE-033:42:DE), so no view ever re-scans bytes.
  • door.js:106 seatOf resolves every shape there is — permalink, path, FSEG partial, ticket code, cross-repo — and splitRef tells an anchored ref from a bare name.
  • view/see.js:43:s0 window already cuts a context window and chunk already frames it as a banded excerpt with the landed line selected.
  • gritzko's shape, verbatim: "take a source or a markdown, anything, tokenize it, figure out the permalinks, and under any line with a permalink add a hunk with its target, one line of context above, two after".
  • gritzko's rulings on scope (2026-08-21): ANY anchored ref, not permalinks alone; the verb is cite; a miss adds NOTHING; a repeated target opens at its FIRST mention only.

Goals

The file, readable end to end, with its references already open.

  • A VIEW, (arg, opts) -> hunks (LITE-045:42:Zg), argument <path>[?<rev>] exactly as cat takes it, so the pager, the three renderers and http take it for free.
  • Every F token whose splitRef yields a line >= 1 — a permalink f.c:12:aB and a plain f.c:12 / f.c:12:24 alike; a bare filename or a ticket code is left alone.
  • One excerpt hunk per opened ref, 1 line above and 2 below the landing, banded with the target's own path and anchor, the landed line selected as see selects it.
  • A cited line past 128 symbols is a screenful in itself and is quoted ALONE — context beside it reads as noise (gritzko, 2026-08-21).
  • In html the quote's HEADER is an anchor onto the whole file it quotes, opened AT the line quoted — we work in permalinks, so a link lands somewhere (gritzko, 2026-08-21).
  • Several anchored refs on one line open in token order, each its own hunk, under that line.
  • The source is SPLIT at each such line: the file's own bytes flow as bare hunks, the excerpts sit between them.
  • A ref that misses, is ambiguous or names a line the file no longer has adds nothing at all — the line stays bare.
  • The same target named twice opens once, at its first mention; a later repeat stays bare.
  • Two anchored refs on ONE line whose windows overlap open as one quote over the union, not as two overlapping ones (gritzko, 2026-08-21).

Constraints

  • No second link scanner and no second resolver (LITE-034:40:zw, BEE-017:14:qe): hook.fTokens, door.splitRef/seatOf and see.window are extended where they fall short, never copied.
  • The file is tokenized ONCE and the tok stream is SLICED per segment — re-lexing a segment would break the very block comments permalinks live in.
  • A ref resolves in the FILE's ambient (BEE-028), its own repo and dir, not the pager's view path.
  • Tests: a fixture carrying a permalink, a plain :line, a bare name, a dead ref, a repeat and a 200-symbol line; a --plain leg and a hunk-level leg; no other suite edited.

WIP

Design decisions

  • see.window grows an asymmetric (bytes, line, up, down) with down defaulting to up, so see's symmetric -C is untouched and there stays ONE line-window reader.
  • see.chunk splits into seatOf + excerpt(seat, ref, up, down, solo); cite resolves its own seats — it needs them for the dedup key and the miss gate — and calls the same builder, so no excerpt is built twice.
  • A hunk gains an optional line0, the file line its first line is; pager.js:413:TJ _srcLine adds it, so a split source hunk's #L stays absolute. Absent means 1, so no existing view moves.
  • Source segments are bare: true — the file must read as one flow — and excerpts bare: false, since an excerpt wears the band (BEE-017:35:qe).
  • The solo cap is a PARAMETER of see.window, not a rule inside it: see's -C is the reader asking outright, and a tested verb must not shift under a ruling made for another.
  • A hunk gains an optional ref, its band's target RE-SPELLED as path + the RESOLVED line, and html links the header through it. The uri itself will not serve — an absolute path carrying a hashlet resolves nowhere (BEE-018) — and the resolved line is what the permalink meant anyway.
  • see.window reports the LAST line it reached and excerpt stamps it on the hunk as win, so cite — the only weaver of several — widens a quote by re-cutting it, and see still never merges (BEE-017:42:qe).
