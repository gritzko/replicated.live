index/lindex.js:126:b_ symsOf decodes every token span with a STRICT utf8.Decode, so a blob whose bytes are not UTF-8 throws and takes the WHOLE scan() down with it — before either mark is written. bee index ///git dies with utf8.Decode(): malformed UTF-8 on t/t3434/eucJP.txt, and since BEE-065's upForeign swallows the throw, the failure is invisible AND unbounded: the LINK/SYM mark never lands, so EVERY new process re-lexes that repo's whole tip tree. Measured: bee sym hlOfText costs 11.6 s of CPU on every run, 11.67 s of it ///git and ≤0.07 s all nine other registered repos. Inside bee http this runs on the one pol loop, so the server is frozen for the duration. The lexers are NOT at fault: DOG-044 landed and holds (see Context) — these files are genuinely ISO-8859-1 / EUC-JP / Shift-JIS, and no grammar can make them decode.

Goals

No single blob may abort a repo's round, and no failed round may be paid twice.

  • A token span that is not valid UTF-8 never throws at a consumer: the three raw-span sites are lindex.js:126:b_ symsOf, hook.js:37 fTokensOn, http.js:402:gw/:407/:415 (the page's own painter).
  • scan() SKIPS such a blob and keeps going — one warning line naming the path and the reason, not per token — and still lands both marks, so the second run of the same tip no-ops off the mark as the lazy contract promises.
  • upForeign stops swallowing: a bring-up that failed says so once, and a repo that cannot complete is not re-walked by every next process.
  • bee http serves a non-UTF-8 blob as a page (whatever the painter shows for a refused byte) instead of 500.
  • Test: a fixture repo with an ISO-8859-1 blob indexes clean, second bee index says up to date, bee sym answers off its rows, the page is 200.

Constraints

  • No second pass over the bytes: scan() already lexes every moved blob and is the hot path — the guard rides the spans it has.
  • A skipped blob is skipped for SYM/LINK rows only; the commit walk, the diff and the weave keep reading it as bytes, as they do today.
  • Worktree only, no main-tree edit, no VC op (work).
