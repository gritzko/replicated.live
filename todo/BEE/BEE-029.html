Nothing on the render path knows what a Markdown YAML preamble is, so a Jekyll-shaped page opens with a <hr /> and its metadata comes out as prose: http://localhost:8888/bee/cat/test.md serves ---\nlayout: post\n--- as a thematic break followed by a setext <h2 id="layout-post">layout: post</h2>, the --- closer being read as the heading's underline. bee mark page.md does the same, both going through mark/html.js:225:3i's toHtml with the file's raw bytes. The rule itself is already written twice in the tree — index/kv.js:126:De's bodyStart skips the preamble for the keyed lane, and MDFMFind (quickjab/dog/tok/MDFM.c:11) pins it for the dog lexer under MARK-017 — so this is one shared splitter short of done, not a new grammar.

Input

Context

The preamble is how every generator on the planet carries .md page metadata (MARK-017), and bee serves such files both over http cat and through the mark verb.

  • Repro, ~/src/bee/test.md: ---\nlayout: post\n---\n\n## Header\n\nsome text\n served at /bee/cat/test.md gives <hr /> + <h2 id="layout-post">layout: post</h2> before the body.
  • bee mark page.md on the same bytes plus title:/tags: lines fuses the whole preamble into ONE <h2 id="layout-post-title-hi-tags-a-b">.
  • index/kv.js:126:De already treats those bytes as metadata for the kv lane, so the index and the renderer disagree about the same file.

Goals

A preamble is dropped from the rendered page, and the rule lives in ONE place.

  • Recognized at byte 0 only: a bare --- first line, closed by a --- or ... line, or by EOF; a --- below line 1 stays a CommonMark thematic break.
  • Both renderers drop it: http cat of a .md and bee mark of a .mkd/.md/.markdown page; .rst is another dialect and is untouched.
  • One splitter, shared: index/kv.js's bodyStart becomes a call into it, so the lane and the page never split a file differently.
  • A page with NO preamble renders byte-identically to today.

Constraints

WIP

Design decisions

  • mark/front.js is the splitter's home: preamble shape is Markdown dialect knowledge, and index/kv.js (the lane) requires it rather than owning it.
  • It exports the render entry too (front.toHtml), so neither http.js nor view/mark.js spells the strip-then-parse pair itself.
  • EOF closes a preamble, matching MDFMFind and bodyStart: an unclosed --- head eats the page, which is the price of one rule across the three impls.
  • A .mkd page gets the same treatment as a .md one — index/kv.js already reads a preamble off either ext.

Blockers and bummers

  • A .mkd preamble is dropped from the rendered page while its keys stay live in the kv lane — the page shows no metadata at all, which MARK-011's link cards will want back.
