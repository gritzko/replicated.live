The board's +1 button is bee push (view/wtstat.js:220:histCell), and pushing a worktree whose upstream is local lands it as the PARENT tree's own ff-merge (sync.js:131:_X the landSite leg). That merge moves the gitlinks HEAD records — and stops there: no descent follows, so the main tree's submodule checkouts stay where they stood. Evidence: after landing DOG-047, git ls-tree HEAD in ~/src/quickjab records dog=060bd00, test=038f1f4, while the live checkouts stand at fbbf85e (dog) and behind (test) — the main tree now BUILDS pre-land sub code under a parent that records the landed commits, and its status reads "new commits" noise until a hand-run git submodule update.

Input

Context

  • The cure already exists ONE function away: sync.js:157:follow detach-advances every live sub checkout to its recorded gitlink, depth-first, fetching a commit the sub has never seen; integrate() (pull, merge) calls it and its comment names this exact hazard (QJAB-007 sat stale the same way).
  • push()'s landSite leg runs the site merge + the autostash-reapply check and returns — follow(site, left) is simply never called there.
  • The forked sub worktrees are worktrees of the SAME sub repos (BEE-026), so the landed sub commits are already in the shared ODB and the follow is a pure checkout, no fetch in the common case.

Goals

  • After the landSite merge succeeds (autostash check included), the same follow descent runs AT THE SITE: every live sub checkout detaches to the gitlink HEAD now records, nested subs recursing.
  • The report line counts the subs moved and the ones left, as integrate's does (push <up> <sha> 2 subs, … 1 behind).
  • A sub that refuses the checkout (dirty main-tree sub) is reported behind, never an error — the merge has landed and no rollback can follow it (sync.js:156:_X rule).
  • The remote-push leg (git push -q) is untouched: there is no site to descend.
  • A repro test: land a worktree carrying a sub commit, assert the main tree's sub checkout advanced and the report line counted it.

Constraints

  • The descent only ever checkout --detachs — it commits nothing, stages nothing (worktree-loop rule: commits are the user's).
  • Uninitialised subs stay untouched (bee fork grows those, sync.js:160:_X); a BEE-059 skipped optional sub stays silent.
  • One follow: reuse sync.js:157:_X, no second descent implementation.
