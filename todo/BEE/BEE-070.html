The bee http rendered view of a .mkd/.md page (/<repo>/cat/<page>) links a bare reference in prose and a [BEE-001] shortcut, but a reference written in backticks — ` index/perma.js:6:ur , http.js:843:gw — renders as a dead <code>. The painted source (/raw/) links the very same bytes. [/meta/comment] and [/meta/link] tell every writer to spell a link in backticks, so nearly every permalink in this journal is unclickable on the page it was written for. Repro'd 2026-09-08 on bee/README.mkd (3 hrefs rendered vs 18 painted) and on meta/link.mkd` (no ref links at all).

Input

Context

  • http.js:390:dX pageHref and http.js:406:dX autoSegs are the door for the rendered page (LITE-043): hk.fTokens(bytes, "txt") scans a TEXT run, refUrl resolves each F token, a miss stays plain. http.js:427:dX pageBody passes both hooks to the ONE emitter.
  • mark/html.js:192:4b the emitter runs opts.autolink on a text node only; mark/html.js:209:4b a code node emits <code id=..> + the escaped literal and never calls the hook. So the door never sees a span the writer fenced.
  • render/html.js:220:eM spansHtml links a painted F token inside a backtick run regardless — the tokenizer's F fires there — which is why /raw/ shows the links and /cat/ does not.
  • Evidence: /bee/cat/README.mkd renders <code id="b709">index/perma.js:6:ur</code>; /bee/raw/README.mkd renders <a href="/bee/cat/index/perma.js#b73"><span class="tok-F">index/perma.js:6:ur</span></a>. A bare http.js:510:dX in BEE-020.mkd:54:Uh prose DOES link (/bee/cat/http.js#b42825), so the door itself is fine.
  • test/http/run.sh:235:1l pins the rendered doc.mkd: the fixture's bare sub/x.txt links, the ticket code naming no file stays prose; no backtick case there.
  • view/html.js (bee html, BEE-062) renders with mark.pageHref and NO autolink hook, so a dumped site page links only [Page] shortcuts; view/html.js:183:MQ landLink already rules a code reference in a shortcut as plain text there. Out of scope unless it comes free.

Goals

  • A code span whose literal the LITE-043 scanner reads as one or more F tokens links through the SAME door a text run does: <a href="…"><code id="b<off>">http.js:843:gw</code></a>; a miss paints the <code> exactly as today.
  • A code span that carries a ref plus other bytes (` bee see index/perma.js:6:ur ) links the ref inside the <code> the way cutRun splits a text run: <code id=..>bee see <a href="…">index/perma.js:6:ur</a></code>`, ids per BEE-052.
  • Never inside an already-open <a> (inA), never inside a fenced block (code_block is lexed per MARK-018 and is not this ticket's).
  • Repro FIRST: test/http/run.sh's doc.mkd fixture gains a backticked ref (` sub/x.txt ) and a bare one on the same line; assert the <code> is wrapped in / carries the <a href="/repo/cat/sub/x.txt"> and the painted /raw/` page is unchanged.

Constraints

  • ONE emitter: the change lands in mark/html.js's code case (and cutRun if the split is reused), not in a second scanner; hk.fTokens stays the ONE F scanner, no regex over the literal.
  • Every other page paints byte-identical; test/mark/* (cmark side-by-side) stays green — a page with no autolink hook emits what it always did.
  • No other test edits, no commits, no push (work); comment budgets per comment.
  • Work in the MAIN tree ~/src/bee (gritzko's explicit permission for this ticket, 2026-09-08); ln -s . jsrc is in place, run with LITEJAB=$HOME/bin/quickjab sh test/http/run.sh.

WIP

Design decisions

  • The <a> goes INSIDE the <code>, for the whole-span case too: the Goals allowed either shape, and one shape means ONE code path — the whole-span case is simply the split with no plain bytes around it, so there is no second branch to keep honest and no code a rule to add (blob/style.css styles neither code nor code a).
  • cutRun is NOT reused: mark/strict.js:155:xd mints parts on a TEXT node only, so a code node carries boff and nothing else; the <code> keeps its BEE-052 id via idOf and the segments inside it need none. The branch is the !node.parts half of case "text" verbatim.
  • The hook stays the ONE scanner: opts.autolink(node.literal) — http.js:406:dX autoSegs -> hk.fTokens -> refUrl. No regex, no second recognizer, and a miss (null segs) emits esc(node.literal), the exact bytes of before, which is what keeps test/mark byte-identical.
  • inA === 0 guards it exactly as the text case does: a fenced ref inside an already-open <a> stays plain code. A fenced BLOCK is code_block, an untouched case.
