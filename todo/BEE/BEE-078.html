BEE-078: pull's autostash lands in the stash shared by all worktrees

Now
OPEN
Sev
HIGH
Rep
///bee

bee pull autostashes uncommitted edits; when they don't reapply it says "your edits are safe in the stash, git stash pop to resolve". But git stash is one stack shared by every linked worktree, so with parallel ticket worktrees git stash pop pops another ticket's edits.

Input

Context

2026-09-24, pg repo, 3 worktrees (MECH-006, MECH-010, BRAIN-006) pulled main within minutes; the stack held On MECH-010: autostash over On MECH-006: autostash etc. An agent ran a bare git stash pop in MECH-010 while stash@{0} was BRAIN-006's (it failed on conflicts, by luck).

Goals

  • The hint names the exact stash (stash@{N} or its hash) and the branch, never a bare pop.
  • Better: stash to a per-worktree ref (e.g. refs/bee/autostash/<branch>), or refuse to pull with a dirty tree and suggest a commit.
