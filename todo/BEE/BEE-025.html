Goals

  • view/todo.js + the todo row in door.js VERBS: todo (board), todo TOPIC (list), todo Key:Value / Key:* / Key: (filter, AND across keys, OR within a key's repeats), todo TOPIC Key:Value (both); a miss is one line + throw, todo: <arg>: TODONONE.
  • Board root: <context>/todo/ when the context repo has one; else, with no //name context, the union of <root>/todo/ over mount.list(), each row prefixed by its repo name where the board mixes repos.
  • Open = Now: OPEN (or no Now: and no closed header mark, the legacy fallback); Sev: paints the bullet — CRIT red, HIGH salmon/orange, MED plain, LOW dim — via the view/theme.js slots the status view already uses.
  • Order: within a topic by code; the all-repos board and the filter list NEWEST FIRST — freshness is the wt mtime for a file whose bytes differ from the tip blob, else the commit time of its REV-CMMT row (be's byFresh); dateRows date separators ride along.
  • Rows: <●> KEY ┄ title, Sub: families nested with the RAIL; the row's U span is see KEY, a topic header's is todo TOPIC, an inline Key:Value is todo Key:Value (TODO-008 click).
  • http: the same view through render/html.js; bee todo --plain stays greppable KEY title lines.

Constraints

  • Read-only: no done/go, no keeper, no write to any ticket; the worktree column and the [..] buttons do not exist here.
  • The lane decides WHICH tickets open, the file decides what shows: title and first line come off the file, never off the index.
  • Arg routing is by SHAPE (bare / TOPIC / Key:Value, the uc ucnum* "-" dgt+ ticket-code rule stays lexical), never by path probing.
  • A ticket is todo/TOPIC/TOPIC-123.mkd or todo/TOPIC/TOPIC-123/README.mkd; todo/done/ never lists; attached files never list.
  • The all-repos board is a FAN-OUT over the mount table, each repo's own kv lane — never one index over many repos.
  • Under ~900 tickets a cold run (sweep + board) must stay interactive; a warm run opens only the files the lane names.

Design decisions

  • RULED (gritzko 2026-08-19): no context, no local todo/ -> ALL registered repos, newest first; no //<name>-journal guessing.
  • RULED: no ticket view — see KEY is the page, the board is the only new verb.
  • RULED (gritzko 2026-08-19): the per-ticket WORKTREE column comes back, as BEE-027 — status quad + ahead/behind per wt, in-process memo under an fsw watcher, $SRC_ROOT scan.
  • The Markdown/YAML status key is BEE-024's open question; until ruled, only StrictMark Now: opens a ticket.
  • RULED (gritzko 2026-08-19, in BEE-028): a context with NO todo/ (bee //linux todo, /bee/todo over http) falls back to the all-repos board; the refusal that landed first (todo: //<name>: no todo/) is gone.
  • Landed at defaults, unruled (four, each the ticket's own wording read verbatim):
    • Now: STALE does not open — be's own HIDDEN set is wider.
    • a time-ordered flat list wears no Sub: rails; rails need the code order.
    • the two BEE-027 frames ride the END of the row, per that ticket's sketch.
    • the all-repos board prefixes the KEY column, and the row still clicks see KEY.
  • kv.find grew ONE option, opts.rows: the matched files' cells ride back with them, so one query per repo per run answers the open test, the OR'd clauses and the Key: absences alike.
