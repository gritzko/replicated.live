bee install wires three things and no fourth (LITE-014 plus BEE-001): merge.bee.name / merge.bee.driver, the line * merge=bee in <gitdir>/info/attributes, and the pre-commit hook — its own report line says "bee is the merge driver and the pre-commit hook for <root>". The word diff appears nowhere in merge.js: no diff.<drv>.command, no textconv, no GIT_EXTERNAL_DIFF. So git diff in a bee-installed repo gives GIT's diff, and bee's own — the BEE-005 projection of ONE weave rooted at the merge base, which is a different and better answer — is reachable only by typing bee diff. This ticket asks whether install should wire that half too, and rules on the impedance that makes it more than a config line.

Input

Context

Observed 2026-08-16 in ///bee at a8b31da: git config --local --get-regexp 'merge\.|diff\.' lists merge keys only, and the reader who ran git diff expecting bee's output got git's.

  • Git offers TWO hooks and they differ in kind: diff.<drv>.command (an EXTERNAL DIFF that writes the whole diff itself) and diff.<drv>.textconv (blob -> text, after which git diffs the text with its own engine).
  • An external diff is called with SEVEN positional args — path old-file old-hex old-mode new-file new-hex new-mode — and /dev/null stands in for a creation or a deletion; it writes to stdout and git ships that through verbatim.
  • bee diff's shape is an ARG and a hunk list (view/diff.js, four forms), not seven paths; pager.js paints the hunks. Nothing today writes a diff to stdout for a caller that owns the pager.
  • THE TWO-BLOB CASE IS ALREADY BUILT: index/weave.js blobDiff(from, to, ext) folds exactly two loose blobs — no index, no rev read, chl may be null — and yields weaveDiff's own shape; it is what keeps bee commit an ODB-only view (ruling, test/commit).
  • So the seven args map straight onto it: the two temp files are from.bytes/to.bytes, the path gives ext, and the hexes give chl when they are real. The gap is only that git supplies no MERGE BASE, so git diff gets the parent->child reading, never BEE-005's rooted projection — and its per-path interface could not carry one anyway.
  • The stale wiring is its own evidence that this is untended: ///bee-journal and ///quickjab still carry merge.lite.* and * merge=lite pointing at ~/bin/bee, a naming two renames old.

Goals

git diff in a bee-installed repo shows bee's weave diff wherever bee can root one, and says nothing new when it cannot.

  • The driver rides blobDiff — the two-blob fold is the RIGHT answer here, not a degradation: it is the same reading bee commit shows, and a rooted one is beyond what git's per-path call can ask for.
  • install wires diff.bee.command and the diff=bee attribute beside the merge pair, idempotently, with the same --fixed-value care.
  • A HISTORICAL range stays the typed verb's: git diff A B still folds pairwise, so bee diff <hex> <hex> remains the only place BEE-005's merge-base rooting is offered, and the docs say which is which.
  • /dev/null sides (a creation, a deletion) fold against empty bytes, the shape blobDiff already takes.
  • git diff output is a byte stream on stdout with no pager and no colour of bee's own — git owns the sink, and a driver that paints unasked corrupts a pipe.
  • Whatever lands, install's report line names what it wired, and README.mkd stops implying merge-only.

Constraints

  • An isolated worktree; repro first, as a test; gritzko commits.
  • The merge wiring and the pre-commit hook must come through untouched — git merge is the load-bearing half.
  • Git calls the driver ONCE PER PATH, so an ODB open per file is a cost to measure before it is paid.
  • The seven-arg protocol is git's, not ours: no flag of bee's may be added to it, and the exit status must stay 0 on a normal diff.
  • textconv is the cheap alternative and must be weighed in writing: it needs no weave at all and would still give bee's TOKENISATION, not its history.

WIP

Design decisions

  1. RULED DONT (gritzko, 2026-08-16): bee diff works nicely and stays the one place bee's diff lives. git keeps its own git diff; bee wires the merge driver and the pre-commit hook and nothing else.
  2. The measurement that settled it — a fixture repo with a stub diff.<drv>.command: git diff and git diff A B DO call the driver and git prints nothing of its own (no diff --git, no index, no ---/+++, no @@), while git show, git log -p, git format-patch, --stat and --numstat all IGNORE it and keep git's diff. --exit-code stays right.
  3. So the wiring buys ONE verb and costs the patch: git diff > x.patch and git diff | git apply stop working, and the repo grows two diffs that disagree by verb. A typed bee diff costs a word and nothing else.

Outcome

Cancelled — no code, no wiring. What the ticket leaves behind is the finding.

  • The B2P route is REAL and stays on the record: a blob hashlet answers which path/rev it is the content of, so a diff adaptor COULD have rooted a weave; the reason not to is the patch and the verb split, not the machinery.
