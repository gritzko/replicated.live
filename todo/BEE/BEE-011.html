A generic name is ambiguous and a reader has no way to say which repo they meant: main.js answers bee/main.js AND quickjab/test/packtoy/main.js, so the ref reaches the chooser and http paints it plain. The natural spelling is the one a reader already writes — bee/main.js, the repo's NAME then the path under it — and it resolves to nothing today, because a mount name is not a path segment and resolvePartial's only repo-naming form is ///bee/.... That form works (1 hit, measured) but is UNREACHABLE from prose: the lexer strips the slashes, fusing ///bee/main.js as bee/main.js — which then misses. This ticket makes the name a legal leading segment, so the ref a reader writes is the ref that resolves.

Input

Context

Measured 2026-08-16 in ///bee at a8b31da, in the ambient of /bee-journal/todo/LITE/LITE-045.mkd:

  • main.js -> 2 rows (bee/main.js, quickjab/test/packtoy/main.js); html.js -> 2 INSIDE one repo (mark/, render/); weave.js -> 3.
  • bee/main.js -> *0 rows*: FSEG matches whole segments (index/resolve.js tailMatches), and no tree carries a dir named bee.
  • ///bee/main.js -> 1 row: resolvePartial's auth branch (path.slice(0,3) === "///") asks mnt.named and descends that one mount.
  • dogtok on prose: ///bee/main.js fuses as bee/main.js and ///bee/main.js:12 as /bee/main.js:12 — the authority slashes are punctuation to /dog/tok/LINK.rl, so the auth branch is reachable only from a typed arg or a URL.
  • The two spellings that DO disambiguate today are the parent dir (render/html.js, index/index.js) and the rooted form with an anchor (/main.js:12:592E -> 1 row) — the latter forcing the author to name a line they may not mean.
  • The URL space ALREADY reads this way: BEE-003 ruling 5 serves a submodule as /quickjab/dog/abc/TCP.c, the parent's NAME then the path.

Goals

The repo name is a legal head of a reference, so bee/main.js resolves exactly where ///bee/main.js does.

  • bee/main.js answers one row — the mount named bee, the path under its root — and clicks through from any page in any repo.
  • A PLAIN partial keeps winning: the name-prefixed reading is tried only where the ordinary one misses, so no ref that resolves today changes its answer.
  • A submodule keeps its BEE-003 address (quickjab/dog/abc/TCP.c) and the two readings agree rather than compete.
  • A name that is ALSO a real dir (test/ is both a mount prefix and a directory in several trees) resolves by the ruled order, not by luck, and the order is written down.
  • ///bee/main.js goes on working from a URL and a typed arg; whether the grammar should carry it in prose is /dog/tok/LINK.rl's business, noted here and not taken.

Constraints

  • An isolated worktree; repro first, as a test; gritzko commits.
  • index/resolve.js stays a whole-segment matcher — the name is stripped BEFORE the FSEG descent, never matched by it.
  • A dup mount (a name claimed by two lines, mount.js list) is not reachable by that name and must not become reachable here.
  • No new lane reads on the hot path: the name lookup is the mount table, which is a handful of lines re-read per call.
  • The fan-out order of BEE-003 ruling 3 (the file's own dir, the ambient repo, then every registered repo) is untouched — this adds a spelling, not a leg.
