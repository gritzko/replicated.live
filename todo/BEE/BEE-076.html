JSRCcoldfan fails under ctest: leg 5 races two bee sym runs over one cold registered repo and wants at least ONE to answer; both exit 0 with empty stdout and empty stderr. BEE-065 promised "the race never costs the answer" (test/coldfan/run.sh:211:Ko), so the fan-out breaks its own word. Seen twice in a row under a full ctest (2026-09-21), 1 of 20 standalone. Not the SIGBUS that run.sh:207 describes: nobody died, the lane reads back whole afterwards.

Input

Context

  • test/coldfan/run.sh:214:Ko starts two sym --paths zqParallel at once over cold repo E; the check is run.sh:218.
  • The ctest log: FAIL a concurrent double bring-up still answers (0/0), all four capture files p1 p1e p2 p2e empty.
  • The very next check, "the raced lane reads back whole", PASSES: the lane E ends up complete, only the two answers were lost.
  • The kept fixture ~/tmp/bee-coldfan.cpChBh/E/.git/be/ holds one .tri.idx (88 b) and one .lite3.idx (208 b) run.
  • index/index.js:1072:Wt upForeign is the ladder: bring-up, then a read-only open of the rows there, then silence.
  • index/index.js:395:Wt fresh reads "no run file yet" — true for BOTH racers at the start, false for the loser's fallback.
  • index/index.js:1064:Wt foreignFailed speaks through progress().note; the piped run's stderr is empty either way.
  • The failure is load-bound: 10/10 green standalone on build/bin/bee, 9/10 on build-unbundled/bin/quickjab.

Goals

  • A reliable RED first: make the race lose on demand (a loop, a load, or a test hook that holds the winner mid-bring-up).
  • Say what each racer actually did — which rung of the upForeign ladder answered, and why that rung held no rows.
  • Two concurrent cold bring-ups of one repo: at least one answers, neither corrupts the lane; better, BOTH answer.
  • A bring-up that lost the race must not answer off a half-written lane as if it were the whole truth, mute.
  • JSRCcoldfan green in 50 of 50 runs under ctest -j16 load.

Constraints

  • The native wh128 writer's SIGBUS between two WRITERS (run.sh:207, DOG-046) is a separate matter, gritzko's to rule on.
  • No new lock file left behind on a crash; no sleep-and-retry loop without a bound; a read-only be/ still degrades quietly.
  • No existing test case edited; a new leg or a new suite carries the repro (work 3, 4).
  • RULING (gritzko 2026-09-21): worked in the MAIN tree; no commit (work); comments per comment, BEE-076 on the change.

Design decisions

  • UNVERIFIED lead: one racer's bringUp throws on the other's in-flight run, fresh is false by then, so the read-only rung opens a lane that has no rows yet — and the winner's own answer is lost some other way. Verify before building on it.
