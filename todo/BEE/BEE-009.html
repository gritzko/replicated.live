BEE-001 ruled that bee knows a repo BY ITS PATH and made bee install refuse a linked worktree, the tell being <gitdir>/commondir. The OTHER registration door was left open: index() calls track(ctx.repo, opts.home) on its own (index/index.js:924), so a bare bee run inside a worktree registers that worktree. $HOME/.config/bee/repos now carries /home/gritzko/src/bee, /home/gritzko/src/bee2 and /home/gritzko/src/bee3 — ONE repository in three checkouts, each with its own lane — so every ordinary filename in a cross-repo ref resolves three times, reaches the chooser, and http paints it PLAIN. The fix follows BEE-001's own ruling: when the path handed in is a linked worktree, register and index THE ORIGINAL — the main worktree named by commondir (index/refs.js:37) — if it is not registered yet.

Input

Context

The symptom is a page full of dead names: /bee-journal/todo/LITE/LITE-045.mkd paints render/html.js, main.js, door.js, theme.js as plain text while ticket codes on the same page link, because a ticket lives in ONE repo and a filename lives in three.

  • bee2 and bee3 are git worktree checkouts of bee: .git is a gitfile, the gitdir is /home/gritzko/src/bee/.git/worktrees/bee2, and each carries its OWN lane (<gitdir>/be/*.lite2.idx) — so each answers the fan-out on its own.
  • door.resolvePartial("render/html.js") in that page's ambient returns three rows (bee, bee2, bee3); html.js returns six (mark/ and render/ in each checkout).
  • seatOf therefore answers {rels} — the LITE-015 chooser — and http.js:228 (if (seat === null || seat.rels) return null) drops every multi-hit to plain painted text, so a reader sees no link at all rather than a choice.
  • merge.js:163 linkedWorktree(gitdir) is the existing probe and it guards install ONLY; index/index.js:924 track() has no such gate, which is how the two lines got written.
  • index/refs.js:37 commonDir(gitdir) already resolves a linked gitdir to the main one — the original's root is that path with /.git stripped, no git shell-out needed.
  • index/mount.js list() dedups by realpath alone, and its under() deliberately rules /src/bee2 NOT inside /src/bee, so nothing folds a worktree family at resolve time either.

Goals

Registration names the ORIGINAL, so one repository is one registry line, one lane and one answer in the cross-repo fan-out.

  • bee index, and a bare bee inside a linked worktree, register the MAIN worktree and never the linked path, saying which repo they took.
  • The original is INDEXED if it has no lane yet — the bring-up follows the redirect, so the lane is the main worktree's, not the linked one's.
  • bee install and this path agree on one behaviour: BEE-001's refusal words, or the same silent redirect — gritzko's call, stated in the ticket before it lands.
  • An already-polluted registry HEALS without rewriting the user's file: a legacy worktree line must stop competing in the fan-out.
  • A cross-repo ref to a file of the family resolves ONCE, so render/html.js on a ///bee-journal page links to /bee/render/html.js.

Constraints

  • An isolated worktree; no VC writes there or in the main tree — gritzko commits, always.
  • Repro FIRST, as a test: a fixture main worktree plus a git worktree add checkout, registered from inside the linked one.
  • No shelling out to git: the tell is <gitdir>/commondir, read through index/refs.js commonDir.
  • $HOME/.config/bee/repos is the USER's file — a run may append, and must not silently delete lines a person put there.
  • No other tests edited; test/index, test/first, test/http, test/click stay green.

WIP

Design decisions

  1. BEE-001's ruling STANDS: the path is the identity, and a linked worktree is a second path over one history — so it is never the registered one.
  2. index/track REDIRECT rather than refuse: a bare bee inside a worktree must keep working, and registering the original is what the reader meant.
  3. The registry is append-only from bee's side; a legacy worktree line is neutralised at RESOLVE time (mount.js folds a family to one mount), never by rewriting the user's file behind their back.
  4. GRITZKO'S CALL, taken as BEE-001's refusal KEPT: install is the verb you TYPE, so a repo that is not the one bee would take is worth a word; the refusal now NAMES the original (commondir), so the next move is a copy- paste. index and the bare run are incidental and redirect in silence, save one phrase on the summary line. Flip it to a silent redirect if you would rather install just do the right thing — one if in merge.js.
  5. The fold keeps the family's FIRST registry line's NAME while pointing its root at the ambient checkout, so ///bee/x.js still resolves while the reader stands in bee2 — a name that followed the root would break it.

  • A polluted registry still holds the dead line; nothing prunes it, by ruling 3. bee never writes it again, and the fold hides it.
