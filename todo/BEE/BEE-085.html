The html list view lays its columns out with space bytes (view/list.js::padName), not with css. A row holds no elastic B span, so render/html.js::'function hunkFeed' paints it as plain text in pre.body{white-space:pre-wrap}, and a summary longer than the window wraps under the marker and name columns in Firefox. In html mode, padding and trimming are the css's job, as they are for the board's BEE-030 flex .row.

Input

Context

Firefox, 2026-09-30: http://localhost:7777/impII-journal/list/todo/ wraps the rows whose last-commit summary is long ("Market, Home soak, browser UI and art pack tickets; wiki rules pages and outcomes"), so the age column scatters.

Goals

  • Every html list row is a flex .row: marker, then a fixed-width name column (ellipsized), then the summary as the one elastic item, then the age flush right, with no wrap at any width.
  • Column width and trimming come from css (a list-scoped rule, e.g. a list class on the .hunk), not from the padding spaces.
  • The summary stays pale (the D dim slot) in the html page and in the pager.
  • The pager rows cut or pad the summary to the terminal width (BEE-030's elasticRow); --plain bytes stay unchanged.
  • A repro test first: the html of a list with a long summary shows the flex row and the elastic summary.

Constraints

Reuse BEE-030's machinery (B span, .row, .els); keep the existing test/list and test/elastic suites green without editing them.
