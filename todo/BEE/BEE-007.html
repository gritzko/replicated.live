index and lindex are two verbs over ONE lane with the same laziness: both are HEAD-only, both no-op off a MARK row (LITE-006 under the ref's hashlet, LITE-033 under the reserved hlOfText("lindex")), both write into <gitdir>/be/. And the link half is the CHEAPER one — it reads the TIP tree's blobs, bounded by the working set, where the commit walk is bounded by the whole history. There is no cost argument for making a user run two verbs, so bee index does both passes and keeps both marks.

Input

Context

main.js runIndex calls index/index.js index(); runLindex calls index/lindex.js lindex(), which itself calls bringUp with track: false before scanning.

  • The two marks are independent watermarks, so each half already no-ops on its own — folding the VERBS does not fold the laziness.
  • The read views (log, list, commit) call bringUp on every invocation; they must NOT start paying for the link pass.
  • BEE-002 made the link query a fan-out over the registry, so the query form has a life of its own regardless of this fold.

Goals

One bring-up verb, two marks, and no read view made slower.

  • bee index [<repo>] runs the commit pass and then the link pass, reporting both in its summary line.
  • Each half still no-ops off its own mark: an up-to-date repo writes nothing and says so.
  • bee lindex [<target>] stays as the QUERY form and keeps working bare.
  • bringUp stays the INDEX half alone, so log/list/commit cost exactly what they cost today.

Constraints

  • Implement in the MAIN TREE /home/gritzko/src/bee — gritzko's call; no VC ops there.
  • The tree carries uncommitted BEE-002 work; build on it, revert nothing.
  • Both halves keep their contracts: mark row written LAST, rows never deleted, re-puts idempotent.
  • opts.track === false still writes no registry line, for either half.

WIP

Design decisions

  1. The VERB folds, the PASSES do not: two marks, two no-op tests, one run.
  2. bringUp is the index half and nothing else — the read views are the reason it exists, and they must not lex a blob to print a log.
  3. install (BEE-001) already calls both; it now calls the one verb.
