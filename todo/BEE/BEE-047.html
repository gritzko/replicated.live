BEE-043

The TUI board's write buttons (go, done/dont, the panel counts, the post ✓) go dead in the web page: their spells name act.js writers, not ROUTE views, so html.js:192 paints them plain. Make them clickable identically to the TUI — the same O spell runs through the same act.js table — behind ONE global read-only switch. RULING (gritzko 2026-08-20): views vs verbs must be an explicit global map (be/ split them as dirs), so http never guesses which words write; writes ride POST only — a GET that mutates is a crawler-shaped disaster.

Input

Context

  • Every face already carries its click spell in the hidden O channel and html.js reads it (html.js:168 oSpell); only href-building drops the write verbs (http.js:48:3E ROUTE has views alone).
  • act.js IS the mutation table (act.js:1:hu) — main.js and pager.js both dispatch through it; commit and merge are SHAPE-SPLIT (a shape predicate tells the writing form from the view).
  • Panel spells are context-first (//name add, wtstat.js:149:Hc), board spells verb-first (done KEY, fork //bee-KEY); urlOf must learn both shapes or panel cells stay dead on shape alone.
  • The server refuses non-GET outright and never reads a body (http.js:489:3E, http.js:668:3E); it binds 127.0.0.1 (http.js HOST).
  • After a write the pager bumps the rev tree so no memo serves stale state (pager.js:648:TJ); http must do the same on an act.

Goals

  • A views-vs-verbs GLOBAL MAP, one source of truth exported by act.js (derived from ACTS + shape, e.g. { commit: true, status: false } — true = the word has a writing form); http and the renderer consult it, never a second list.
  • Write faces render as self-contained <form method="post"> buttons wearing the exact wtstat cell look; read faces keep their plain hrefs; a resolving-to-nothing spell stays plain text (ruling 2026-08-15).
  • One POST act endpoint: parse the form body, check the word against the map, run the spell through act.js exactly as pager.js _actSpell does (same context-slot resolution), cache.bumpRoot(), answer 303 See Other back to the Referer so the page repaints with the new state.
  • The global switch: acts ON by default; --ro (flag and/or config) makes handle() refuse POST as it refuses PUT today AND paints the write faces plain, so a locked server shows no live-looking buttons.
  • The act's one report line (act.js run) must reach the user: surface it on the redirected page or as the response body on refusal.

Constraints

  • POST only for writes; the act route checks Origin/Referer host against the server's own, since cross-origin form POSTs reach 127.0.0.1 without CORS.
  • Self-contained pages: no JS for the buttons, forms and CSS only (blob/style.css may gain .btn form resets); CSP stays as is.
  • No second verb table anywhere: the map derives from act.js rows, shape-split words gated by their own shape at POST time.
  • Body reading lands in the ONE transport spot (http.js:40:3E drainHead kin), capped like the head is; oversize is 413, not a hang.
  • Tests: a webact suite under test/ in the house pattern (test/gobtn, test/cpanel kin) — RO refusal, a live act flipping real state, Origin refusal; no other tests edited.

WIP

Design decisions

  • Map polarity: word -> writes? with shape-split words true (the POST gate then asks the row's shape); absent = view.
  • The form wraps ONLY the face cells that carry a write spell; brackets, gaps and counts keep their spans, so the frame's look is byte-identical when acts are off.

Blockers and bummers

  • The report line rides a ONE-SHOT server-side flash the next page spends: a ? param would pose as the view's rev (http.js:112:3E).
  • POST /<repo>/act names the TOP repo only, so a spell with no //name of its own runs in the parent's ambient, never a submodule's.
  • --ro is a flag alone; no config key reads it yet (goal said "and/or").
