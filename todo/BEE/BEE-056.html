The COMMIT frame's ✓ shows iff stat().staged > 0 (view/wtstat.js:216 commitCells), but that count is the WHOLE TREE's: foldSubs (BEE-040) adds every submodule's staged rows into f.staged. bee commit (sync.js:50) runs plain git -C <top> commit and never descends into subs — so a tree whose TOP index is empty while a sub holds a staged file lights a green ✓ whose spell git refuses ("nothing to commit"). bee status says clean for the very same tree, so the board and the CLI disagree. BEE-040's tree-wide fold is right for the FILE frame (add/rm DO sweep every mount); the ✓ must gate on the verb's own reach.

Input

Context

  • Seen 2026-08-21 on the QJAB-008/009/010 rows: top repos fully committed, each test sub carrying one staged A qjab00N.js, every ✓ green.
  • view/wtstat.js:203 already rules "the ✓ shows iff staged — never a grey one"; the bug is WHICH staged count answers.

Goals

The ✓ shows iff the spell it mints would commit something.

  • Top index empty, sub index staged: the ✓ slot is BLANK.
  • Top index staged: the ✓ shows, as today.

Constraints

  • Keep BEE-040's tree-wide fold for the FILE frame untouched — the stats stay whole-tree, subs included.
  • The sub commits carry the SAME message as the top's — one act, one line.

WIP

Design decisions

  • Ruling (gritzko 2026-08-21): commit goes RECURSIVE, as in Beagle — the verb sweeps every mount as add/rm do (BEE-040 symmetry), so the tree-wide ✓ gate becomes correct as it stands and wtstat.js does not change.
  • Depth-first, bottom-up: commit each sub whose index is staged, stage the moved gitlink in its parent, then commit the parent — so one click leaves no half-committed level behind.
  • A level with nothing staged and no gitlink move commits nothing and is no error; the whole run refuses only when NO level has anything to commit (git's own words).
