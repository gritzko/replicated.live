bee mark (view/mark.js) renders any page to stdout and its BODY is good — token spans, heading slugs, .mkd→.html names. Its doc() shell is not: chromeless, filename title, no og: card, a .cast image renders as a broken <img>, a dir link 404s. A site built from it loses the banner, the footer, the feed and every dir page. New verb bee html: same body, real page shell, still stdout. Evidence: 2026-08-23 diffs against the replicated.live pages be mark built.

Input

Context

  • bee-journal is git-only: jab mark dies PROJECT: no .be below $BE_ROOT, so beagle's site renderer cannot run there and make has no renderer at all.
  • The standalone mark binary is not a substitute: it writes <src>.html BESIDE the source (1172 stray files in one run) and emits no og: head.
  • Body parity is already there: strip the <span id="bNNN"> wrap and bee's prose, lists, code and .mkd→.html link names match the live pages.
  • README.mkd is byte-identical in both trees, so its anchors isolate the renderer: live <a href="/blog">blog</a> vs bee <a href="/blog.html">/blog</a> — dead target AND the whole path as text.
  • blog/click.mkd's ![…][3] with [3]: ./img/todo2.cast: live emits <figure class="asciicast"><div data-asciicast=…>, bee emits <img src="./img/todo2.cast">, which mounts nothing.
  • html/head.html carries only the loader (asciinema CDN css/js + /assets/js/asciicast.js); its hook is [data-asciicast], so the element is the renderer's job.
  • rss.sh (new, bee-journal) builds feed.rss by reading og:title/og:description/og:url back off the rendered pages — no og: card, no feed.
  • Size, meta/abc.mkd: bee 80753 b vs live 14195 b — the token spans, kept on purpose (permalinks), not a defect.

Goals

  • bee html <page> prints ONE document to stdout; make in html/ does bee html ../blog/click.mkd > blog/click.html, no output policy in the verb.
  • Chrome from the CWD: ./header.html inlined at the top (head + banner), ./footer.html before </body>; absent file = that part omitted, never an error.
  • .md/.mkd title is the page's first heading; every other dialect keeps today's filename title (view/mark.js:57:titleOf).
  • .md/.mkd emit the og: card — title, description (intro, one line), type=article, url, image (the first one), absolutized against the output CNAME.
  • A .cast image target emits <figure class="asciicast"><div data-asciicast="<target>" aria-label="<alt>"></div><figcaption><alt></figcaption></figure>; a plain link to a .cast stays an <a>.
  • An image OPENING a paragraph is a <figure> too (gritzko, 2026-08-23): <figure class="right w30"><img src="…#rightw30" alt="…"><figcaption>…</figcaption></figure>; an inline image stays a bare <img>.
  • A link to a DIRECTORY keeps the directory as href (/blog, served by its index.html) and shows the leaf name as text; [/meta/work] reads "work", not "/meta/work".
  • <html lang="en">, matching the live pages.
  • The verb takes flags — at least --strict, which bee mark cannot even be passed today (every non-page arg is refused, view/mark.js:68:lc).

Constraints

  • bee mark stays as it is: the pager and bee http share the emitter (http.js:301:3E), so the shell work goes in the NEW verb, not into doc().
  • Token spans and heading slug ids STAY — they are why bee's html is wanted (gritzko, 2026-08-23).
  • Dir pages stay README.html copied to index.html; the list view is NOT the dir page — it leaks wt state and commit subjects onto a public site.
  • No beagle dependency: the verb must work in a plain git tree, no .be, no be/verbs.
  • The domain is the OUTPUT tree's CNAME (replicated.live), NOT the repo root's (replicated.wiki) — read it from the CWD the redirect writes into.

WIP

Design decisions

  • New verb, new file (view/html.js), registered beside mark in main.js:230:Du; view/mark.js is reused for the body, not forked.
  • Chrome is read, not generated: header.html/footer.html are the site's, and today's head.html + banner.html fold into one header.html.
  • Title and og: come from ONE extractor over the parsed page (heading + intro + first image), so the head and the feed can never disagree (beagle's MARK-011 rule).
  • The figure class list is the img fragment split: #rightw30 -> right w30, #center -> center, #centerw100 -> center w100; style.css:114 defines left/right/center and w30/w40/w100, so the renderer only splits, it invents nothing.
  • The figcaption text is the image's alt, as the live pages carry it (html/blog/click.html:109).
  • The dir-link fix needs an existence probe — beagle passes opts.exists; here view/fs.js can stat the tree, view/mark.js:44:pageHref is where the .html name is chosen.
