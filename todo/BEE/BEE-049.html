BEE-048 made resolution warm and the timers now name the rest: of a 8.2s warm board redraw (debug, full registry) 6.9s is the painter — spansHtml/esc re-emitting the same 780KB over 950 rows, warm equal to cold (release ≈ ¼ of that, still 2s). The proposal: cache the RENDERED PAGE — route → body bytes, held for the process life, dropped by the same per-repo fsw witnesses BEE-048 installed: a rev move on any repo the page touched invalidates that page and nothing else. Warm redraw becomes a buffer write; after a BEE-047 act click only the first repaint pays.

Input

Context

  • handle() rebuilds the body from zero per request (http.js:603); the only memo is per-PAGE ref hrefs (http.js:228 memoUrl), gone when the page is.
  • The painter is pure interpreted JS (render/html.js:145 spansHtml) — no I/O, so BEE-048's resolution caches cannot touch its 6.9s; only not calling it can.
  • index/cache.js:175 rev hands a per-root token that moves on any event under the root, and BEE-048 armed the gitdirs (HEAD, refs/, .git/be) too — a staleness witness already stands per repo.
  • A page's repo set is knowable at render time: the mount it runs in, the repos the view read files from, and every repo the ref fan-out answered in (pg.refs fills as urlOf runs).
  • Writes already converge on the witness: the pager and the BEE-047 act endpoint bump the rev tree (index/cache.js:73 bumpRoot), so a post-click repaint recomputes by the same rule as an external edit.

Goals

  • A whole-page cache in http.js: full route identity (repo, verb, arg, query, raw/rendered) → {title, body bytes, touched roots + their rev tokens}, process-life, no TTL.
  • Hit = every touched root's rev token still current; any moved root means a lazy recompute — per-repo staleness, BEE-048's rule lifted one layer.
  • Only 200 GET pages cache; error pages, choose, bytes/raw streams and any page carrying a BEE-047 one-shot report line render fresh.
  • Bar: the second identical /todo/Now:* request calls spansHtml ZERO times and answers byte-identical bytes; a touch under one touched repo drops that page, a touch elsewhere does not.

Constraints

  • Cache only under a live watcher (wtstat.js law); one-shot paths behave exactly as today.
  • A page that touched a BLINDED root (refs/ fan past 64 dirs, BEE-048 bummer) must not cache — a witness that cannot see a ref move must not vouch for bytes.
  • Key on the normalized route, not the raw URI, so escaped spellings of one page share an entry and 404s never occupy one.
  • Memory: cap the cache (bytes, LRU) — a board page is ~780KB, a handful of boards must not eat the process.
  • Tests: warm zero-paint bar, per-repo drop, cross-repo no-drop, post-act repaint showing the new state; no other tests edited.

WIP

Design decisions

  • Validate-on-hit by rev-token compare rather than eager drop on fsw event: the witness stays BEE-048's, and no event handler needs to know which pages touched which repo.
