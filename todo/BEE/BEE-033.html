Every "when" bee answers ends in readCommit — an ODB object read per attribution, memoized only within one run (index/index.js:280). Yet the bring-up walk PARSES every commit's times anyway, for the topo-order date tiebreak (index/index.js:591), and then throws them away. A CTS row (kind 8) keeps them: key commit_hl:60|8, val the author time, minted at seal where the parsed commit is already in hand — zero extra ODB reads, ~16 bytes per commit, immutable forever since a commit's date never changes. With it, blob -> date is pure index: B2P -> REV-CMMT -> CTS, three seeks and no ODB — be solved the same want as a whole mtime.idx lane (BRO-044); bee inherits it for one row per commit.

Input

Context

  • readCommit (index/index.js:280) yields ats (author time, what be log and the list age column display) and ts=cts (committer time, what git orders by); both are parsed for every walked commit.
  • Commits seal at index/index.js:910 — rev rows first, CPAR rows LAST, since a seal persists a prefix and CPAR is the done flag.
  • Nibbles 0 and 8..E of the lite2 key space are free (INDEXES.mkd).
  • Time consumers today: view/list.js lastCommitOf (needs the subject too, so it keeps its ODB read), view/todo.js lastTs, view/log.js.
  • KNOWN TRAP: range/prefix can answer nothing for a key a seek finds — every reader rides the seek cursor (INDEXES.mkd).

Goals

One new immutable record kind plus the reader that makes dates index-only.

  • CTS (8) — key commit_hl:60|8, val ats:60|vnib:4, ats the author time in epoch seconds, vnib 0 (a committer-time row can ride vnib 1 later, no format break).
  • Mint at seal, in the same batch as and BEFORE the CPAR rows, so a CPAR row on disk proves the CTS row is on disk.
  • Reader commitTs(ix, hl) -> ts | null in index/index.js, one exact-key seek; a miss returns null, never a wrong answer.
  • Reader blobTs(ix, hl): B2P -> exact path_hl|rev|2 -> CTS, min-folded over carriers — the BRO-044 answer with no new lane.
  • INDEXES.mkd gains the kind in the catalogue and the derivation bullet under "What the records buy".
  • Golden: cold bring-up mints the rows; commitTs equals readCommit(...).ats for every indexed commit; a warm rerun writes nothing; a missing row answers null.

Constraints

  • Already-indexed commits have NO row and the walk never re-enters them: either bump the lane ext (full rebuild — the data is derived and the sweep sanctions it) or read-repair on miss; pick ONE, document it, and never let a stale lane answer wrong.
  • Never delete, idempotent re-puts, the 200-row batch discipline — the standing lite2 contract, unchanged.
  • Do NOT retrofit lastCommitOf: it needs the subject, its memoized ODB read stays; new time-only consumers use commitTs.
  • Comment budgets per comment: file 8, function 4, inline 2.

WIP

Design decisions

  • Author time in vnib-0 rows, not committer time: every display today shows ats; ordering during bring-up parses commits regardless.
  • A row per commit, not per blob: blob -> date derives in three seeks, so a blob-keyed row would duplicate what B2P already says.
  • STALE LANES ANSWER NULL, no ext bump: a miss costs the caller the readCommit it pays today, a bump re-derives every indexed repo.
  • The ext is also a fixture NAME: five landed suites grep or glob *.lite2.idx, so a bump is a rewrite of tests this ticket owns none of.
  • blobTs nulls the WHOLE fold the moment one carrier has no CTS row, so a half-filled lane can never answer a too-new date.
  • No read-repair: a query opens foreign indexes READ-ONLY (BEE-002), so a write on a read path would need a guard and a seal per row.
