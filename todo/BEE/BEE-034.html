be's board buttons are a visible face plus a hidden O token whose bytes are #<pale><tone> <verb args> — the pager sheds the colour prefix at the first space and runs the spell (be views/todo/todo.js:750, view/bro.js whyBgAt). bee already HIDES O spans in every renderer (render/wrap.js:31:aS) but nothing emits one and the pager follows only U (pager.js:549:_targetAt), so a verb click has no channel to ride. This ticket opens the channel: emit, follow, shed — paint and dispatch stay their own tickets (BEE-035, BEE-038).

Input

Context

  • A U target with a space already dispatches as a verb line (door.js:531 openTarget), but U means push-nav and address; the button channel must be a SEPARATE tag so a row's nav click and its button clicks coexist.
  • be retired the visible Y label slot — the face rides its class tag, the O carries look AND click (be todo.js:144:i4).
  • render/html.js paints from the same toks, so the browser needs the twin: an O span becomes the enclosing face's href/action, never visible bytes.

Goals

  • A visible token FOLLOWED by an O token is a button: Enter on it or a click runs the O's bytes, prefix shed at the first space.
  • _targetAt's U behaviour is untouched; a row carrying both U and O follows whichever token the cursor/click sits ON.
  • Plain and --plain output never carry O bytes (the why-plain precedent, be todo.js:695:i4).
  • An empty spell after the prefix falls through to the row (be's infoCell contract).

Constraints

  • No new hunk fields: tag + bytes only, tok32 as is (dog/tok/TOK.h).
  • Worktree and build of the assignee's own; no main-tree edit, no commit (work).
  • RED first; no existing test case edited. Comments per comment: 8/4/2, BEE-034 on the change.

WIP

Design decisions

  • Prefix grammar is be's verbatim: #<bg-hex><fg-hex> — both truecolor, bg first (whyBgAt order); shed = everything through the first space.
  • Keyboard parity is free once _curTarget asks the O like it asks the U.
