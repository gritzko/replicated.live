The LITE-026 pre-commit pass rewrites a fresh file:line(:col) ref in the staged text into a LITE-025 file:OFF:HASHLET permalink, hashing the blob the ref points INTO. When that file lives in ANOTHER repo the hook has no blob to hash without opening a foreign ODB, and any hashlet it did mint would pin content this commit does not control — a permalink stale the moment the other repo moves. Today the hook silently treats such a ref as a local path, so it either mints nothing or mints against a same-named local file.

Input

Context

index/hook.js precommit reads the staged files, takes each F token through fTokens, resolves the ref against the repo's own tip/staged state and rewrites it; the rewritten files are re-staged.

  • A permalink's whole promise is that the target BYTES are pinned — a hashlet of a blob in a repo with its own independent history cannot promise that.
  • A wrong mint is worse than none: it re-stages text the author did not write, in a commit hook, on every commit.
  • BEE-002 gives the backlink lane cross-repo reach with no permalink involved, so an unminted cross-repo ref is still indexed and still findable.

Goals

A cross-repo ref gets ONE ruled treatment, and the hook never mints against the wrong file.

  • A ref that names another registered repo is recognised AS such, not mistaken for a local path.
  • Whatever the ruling, the hook stays silent-on-success and never blocks a commit.
  • A same-repo ref keeps minting exactly as LITE-025 rules today.

Constraints

  • Repro first, as a test under test/hook/; no test outside the suite is edited.
  • No new runtime binding; fTokens stays the one recognizer.
  • A hook may not depend on another repo being indexed, registered or clean.

WIP

Design decisions

Hand written — gritzko's ruling pending; the two candidates, cheapest first.

  1. CHEAP (recommended default): the hook mints only for SAME-REPO refs and leaves a cross-repo ref as plain text. Nothing foreign is opened, nothing false is pinned, and BEE-002's lane still records the link.
  2. EXPENSIVE: mint against the target repo's HEAD blob, with the repo named in the URI. Buys real cross-repo permalinks; costs a foreign ODB open inside a commit hook, and a link that goes stale whenever the other repo rewrites.
