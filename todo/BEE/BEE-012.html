The pager has answered a several-hits reference since LITE-015: door.openTarget hands the rows to view/fs.js buildChooserHunk, which builds a hunk of one row per candidate — the name as an F token, the full target hidden behind it as U, and the REPO named on the row when the resolver crossed repos. http has no such page: http.js seatRel reads if (seat === null || seat.rels) return null, so a multi-hit and a MISS come back identically as "", and hunkHtml paints the reference as dead text. A reader clicking main.js on a page therefore learns nothing, though bee knows perfectly well that it is one of two files. This ticket gives http the page the pager already shows.

Input

Context

Measured 2026-08-16 on /bee-journal/todo/LITE/LITE-045.mkd, served by a build carrying BEE-009: 18 F tokens paint plain, and every one of them is a real multi-hit or a real miss.

  • main.js -> 2 rows, html.js -> 2 (mark/ and render/, one repo), weave.js -> 3, index.js resolve.js hook.js ansi.js -> 2 each; serve.js -> 0, which is a miss and PAINTS RIGHT.
  • A multi-hit and a miss are indistinguishable to the reader, though only one of them is bee saying "I do not know".
  • buildChooserHunk(arg, rows, tail) already emits { uri, verb: "hunk", text, toks, kind: "chooser" } — F name plus hidden U full target per row.
  • render/html.js hunkHtml ALREADY links a token whose next token is U (that is how a pager click and an href stay one mechanism), so a chooser hunk would render as links with no new painter.
  • The rows carry the repo name (view/fs.js, BEE-003 ruling 4), which is exactly what tells two main.js apart.
  • BEE-011 will remove many of these by letting a reader WRITE bee/main.js; the chooser is what answers when they did not.

Goals

An ambiguous reference opens a page listing the candidates, each a link, and a miss goes on painting plain.

  • A multi-hit reference gets an href to a chooser page instead of "" — the reader sees the choice bee saw.
  • The chooser page lists one row per candidate, naming the repo, and every row links to that file's own /<repo>/cat/<path> page.
  • The reference resolves in the AMBIENT of the page it was read on, so the chooser URL must carry that ambient — the same ref on a page in another repo may name other files.
  • A MISS keeps painting plain text (the 2026-08-15 ruling: never a link that 404s), and the two cases stop looking alike.
  • The pager and http show the SAME candidate list, from the same buildChooserHunk — no second chooser is written.

Constraints

  • An isolated worktree; repro first, as a test; gritzko commits.
  • One mechanism: the chooser hunk is the pager's; http renders it through hunksHtml, adding no painter and no second resolver.
  • The route must fit routeOf's existing shape (/<repo>/<verb>/<arg>) without stealing a path that names a file.
  • The per-page REF_CAP budget and the resolution cache still hold — a chooser href costs the one resolution the reference already paid for.
  • test/http and test/click stay green; no other test is edited.
