be's ruling (BE-041 r2): a button click shows NO result screen — the mutation runs, the CURRENT view re-renders in place, scroll kept; only view spells push-nav. bee's pager can only push (door.js openTarget -> _openPush), and door VERBS knows only views, so a mutation spell has neither a route nor the refresh semantics. This ticket adds both: a mutation verb table the O dispatch consults, and _actSpell — run, drop the memo'd hunks, re-open the view's own spell, keep the scroll.

Input

Context

  • be gates by a verbs/-tree probe (_isMutation, be views/todo BE-041 notes); bee has no verbs/ dir, so the gate is a TABLE — the main.js writer verbs (add, rm, commit, push, pull, merge, done, dont, fork) vs door's views.
  • wtstat's memo drops on any event under the tree (view/wtstat.js:5), but a ref move under .git needs the tips fingerprint — a refresh after commit/pull must re-ask, not trust the memo.
  • BACK/r replay the popped view's spell already; in-place refresh is the same re-open without the push.

Goals

  • An O spell whose verb is in the mutation table: run it, then _refresh the current view in place (scroll and cursor kept); stderr/refusals land in the pager's message line.
  • An O spell naming a VIEW verb keeps push-nav ( i status, ≡ log ride existing machinery).
  • Keyboard parity: Enter on the face does what the click does.
  • A mutation typed at the : bar behaves the same — run + refresh, no push.

Constraints

  • Worktree and build of the assignee's own; no main-tree edit, no commit (work).
  • RED first, headless: click a mutation O in a scripted pager — stack depth unchanged, hunks re-built; no existing test case edited. Comments per comment, BEE-038 on the change.

WIP

Design decisions

  • The table lives beside the verbs (main.js exports it); door and pager import ONE name, so a new mutation verb registers once.
  • The refresh re-runs the view's recorded spell through the ordinary open door — no pager-local dispatch (be CI-004 spirit).

Outcome

  • act.js (new, 78 lines) is the ONE mutation table: add/rm/push/pull/ fork plus the SHAPE-SPLIT commit/merge rows (shape(args) decides, so commit <rev> and LITE-014's three-file merge stay views). Registering a writer is one row; done/dont (BEE-043) will be two more.
  • pager.js (+45): _actSpell runs the row in the clicked hunk's ambient, then _refreshes THIS view (no push, scroll and cursor kept) and puts the report — or the throw, verbatim — on the message line; _spell is the one O dispatch the three follow sites (row, cursor/Enter, mouse) and the : bar share, so keyboard and click parity is structural, not duplicated.
  • main.js (+27/-6): runFork/runAdd/runRm/runCommit/runPush/ runPull collapse into one runAct(word), SIDE grows the shapeless rows off act.ACTS in a loop, and run() picks a shape-split writer once, for both commit and (newly) bare merge.
  • test/actspell/ (new, 4 files, 50 checks): RED on the unmodified pager (9 of 34 headless + 5 of 11 pty checks failed, all "cannot open add one.txt"), green after. It asserts the table incl. both shape splits, then clicks a real fixture repo: the writer lands (index moved, stack 0, view re-opened, scroll and cursor kept, report on the bar), push with no upstream refuses in words and moves nothing, cat one.txt on the same row still push-navs, and the : bar does what the click does. The pty leg fires the same button by SGR click AND by Enter — the screen stays the board both times.
  • Tally: ctest -j16 -R '^JSRC' 47/47 (46 + JSRCactspell); cmake . was needed to glob the new suite in.
  • DEVIATION: door.js does NOT import the table — it maps a target to hunks and a writer has no hunks to give, so the gate sits where the decision is made (the pager) and door stays views-only. http.js is untouched: a browser click on a writer spell still 404s, which is BEE-038's scope no more than BEE-034's was.
