In the pager, :add! on the status view lands the staging and then the bar says "cannot open status". The act path is right; the refresh after it is not: the view's recorded spell is the bare verb status, and the door recognises a verb only when an argument follows it, so the bare spell is looked up as a FILE named status, misses, and the refresh fails. Every argument-less view — status, log, todo, wts — loses its refresh after any act the same way.

Input

Context

  • view/status.js:371:we spells the view's uri as "status" + (arg ? " " + arg : ""), so with no arg the path the pager keeps (pager.js:143:TJ setHunks) is the bare status.
  • pager.js:644:TJ _actSpell runs the act, then _refresh (pager.js:626:TJ) re-opens v.path through door.openTarget; an empty answer becomes "cannot open <path>".
  • door.js:553 openTarget: const sp = target.indexOf(" "); const fn = sp > 0 ? VERBS[target.slice(0, sp)] : null; — a spell with no space is never a verb and goes to seatOf, which resolves it as a reference and misses.
  • Found 2026-08-22 by gritzko in the BEE-057 worktree; door.js is unchanged there, so the main tree has it too. bee status from the CLI after the same add answers fine.

Goals

  • A bare verb spell (status, log, todo, wts, any VERBS key) opens through the verb with an empty argument, in openTarget and nowhere else.
  • After :add! / :rm / :commit on the status view the bar carries the act's report and the rows re-read, as BEE-038 intended.
  • A file literally named like a verb still opens when spelled with evidence (./status, status:1); the bare word is the verb, as it is on the CLI.

Constraints

  • The fix lives in door.js openTarget; no view spells its uri differently.
  • Tests: one pty (or hunk-level) check that _refresh on a view whose path is status re-opens; the three pty suites that pin "cannot open <ref>" must not move.

WIP

Design decisions

  • openTarget now asks verbOf (door.js:105, an own-property test) instead of indexing VERBS directly, so the bare-word leg cannot answer constructor.
  • The bare verb runs on "", the same arg an empty CLI line gives it; nothing else in the door moved, and seatOf still takes every spelled reference.
