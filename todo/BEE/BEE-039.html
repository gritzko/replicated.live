be's count slot is THREE-STATE: rows left to stage LIGHT the button (count = unstaged), a wholly staged class keeps its colour but sheds wash and spell (info), an empty class blanks — only the wash says clickable (be views/todo/todo.js:786,493 UN_COL/ST_COL). bee's wtstat frames tally the quad's five COLUMNS (track/head/stage/wt/con — view/wtstat.js:64:Hc), a different axis: it says WHERE a change sits, not whether a staging button still has work. This ticket re-derives be's model from the quad rows: per class chg/add/del, unstaged vs staged.

Input

Context

  • The mapping: an unstaged class is what add/rm would ACT on — wt-column modified rows -> un.chg, untracked -> un.add, gone-on-disk -> un.del, conflicted -> un.chg; stage-column rows split st.chg/st.add/st.del by their quad kind.
  • The memo keeps its two witnesses (rev + tips fingerprint, view/wtstat.js:31:Hc); only the derived shape changes.
  • Frame layout adopts be's CI-004 geometry so columns never move when CI lands later: FILE 16 with the LAST slot blank for now, COMMIT 13 with the ✓ as its last slot.

Goals

  • wtstat.stat(root) grows { un: {chg,add,del}, st: {chg,add,del}, staged, dirty } beside the quad counts.
  • fileFrame/commitFrame render off the new shape: three-state slots, the countFace discipline (~3/-2/+9, bare two digits, clamp 99).
  • Plain frames stay ASCII and greppable; the ✓/blank rule: lit iff staged > 0, blank otherwise — no grey ✓ (be 2026-08-03 ruling).

Constraints

  • Model only — no buttons here; the O/paint/emission land in BEE-041/BEE-042.
  • Worktree and build of the assignee's own; no main-tree edit, no commit (work).
  • RED first over fixture wt states; the existing test/wts and test/elastic/board goldens change ONLY where the layout ruling says so. Comments per comment, BEE-039 on the change.
