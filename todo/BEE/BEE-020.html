view/log.js was ported from be/views/log/log.js under LITE-007/LITE-020 and carries the row shape, the grey off-spine rows and the hidden commit <hex> click target. Three legs of the be view never arrived: the ?<ref> tip form (log:?main), the LOG-002/SUBS-045 SUBMODULE descent (log:<sub>/<path> logs the sub's OWN history and its rows still click), and the BRO-012 ticket-code split (a BEE-012 in a commit summary is an F token that opens the ticket). Today bee log dog/INDEX.md from quickjab prints NOTHING, bee log ?main prints nothing, and a ticket code in a summary is dead text. This ticket lands the three, bee-style: ?<rev> like cat/list/tree, the mount table for the sub, the door for the ticket.

Goals

The be log: contract, spelled the bee way, through the ONE view shape (arg, opts) -> hunks so CLI, pager and http get it together.

  • bee log [<n>] [<hex>|<path>][?<rev>]: ?<rev> names the tip — a branch, tag or hexlet through rd.revCommit; bare log ?main walks main's ancestry, log <path>?<rev> the file's revisions reachable from that tip only. The tip is brought up if unindexed (BEE-005 bringUp {tip}), never refused.
  • bee log <sub>/<path> from the parent logs the SUB's own history: the deepest worktree holding the path (mnt.deepest) is the repo the view opens, the arg is re-rooted, the banner keeps the spelling typed. Recurses (dog/abc/S.h).
  • A row of a DESCENDED log still opens its commit: from the pager (a click/Enter on the sha8) and over http (/quickjab/log/dog/INDEX.md rows). The commit <hex> target must resolve in the sub's ambient, not the parent's.
  • A ticket code in a summary is an F token: BEE-011,012: yields F(BEE-011),S(,012:); a click opens the ticket through the door's ticket-code resolver (door.js:180:WK), over http the F becomes an href like any reference. Codes that resolve to no ticket stay S (be's rule) — OR every F the lexer mints becomes a span and the door decides at follow time; ruled below.
  • ~~A path no repo answers says so~~ — dropped, decision 6: an unknown path stays an empty log (git parity, test/index pins).
  • --plain bytes of every existing case unchanged (the git log parity diffs in test/logspine and test/first).

Constraints

  • Main tree ~/src/bee, by gritzko's explicit say-so for THIS ticket (2026-08-16); no VC operation of any kind — no git add, commit, stash, checkout. Build ninja -C ~/src/quickjab/build, test ctest --test-dir ~/src/quickjab/build -j16; ~/bin/bee is a stale bundle, never the oracle.
  • Repro FIRST, RED on the base: a fixture repo with a submodule (see test/first/test/index for how fixtures are built with git), a branch off HEAD for ?<rev>, and a summary carrying a ticket code that a todo/TKT/TKT-1.mkd in the fixture answers.
  • No new tokenizer, no regex over summary bytes: index/hook.js fTokens (or tok.parse with the same F rule) is the scanner. No second ref resolver: the door's.
  • No walk added at query time: the sub's history comes off the SUB's index (its own bringUp), the ?<rev> tip off revCommit, and fileLog/ancestry are not rewritten.
  • Comments: 8-4-2 line budgets, why/goal only, BEE-020:<line> links; no wiki [brackets] in code (meta/work.mkd politeness).
  • Existing tests untouched unless a --plain byte pin is genuinely wrong; say so and ask.

WIP

Design decisions

Proposed by the planning session; the agent confirms or amends with a reason.

  1. ?<rev> over be's #frag: bee's views spell a revision as ?<rev> (cat, list, tree), the count is <n> (LITE-045); # is the permalink/anchor character in bee. #N/#hashlet are NOT ported.
  2. Spine stays ord-0 (git first-parent, LITE-020); be's newest-timestamp mainline rule (log.js:254:eo) is a be DAG quirk, not git's, and bee's spine test pins first-parent parity.
  3. The DESCENT is mnt.deepest(root + "/" + rel), the same probe http.js:510:dX uses; the view re-roots from and the arg, then runs unchanged. The banner is log <arg as typed>.
  4. The row's ambient: the U target stays commit <hex> (a verb line the door already opens); the HUNK carries pos: { repo, path } of the repo it walked and the pager hands it to open(target, pos) — door.openTarget takes a pos today (door.js:471:WK). http already runs the view inside the re-rooted pos (http.js:524:dX) and pathIn gives a hexlet no prefix (http.js:183:dX) — so a sub page's commit <hex> href lands in the PARENT: fix by prefixing the hexlet with pg.prefix and re-rooting <prefix>/<hexlet> in the URL parser, or leave and open a ticket. Agent picks, states why.
    • CONFIRMED, the FIX: the hexlet takes pg.prefix like any other path (http.js:180:dX) and the router re-roots it. The re-rooting probe was mnt.deepest, which realpaths and so answers null for a path the worktree does not carry — a hexlet, and equally a file GONE at the rev asked for. So the probe became mnt.serves(root, rel) (index/mount.js:110:M5): deepest, climbing to the nearest LIVE ancestor. That is one general rule instead of a hexlet special case, it fixes /<repo>/cat/<sub>/<deleted>?<rev> along the way, and view/log.js descends by the very same call — one probe, two callers.
  5. Ticket spans: EVERY F token the lexer mints in a summary becomes an F span, unresolved or not (the door refuses at follow time with words; http refUrl yields no href for a miss). Cheaper than be's per-row resolve (LOG-005 had to memoize it) and consistent with how a cat page treats refs. Off-spine rows keep grey Q for the rest of the row, the F keeps its own slot.
  6. DROPPED (orchestrator, 2026-08-16): an unknown path stays an EMPTY log, exit 0 — test/index/run.sh:181:ZR ("git says nothing either") and :320 are earlier rulings and were not to be edited; the pathThere refusal was reverted, test/logport L6/port-6 pin the empty answer. gritzko may reopen; the refusal is a 10-line re-add.
    • CONFIRMED and landed — and it COLLIDES with two pins of test/index/run.sh (see Blockers 1). "Exists" is read as: at the walked tip's tree, or in the worktree; so an untracked-but-real file keeps its empty log.

Amendments the implementation forced:

  1. logQuery needed NO change: the <n> split is orthogonal to the URI slots, so ?<rev> lands in log()'s own rd.argSplit (view/log.js:322:eo) and logQuery's target passes through verbatim. The banner stays the spelling typed, as ruled.
  2. rd.argSplit THROWS on a name the URI leaf refuses (a raw space: a b.txt), which would have cost such a file its log. log() falls back to "the arg is all path" — http.js:198:dX's own out. cat/list/tree still throw for such a name; not this ticket's to fix (Blockers 3).
  3. log <path>?<rev> needs a SIEVE, not just a seed: the index holds every tip ever brought up, and fileLog is a path_hl prefix scan over all of them. The tip's own CPAR closure (ancestry uncapped, no rewrite) filters the revs — paid only when a ?<rev> is given, so the bare form's cost is exactly what it was.
