Input

Context

  • Repro: in ~/src/bee-CODE-041, bee dog --color view/wtstat.js | sed -n '120,135p' — the foldSubs(d, s.wt); call renders twice, the rm row marking only its 21-space run, the in row marking , seen and its 15-space run.
  • wrap.classifyLines tallies that segment in=21 rm=21 eq=51; the fold emits ONE W token per side for the comment padding (" " RM, " " IN) beside the 6-byte , seen insert.
  • lineKind: changed = max(21,21) = 21, gate 21*4 < 21+51 is 84 < 72 = false → K_MOD_SPLIT. Discounting the two whitespace-only runs gives changed = 6, 24 < 57 → K_MOD_INLINE, one row.
  • The visible edit is SIX bytes against fifty-one shared ones; nothing about it is heavy. It is the realignment of the trailing // then its own grandchildren that pays for the split.
  • A whole-file dump of the hunk's 279 rows carries no two rows with identical painted text, so this is the classifier's verdict, not a duplicate-emit bug.

Goals

  • A line whose only VISIBLE change is a light token edit paints INLINE, whatever the whitespace around it did.
  • test/render/split.js grows the repro as a hand-built weave: eq body + a 6-byte insert + a W-token pair of unequal length must be ONE PASS_NORMAL row.
  • --plain stays byte-identical (it never reads lineKind); --color and --html move together, they share wrap.indexRows.

Constraints

  • Must NOT recreate DIFF-017's glued chimera: a PASS_NORMAL row hides nothing, so an inline verdict here would paint 21 + 15 = 36 columns of padding, a comment column matching neither side. Charging only visible bytes for the GATE therefore needs a paint rule for a whitespace-only changed run as well — collapse to one side, or keep the wider. That pairing is the ticket, not the gate alone.
  • BRO-041's -[ ] -> -[x] one-row assert in test/render/split.js:48:TI is the pinned spec and may not be edited.
  • DIFF-017's glue/wsOnly rule is RELATED BUT DIFFERENT — it splits a two-sided LEADING-indent or all-invisible change; this one is a mid-line padding run beside a visible insert, which DIFF-017 would leave split. BEE-021:29:3X records that DIFF-017 was never ported to bee; port or supersede it in the same pass, do not stack a third rule.

WIP

Design decisions

The gate weighed RAW bytes and the paint showed BOTH pads; BEE-060 changes the two together, either alone is a lie.

  • GATE: lineKind weighs VISIBLE bytes, max(nwIn,nwRm): a pad run realigns a comment, it does not edit it (wrap.js:166:aS).
  • PAINT: on an inline row a REMOVED all-pad token run takes no column, so the row carries ONE alignment (wrap.js:41:aS).
  • That alignment is the NEW one, not the wider: an inline row reads as the file now reads; removed blanks lose no glyph.
  • Pad is space/tab/CR. 'n' is NOT pad — hiding a removed one would run two rows together (wrap.js:102:aS).
  • vis == 0 beside eq context SPLITS: a change no reader can tell apart in place takes two rows, each under its own wash.
  • passHides stays the ONE hidden-byte predicate; it now reads the token's whole run, so its 5 callers go per TOKEN.
  • DIFF-017 PORTED, not stacked: its wsOnly IS vis == 0, widened to the one-sided case; its glue is superseded.
  • glue needs no rule: with the removed pad hidden, indents can no longer glue — only ONE indent ever paints.
