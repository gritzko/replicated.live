bee fork minted -b KEY with no --track, so a ticket worktree's branch had NO upstream: the COMMIT frame's ahbeh pair blanked (wtstat witnesses @{u}, exactly as git status -sb shows nothing there), and pull/merge had no edge to integrate. Found live on //bee-MARK-018 — behind main by 1 and showing nothing. RULING (gritzko 2026-08-20): a fresh fork TRACKS the branch it forked off.

Input

Context

  • Landed same day (fork.js:127): a fresh branch mints via git worktree add --track -b KEY <dest> <from>, <from> = the main tree's checked-out branch; a detached HEAD forks untracked as before; an existing branch still just checks out.
  • Existing upstream-less wts need one git branch -u <branch> each (MARK-018 done by hand).
  • With upstream = a local branch, pull/ahbeh work; a bare push targets the checked-out parent branch and git refuses — landing a wt onto its tracked LOCAL branch is merge-side work, its own ruling.

Goals

  • Every fresh fork's board row lights its ahbeh against the tree it forked off; pull fast-forwards off it.
