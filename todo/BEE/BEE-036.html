bee is read-only today: door.js VERBS are all views, the only writers are CLI fork/mint/hooks. The board's FILE-frame buttons each stage exactly ONE class — changed, gone, untracked — so their verbs must too, or the count on the face lies about the click's reach (be views/todo/todo.js:488 UN_COL). RULING (gritzko 2026-08-20): verbs are named GIT-STYLE — add, add +, rm, not be's put/delete. This ticket adds them as bee verbs, shelling out to git per the fork.js:94 precedent (io.spawnFds argv, never a shell string), plus the explicit-path forms.

Input

Context

  • be's classes: chg = modified tracked, add = untracked, del = gone-on-disk; staged rows are put/new/del and a re-stage is a no-op (be BE-041 round-2 ruling).
  • git add -u swallows deletions — the reason the chg mapping below filters, so add never acts on the -n slot's files.
  • The index lane needs nothing here: bee's .git/be tracks commits, not the stage; the post-commit hook (BEE-031) covers the commit side.

Goals

  • Bare verbs act on the whole class; add <path>.../rm <path>... act on the named files, verbatim wt-relative (be BE-039 law: no context pre-merge).
  • One report line per verb run (counts staged), errors loud with git's own words; exit status is git's.
  • Counts after the run match bee status exactly — the FILE frame re-render shows the flip.

Constraints

  • git only via argv spawn; never parse porcelain with regexes, -z NUL framing throughout (work "things not to do" spirit).
  • Worktree and build of the assignee's own; no main-tree edit, no commit (work).
  • RED first in a fixture repo; no existing test case edited. Comments per comment, BEE-036 on the change.

WIP

Design decisions

  • Git mapping, one class per verb:
    1. add (chg): git diff --name-only --diff-filter=M -z | git add --pathspec-from-file=- --pathspec-file-nul
    2. add + (untracked): git ls-files --others --exclude-standard -z | git add --pathspec-from-file=- --pathspec-file-nul
    3. rm (gone): git ls-files --deleted -z | git update-index --remove -z --stdin
    4. explicit paths: git add -- <path>... / git update-index --remove -- <path>...
  • The two-step pipes run as list-then-feed (two spawns, bytes passed), no /bin/sh -c.
  • Verbs register beside fork in main.js's table; pager reachability is BEE-038's gate, not door VERBS.

Round 2 — the forceful ! flag

  • RULING (gritzko 2026-08-20): a trailing ! on ANY verb word is the FORCEFUL flag — dispatch (act.js rowOf) strips it, the VERB interprets it via its row's bang runner; a verb with no forceful reading refuses in one line (bee: push!: no forceful form).
  • First reading landed same day: add! = add EXTENDED (the be status! sense) — the edited class plus the untracked one in ONE move, one summed report; deletions stay rm's so the FILE-panel counts keep matching their reach.
  • stage.js addAll + act.js bang plumbing + main.js banged SIDE aliases; test/stage/run.sh legs (stages both, leaves the deletion, quiet rerun); suite 53/53.

  • bee/main.js +13: runAdd/runRm beside runFork, add/rm in the SIDE table.

  • DEVIATION: a git refusal exits 1, not git's own code — the runtime has no io.exit, a throw is the only non-zero door (main.js:12 BE-002). git's words still reach stderr untouched, since every child inherits fd 2.
  • DEVIATION: an explicit-path run reports the count of paths NAMED, not of index entries git actually moved — git says nothing else, and it refuses loudly.
