Requested (gritzko 2026-08-20): in the status view, file NAMES must be clickable; an unchanged/untracked row opens cat, a CHANGED row must open the file WHOLE with its changes diff-washed — not a hunk listing. Rows already carry cat/diff U navs (view/status.js:260:we) but the click's reach and the target both fall short: diff renders the weave's hunk window, and the wt's UNCOMMITTED edits may not be diffable at all (view/diff.js folds committed revs). Wanted: a whole-file washed view a mod/con row lands on, wt bytes against HEAD.

Input

Context

  • view/diff.js weaveEmit already has a full (whole file) form; what it lacks is the WT side — the on-disk bytes are no rev.
  • The wash machinery exists (render side: DIFF_WASH precedent, html washInPale) — reuse, never a second painter.
  • The pager follows the token the click sits ON; the filename token must carry the U precisely (the view/list.js discipline), not just the row.

Goals

  • Clicking a status row's FILE NAME: ok/untracked/new -> cat <path>; changed (mod/pat/con, staged or not) -> the whole file, current wt bytes, changed spans washed (in/out), conflict markers visible.
  • The same view is typable: a verb form (e.g. diff <path> growing a whole-file wt mode, or a flag) — decide against the existing diff.js shape and SAY WHY in the ticket.
  • Plain/pipe: the washed view degrades to plain bytes (or a unified form), no SGR; http twin renders the wash via the existing classes.

Constraints

  • Reuse view/diff.js's weave/emit machinery and the one wash palette; no second differ, no porcelain regex.
  • RED first (fixture repo, one file per row class); no existing test edited; suite stays green.
  • Comments per comment, BEE-046 on changes.

Design decisions

  • THE WT SIDE WAS ALREADY THERE. diff <path> on a FILE argument already folds the worktree bytes as the last layer (index/weave.js foldWt, the to.wt leg of view/diff.js weaveEmit) and already emits the WHOLE file (diff.js:447:pn diffWt(..., full=true, exact=true) -> emitFull), sides and all. So there was no differ to write: the only real gaps were the nav's TARGET and what happens when there is nothing to diff.
  • A NEW VERB, dog <path>, not a diff mode and not a flag. diff is a QUESTION ABOUT CHANGE and must answer NOTHING when nothing changed — bee diff x.c --plain piping into a patch reader, and the bare form's changed-files-only set, both depend on that silence. A status row's NAME is the opposite contract: it must open THE FILE, always. Under diff those rows died silently — .o../.v.. (ahead of upstream, worktree clean) and ..o. (staged add, no HEAD blob) all produced ZERO hunks and a "cannot open" click. A flag (diff --full <path>) would have put the two contracts under one verb and one plain output, and main.js fuses a verb's words, so a flag inside a nav spell is second-class. dog is named for the one thing it adds over cat — render/theme.js's washIn/washRm, the single palette.
  • THE FALLBACK IS cat's OWN HUNK. With nothing to wash (unchanged, untracked, staged add, no HEAD side at all) view/wash.js pushes index/read.js textHunk over the worktree bytes — the very hunk cat builds. So hunks is never empty by construction and no row's name can land on a blank page. --plain then writes the file byte for byte (bare: true), while a washed file writes the C unified render, SGR-free either way.
  • cat STAYS PURE. LITE-017:14:Cv rules cat carries no diff; the wash is a second verb over the same bytes rather than a mode of it, and the untracked rows keep their cat nav untouched.
  • ONE ROW EACH IN THE TABLES. door.js VERBS, http.js ROUTE, view/status.js rowsOf — the verb needed no main.js edit (it dispatches off door.verbOf) and no render edit (kind diff hunks already paint side-in/side-rm).
  • THE CLICK PRECISION WAS ALREADY RIGHT and is now PINNED: status.js hunkOf puts the hidden U straight after the F/N name token, so the pager's own _targetAt answers the nav on every byte of the NAME. test/statnav asserts it on the first AND last byte of each row class, so no later edit can slide the target back onto the row.

Round 2 — the verb is dog

  • RENAME (gritzko 2026-08-20): the whole-file washed view is bee dog <path> (/repo/dog/<path> over http), view/dog.js; the layout stays fixed context/verb/args, so nothing legitimate is shadowed.
  • The http fixture's dog/abc sub renamed lib/abc (its rows pinned the NON-verb-word fallback and the 301s, and dog stopped being a non-verb); a bare /repo/dog/... ref now serves the dog view — which on a clean file answers cat's own hunk, so bare libdog refs still serve the file.

  • Wiring, 13 lines over 4 files: door.js VERBS dog, http.js ROUTE dog, view/diff.js exports diffWt (one worktree differ, one caller shape), view/status.js rowsOf diff -> wash with the why in its titular comment.
