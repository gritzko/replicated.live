RULING (gritzko 2026-08-20): TWO verbs, not be's overloaded post — commit 'KEY: title' commits, push pushes; the panels already separate them (the ✓ is the commit, the +a slot the push). This ticket extends the same honest-to-git split to the fetch side — pull fast-forwards, merge integrates a diverged pair — naming CONFIRMED (gritzko 2026-08-20: git-style across the verbs); the BEE-039 CI-004 geometry confirmed the same day. The dirty-wt law from the same session: NEVER manual stash/pop (the pop can conflict leaving a dirty wt PLUS a live stash — the BE-010 clobber class); the built-in --autostash is the atomic stash-merge-pop, abort-safe.

Input

Context

  • git merge --autostash (git >= 2.27) restores the stash on a failed or aborted merge; a manual sequence strands edits between steps and stacks stashes on re-run.
  • Content conflicts resolve through the weave merge driver hooks; the residual risk is the autostash RE-APPLY conflicting after a successful merge — git keeps the stash and says so, degrade loud, lose nothing.
  • commit gets reindexing free: the BEE-031 post-commit hook runs the lane up.

Goals

  • commit 'msg': git commit -m <msg>; refuses with git's words when nothing is staged.
  • push: git push to @{u}; a push refusal (non-FF) reaches stderr untouched.
  • pull: git fetch then git merge --ff-only --autostash @{u} — behind-only is FF by construction, --ff-only makes a lying count fail loudly.
  • merge: git fetch then git merge --autostash @{u}; on failure the verb runs git merge --abort (restores the autostash) and reports ONE line.
  • Every verb: one report line on success, exit status honest.

Constraints

  • git via argv spawn only (fork.js:94 precedent); no /bin/sh -c, no porcelain regex parsing.
  • Worktree and build of the assignee's own; no main-tree edit, no commit (work).
  • RED first over a fixture origin+clone pair; no existing test case edited. Comments per comment, BEE-037 on the change.

WIP

Design decisions

  • The verb name merge collides with bee's merge.js MODULE (install/hooks), not with any verb — the verb file lives apart; rename to patch (be's word) stays a one-line override.
  • The autostash-reapply-conflict path is pinned by a test: merge succeeds, stash kept, verb reports it and exits nonzero — the "failproof" claim tested where it bends.
  • commit collides with the READING view (door.js:44 bee commit <rev>), which the ruling did not foresee. The arg's SHAPE tells them apart: git forbids a space in a refname, so a word carrying one can only be a message, and -m '<msg>' says it outright. No existing case moves.
  • The tell for a stranded autostash is refs/stash moving across the merge — git merge --autostash exits 0 even when the reapply conflicted, so the exit code alone cannot see it and no stderr text is ever parsed.
