BEE-050 opens a file's OUTGOING references under the lines that name them. bee cited <path> is the mirror: the same file, with every INCOMING reference — the lines elsewhere that point at it — quoted under the line they point at, the same 1-up-2-down window, the same solo cap, the same merge of touching quotes. The backlink index (LITE-033 LINK rows, index/lindex.js suspects) already names the carriers as SUSPECTS; this view is the precision half the suspects contract defers to the caller: open each suspect, lex it, keep the refs that really land on this file.

Input

Context

  • index/lindex.js:220 suspects(ctx, ix, target, opts) answers "who may link here" as repo-qualified paths, the local repo first, every registered index after (BEE-002:60). Rows drop the anchor and never delete, so a suspect is a grep narrower, not an answer (INDEXES.mkd "The suspects contract").
  • view/cite.js:63 citations is the one loop that turns a file's bytes into seats: hk.fTokens -> door.splitRef -> door.seatOf -> see.excerpt; weave cuts the page around a sorted {hi, hunk} list.
  • door.js:106 seatOf resolves in the CARRIER's ambient (index/mount.js within, BEE-028), which is what a cross-repo suspect needs to land where its author meant.
  • gritzko's shape (2026-08-22): "cited view that shows incoming links (as text snippets/hunks), same rules as cite".

Goals

  • A VIEW cited(arg, opts) -> { uri, rel, hunks } (LITE-045:42), argument <path> as cat takes it; the worktree file only (a ?<rev> is refused in plain words — the backlinks index the tip, not a rev).
  • The page IS the target file, split as cite splits it: under the line an incoming ref lands on, one excerpt per citing place — the CITING line, 1 up, 2 down, banded with the carrier's path and line, the citing line selected, ref set so html links the header onto the carrier.
  • Refs with NO anchor (a bare cite.js, a ticket code) land on no line; they are quoted in a leading block above the file's first segment, in carrier order.
  • A suspect that on opening carries no ref landing on this file adds nothing — that is the false suspect the contract promised and this view absorbs.
  • Same carrier, same landing line quoted once; touching windows under one line merge as cite merges them (joins/widen).
  • Carrier order is the suspects order (local first, then registry sorted), byte order within a carrier; the page never reads a suspect twice.

Constraints

  • No second link scanner, resolver, window cutter or suspect finder: hk.fTokens, door.seatOf, see.excerpt, lindex.suspects and cite's weave/joins/widen are REUSED — extracted into helpers where cite.js keeps them private, never copied.
  • Each suspect is lexed ONCE, in its own ambient (mnt.within on the carrier's repo+dir).
  • The target is matched by the SEAT (seat.full equal to the target's full path), never by comparing ref text.
  • The verb joins door.js VERBS and http.js ROUTE both (BEE-050:76 — the door's table is not the router's).
  • Tests: a fixture repo with a target file, three carriers (an anchored ref, a bare-name ref, a ref to another file sharing the name — the false suspect), a --plain leg and a hunk-level leg under test/cited/; bee index brings the LINK rows up in the fixture before the view runs; no other suite edited.
  • Comment budgets and TICKET:line links per comment.

WIP

Design decisions

  • view/cite.js exports weave, joins, widen, UP/DOWN/SOLO (or moves them to a small view/quote.js) so cited orders excerpts the same way; citations grows nothing.
  • The excerpt is cut over the CARRIER: see.excerpt(carrierSeat, refText, UP, DOWN, SOLO) where carrierSeat is {full: carrier, line: citing line} — the carrier line is found from the token's byte offset, so no second scan.
  • The landing line on the page is seat.line of the resolved ref; the hunk list is sorted by landing line before weave, and weave takes a landing-line key rather than a byte hi (or hi is computed as the end of that line).

Blockers and bummers

  • "Same carrier, same landing line quoted once" and the joins/widen clause contradict each other: dedup that coarse leaves the merge nothing to merge. The key implemented is (carrier, CITING line, landing), so a carrier pointing at one line from two far-apart places quotes both — two places really are two backlinks — while two ADJACENT citing lines merge, as ruled.
  • The target is resolved by lindex.suspects itself (index/resolve.js resolve over the tip tree), so a repo holding two files whose last two segments match the argument refuses in lindex's own words rather than answering. Inherited from the query verb, not new here.
  • A ticket page is cited BY CODE as often as by path, and the two key different LINK rows: bee lindex LITE-028 lists index/index.js, bee lindex todo/LITE/LITE-028.mkd does not. cited therefore asks lindex twice and unions the suspects, in query order, deduped; the code half is best-effort, so a refusal there costs the page nothing. door.js:240 ticketCode stays the one recogniser — ticketOf only inverts the six spellings it resolves by.
  • gritzko's ruling of 2026-08-22: a page never cites ITSELF. A ticket names its own code in its title, in a work/LITE-028 dir and in a suggested commit line, and the indexer mints a row for each — the self-link gate keys on ref TEXT (sp.path === c.path), which a code never matches. cited therefore drops a suspect whose realpath is the target's before reading it, so the page costs nothing and quotes nothing of itself.
  • cited prints every band as an ABSOLUTE carrier path, so the reader feeds one back and the view must take it: an absolute argument now positions on door.js:528 posOf(...).repo and opens THAT, refusing a path in no repository in plain words. cat and cite still open opts.from || cwd() first and refuse an outside path through index/read.js:28 repoRel — the same bummer, left alone here on purpose.
  • Every cited call brings the LINK rows up — it goes through lindex, the query verb — where the read views stay on the commit half (BEE-007). A first run over a big repo pays for one tip scan; every later one no-ops.
  • test/http fails one of its 183 checks in this worktree, and identically on main with nothing of BEE-057 in it, so it is somebody else's bummer.
