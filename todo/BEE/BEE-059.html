bee fork //quickjab-TKT-123 refuses outright: quickjab's qjs submodule is quickjs-ng, whose own .gitmodules pins test262 with update = none, shallow = true — a submodule upstream never means to check out, 500+ MB of conformance suite. It is not initialised, so fork.js:88 finds no repo at its path and throws, and the rollback removes the tree it had already built. Every other reader in bee (index/index.js:938, index/subs.js:27) SKIPS an uninitialised gitlink in words; only fork treats it as fatal.

Input

Context

  • Repro, 2026-08-23, main tree: cd ~/src/quickjab && bee fork //quickjab-BEE-059 -> bee: submodule test262: there is no repo at /home/gritzko/src/quickjab/qjs/test262, exit 1, nothing left behind.
  • git submodule status --recursive there marks qjs/test262 with - (uninitialised); the dir is empty, .git/modules/qjs/modules does not exist.
  • qjs/.gitmodules carries update = none and shallow = true for test262 — upstream's own statement that this sub is not part of a checkout.
  • fork.js:84 grow() walks every gitlink the recorded tree names, and fork.js:88 makes a missing repo at the source path a refusal (BEE-026 ruling: a sub whose commit is not fetched must not leave a half-built tree).
  • index/index.js:938 submodules() skips (not initialised) and index/subs.js:27 marks it live: false; the tally and the staging never refuse on it.
  • The refusal names test262, not qjs/test262: grow recurses with the nested parent's own paths, so a deep sub is reported unlocatably.

Goals

  • A gitlink with no repo at the source path is SKIPPED, not fatal: fork builds the tree, leaves that dir empty exactly as the source has it, and the parent keeps recursing into its live siblings.
  • The one report line says how many subs were skipped, in the shape index/index.js:938 already uses, so a silently-empty submodule dir is never a surprise.
  • A gitlink whose repo IS there but whose commit is unfetched still refuses and still rolls back — that is BEE-026's case and it does not move.
  • Refusals and skips name the path from the FORK ROOT (qjs/test262), not from the nested parent.

Constraints

  • .gitmodules is not parsed for update = none: absence of a repo at the path is the test, which needs no config reader and matches how the rest of bee decides liveness.
  • No change to subsAt/submodulePaths; the walk stays as BEE-026 wrote it.
  • test/fork/run.sh gains the case; the existing missing-gitlink refusal case must not move.

WIP

Design decisions

  • RULED: a skipped sub suppresses recursion into ITS gitlinks — there is no worktree to hang them under (the default stands).
  • The tally rides a { n, skipped } object through grow, and the prefix is a plain string arg, so the recursion stays one walk.
