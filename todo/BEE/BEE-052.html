Every reference http paints resolves to /<repo>/cat/<rel>#b<byte> (http.js:296 refResolve), and the #b<byte> id is minted by the token painter (render/html.js:216). A .md/.mkd target is not painted: LITE-035 renders it as a PAGE, and the rendered page carries no token spans at all — so the fragment names nothing and the browser leaves the reader at the top. We work in permalinks; a link that lands on the file rather than on the line loses exactly what the permalink was for. Source targets are unaffected: their cat page IS the painted tokens.

Input

Context

Found while landing BEE-050, whose quote headers link the same way — the band inherits the miss rather than causing it.

  • /bee-journal/cat/todo/LITE/LITE-011.mkd carries ZERO id="b…" attributes; /bee-journal/raw/todo/LITE/LITE-011.mkd carries 2721 of them, b4246 among them.
  • refUrl -> refResolve (http.js:296) writes the fragment for every ref shape alike, having no idea the page it names will render instead of paint.
  • The same href is emitted for a body reference and, since BEE-050, for a quote's header; both land at the top of LITE-011 rather than on line 51.
  • In the pager the same reference lands correctly — land rides the hunk and the pager selects the row, so this is an http-only loss.
  • ROOT CAUSE (gritzko, 2026-08-21): the Markdown->HTML render breaks the token structure. anchorId is minted in ONE place, render/html.js:216, and has been since LITE-034; mark/ has never emitted one, so a rendered page has no byte to be named.
  • The highlight is already there and needs nothing: pre.body span:target wears the theme's band (render/html.js:116), which is what makes a landed token visible on a PAINTED page.
  • mark/node.js carries sourcepos (line/col per node), so the rendered page has the material for an anchor; it is a line, not a byte, and #b<byte> is what every href spells.

Goals

A reference into a markdown file lands where it points, without giving up the rendered reading.

  • The rendered page carries an anchor per source line (or per block), minted from the SAME byte offsets the painter uses, so one fragment spelling serves both faces.
  • Failing that, a LANDED reference into a .md/.mkd routes to /raw/ — the painted bytes, where the anchor already exists — while an anchorless one keeps the rendered page.
  • Whichever way: /…/cat/todo/LITE/LITE-011.mkd#b4246 either resolves or is never emitted.

Constraints

  • One fragment vocabulary: #b<byte> is what the painter mints and what anchorByte computes; a second spelling would need a second resolver.
  • The rendered page must stay the DEFAULT reading of a .md (LITE-035); this ticket must not turn markdown back into source.
  • Tests: a served page proving the anchor a ref emits exists in the page that ref opens, for a source target and a markdown target alike.

  • [v] render/html.js: .mark :target wears the same band the painted page's landing does.
  • [v] the four suites that pinned the old .mkd html read it with the anchor plumbing stripped (bare()); the anchors are pinned on their own in test/strict.
  • [ ] test: every emitted #b<byte> exists in the page it names.

Outcome

Landed with BEE-053 and DOG-045 in the one build. /bee-journal/cat/todo/LITE/LITE-011.mkd carries 2419 id="b…" where it carried none, #b213 is a real <p>, and a cite band pointing at it lands and highlights. DOG-045 made the offsets trivial: with line-coherent tokens a piece's byte IS its token's start, so tokLines needed no accounting of its own. Suite 179/179.
