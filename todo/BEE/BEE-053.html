index/index.js:879:cn resolves correctly — line 1035, the if that does the watermark check — and the href http emits for it is #b41999, a byte the served page carries no id for, so the browser does not move and nothing is highlighted. Two causes, one line apart: the permalink's own token comes off the WEAVE's tokenizer (index/perma.js:238:Ab), which cuts a \n and the indent that follows it into separate tokens where the painter fuses them into one, so seat.lo falls BETWEEN two painted spans; and the token it names is the two-space indent, which would paint an invisible landing even if the id existed. A permalink must jump to a specific token AND that token must show.

Input

Context

Reported by gritzko 2026-08-21 while reading a cite page, and reproduced from the CLI.

  • door.seatOf("index/index.js:879:cn") -> {line: 1035, col: 1, lo: 41999, hi: 42001}, and bytes 41999..42001 are " ", the line's indent.
  • /bee/cat/index/index.js carries id="b41998" (the painter's \n token) and id="b42001" (if), but NO id="b41999" — the href pointed between them.
  • anchorByte (http.js:314:3E) returned seat.lo VERBATIM whenever the resolver walked a token, so nothing checked the byte against the stream the page would actually emit.
  • Without a hashlet the same landing goes through wrap.landAt + tokSpanAt, which answers the token CONTAINING the line's first byte — the previous line's trailing \n run — so that path lands one line early on blank ink.
  • pre.body span:target (render/html.js:116:BN) paints the landed span with the theme band; a blank span paints nothing a reader can see.

Goals

Every #b<byte> http emits names a span the target page emits, and that span carries ink.

  • anchorByte answers a token of the SERVED hunk, always — a permalink's own byte is snapped through tokSpanAt rather than trusted.
  • A blank token is walked off onto the ink after it, never past the end of the landed line: a landing names a line, and the next line is a different claim.
  • Both landing shapes — the walked token and the bare line:col — come out of the one snap, so neither can drift from the other again.

Constraints

  • The two segmentations ARE unified, at the lexer (DOG-045) — the byte a permalink names is a painted span again. This ticket keeps the snap all the same: agreeing boundaries do not make an indent visible.
  • The bytes snapped through are openOnce's, the very hunk /cat/ serves, so the offsets cannot disagree.
  • Tests: an emitted #b<byte> exists as an id in the page it names, and is not a blank span.

WIP

Design decisions

  • Snap at the anchor, not at the resolver: seat.lo stays the identity LITE-029 hands the pager, and only the URL spelling is made to fit the page it addresses.
  • Two fixes, not one: DOG-045 makes the byte EXIST as a span, this one makes the span SHOW. Either alone leaves a permalink that does not land.

Outcome

Worktree ~/src/bee-BEE-053 off 9bc53e1, build ~/src/quickjab/build-bee-BEE-053, suite 179/179. index/index.js:879:cn now emits #b42001 — an id the page carries, on the if of line 1035. With DOG-045 in the same build the page also carries id="b41999", the permalink's own byte, so the two segmentations agree and the snap only has to step off the indent.
