A be button is 2 cells of tone FOREGROUND over a VERY PALE wash of that same tone — never an inversion — and both colours ride the button's own O prefix, so the button needs no tok tag of its own (be views/todo/todo.js:97,728: theme BTN/BTN_FACE/BTN_TAG + the ONE pale()). bee's render/theme.js is 256-slot palettes with no truecolor pair channel and no wash derivation. This ticket ports the scheme: the tables, the pale() derivation, the pager paint of the #<pale><tone> pair over the face's cells, the disabled grey, and the html.js CSS twin.

Input

Context

  • Faces and tones are THEME data, never view-local literals (be's DIFF_WASH precedent); one place an SGR value lives.
  • A lost prefix must degrade to the face's legacy 16-palette class tag, never to grey — grey is the DISABLED signal (be todo.js:732:i4).
  • The disabled face is plain grey fg, no wash, no spell; the info face is class colour, no wash, empty spell (be todo.js:770:i4).

Goals

  • theme.BTN (tone per button name), theme.BTN_FACE (the 2-cell glyph faces), theme.BTN_TAG (fallback slot), theme.pale(tone) in render/theme.js.
  • The pager paints every cell of the face with the O's bg+fg pair; every cell of it clicks — no dead padding.
  • html.js emits the pair as inline style / generated classes, same $BRO_THEME switch as the rest (render/html.js:86:BN).
  • --plain and pipes: faces appear as their ASCII bytes only, no SGR.

Constraints

  • Worktree and build of the assignee's own; no main-tree edit, no commit (work).
  • RED first; no existing test case edited. Comments per comment, BEE-035 on the change.

WIP

Design decisions

  • Faces start as be's: status i, log ≡, commit ✓, done ✓, dont ✗, go go, counts <sigil><digit>/two digits.
  • pale() is derived, not tabled — one formula, so a new tone never ships without its wash.
