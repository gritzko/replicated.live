A page of several hunks read as one undifferentiated wall in the ascii view: the file's own segments carried no title at all, and the bands that did print — hunk <uri> — were a word like any other in the body under them. Both halves are one fix. The band's sigil becomes §, and a view answering with more than one hunk titles them ALL, its own bytes included. A view answering with ONE bare hunk still writes it alone, so bee cat x | diff keeps getting the file.

Input

Context

Reported off bee cite index/index.js over http, then read back in --plain.

  • render/plain.js:43:le printed hunk <uri> for an excerpt and NOTHING for a bare hunk, so a cite page's source segments were untitled.
  • pager.js:380:TJ drew the uri alone; with --no-color a header is indistinguishable from the line under it.
  • html has never honoured bare — render/html.js:309:BN bands every hunk — so the two views disagreed on the same hunks.
  • gritzko, 2026-08-21: "that applies to all views. What is not a part of Markdown or any programming language, but clearly a separator?"

Goals

A header that cannot be read as its body, on every hunk that needs one.

  • The band's sigil is §: Markdown syntax at no position, and no language's operator, comment or sigil, so a title never reads as code or prose (gritzko, 2026-08-21).
  • A view yielding SEVERAL hunks titles all of them, a bare segment among excerpts included — the reader has to see where the file resumes.
  • A view yielding ONE bare hunk writes its bytes alone, as cat, blob, list and log always have.
  • An excerpt still wears its band when it is the only hunk (BEE-017:35:qe), so bee see <ref> is unmoved.
  • A SEGMENT of a split file names the line it resumes at, § cite doc.mkd:666, so a repeated title still places the reader.

Constraints

  • ONE spelling of the title, render/plain.js bandTitle, read by the plain sink and the pager alike — a second would drift.
  • bee cat x | diff and bee commit <sha> | git cat-file keep their bytes; only a multi-hunk page gains a line.
  • Every suite asserting the old hunk <uri> band is amended, none dropped.

WIP

Design decisions

  • bare stays a per-hunk word — "this hunk IS the answer" — and the page-level rule sits in render alone: many || !h.bare. No view had to be touched to gain the titles.
  • The pager takes plain.bandTitle rather than spell the band again; its colour path keeps the pale-yellow wash, now over a § line.
  • line0 (BEE-050:51:wg) already rode every split segment, so the resume line was there to print and no view shape changed.
