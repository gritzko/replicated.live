BRO-045: the pager does not repaint on a terminal resize — the screen stays stale until a keystroke

Now
DONE
Sev
MED
Rep
///be/

Pager.render() re-reads tty.size(this.fd) on every frame and rows(cols) already re-wraps and re-caches by width, so a resized terminal renders correctly — the FIRST time anything paints it. Nothing paints without a wake: the key loop spins on a 100ms io.read timeout and only leaves the spin for a key, a tick deadline or a CI-badge flip. A resize is none of those, so the frame on screen keeps the old cols/rows until the reader presses something. Add the size change as the THIRD non-key wake condition; the repaint machinery already exists and needs no change.

Input

Context

Read from the live pager 2026-08-04; no ticket covers it (BRO-036 sizes the elastic B span, it does not repaint).

  • views/bro/pager.js:1466 — "VMIN=0 VTIME=1 means io.read returns 0 on a 100ms timeout, so spin until a byte arrives".
  • The spin already breaks WITHOUT a key twice: due && this._nowMs() >= due (CI-004 live views) and this._ciBadge() !== ci0.
  • render() (pager.js:432) re-reads tty.size every frame, defaulting 80x24; rows(cols) (pager.js:415) re-wraps whenever cols moves and caches per width.
  • jab exposes NO signal API — tty is raw/cook/size/openpty/setSize only, and no SIGWINCH handler exists anywhere in jab/. The 100ms spin is the wake mechanism available, so this needs no ///jab change.
  • On the alt screen (BRO-027) a shrink lets the terminal reflow what is displayed, so the stale frame is not merely small — it is scrambled.

Goals

A resize repaints the board within one spin tick, with no keystroke and no new binding.

  • The key spin leaves on a tty.size change, exactly as it leaves on a tick deadline.
  • Both axes count: a cols change re-wraps, a rows-only change repaints (viewRows and the bottom status/address bar move).
  • The elastic B span (BRO-036) re-fits to the new width, which rows(cols) already does once it re-runs.
  • Scroll position survives a resize — the reader stays where they were reading, not snapped to the top.

Constraints

The repaint path is not to be rewritten; this is a wake condition, not a render change.

  • Up to one 100ms tick of latency after the resize is acceptable — do not add a busier spin.
  • tty.size per spin iteration is an ioctl; call it once per tick, not per inner loop pass, if that reads hot.
  • No new jab binding, no signal handler: if the fix seems to need one, stop and report.
  • BRO-027's alt-screen enter/exit bytes stay exactly as they are.

WIP

Design decisions

  • The wake belongs in the inner spin beside _tickDue()/_ciBadge() — same shape, same place, one more break.
  • Remember the size the LAST FRAME painted, compare against it; do not compare against a size captured before the spin.
  • A rows-only change must still repaint even though the width cache is untouched — key the check on both fields.
