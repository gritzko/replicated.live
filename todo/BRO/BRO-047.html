The pager's clickables (U nav targets, O button spells, F ticket keys) are mouse-only; Enter follows the TOP row's hunk URI. Add a link cursor: Tab / Shift-Tab (a/d synonyms) cycles the view's links, inverse video marks the selection, the status bar previews the resolved spell, Enter drives it through the SAME dispatch a mouse click takes.

Input

Context

views/bro/pager.js: the click path is _mouse → _screenToByte(row,col) → _uriAt(hunk,off) → SPELL.parseOspell → mutation gate → _actSpell | _runSpell. Display rows come from rows()/indexAll, cached per (cols, wrap); there is NO cursor state — Enter is _followRow(v.scroll) (the top row).

  • Clickables per _uriAt: a visible token whose NEXT token is U (hidden URI) or non-empty O (button spell, three-part invite BRO-025/BRO-039); an F issue key resolves via shared/ticket.js; the _lineUri lone-U fallback covers whole log/ls rows.
  • Painters: emitBody (plain PASS_NORMAL walk, pager.js), paintDiffRow + paintWhyRow (view/bro.js, shared with pipe --color).
  • SGR is the ansi64 model (view/bro.js): attr flags exist, inverse = flag 0x20 → SGR 7/27, already in FLAG_ON/FLAG_OFF — no new escape machinery needed.
  • _feed decodes ONLY mouse (ESC[<) and paste (ESC[200~) brackets; Shift-Tab arrives as ESC[Z and needs a decode arm.
  • Key collisions in _keyScroll: w/W = wrap, s unused but adjacent; a/d free; Tab free in scroll mode (0x09 is Tab-complete only in command mode).

Goals

Mouse-free link clicking, visually equal to a click: select, see, press Enter.

  • Tab / d = next link, Shift-Tab (ESC[Z) / a = prev link, cycling over the view's links in row order; auto-scroll to reveal the selection.
  • Selected link renders inverse-video over its visible span; composes with diff/why washes (flip, not overwrite).
  • Status bar left slot previews the spell Enter would run (the _uriAt output, context and all) while a selection is live.
  • Enter with a live selection activates it via the exact mouse dispatch (mutation gate included); without one, today's _followRow stands.
  • help:/SHORTCUTS stays truthful (single source, BRO-007).

Constraints

  • ONE dispatch path: factor the _mouse tail into _openTarget(target); keyboard and click both call it — no parallel resolution logic (see resolve_hash law: no reimplementation, ever).
  • No new SGR machinery: highlight = aOr(want, aFlag(0x20)) inside the existing painters; no color-based selection (fights the I/O/J/K washes).
  • Existing keys keep their meaning (w wrap, m mouse, j/k scroll); no test edits outside new files without explicit permission.
  • Verified through the real UI path: a pty repro that flips (drive the pager on a pty, send Tab/Enter bytes, assert the nav happened) — TLV/unit probes alone do not count.

WIP

Design decisions

  • Link index derives from the row index: one walk per rows() re-index collects links = [{ri, colLo, colHi, hunk, off}], cached under the same (cols, wrap) key; the walk mirrors _screenToByte's column accounting (els inserts, hidden U/O bytes).
  • Selection is ONE integer on the view (view.link, like scroll); reset on nav/re-index; when the selected row leaves the viewport, the next Tab snaps to the first VISIBLE link (the lynx rule), never yanks the viewport back.
  • A soft-wrapped link highlights per display row — each row's index entry carries its own span slice.
  • Dead O cells (colour, no spell — TODO-007) are NOT links: the index skips them, same as the click path's inert-cell rule.
  • Impl deviation: index entries carry BYTE spans, not columns (the painters are byte-driven; columns mis-map an els row), and the index builds LAZILY on the first Tab, cached on the same (cols, wrap) key — a plain scroll pays nothing.
  • Impl deviation: adjacent cells with the SAME target coalesce into one stop (a why: row: 368 stops → 15); a plain cell between them breaks the run.
