BRO-011: the jab bro-pager double-encodes multibyte UTF-8 (— renders as â…) — the frame is a JS string then utf8.Encode'd a 2nd time

The interactive bro pager (views/bro/pager.js) renders non-ASCII text as mojibake on a TTY: an em-dash — (UTF-8 E2 80 94) shows as â…. Root cause: render() assembles the frame as a JS STRING where each text byte becomes a code unit via String.fromCharCode(text[pos]) (paintRow / paintDiffRowStr), then ttyWrite runs the whole frame through utf8.Encode a SECOND time — so E2→C3 A2, 80→C2 80, 94→C2 94 (double-encoded). The piped --plain/--color paths are byte-correct (renderHunkLog→C .plain/.color, and colorDiffHunk's enc/raw byte split); only the pager's string-frame path re-encodes. Scope: be/ JS pager. See Bro; method Issues.

Input

Context

  • Repro: any UTF-8 file (an em-dash —) viewed through the pager on a TTY renders â…; the same via --plain / | cat is byte-correct.
  • render() (views/bro/pager.js:239) builds frame (a JS string) then calls ttyWrite (:47), which does utf8.Encode(str) — a 2nd encode over text already carried as per-byte code units.
  • paintRow (pager.js:101) out += String.fromCharCode(text[pos+i]) and paintDiffRowStr (view/bro.js:332) emit raw bytes as code units 0..255 — a latin1-ish string the frame re-encodes.
  • The byte-correct reference already exists: view/bro.js colorDiffHunk/paintDiffRow use an enc/raw split (SGR utf8-encoded, text bytes fed VERBATIM) precisely to avoid this; the comment at view/bro.js:279-281 warns of the double-encode.

Goals

  • The pager writes UTF-8 to the fd byte-for-byte: text bytes verbatim, only SGR/ASCII utf8-encoded. An em-dash (and any multibyte codepoint) renders correctly on a TTY.
  • No regression to the piped --plain/--color paths, or to the pager's colour / mouse / soft-wrap behaviour; paintRow keeps its string API for the driver/pty tests.

Constraints

  • be/ JS only (views/bro/pager.js; view/bro.js only if needed). ABC/JS house style, ≤2-line comments.
  • Preferred design (user): build each frame as UTF-8 bytes in an io.buf and io.writeAll it — NOT a JS string that utf8.Encode re-encodes whole.
  • Repro-first: render an em-dash hunk to a tty.openpty() slave and assert the drained bytes contain E2 80 94, not the doubled form — like test/bro/pager/pty.js.

WIP

Design decisions

  • Factor the cell walk into one emit sink emitBody(hunk,off,end,color,pass,enc,raw); render() feeds an io.buf (enc=utf8.Encode, raw=text.subarray verbatim); paintRow wraps emitBody with a string sink (raw via utf8.Decode) so its API + the ASCII driver/pty asserts are unchanged.
  • Route the pager's diff branch through the byte-based view/bro.js paintDiffRow (enc/raw) — retires the string-only paintDiffRowStr for the pager (then dead; drop or leave per review).
