Design decisions

  • ROOT CAUSE (iter 2, pty-verified + orchestrator-corroborated): *fd exhaustion in the view drive*, not context logic. ONE why <file> drive consumes 1007 fds (ordinary cat/status drives leak 17-20 each); then abc.mmap("ULOG", <wt>/.be, "r") throws No file descriptors available and the pager's file→dir oracle goes BLIND: _ctxFrom (pager.js:822) only reduces a file when _ctxKind→reg, which runs discover.wtdir → treeAt → climb → anchors() (resolve_hash.js:61) → ulog.each. So the FILE survives as a dir segment (//BRO-040/CMakeLists.txt/) and every later resolve fails. The carrier is the BE-048 launch context, which for jab why <file> is deliberately the FILE — harmless while the oracle works, junk the moment it blinds.
  • THE MASK: ulog.each (shared/ulog.js:42-48) swallows a failed mmap with catch (e) { return; } → ZERO rows, no error; anchors reads that as !!row0 false → "no worktree". A resource failure is indistinguishable from an absent/empty log — the JS-074 disease in a second place. Orchestrator verified the swallow in the main tree and reproduced the fd-hunger differentially: under ulimit -n 64, jab status completes, jab why CMakeLists.txt dies Error: No file descriptors available.
  • Segment grows at STEP 3 (back), not step 4; step 4 only surfaces it, and only from a row in a DIFFERENT chunk (rows 6/10/18/22/30 fire; an in-chunk row like 14/26 passes).
  • TREENONE reconciled: SAME fault, one cause — the earlier main-tree TREENONE is this exhaustion seen at tree.js:130 instead of at anchors. Explains every symptom: accumulates with clicks, path-independent, error-kind roulette (no hunks / no worktree / TREENONE / the JS-074 plain-args phantom, all reproduced from one exhausted process), and "cold headless is fine".
  • (iter 1, SUPERSEDED) the headless "nothing rots" verdict was WRONG: a headless instrument never exhausts fds, so the oracle never blinds — the [verify-through-real-ui-path] rule earning its keep. BRO-015/BRO-018 remain genuinely cured by BRO-024. drives of both repros dump byte-identical this.ctx, view.uri, view.call{verb,spell,context}, be.prev_uri across N iterations — no pager coordinate rots. BRO-015 (replay strips rest) and BRO-018 (file-as-dir) are already CURED by landed BRO-024; _ctxFrom strips ?query, so no ?hashlet leaks into the context. Suspects 1-3 all cleared.
  • the real fault is DOWNSTREAM of the context: real-pty repro on the MAIN TREE dies err: TREENONE — views/tree/tree.js:130 (resolve_hash(ctx,bare) throw) / :144 (pin absent from the sub store) as the commit view resolves its tree object — and the persisted pager context was CORRECT (//) at that exact step.
  • it is a RESIDENT-state fault: cold jab commit ?hashlet is OK, standalone interactive jab commit ?hashlet renders, and the same driveSpell returns 214 hunks in every headless config; it fails ONLY as a click-driven reentrant drive inside a long-lived interactive process AND only on the complex main-tree store (an authority-bearing fixture hive clicks the same why→commit path clean). Store/resolve_hash/tree-object resident state — kin of the fd/mmap hazards (ABC-014, keeper) — NOT the pager.
