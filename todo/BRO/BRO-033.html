BRO-033: gitlink click navigates INTO the submodule (context += path)

Now: OPEN

Input

Context

Ruling (gritzko 2026-07-18): clicking a gitlink row in bro must switch to that submodule — append the gitlink's path to the context, exactly the compose-by-path rule (the sub of ///jab is ///jab/dog; context is //WT/rel/dir/, BRO-024, mutated only by navigation — this IS navigation).

  • Today a gitlink/sub row click dead-ends (dir rows fall into cat, which refuses: "cat: needs a path" / no hunks).
  • Gitlink rows appear in status (mount rows, /todo/SUBS/SUBS-033), ls/tree listings, and diff.

Goals

A left click on a gitlink row makes the sub the current scope.

  • Context becomes <context>/<gitlink-path>/ (e.g. // + be → ///be/); the bar shows the new context; the view refreshes in it (same verb, new scope — BRO-031 semantics).
  • Works from every view that renders gitlink rows; the emitted U spell must carry the sub-rooted path (/todo/SUBS/SUBS-045 ground: no dropped mount prefix).
  • Descending into a nested sub composes further (///be → ///be/dog).

Constraints

  • Pager stays arg-blind: the row's U token carries the navigation target; no pager-side path surgery; resolution via resolve(context, base, rel) / resolve_hash.
  • Dir-row clicks are adjacent but separate ground — do not redefine them here beyond what the U token already encodes; the audit is BRO-032.
  • pty-verified before/after (real click), per the standing verification rule.
