BRO-039: strict three-part O wire form — CTX: verb args, context MANDATORY, . = here, no silent fallback

Now
OPEN
Sev
HIGH

RULING (gritzko, chat 2026-07-19): the arg-into-context bug was fixed twice (BE-053, BRO-038DONT→BE-053) and returned (WORK-013) — the part gets REWORKED, not patched. Every O token is three-part CTX: verb args with the context slot ALWAYS present: . = empty ("here", leaves the pager context), /… = absolute (REPLACES the context), anything else = relative (COMBINES with the context). Args pass to the verb VERBATIM. parseOspell becomes one strict regex; a non-matching token is NOT an O spell — loud error, never "context-less spell".

Input

Context

  • The reinfection door: shared/spell.js parseOspell (:154-162) arms the split only on a leading //; every other token silently degrades to {context:"", spell:token} — so mis-baked mints keep working wrong, and the pager scavenges context from ARGS instead (_fillAuth graft pager.js:740, _ctxFrom(arg) reduction :744 — the audited leak list, 2026-07-19 bro-derivation inspection).
  • BRO-025 iter-1 "context-less token = here" impl decision is hereby OVERTURNED by the ruling; BRO-025's three-part concept and the drive-in-own-context machinery (_actSpell/_runSpell ctxOverride → driveSpell, loop context-first RAW args) STAND and are reused.
  • Audit facts (2026-07-19, both inspections): all current O mints conform (empty/absolute ctx, args literal); kind 3 (relative) is unrepresentable in the codec; two producers bypass mintOspell (views/todo/todo.js:260 raw done KEY, views/why/why.js:154 hand-baked #rgb commit ?hashlet); "//" is used as an empty-context alias (work.js:444/446); pager persists the NEXT context off the ARG, not the O context (pager.js:720 vs :744).
  • O tokens exist only inside rendered TLV hunks, regenerated per paint — mint+parse switch in ONE commit is a safe flag-day, nothing persisted to migrate; view.call stores context and spell separately already.

Goals

  • Wire form: CTX: verb args, CTX mandatory — .: todo BE-021, ///jab/dog/abc/: status, dog/abc: status. parseOspell = one regex ^(\S+): (.*)$ (context = the space-free token before the FIRST : ; contexts are URIs/paths, never contain spaces, so : inside args stays safe). Trailing / shed off the context as today.
  • mintOspell always emits the context slot (. for empty); every O producer routes through mintOspell — the todo.js:260 and why.js:154 bypasses are converted (the #rgb tint becomes its own leading marker, not welded into the spell text).
  • A token failing the regex is NOT an O spell: the pager rejects it loudly (plain-words error naming the token), never degrades. This is the anti-reinfection core.
  • Pager context seam: ONE helper combine(current, ctx) — ./empty → current; leading / → replace; else → join — used BOTH for the drive context and the recorded next this.ctx; the _fillAuth graft and _ctxFrom(arg) reduction leave the O path; args are display-verbatim, never context donors.
  • All three kinds round-trip mint→parse→combine; pty proof per kind.

Constraints

  • U tokens untouched here: U-follow arg→context reduction is a separate pending ruling (BRO-024 $PWD model vs args-verbatim) — do not change U behavior in this ticket.
  • Typed : spells (_applySpell/_driveApply) and slot-edits keep today's behavior; only the O token path reworks.
  • Rulings in force: pager arg-blind, resolution via core/resolve_hash.js, errors in plain words; the regex splits the three parts ONLY — the context substring goes to the standard URI/resolve machinery, never regex-parsed as a URI.
  • Overlaps in-flight WORK-013 (work.js U→O mints via mintOspell — its output re-bases onto the new mint form cleanly); land order: whichever first, expect a weave.
  • test/bro/ospell (BRO-025's 15 checks) pins the OLD optional-context form — amending it to the strict form is AUTHORIZED; test/work/view, test/todo/view, test/done/buttons token pins likewise; no other test edits.
