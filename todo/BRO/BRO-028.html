BRO-028 MED: mkd syntax colour desyncs mid-file — tokens land mid-word with a growing shift (jab cat todo/ABC/ABC-011.mkd)

Reported by gritzko 2026-07-17: jab cat todo/ABC/ABC-011.mkd renders the first ~8 lines correctly (header spans, backtick code spans magenta), then colouring goes funky — SGR runs start landing mid-word (^[[32mt^[[39mest co^[[32mv^[[39mers), and the shift GROWS down the page. Looks like a byte-vs-codepoint (or escape-length) desync between the tok32 offsets and the painter's cursor. Repros PIPED (--color), so no tty needed.

Input

Context

Evidence: jab cat todo/ABC/ABC-011.mkd --color | cat -v — clean until the line "GET / HTTP/1.1\r\n\r\n".; from there single letters mid-word carry colour and the misalignment accumulates. The page is dense in em-dashes (UTF-8 —), a ≥, →, and backslash sequences (\r\n) inside prose and quotes.

  • First 8 lines paint correctly, so base tokenization works; the desync onsets at/after the backslash-quote line and grows — cumulative offset error, not a one-off.
  • Painter side: be/view/render.js + the cat view (be/views/cat/cat.js); tok32 comes from the native jab tokenizer. BRO-011 fixed a double-UTF-8-encode in the pager frame; this may be the sibling in the offset accounting (JS string UTF-16 units vs tok32 byte offsets).
  • The same funkiness presumably affects the pager's mkd views, not just piped cat.

Goals

Colour runs align with the text for the whole file; a repro pins it.

  • Repro FIRST: a small .mkd fixture (em-dashes + \r\n-style backslashes + quotes) where the current renderer emits SGR mid-word; assert colour-run boundaries fall on token boundaries.
  • Diagnose: byte vs UTF-16 cursor in the painter, or tokenizer emitting wrong lengths for escapes/multibyte — pin which side before fixing.
  • Fix the one offset accounting; jab cat todo/ABC/ABC-011.mkd --color paints clean end to end.

Constraints

  • Fix the OFFSET ACCOUNTING, not the palette; BRO-010/BRO-011 ground (verb colour, double-encode) must stay green.
  • If the defect is in the NATIVE tokenizer (jab side), do not patch ~/src/jab — diagnose, prove which side, and report for a JAB ticket.
