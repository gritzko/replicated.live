BRO-024: reduce the context URI to //WT/dir/ ($PWD); prompt-like address bar //WT/dir/: verb args; cd before verbs

Now:
DONE

The fat context URI (authority+path+?rev+#hash all mutable slots) is not working well; ruled 2026-07-12 to reduce context to worktree+path only, exactly $PWD for the verbs. The pager address bar becomes a shell-like invite: context left of : , verb invocation right of it. Verbs execute with the process actually cd'ed into the context dir so nothing is mistaken; the revision axis leaves context and goes explicit into spells and links. Rewrites the context part of Nav (already flagged stale, BRO-023, BE-030).

Input

Context

  • Nav lets the context carry ?branch/#hash; the slot-edit machinery around that bred bugs: mergeUri slot edits BRO-018, the stale follow resolver BRO-016, the empty initial context BRO-017, completion context BRO-022.
  • Verbs already own resolution — resolve(context, base, rel) at the verb entry, the pager is arg-blind (URI-010, URI-011, BE-039).
  • Ruling (gritzko, 2026-07-12): context = //WT/rel/dir/, nothing else; it is the $PWD of the nav framework, in the CLI it literally IS the pwd.
  • LIVE SIGHTING 2026-07-17 (BRO-030 session): bare :post in a pager at context //BRO-030/ ran against the LAUNCH tree (journal/be) — BE-039 threads context onto ARGS only, so an arg-less mutation verb keeps the launch ambient; post's implied ///be/ track then hit the POST-026 self fall-through → ` ? can not be fast-forwarded `. A MUTATION aimed at the wrong tree — the cd-before-verbs goal is the fix.

Goals

  • Pager address bar renders a prompt-like invite //ABC-123/dog/: and the typed spell after it, e.g. //ABC-123/dog/: status.
  • Verbs and views run cd'ed into the context dir; execution is serialized (chdir is process-global), cwd restored on throw.
  • Revision goes explicit: ?rev/#hash appear in spells and in clickable links only; diff/status take the base of comparison as an arg, object-extraction views (blob, tree, commit) take it likewise; walking around a commit uses hash-carrying links.
  • No jumping out of a worktree: .. clamps at the //WT root; // addresses the main tree.
  • A deleted context dir shows the invite red; the user cd's out of it; verbs report cleanly instead of raw ENOENT.
  • CLI context derives from pwd; pwd must be under SRC_ROOT (the main tree root, aka ///), outside it there is no context.

Constraints

  • resolve() + absolute paths remain the law at verb entry; the cd is a backstop, not a substitute — cross-worktree args (//OTHER-999/file) still resolve explicitly.
  • Remote browsing (a be:// context) stays out of scope: TODO, remote resources reachable via explicit verb args only.
  • Nav.mkd rewrite rides this ticket; wiki budgets per /meta/wiki.

WIP

Design decisions

  • (gritzko, 2026-07-12) revision axis is meaningful for diff/status (comparison base) and object-extraction views — keep it explicit in spells and links, never in context.
  • (gritzko) serialize verb execution around chdir; safe to keep resolve+abs paths as the primary mechanism.
  • (gritzko) worktree escape forbidden; //WT or // for the main tree; pwd must sit under SRC_ROOT (///).
  • (gritzko) rm'ed context dir: paint the invite red, let the user cd out.
  • (gritzko, 2026-07-12, the ONE-VAR ruling) the context is tracked in ONLY ONE PLACE — the process cwd; the prompt invite must MATCH cwd by construction; navigation = io.chdir (landed in the jab runtime + installed); all other context carriers (pager this.ctx, launch this.context, session be.ctxDir) get DELETED, then tests made pass. Trigger: bare :put at //BRO-024/ staged only test/bro/context/* — PUT-008's ctxSub read be.ctxDir, a THIRD context source diverging from the handed context (launch dir was the cell root, so the divergence is in the ctxDir mint, not launch-stale).
  • (gritzko, 2026-07-12) bare verb after a single-file view takes THAT file as the implied arg: :diff shared/spell.js then :vim opens the file, because it was the only hunk open. The default arg comes from the VIEW's sole subject, never from the context (context stays dir-only); ambiguous multi-file views imply nothing.
