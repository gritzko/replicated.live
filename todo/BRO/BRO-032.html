BRO-032: audit — every dir-capable view must support dir/sub scoping

Now
OPEN

Input

Context

Ruling (gritzko 2026-07-18, out of BRO-031): status can be scoped to a sub like all others — dir scoping is the norm, not per-view charity. Audit every view that can meaningfully take a directory and verify it honors a dir both as an explicit arg (view ///be/verbs/) and as the $PWD-like context (no-arg view after :./dir nav).

  • Views under be/views/: blob, cat, commit, diff, grep, help, list, log, ls, lsr, refs, regex, sha1, size, spot, status, todo, tree, type, why.
  • Known ground: diff no-args is whole-wt, ls/tree are dir-native, spot/grep/regex subtree scope is ruled in /todo/SPOT/SPOT-003 (path-slot scope); file-only views (cat, why, blob) are out of scope except for their error message on a dir.

Goals

A pass/fail matrix, then fixes or spawned tickets for the failures.

  • For each dir-capable view: explicit dir arg leg + context-scoped no-arg leg (after :./dir), both checked in a real pty session AND piped plain mode.
  • Scoped output must clip to the subtree; row paths and clickable U spells must compose sub-rooted (the BRO-031/_runSpell compose-by-path ground).
  • Failures too big for a 1-liner get their own tickets, linked here; matrix lands in this ticket's WIP.

Constraints

  • Verify through the real path first (pty + click a row where applicable) — probe output alone does not count.
  • No behavior redefinition in the audit: dir-native semantics per view stay as they are; only MISSING dir support is a failure.
  • Verbs resolve args via resolve(context, base, rel); the pager stays arg-blind — fixes must not scope-filter in the pager.
