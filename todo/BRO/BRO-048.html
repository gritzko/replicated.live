One piped jab todo draw makes 18k syscalls; 5240 of the 6506 file-touching ones are two full passes over todo/ — a stat sweep of 887 entries, then whole-file reads of 871 tickets (3.6 MB) to draw 405 rows. jab status makes 57k, dominated by sub walks plus 260 re-opens of 10 distinct .be stores. The waste is not stats (BRO-043 measured 2.7 µs each) but repeated drains, reads and parses of the same bytes within ONE dispatch: no memo exists for be.treeAt, wtlog.open (63 call sites, ≥3 full drains of one wtlog per status draw), gitmodules.parse (~312 maps/board, BE-064 covered only the arm/classify pair) or ignore.load; store readers reopen per call site (72 sites), re-running the keeper.idx audit each time. The fix is the BE-064 ruling generalized: hand the work down through a per-dispatch run frame, and make the board enumerate once and read once.

Input

Context

Strace + code audit 2026-08-07 (main tree, piped, 59 topics / 918 tickets). Cold-run hashing cost is out of scope here — that is GET-049 + STATUS-011 (stamp fast path). Whole-tree walk on gitlink pins is WORK-018. Junk watcher events are TODO-012.

  • Ticket tree enumerated 3-4x per cold draw: cache.arm(todoRoot) walk, listTopics readdir, a fresh recursive arm walk per topic dir (its published walk never taken), then metaidx.find's own recursive readdir (metaidx.js:181).
  • Every ticket read twice + stat'd thrice cold: metaidx.lex full read, pageHead full read (ticketpage.js:76), metaidx.scan stat.
  • Filter path (todo Now:OPEN) never memoized: runs metaidx.find() twice per draw (todo.js:1227, todo.js:192), reads each hit twice (pageTitle + pairs), re-probes pageFile with up to 6 stats though e.file is in hand.
  • Per wt row per draw: treeAt climb replays the whole .be ULOG for row 0, then wtlog.open drains it again (todo.js:562-563); CI.status stats /tmp/be-ci/verdicts per row (ci.js:135).
  • status: stateOf drains ULOGs and resolves tracks BEFORE the rev/memo compare (status.js:280-308); .gitmodules mapped ≥4x per repo per draw; quad + gitlinkPins walk whole trees repeatedly.
  • 42 of ~60 topic dirs opened twice, bare and trailing-slash spelling, each with its own getdents (see JAB-011).

Goals

  • A warm non-filter board draw does zero ticket reads; a cold one does ONE read per ticket and ONE enumeration of todo/.
  • A filter draw costs one metaidx.find and one read per HIT, and memoizes like the board.
  • One status draw drains each wtlog once, parses each .gitmodules once, opens each shard once.
  • jab todo file-touching syscalls roughly halved; measure before/after with the same strace harness.

Constraints

  • Rulings stand: cache lifetime under the live watcher only (BRO-043/STATUS-019), no persisted cold cache, rows-not-paint (TODO-006). The run frame is NOT a cache — it is within-dispatch dedup, dead at the closeAll boundary, legal in one-shot CLI runs.
  • mmap stays the ONE ULOG read mechanism (BE-050); no parallel byte-copy readers.
  • All resolution stays on core/resolve_hash.js — memoize around it, never bypass.
  • metaidx decides WHICH tickets open, it never renders (TODO-003); handing already-read bytes down is fine, storing titles in the lane is not.

WIP

Design decisions

The run frame is one object minted in loop.js cli() and swept where storelib.closeAll already sweeps. Consumers take resources from it instead of opening their own; tree objects are immutable so tree-map memos are safe unbounded within the frame (same precedent as the dag ts memo).
