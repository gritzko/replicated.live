BRO-041: diff row inline-vs-split must weigh max(in,rm), not in+rm

Now
DONE

A one-token edit renders as TWO rows (rm-row + in-row) where it must render as ONE inline row with only the changed token washed and the rest of the line white. The row classifier weighs an edit by changed = in_b + rm_b, so a symmetric token swap is charged twice and trips the changed * 4 < total inline gate. Ruling (gritzko, 2026-07-29): use changed = max(in_b, rm_b) and total = max + eq_b ("for now"). C dog/HUNK.c hunk_line_classify and JS bro.js lineKind are the deliberate BRO-009 pair and move in lockstep. Live repro in work/StrictMark; see BRO-009 for the two-pass renderer this sits in.

Input

Context

  • Repro: work/StrictMark, jab diff --color | cat -v on todo.mkd — the row -[ ] uniform headers edited to -[x] uniform headers (ONE byte, → x).
  • Observed: two rows — -[ ] uniform headers (bg 217 on -[ ], bg 224 on the body) then -[x] uniform headers (bg 157 / bg 194). Expected: one row, -[ ]/-[x] washed, body white.
  • Arithmetic today (beagle/dog/HUNK.c:761, be/view/bro.js:350): rm_b 4 + in_b 4 = 8 changed, eq_b 16, total 24; 8 * 4 = 32 >= 24 → MOD_SPLIT.
  • The gate admits inline only when eq_b > 3 * (in_b + rm_b), so a 4-byte token swap needs a 24+ byte unchanged remainder — unreachable for ordinary todo/prose lines.
  • Token granularity is NOT the bug: the diff already marks exactly -[ ]/-[x]; the one-byte edit inflates to 4+4 only because the lexer glues the marker into one token.

Goals

  • changed = max(in_b, rm_b), total = changed + eq_b; keep the changed * 4 < total shape. The repro line (max 4, eq 16 → 16 < 20) classifies MOD_INLINE.
  • Both impls change in lockstep: C hunk_line_classify and JS lineKind stay byte-equivalent in behaviour (BRO-009's one-C-one-JS invariant).
  • Verified through the REAL UI path: jab diff --color | cat -v in the repro wt shows ONE row for the edited line.

Constraints

  • Metric change only — no touching bro_classify_lines, the two-pass walk, hunk_line_continues, or the eq_b == 0 pure/split arm above it.
  • total = max + eq_b is the ruling FOR NOW; do not "improve" it to in_b + rm_b + eq_b (also flips the repro, but is not what was ordered).
  • Inline still renders both sides adjacently (-[ ]-[x] uniform headers); that widening is accepted, not a regression to fix.
  • No native be/graf oracle exists for --color (it LAGS jab): be/test/diff/lib/diffcase.sh:71-78 only smoke-tests that the render is non-empty and exits clean.

WIP

Design decisions

  • Two trees, one ticket: JS ///be/ is what jab diff --color actually renders; C ///jab/dog/ (libdog) is the twin that keeps graf/bro parity.
  • beagle/dog/HUNK.c is a SECOND libdog pin (branch ?/libdog/.beagle) and is out of scope — the trunk copy is ///jab/dog/.
