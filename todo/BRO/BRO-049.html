jab commit cf9f1b9c (in any clone of ///quickjab/dog) prints ONE line — JS exception: Error: hunk.render: out full — and nothing else: no headers, no diff, exit non-zero. The same commit renders fully in the pager. be/view/bro.js:959 sizes the per-hunk output buffer as (tlen + ulen + 64) * (mode === "color" ? 10 : 2) + 256 and calls the native log.plain(o) / log.color(o); when the render exceeds that cap the binding throws out full and renderHunkLog lets it escape. Plain gets 2x, colour 10x — hence a hunk that is fine on screen dies through a pipe. This is DIFF-010's grow-on-out full retry (and PATCH-012's) missing on the RENDER edge, the last hop every content view shares.

Input

Context

The bug hides work: the commit renders in the pager, so it looks healthy until someone pipes it, greps it, or a script reads it. Found while auditing the DOG-028/DOG-033 merge in ///quickjab/dog.

  • Repro: mkdir -p $WORK_ROOT/BRO-049 && cd $WORK_ROOT/BRO-049 && jab get ///quickjab/dog/, then jab commit cf9f1b9c 2>&1 | cat → JS exception: Error: hunk.render: out full, zero rows.
  • Reproduced from two independent clones (//DOG-028-dog/, ///quickjab/dog in the main tree) — the repo path is irrelevant, the commit's content is the trigger.
  • Mode-dependent, NOT size-dependent: under a pty the same jab commit cf9f1b9c paints the full view (10x cap), and sibling commits render in plain at 1957 rows (8c566732) and 2764 rows (39158d0c) while the failing one dies before its first row.
  • cf9f1b9c is DOG-034 (path ref anchors), touching the generated tok/MKDT.rl.c + tok/FREE.rl.c — thousands of SHORT table lines, where per-row markup overhead beats the 2x plain budget.
  • The per-file diff: view over the same table files renders in plain (diff:tok/MKDT.rl.c?1c8c4583, 1441 rows), so the overflow is the commit: view's hunk, not any table file per se.

Goals

  • renderHunkLog grows and retries on out full instead of throwing, so plain and colour render the same content.
  • A failing render never eats the whole view: partial output is worse than none only if it is silent, so any residual failure names the hunk's URI.
  • Repro-first: a test that renders the offending hunk shape in plain mode and fails before the fix.

Constraints

  • Reuse the landed grow-on-out full discipline (be/core/loop.js _hunkSink, be/views/diff/diff.js DIFF-010, be/verbs/patch/patch.js) — no fourth hand-rolled retry loop.
  • Bounded growth: double the cap with an iteration ceiling, as _hunkSink does, never an unbounded realloc loop.
  • The colour path must keep byte-identical output — this is the sink every content view (cat:, blob:, grep:, why:, commit:) shares.

WIP

Design decisions

  • A cap heuristic cannot be made "big enough" — the render's expansion factor is content-dependent (short lines, dense markup), so the retry, not a bigger multiplier, is the fix.
