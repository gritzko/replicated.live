BRO-026: du — store disk-usage view, one table row per shard

Now
DONE

A disk-usage verb: du locates the STORE backing the current repo and tables EVERY shard in it (the per-project dirs a sharded store hosts, /blog/git). Motivation: tens of forked/rm-rf'd worktrees share one store; it accretes packs and indexes with zero visibility ("has yet to show its limits of scalability"). One row per shard: packs, indexes, refs, total — plus the store TOTAL row.

Input

Context

  • Store layout (~/.be/<shard>/, flat): NNNNNNNNNN.keeper pack logs; *.keeper.idx / *.graf.idx / *.spot.idx LSM indexes; refs + .refs.idx; wtlog; .lock* (zero-size).
  • Live sample 2026-07-14: 15 shards, beagle 222M, beagle.new 44M, dogs 43M, journal 12M, beagle-ext 6M/95 files (87 keepers).
  • A worktree resolves to its store via the .be redirect (be.find / the GET-038 resolveLocalSource kin) — du must reuse that resolution, never assume $HOME/.be.

Goals

  • Bare du: resolve the current repo's store, readdir the store root, tally every shard dir; unreadable/non-dir entries skip silently.
  • Row = shard: name, pack count, pack bytes, index bytes, other bytes (refs/wtlog/misc), total; final TOTAL row across shards.
  • Human-readable sizes (K/M/G) in the pager; plain mode (.jab plain format) emits tab-separated raw bytes for scripting.
  • Rows sorted by total size, largest first; the current repo's own shard visibly marked.
  • Read-only: io.readdir/io.stat only, one pass per shard, no recursion below shard dirs, never shell out to system du.

Constraints

  • Pure JS on the jab runtime (io.*, no node APIs); JAB-004 plain-verb shape; hunk emission via the shared span/feed model (see views/work/work.js, views/todo/todo.js).
  • BE-003 miss discipline: ONE uniform line + throw; bare/. arg only, anything else is du: <arg>: DUNONE.
  • Wiki: a Verbs.mkd one-liner rides this ticket; budgets per /meta/wiki.

WIP

Design decisions

  • sort = total size desc (name tie-break for stable/byte-exact output); the repo's own shard marked with *.
  • columns = shard name, keeper (pack) count, keeper bytes, index bytes, other bytes, total; a final TOTAL row sums each.
  • index bytes = *.keeper.idx/*.graf.idx/*.spot.idx ONLY; .refs.idx groups with refs/wtlog under OTHER (ticket /blog/git layout).
  • PLAIN = one tab-separated raw-byte row per shard name<TAB>packs<TAB>keeperB<TAB>idxB<TAB>otherB<TAB>total; the current shard trails a 7th <TAB>* (data fields stay positionally stable for cut/awk).
  • human sizes = raw bytes under 1K, else K/M/G/T with one decimal below 10 (4.0K, 5.4M, 222M) — the du -h feel.
  • store root = PARENT of store.shardDir(repo.storePath, repo.project) — works for a colocated primary (<wt>/.be) AND a secondary-wt .be redirect; never hardcodes $HOME/.be.
  • HOME: du lives at views/du/du.js (by-file registry, registry.js) and rides the shared hunkrows sink; wiki one-liner went to View (where sibling read-only views size:/log:/refs: live) plus a git count-objects -vH → be du line in Verbs's cheat sheet.

Blockers and bummers

  • BRING-UP: jab get file:/home/gritzko/.be/?/beagle-ext SUCCEEDED — jab status works in the cell; the GET-041 self-locator/ASan fallback (cp -a) was NOT needed.
  • io.readdir HIDES dotfiles (verified): the DOTTED store files .refs.idx and .lock* are invisible to a read-only scan, so they are NOT tallied into OTHER. Negligible (locks are 0 bytes, .refs.idx a few KB) and the only honest option — shelling out to system du is forbidden. Documented in du.js + the test asserts the exclusion.
  • meta/index.mkd is the index-FORMAT SPEC, not a per-verb API list, and verbs register BY FILE (registry.js, no explicit list) — there is no views index file to add a du entry to, so the doc landed in wiki/View.mkd instead.
