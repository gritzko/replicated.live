BRO-014: pager w/W soft-wrap toggle + per-view default preference

Now:
DONE

The jab bro pager ALWAYS soft-wraps long lines to the viewport width (indexRows / rowEndPass at cols). Add a wrap MODE the user toggles: w flips soft-wrap ↔ no-wrap for the CURRENT view; W sets the DEFAULT wrap preference for that view TYPE, so future views of the same kind open in the chosen mode. No-wrap truncates each logical line to the viewport (a horizontal pan is a possible follow-up, not this slice). Producers are unchanged — wrap is pure presentation. jab + JS only. Method: Issues.

Input

Context

  • views/bro/pager.js rows() → indexAll → bro.indexRows(h, cols) soft-wraps every hunk into display rows at the live width; there is NO no-wrap path and no wrap key today (pager.js:289, view/bro.js indexRows / rowEndPass).
  • The help SHORTCUTS list (pager.js:26, single-sourced to views/help/help.js per BRO-007) enumerates the keys — a new key MUST be added there too or it drifts.
  • No per-view / per-session preference store exists in JS beyond env $BRO_THEME (theme.js:152, io.getenv); a wrap default needs a small pref mechanism.

Goals

  • w (current view): flip the CURRENT view soft-wrap ↔ no-wrap, re-index + repaint in place, keeping the scroll position where possible.
  • W (preference): set the DEFAULT wrap mode for the current view's TYPE (ls/log/diff/cat/…); views of that type opened later inherit it.
  • Each view MAY declare its own default wrap preference (e.g. cat/blob/diff → no-wrap, log/status → soft-wrap) — a per-type default table W overrides.
  • No-wrap = truncate each logical line to cols visible cells (the tail hidden); soft-wrap = today's behavior. Reflect both keys in SHORTCUTS (BRO-007).

Constraints

  • Presentation ONLY: no producer/hunk change; the toggle lives in the pager + the indexRows wrap path.
  • Preference SCOPE: a session-scoped per-type default map is the minimal target; cross-session persistence (a config/rc) is a follow-up — do NOT invent a config format here (only $BRO_THEME env exists today).
  • Reuse the existing indexRows/rowEndPass width logic; add a no-wrap BRANCH (row = whole logical line clamped to cols), not a parallel renderer.
  • jab + JS only; comments ≤2 lines; keep the key table single-sourced.

WIP

Design decisions

  • State: view.wrap ('soft'|'nowrap') on the Pager view; rows(cols) keys its cache on (cols, wrap) so a toggle re-indexes but a scroll does not.
  • Default: a WRAP_DEFAULT[type] table (soft unless declared); W writes the user override into a session map keyed by view type; new views read override→table.
  • View type = the view's verb/scheme (ls/log/diff/cat…), already tracked as view.verb (pager.js _verbUri).
  • No-wrap index: indexRows gains a mode flag — nowrap emits ONE display row per logical line, end = the rowEndPass clamp, remainder skipped to the 'n'.
  • Horizontal pan (see the truncated tail) is OUT of scope — note as a BRO follow-up.
