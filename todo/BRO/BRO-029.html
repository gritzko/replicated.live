BRO-029: cat path?ref prints NOTHING for a file absent from the worktree — why renders the same URI fine

Now:
DONE

Found 2026-07-17 recovering test/EXIT.c from commit ?467fb44b (the GET-048 incident, work/ABC-016): the file exists in that commit's tree but not in the checkout. jab cat 'test/EXIT.c?467fb44b' exits silently with zero output — no hunk, no error; --plain and the cat: scheme form likewise. jab why 'test/EXIT.c?467fb44b' resolves the SAME URI and renders the full content, so ref resolution and the blob are fine — the cat view drops the rev'd read somewhere. Recovery had to go through awk over jab commit diff output.

Input

Context

Repro (any repo): commit a file, delete it from the checkout (or check out a rev that lacks it), then jab cat 'path?rev' for a rev that HAS it.

  • Expected: the file content at that rev (spec GET CLI table documents file.c?feat reads as rev-scoped; cat is the read view of the same URI shape).
  • Actual: empty stdout, no error — silent-empty is the worst failure mode (scripts read it as an empty file).
  • why: with the identical URI renders content — compare views/why vs views/cat blob resolution; cat likely reads the WORKTREE path and ignores/half-applies ?ref.

Goals

cat path?ref reads the blob at the ref like why does; a missing path at that rev errs loudly (CATNOFILE-style), never silent-empty.

  • Repro test first (rev'd cat of a file absent in the checkout; assert content + a loud error for a truly-absent path).
  • Fix views/cat/cat.js resolution; keep plain worktree cat path behavior untouched.

Constraints

  • be/ JS only; resolution goes through the ONE composer/resolver (no reimplementation — resolve_hash law).

WIP

Design decisions

Root cause was a resolve_hash-law violation: cat's old readRefBytes used core/resolve.js resolveHex — a TIPS+REMOTES-ONLY twin resolver — so a historic commit hashlet resolved null, and null fell into return; → silent exit 0. why worked because it resolves via resolveHexAny. Fix routes ?ref through core/resolve_hash.js (same path as views/blob), reads via k.getObject; absent-at-rev path → loud CATNOFILE. No-ref branch untouched.
