BRO-013: address-bar TAB path-completion from displayed-hunk tokens (U/F), FS fallback, cycle

The pager address bar (:) now RETARGETS on a bareword path (URI-011b: the composer's wt-relative bareword + the isVerb probe, shared/spell.js), so verbs in ls //WHY-001 opens ls //WHY-001/verbs. But a PARTIAL word (ve) is still ambiguous verb-vs-path and the user must type the whole path by hand. Add Tab completion in command mode: complete the word being typed from the CURRENT view's hunk tokens — the hidden U nav URIs (universal, single-sourced via navlib.navLink, wt-relative) and the visible F filenames (listing views) already carry every on-screen path, so NO new token is needed (the "token for paths" is the existing U/F). Many matches CYCLE on repeated Tab; the inserted token is WT-RELATIVE with a trailing / for a directory, so it is URI-shaping (dodges the verb-peel) and compose routes it to arg 0. No hunk match → fall back to the FILESYSTEM under the view's context (//-authority wt root + path dir), stat-guessing dir-vs-file. JS (jab) pager only. Method: Issues.

Input

Context

  • URI-011b just landed: compose/shapeArg0/mergeUri treat a leading bareword as a WT-RELATIVE path and an isVerb probe stops a non-verb word (verbs) from being peeled as a verb. Completion is the missing input aid — a partial ve can't yet disambiguate to a path.
  • Hunk tokens ALREADY carry every path: U (hidden nav URI, wt-relative, single-sourced navlib.navLink) in status/ls/log/tree/cat/diff; F (visible filename) in ls/tree/bro-dir (views/ls/ls.js:64, views/tree/tree.js:64, view/bro.js:532). The pager already walks them: _uriAt/_lineUri.
  • The address-bar edit buffer is this.cmd, driven char-by-char in _keyCommand (views/bro/pager.js); Tab (0x09) is unhandled today — it falls through and is ignored.
  • dir-vs-file is knowable WITHOUT a stat for hunk candidates: an F name followed by a P slash is a dir; a U scheme of ls:/tree: is a dir, cat:/blob: a file. For the FS fallback, io.stat().kind.

Goals

  • Tab in command mode completes the LAST whitespace-delimited word of this.cmd against the current view's hunk paths: a unique match replaces the word, a shared prefix extends it, ambiguity CYCLES on repeated Tab.
  • The inserted token is WT-RELATIVE (the hunk paths already are) with a trailing / for a directory, so it is URI-shaping — compose routes it to arg 0 and the verb-peel can't grab it.
  • No hunk candidate → readdir the view's context dir (its // wt root + path dir) and complete from the FS, stat-appending / for a dir.

Constraints

  • Reuse the existing tok32 U/F walk (_uriAt/_lineUri style) — NO new tag, NO new hunk field. The "some token for paths" the user asked about IS the existing U/F.
  • Never hand-compose or regex-parse a URI: resolve the context dir via be/core/discover.js + the URI class (URI-011, work Things-NOT-TO-DO).
  • Completion is WT-RELATIVE by default (matches URI-011b); a ./-led stem completes context-relative.
  • Repro-first, headless driver test (feed keys, assert this.cmd); no other tests edited without leave (Issues).

WIP

Design decisions

  • Candidate source order: (1) current-view hunk tokens — U decoded path + F visible name; (2) FS readdir of the context dir. On-screen first (what the user sees), FS as the miss fallback.
  • Cycle state on the Pager: {stem, cands, idx, atCmd} — set on the first Tab of a stem, advanced on repeat, RESET by any non-Tab key in _keyCommand (editing restarts completion).
  • dir-vs-file: from a hunk, F+P or a ls:/tree: U scheme = dir, else file; from the FS, io.stat().kind. A dir gets a trailing / (an unambiguous path token + a "descend" affordance).
  • Word boundary: complete the last space-split token of this.cmd; a leading verb word (cat te) stays, only the tail completes.
