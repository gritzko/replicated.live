BRO-008: status bar drops the scheme for listing/query views (ls:be → be/#L1); keep it (C + jab parity)

Now
DONE

The bro status bar renders a fragment-less ("cat-style") hunk URI as <path>#L<line>, DROPPING the scheme: jab ls:be shows be/#L1 (ambiguous — reads like a bare file path) when it should show ls:be/#L1. Same for tree:/status:/grep:/refs:/log:. Both impls AGREE today (verified) — so this is NOT a jab bug but a shared status-bar convention change: keep the scheme for listing/query views so the status URI is unambiguous and re-typeable. RULING (user 2026-06-26): change BOTH C bro and jab, kept at parity. Method: Issues.

Input

Context

  • jab: be/view/bro.js:150 statusURI(hunk,line): const u = uri._parse(hunk.uri); if (!u.path) return hunk.uri; return u.path + "#L" + line; → for ls:be/ (u.path=be/) returns be/#L1, scheme gone.
  • C: bro/BRO.c:1717 BROStatusURI: if (!bro_uri_is_line_or_empty(ch)) { …verbatim… } else BROHunkLoc(&loc,ch); … snprintf(out,"%s#L%u",loc.path,center). bro_uri_is_line_or_empty (BRO.c:1646): empty fragment → YES (line-or-empty). BROHunkLoc (BRO.h:50): loc.path = the parsed URI path (be/ for ls:be/). So ls:be/ (no fragment) → line-or-empty → loc.path#L<center> = be/#L1. Scheme dropped, EXACTLY like jab — they're already at parity on the (undesirable) behavior.
  • The cat-style path#L<n> form is RIGHT for file-content views (cat/diff/blob): an editor-like file:line. It's WRONG for listing/query views (ls/lsr/tree/status/grep/ regex/spot/log/refs) where the scheme IS the resource and the path alone is ambiguous / not re-typeable.

Goals

  • The status bar keeps the scheme for listing/query view URIs: ls:be/#L1, tree:<p>#L<n>, status:#L<n>, grep:#<w>…, refs:…, log:….
  • File-content views (cat/diff/blob) keep the bare <path>#L<line> cat-style form (NO regression — be diff:/cat: status unchanged).
  • C bro (BROStatusURI) and jab (statusURI) stay BYTE-IDENTICAL — fix BOTH.

Constraints

  • Pick ONE discriminator and apply it identically in C + jab. Candidate: a small "keep-scheme" scheme set (ls/lsr/tree/status/grep/regex/spot/log/refs) vs the cat-style set (cat/diff/blob); single-source the set per impl. (Alt: a hunk property rather than a scheme list — decide what stays parity-clean + readable.)
  • Snippet URIs (#'sym', #abc1234) already render verbatim in C — keep that arm.
  • Repro-first (CLAUDE §17): assert the status string per view, C and jab matching.

WIP

Design decisions

  • (decided) discriminator = explicit keep-scheme scheme-set, single-sourced next to BROStatusURI/statusURI (C BRO_KEEP_SCHEME/bro_uri_keep_scheme; jab Set), each with a comment cross-referencing the other side. Easy to keep at byte parity.
  • (decided) form = <scheme>:<path>#L<line> (keep #L), per ls:be/#L1. cat/diff/blob stay bare <path>#L<line>.
