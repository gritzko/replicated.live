The plan: bee (///bee) merges into Beagle, and Beagle splits into two floors — floor 1 is revision control proper (store, refs, wire, worktrees, stage), floor 2 is a mini Gerrit/GitHub for agents (index, views, diffs, permalinks, tickets, boards, CI) that does not care whose objects it indexes: git, jj or be. The split already exists de facto: bee IS floor 2 over git's ODB, its whole backend surface being five git.* bindings in index/ (open/tree/parseCommit/getTreeDiff/getHex) plus refs and worktree discovery; Beagle has the same floor-2 pieces in shared/ (dag, weave, quad, ticket, cache — bee's index/weave.js is a port) fused to its own floor 1 (store.js pack-log + ULOG, wire, relate, stage, checkout). Goal: name the floor-1 interface, pick ONE implementation per shared piece, and make floor 2 degrade by backend capability instead of demanding git's full set.

Input

Context

  • bee: 14 k lines, .git/be/ wh128+kv index keyed by sha hashlets (LITE-006, INDEXES.mkd), worktrees found by the $SRC_ROOT/<name>-<TKT> naming rule (BEE-027), registry ~/.config/bee/repos (BEE-001).
  • be: 32 k lines, own store over git.pack/abc.index/ULOG, .be dirs, wtlog tree-of-life, get/post/patch/put/delete verbs, graf ahead/behind cache, wire push/pull.
  • Both run on jab/quickjab with the same abc/dog bindings and the same CFOLD weave; no file is shared by identity, the duplicated set is dag/weave/quad/ticket/cache/dag-cache.
  • bee's README concedes git's worktree/submodule model does not reproduce Beagle's worktree flows — floor 2 can not assume every backend has every verb.
  • jj with the git backend yields the same object shas, but heads are bookmarks + anonymous heads, change IDs are extra identity, and conflicts are first-class tree content — none of it is a "ref tip" in the git sense.

Goals

  • A written floor-1 contract, one page in the wiki, that floor 2 codes against: objects (commit/tree/blob by sha), heads (not refs: a named-or-anonymous tip set), worktrees (a working copy + its base commit), stage (OPTIONAL), conflicts (how a backend spells them).
  • Three backends behind that contract: git ODB (bee's bindings), be store (shared/store.js), jj-over-git (objects via git, heads via jj's bookmark/op-log spelling); each declares its capability set.
  • ONE implementation of each duplicated floor-2 piece (dag, weave, quad, ticket, cache, the index); the other deleted, with its tests carried over, not dropped.
  • bee's views (cat/blob/tree/list/log/diff/cite/see/todo/quad) and Beagle's (bro/work/ticket/ci/why/spot) converge into one view set; byte-identical output for whichever one is kept per verb, the suites of both repos green.
  • Quad columns that a backend lacks (stage) render as absent, never as .; a verb a backend lacks says so in one line, never throws a stack.

Constraints

  • Incremental: every landing keeps be AND bee binaries building from the one tree; no big-bang rewrite.
  • The index stays derived and keyed by sha hashlets — no backend may require names in the index; jj change IDs and be ULOG stamps go in as extra record kinds, not as key replacements.
  • The floor-1 contract is ~10 functions; anything a single backend needs beyond that lives in that backend's capability flag, not in the contract.
  • Readability budget: the kept implementation is the one with keyed O(1) reads and capped walks (BEE-005); richness (graf counts, relate) is re-attached over it, not the other way round.
  • No shipping C edited for this; a binding a backend needs and lacks becomes a jab/quickjab ticket linked from here.

WIP

Design decisions

  • Pending: which index is the keeper — bee's .git/be/*.lite2.idx (hashlet keys, nine record kinds) or be's memidx/metaidx/graf family; the first is leaner, the second already carries ahead/behind counts.
  • Pending: the worktree model — naming rule vs .be + wtlog; the contract exposes "working copies of this project, each with a base", both spellings satisfy it.
