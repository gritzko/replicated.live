Ruling (gritzko, 2026-08-04): the io.mmap(p,"r").data().slice() copy is cargo cult — view or copy, release is GC-driven either way, so the memcpy buys nothing (ABC-023 Context). With ABC-023 landed the fd closes at map time, so holding the raw .data() view costs mapped pages only. Drop the copy at the RO mmap call-sites and hand the view onward, zero-copy.

Input

Context

  • Known sites: diff.js:520 readWtFile, why.js:32 — the exact io.mmap(path, "r").data().slice() shape; sweep for others.
  • gitmodules.js:20 / ignore.js:188 already pass the raw view into utf8.Decode — the pattern to converge on.
  • Scratch-buffer slices (io.buf + readAll + slice) are a DIFFERENT thing — they trim oversized scratch; keeping the scratch alive via a subarray is a real cost. NOT in scope.

Goals

  • RO mmap call-sites return the raw .data() view; bytes flow to consumers unchanged, no copy, no behavior change.
  • Full suite green; diff/why goldens byte-identical.

Constraints

  • A PROT_READ view is write-protected: verify no consumer MUTATES the returned bytes — a site whose caller writes into them keeps its copy, with a 1-line comment saying why.
  • A view is live, not a snapshot: a site that reads the same file twice expecting a stable before-image keeps its copy.
  • Only "r" mmap sites; io.buf/io.ram slices and all test/ files stay untouched.

WIP

Design decisions

Sweep verdict — the ONLY non-test io.mmap(p,"r") + copy sites in be/ are the two known ones (jsrc/ is a symlink to ., its hits are the same files). Per-site audit:

  • diff.js:520 readWtFile — DROPPED the copy. Consumers of the wt bytes: frameSha (feeds a fresh io.buf), isBinary/bytesEq (index reads), weave.fold → CFOLD (copies the source into its own ram buffer). No writer, and no caller re-reads the path — one read per file, consumed before the next.
  • why.js:32 readWtFile — DROPPED. Same shape: wtBytes go to weave.fold / weave.foldWt (bytesEq + CFOLD fold), read-only.
  • ingest.js:165/564, ignore.js:188, gitmodules.js:20, mark.js:19, rss.js:18, view/bro.js:615 — already raw .data()/subarray, no copy to drop.
  • ulog.js:237 abc.mmap("ULOG",path,"r").slice() — KEPT, and out of scope anyway (ULOG binding, not io.mmap): it is the textbook SNAPSHOT case — abc.book on the next line TRUNCATES the same file, so the survivors must already be off the map. Left untouched (no comment added: the existing _book header already says "abc.book truncates on open, so snapshot first").
  • git.pack.mmap (store.js:191, ingest.js:341/476, log.js:131) and io._mmap "rw" (ingest.js:397) — different bindings/modes, no byte copy; untouched.
  • io.buf/io.ram + readAll + slice scratch trims: out of scope per the ruling, none touched.
