Context

In work/ABC-006 the pager's ticket-key click composes cat:///todo/ABC/ABC-006.mkd and answers no hunks: — the file exists in the meta tree.

  • shared/ticket.js ticketUri() composes the link from the todoRoot HIT root (the meta) via navCwd(root) → the bare // (BE-031: the meta has no //name).
  • core/discover.js resolve() maps host "" → launchTop() (BE-037); topWt() treats a hive cell as its OWN top (the BE-031 hive boundary), so a cell launch resolves ///todo/… INTO the cell, where todo/ is absent.
  • navCwd() and resolve() thus DISAGREE on what // names exactly when jab runs inside a cell; navCwd never names a cell // (a cell always gets //<name>).
  • Repro: cd work/ABC-006 && jab cat '///todo/ABC/ABC-006.mkd' --plain → empty; the same spell from the meta root prints the page.

Goals

  • the bare // means ONE tree everywhere: the tree navCwd names // — the hive's meta (srcRoot()'s parent) when it anchors, else the launch top (plain wt, BE-037 behavior kept).
  • ticket links clicked inside any cell open the meta's todo/ page.

Constraints

  • fix in resolve()/wtdir() (the one chokepoint), not per-view; minimal diff, end-to-end verify (work).
  • flat-legacy $SRC_ROOT hives (no meta wt above the hive) keep the launchTop() fallback.
