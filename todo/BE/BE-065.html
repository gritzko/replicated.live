Profiled 2026-08-11 under a real pty (JAB-036 re-measure): path/URI resolve is the pager first frame's DOMINANT term — 39.7% of quickjab CPU, 36.7% of its engine allocations; jab pays the same work JITed. core/discover.js wtpath() caches the context STRING per wt (_wtCtx) but re-runs uri._parse(ctx) + the full resolve_hash.resolve() on EVERY call: 203,535 uri._parse calls in one tty todo vs 2 piped. Goal: memoize per wt, cut the crawl's path math to plain string work, byte-identical output on both engines.

Input

Context

Numbers from the JAB-036 "Perf re-measure 2026-08-11" tables (python pty harness, first frame, journal tree, medians of 5; gritzko's shell confirms: quickjab 6.19 s vs jab 3.07 s wall).

  • jab (JSC) 2.95 s / quickjab (-O0) 5.97 s first frame; either PIPED 0.13 s — the whole cost is the tty pager path arming the repo cache over the crawl.
  • wtpath() warm micro, 200k iters: 2.85 us jab / 5.88 us quickjab — MORE than the io.lstat it precedes (2.30 / 2.44 us); pathlib.wtJoin alone is 0.14 / 2.98 us.
  • discover.js:248 uri._parse(ctx) runs per call even on a _wtCtx HIT; then resolve() (resolve_hash) re-walks split/resolveInTree/safeRel per call, ~2 parses per stat'd file.
  • Second term: isFullSha (shared/util/sha.js) reads s[i] 40 times — one JS string PER CHARACTER, 11.2% of ALL engine allocations; the STATUS-020 glob bug verbatim, cure is charCodeAt.
  • util/path.js split() allocates p.split("/") + a segs array per call; safeRel() same split cost though it is a pure predicate; wtJoin → resolveInTree → split on every miss path.
  • Engine allocator traffic 34.5 M ops post-STATUS-020; path math owns most of the remainder. sha1dc re-hash (~0.7 s, engine-independent, 23% of jab's frame) is OUT of scope — its own ticket once path math lands.
  • No ticket owned this: CODE-028 fixed the require() half only (DONE); STATUS-019/TODO-006 cache RE-renders, not the cold first frame; BE-037/BE-064 unrelated.

Goals

  • A _wtCtx hit costs NO uri._parse and NO resolve_hash walk: memoize the PARSED context and the resolved base dir per wt; the hot path is a confined base+rel join.
  • isFullSha via charCodeAt, zero per-char allocations; safeRel/split hot callers scan by index, no throwaway arrays on the crawl path.
  • Output BYTE-IDENTICAL (todo, status, diff, piped and pty) on BOTH engines; be suite and jab suite green, no test edits.
  • Before/after first-frame table (jab + quickjab, pty medians) recorded here; uri._parse count per tty todo back to O(worktrees), not O(files).

Constraints

  • resolve_hash.js stays THE resolver (BE-030/URI-016): memoize its RESULTS keyed per wt — never a second resolution implementation. A rel containing ./../empty segments falls back to the full resolve() path.
  • NAVESCAPE confinement EXACT: the wt-boundary guard in wtpath() keeps refusing climbs byte-for-byte as today; safeRel keeps its reserved-name policy (.git/.be/..be.idx).
  • Cache lifetime = per-process, same as today's _wtCtx; no new invalidation machinery.
  • Fix lives in be/ (core/discover.js, shared/util/path.js, shared/util/sha.js); no engine or C changes.

WIP

Design decisions

  • wtpath memo per wt: {parsedCtx, baseDir} where baseDir = resolve(parsedCtx, "") — computed ONCE via resolve_hash, so resolution authority is unchanged; the per-call work is baseDir + "/" + rel plus the existing prefix guard, with the dotted-rel fallback re-entering resolve().
  • isFullSha: charCodeAt(i) range checks (48-57, 97-102), no string indexing.
  • split()/safeRel(): index scans (indexOf('/')) — safeRel allocates nothing; split keeps its return contract for callers that need the array.

Re-measure 2026-08-11

Same pty harness (ptyrun.py, first byte to the tty), journal tree, todo, 10 runs per leg, median. ONE cwd (work/BE-065) throughout, the three files SWAPPED in place between legs — jab <other>/main.js does NOT load another tree's be (require resolves core/* off the cwd's jsrc/), so a two-clone A/B is a NULL experiment and the swap is the only honest one. Binaries: /bin/jab (JSC) + /bin/quickjab (-O0), both non-ASAN, identical to jab/build/bin + quickjab/build/bin.

| leg | jab first frame | quickjab first frame | |------------------|-----------------|----------------------| | before | 2.70 s | 5.65 s | | after | 2.29 s | 4.98 s | | delta | -15.2% | -11.9% |

  • uri._parse per ONE pty todo: 206,635 -> 2,481 (-98.8%); piped stays 2. O(worktrees+views), no longer ~2 per stat'd file.
  • wtpath calls in that same run: 102,077 — ALL on the memoised base+rel fast path (fallback 0, wtJoin-confine 0). Counter behind an env guard, removed before staging.

Blockers and bummers

  • jab's own C suite NOT run: this is a be/ JS-only change and running it would mean building in the main tree. be suite green covers the JS.
  • The gain is smaller than the profile's 39.7% "path/URI resolve" share: that phase also carries the wtJoin/join calls left on the resolve-free path plus the io.lstat frames under them. sha1dc re-hash (~0.7 s, engine-independent) is untouched and is now jab's top term, as JAB-036 predicted.

Outcome

Staged (put only, NO post) in //BE-065, base ///be/#d28f7b9e: core/discover.js (+41/-9), shared/util/path.js (+26/-7), shared/util/sha.js (+7/-5).

  • _wtCtx[wt] now holds { c, base } — the PARSED context and resolve(c, ""), kept only when it reproduces wt. resolve_hash stays THE resolver: it computes base ONCE per wt, and every rel it can not prove plain re-enters resolve().
  • _plainRel(rel): relative, no ""/"."/".." segment, no ":" (the only way _relPath could read a scheme). Everything else — .., a/, /abs, x:y, //other — falls back, so the NAVESCAPE throws are the SAME throws on the SAME inputs.
  • isFullSha/isZeroSha on charCodeAt; safeRel is an index scan that allocates nothing (only a .-leading segment is sliced); split scans by index and keeps its array contract.
  • Design deviation, one: isZeroSha got the same charCodeAt cure as isFullSha — same file, same per-char string allocation, 1 line. Both now demand typeof s === "string" where they said !s (no caller passes anything else).
