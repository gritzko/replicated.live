BE-009: be submodule absent from be status (no gitlink row, no recursion)

Now: DONE

be is registered in journal/.gitmodules (path = be, the beagle-ext JS impl), yet bare be / be status from the journal root shows NEITHER a put be gitlink row NOR a status:be recursion block — while its NESTED sub be/test IS listed (status:be/test … 101 ok). So the whole be/ subtree's own changes are invisible to status and unreachable by be post. Compounded by STATUS-003: cd be && be status → SNOROOM/BEDOGEXIT, so be/ can't be statused standalone either. Method: Issues.

Input

Context

  • journal/.gitmodules: [submodule "be"] path = be url = …/beagle-ext.git (alongside html and beagle, which DO appear).
  • Bare be (journal root) recursion lists: status:html, status:be/test, status:beagle, status:beagle/abc — and a parent 23:08 put beagle gitlink row — but NO status:be and NO put be row. be/test (a deeper mount, ?/beagle-ext-tests/.beagle-ext/.journal) is reached; its parent be/ is not.
  • be/.be is a 34 KB .be-FILE mount (store-backed worktree); be/test/.be a 2.8 KB file. The discovery enumerates the nested mount but skips the be/ mount.
  • cd be && /…/be status → Error: SNOROOM / Error: BEDOGEXIT (no ok count) — be/'s own status overflows the STATUS-003 aggregate buffer, so even if it were discovered the recursion would abort.
  • IMPACT: the be/ code-review fixes (JS-065..091, all under be/shared, be/views, be/core, be/verbs) are NOT shown by be status and cannot be committed via be post from the journal root.

Goals

  • Bare be / be status discovers the be submodule: a put be gitlink row when its tip moved, and a status:be recursion block (like beagle/html).
  • Determine whether be/ is skipped by a discovery bug (nested-mount shadows its parent) OR purely because its status SNOROOMs (STATUS-003) and is dropped.

Constraints

  • Native BE/sniff submodule discovery + the .be-file mount walk; do not regress html/beagle discovery or the be/test nested-mount handling.

WIP

Design decisions

  • First fix STATUS-003 (the SNOROOM), then re-check: if status:be then appears, BE-009 was a swallowed-SNOROOM drop; if still absent, it is a real discovery gap (a sub whose own nested mount is enumerated but the parent mount is not).

TODOs

  • Repro-first: a fixture parent + a .be-file submodule that itself contains a nested mount; assert bare be emits a status:<sub> block + gitlink row for the OUTER sub, not only the nested one.
  • Trace the submodule-discovery walk (.gitmodules + .be-file mounts); fix the skip; verify be/ appears after STATUS-003.

Blockers and bummers

  • ← STATUS-003: be/ status SNOROOMs, so BE-009 can't be fully verified until the buffer overflow is fixed (the two are entangled).

Outcome

  • FIXED-BY-DEPENDENCY (no native change): with STATUS-003 landed, bare be over the journal tree now emits status:be (verified, between html and be/test). Discovery was never broken — the be/ mount IS enumerated; the status:be block was produced then dropped when the relay child SNOROOMed. Residual (out of scope, separate SUBS work): a FLAT be status row for a clean-gitlink sub with UNCOMMITTED edits needs SUBS_DIRTY_EDITED (a sub-wt content scan) — would change the test-#201 flat-vs-recursing contract.
