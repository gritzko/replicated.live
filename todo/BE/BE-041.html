BE-041: [put] buttons on status rows — pager-visible O spells

Now
OPEN
Sev
MED

Status rows name the actionable states (unk, mod, new) but acting on one still means typing put <path>. Wanted: a visible [put] button on those rows in the PAGER, clicking it runs the hidden O put <path> spell (Nav); plain/CLI output stays byte-identical (buttons are pager-only chrome). Twin of the [done] button round in BE-040; requested by gritzko 2026-07-10.

Input

Context

  • O click-targets are verb args spells followed token-precisely by _uriAt (views/bro/pager.js); the row's existing hidden U nav (diff:/cat:, BRO-006/DIS-057) keeps handling clicks on the filename — _lineUri's lone-U fallback counts only U tags, so a stray row-click can never fire the button.
  • test/status/links asserts PLAIN output byte-identical to the retired native be status --plain — a visible [put] in plain would break it, so the button label must render in the pager ONLY (a hidden-in-plain, painted-in-pager tag pair, the U/O hiding precedent).
  • Put/delete args stay RAW wt-relative and the pager never pre-merges — the O spell carries put <wt-relative-path> verbatim, the verb resolves (BE-039 ruling, BE-030).
  • Refresh UX v1 (the click pushes put's confirmation view, BACK refreshes) is SUPERSEDED — gritzko 2026-07-10 ruling: a button click shows NO result screen, the current view refreshes in place (BRO-015-kin, scoped to button O spells).
  • Round 2 ruling (gritzko 2026-07-10): already-staged rows (put, new) carry NO button (re-stage is a no-op); mod/unk keep [put]; mis gains [del] (the delete verb unstages the gone file).

Goals

  • In the pager, unk/mod file rows show a [put] button, mis rows a [del] button (verb palette colors); put/new/ok rows show none; a left-click runs the spell and the row re-buckets.
  • A button click pushes NO result view: the mutation runs, then the CURRENT view re-renders in place (scroll kept); view-spell clicks (filename nav, WHY origin) keep the push-nav.
  • Plain and TLV-to-CLI output are UNCHANGED — test/status/links native-parity stays green untouched.
  • Clicks elsewhere on the row keep their current meaning: filename → diff:/cat: nav, row fallback unchanged.
  • Keyboard parity is free: the same put <path> spell stays typable in the address bar.

Constraints

  • No existing test edited; new cases live in test/status/buttons/ (fixture wt, the test/status/links runner pattern).
  • Repro-first: red asserts the button token pair (visible label + O spell) in the TLV stream and its ABSENCE in plain; suite stays at baseline.
  • Rendering via the existing hunk/token machinery — a tag the plain serializer skips and the pager paints; no new renderer.
  • If pager-only visibility proves impossible without touching the shared serializer contract, STOP and report for a ruling — do not relax the parity test.

WIP

Design decisions

  • As built (wt work/BE-041): NO pager/serializer change — pure views/status/status.js emission riding the WHY-001 machinery; button row layout path U:nav " " Y:"[put]" O:"put <path>" S:"\n" — the U stays byte-adjacent to the path (token-precise filename click), the Y label paints in the put theme slot, _uriAt follows the O verbatim (no # prefix).
  • Plain stays byte-identical because --plain/piped takes the columnar path that never renders the button tokens; O toks route the hunk through the existing why paint passes (U+O hidden, label painted). Side effect: --color | cat shows the same [put] chrome + padded banner band — no test asserts color bytes.
  • The O arg is "put " + navPath RAW — deliberately not navLink (it injects //authority; the BE-039 law).
  • This layout is the house button scheme: BE-040's [done] round reuses it verbatim.
  • Round 2: act is {label, tag, spell} — ACT_PUT={unk,mod} → [put]/'Y' (blue), ACT_DEL={mis} → [del]/'X' (del brown, the delete verb); the label paints in its verb's palette slot.
  • Click gate: loop._isMutation(w) = registry.verbFile(w, _, ["verbs"]) (the verbs/-tree probe, views/ excluded); pager _mouse routes a mutation O spell to _actSpell (drive, drop hunks, _refresh in place, no back-stack push) — WHY's commit ?sha O spell stays push-nav (a views/ verb).
