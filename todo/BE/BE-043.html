Context

The project root's work/ dir holds one worktree per ticket (Project item 5); no view lists them today, so tending the fleet means raw ls work/ plus hand-typed spells.

  • A worktree's ORIGIN rides its .be FIRST line: <stamp> get <uri>, e.g. work/BE-041/.be → file:/home/gritzko/.be/?/beagle-ext, work/JS-115/.be → file:/home/gritzko/src/jab.be/.be/?/repo.
  • //TIKT-123 is the worktree authority in context URIs (Project §Addressing).
  • Models: BE-038 todo board (shape-routed rows, hidden U spells), BE-040 r3 / BE-041 button pairs (visible Y label + hidden O click spell), views/status/status.js sinkOut.

Goals

work lists all ticket worktrees under work/, one row each:

  • the key TIKT-123 navigates — hidden U spell status //TIKT-123;
  • [update] button — get-update from the orig tree (O spell; origin = .be line 1);
  • [merge] button — merge into the orig tree as mounted under the current project (origin detected from the worktree's .be line 1);
  • [diff] link — the worktree diff (diff //TIKT-123);
  • a SAFETY GAP, then [rm -rf] — discard the worktree; needs a worktree-only remove verb, see BE-044.

Constraints

  • Work-root discovery mirrors be.todoRoot(): the project root owning work/; NOTHING hardcoded.
  • No absolute fs path ever reaches a token — word spells only (the BE-038 rule).
  • .be line 1 parses via uri._parse, never regex/string surgery (work §NOT TO DO).
