BE-052: todo view — severity bullets on ticket rows; wt-backed rows swap the bullet for a fat-arrow status button

Now:
OPEN

Ordered by gritzko 2026-07-19. The BE-038 todo board lists ticket rows with no severity marker; add a leading bullet (small circle) colored by the ticket's severity: CRIT red, HIGH orange, MED yellow, LOW green. When a worktree named for the ticket exists (//TKT-123 under work/), the bullet is replaced by a one-symbol BUTTON — a fat right-pointing arrow, same severity color — that navigates to status //TKT-123, so a ticket with live work is one click from its tree.

Input

Context

  • Ticket severity is in the header status mark (todo): [HIGH]/[MED]/[LOW] open with severity, [OPEN] generic; the board (be/views/todo/todo.js) already reads page titles/headers for its rows.
  • Wt existence is discoverable the WORK-001 way: readdir of work/ with the .be-file gate; the wt key matches the ticket code.
  • Row click-targets are hidden U/O spells (BE-038 design); a colored one-symbol button is the same token machinery as the work-view buttons (WORK-004).

Goals

  • Each ticket row leads with a small-circle bullet colored by severity: CRIT red, HIGH orange, MED yellow, LOW green.
  • If a //TKT-123 worktree exists, the row leads with a fat right-pointing arrow button INSTEAD of the bullet (RULING, chat 2026-07-19: fat arrow), same severity coloring; click mints status //TKT-123.
  • Plain (piped) output stays chrome-free as elsewhere (BE-051 delivery pattern).

Constraints

  • Colors in the THEME idiom (view/bro.js) — 256-color shades near the WORK-004 picks, no raw hardcoded SGR in the view.
  • Wt detection reuses the work-view discovery seam — no second readdir/classifier; ticket-key matching via the shared ticket lookup, no new parsing.
  • Composes with BE-051's row-leading fade token; test via the todo-view fixture + a pty click through the real UI path.
