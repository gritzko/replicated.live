Local one-keystroke CI: the pager's v button detects the project's conventional build+test entry point ("default stuff": ./ci.sh, ./scripts/ci.sh, cmake+ninja+ctest, ./configure && make && make test, and the per-language equivalents), runs it as a detached background job in the worktree, and puts the verdict into the per-repo cache. Separate from the qemu runner fleet (CI-001/CI-003) — this is the local leg; the fleet can later reuse the same detector script inside its VMs.

Input

Context

  • CI-001 covers remote per-commit runners; nothing runs the build/tests locally from the pager today — the user shells out by hand.
  • Cache model updated by STATUS-019: the shared cache is now a per-dir REV TREE storing no values — the CI verdict is a CONSUMER memo keyed by the rev(wtDir) it ran at, so the first edit after the run stales it automatically, same property as the old bucket drop.
  • RULING gritzko 2026-08-04: ci MUST BE A VIEW — a views/-tree read-only verb like status/log/todo (Views is the open category; only the mutation basis is closed). The ∞ click mints the normal view spell, the pager pushes the ci view like any other: it starts or attaches to the run and renders the log tail (TODOs 7-9). The _pagerSpell reserved-word interception built on 2026-08-04 is WRONG and must be removed — no pager-local dispatch, no special case. The extension-script entry (jab ci.js) stays for the CLI and the CI-001 fleet.

Goals

  • v in the pager kicks off the detected default build+test for the current worktree as a background job; the pager stays interactive.
  • Ruling gritzko 2026-08-04: the TODO BOARD grows a CI BUTTON per wt-having row — face [ ∞] (2-cell, frame conventions of TODO-005), tone #5883a7 (a new view/theme.js BTN slot; the ci name is taken by the commit ✓ — pick a fresh name, e.g. run).
  • Placement, gritzko's lean: the ∞ goes at the END of the FILE panel (where the ✓ sits today) and the post ✓ MOVES to the END of the COMMIT panel — staging surface ends in "test it", history surface ends in "commit it"; frame widths shift 16/10 → 16/13.
  • The button's click runs the CI-004 runner on the row's wt; while a job runs the face reads in-progress, and the landed verdict tints the button green/red off the consumer memo until rev(wtDir) moves.
  • Ruling gritzko 2026-08-04: starting a run must SHOW the output, not just the badge — a CI LOG VIEW over the run's log file: render the LAST 4 KB, positioned at the END; r refreshes (re-reads the file, stays at the end while the job appends). The log already lands in a file, so the view is a tail over it, no second capture path.
  • On exit the result — green/red, exit code, log path — lands in the per-repo cache so status/pager surface it until the tree changes.
  • Detection ladder, first hit in the worktree root wins:
    1. ./ci.sh
    2. ./scripts/ci.sh
    3. CMakeLists.txt → cmake + ninja + ctest -j16
    4. ./configure && make && make test
    5. Makefile → make && make test
    6. Cargo.toml → cargo test; go.mod → go test ./...; package.json → npm test; pyproject.toml/setup.py → pytest

Constraints

  • stdout+stderr captured to a log file; the cache row carries the log path, never the log body.
  • No hand-rolled URI/path composition; resolution via the standard library (resolve_hash.js), paths via the worktree root only.
  • The runner is arg-blind like any pager action: it acts on the current context worktree, no per-invocation configuration.

WIP

Design decisions

  • One shared detector script (extension), so the CI-001 fleet runs the exact same "default stuff" inside its VMs later — no fleet-only logic.
  • Result is cache-resident only: a stale verdict silently disappears with its bucket; no persisted CI history on this leg (that is the fleet's job).
