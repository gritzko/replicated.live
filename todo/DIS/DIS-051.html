DIS-051: no clock-override for deterministic commit identity

Now
DONE

A commit's author/committer time derives from the post row's ron60 stamp via local-tz mktime (sniff/POST.c commit body + sniff/AT.c:688), and the stamp comes from the wall clock (SNIFFAtNow/RONNow). So two independent posts of the SAME tree produce DIFFERENT commit shas unless pinned to the same wall-clock second — there is no SOURCE_DATE_EPOCH-style override. Surfaced porting JS-051, whose sha-parity tests need a future-seed clamp hack to force both tools onto one second.

Input

Context

  • JS-051 be post parity can only assert byte-identical commit shas by seeding a near-future post row so native + JS both clamp to tail+1 (same second); without it the author/committer epoch differs → different shas for one tree.
  • Root: RONNow/SNIFFAtNow read the wall clock with no test/CI override; the commit ts is local-tz mktime of that ron60 (DST/tz also enter the epoch).

Goals

  • Add a deterministic clock source: a SOURCE_DATE_EPOCH-style env honored by RONNow/SNIFFAtNow (or a test-only clock hook), so a given tree+message+parent yields a stable commit sha across machines/times.

Constraints

  • Must not perturb normal interactive timestamps; opt-in via env. Keep ron60's 2000–2099 ms domain; document tz handling (commit epoch should be tz-stable).
