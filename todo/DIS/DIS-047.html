Now
DONE

GRAFMergeWtFile / WEAVEMerge is very slow merging a large file (beagle/BE.cli.c, ~5k lines) during be get. Surfaced updating the JS-027 worktree. Method: Issues.

Input

Context

  • be get onto trunk 371ad14b weave-merged beagle/BE.cli.c (both sides edited it: SUBS-027b be-head + the JS-025 hook) — "merge of BE.cli.c was veeerey slow" (user, direct observation).
  • BE.cli.c is ~5000 lines; the single-file merge took noticeably long.
  • Path: GRAFMergeWtFileTunable (graf/GET.c:301) → WEAVEMerge / GRAFMerge3Bytes / WEAVENext (dog/WEAVE). Suspect superlinear token scan or repeated whole-blob rewrites per WEAVENext (the blob is rewritten whole — see dog/WEAVE.h "rewrite the whole blob").

Constraints
