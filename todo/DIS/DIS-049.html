DIS-049: be get file:<repo>?/<project> clones the whole repo, not just the project

Now
DONE

The ?/<project> selector should clone ONLY that project shard, but be get clones the ENTIRE multi-project repo (all top-level files + every submodule), and the named project arrives at the parent's stale gitlink pin instead of its own tip. Found creating worktrees for the DIS fix-and-land loop. Method: Issues.

Input

Context

  • Repro: be get file:/home/gritzko/beagle-journal?/beagle into an empty dir produced the WHOLE journal — CNAME wiki/ html/ blog/ todo/ meta/ assets/ + beagle/ (the codebase as a SUBMODULE) + beagle/abc — not just the beagle project. (new wiki/Worktree.mkd, get html?0f72708f, get beagle?5b11dad9, get beagle/abc?….)
  • Worse, the beagle subtree came in at the journal's GITLINK PIN 5b11dad9 (an old JS-024 commit), NOT the beagle project's own trunk tip 125d5c8f — so you get stale code wrapped in the whole journal, no single-project worktree.
  • Intended: ?/<project> selects ONE shard; the clone is that project at its own tip, rooted at the worktree (no journal wrapper, no submodule indirection).

This MUST work (clone the beagle project to a worktree at its tip). Same no-baseline family as GET-029 (the source wtlog tail is a bare post); fixing baseline resolution likely fixes both.
