DIS-078: track/base are fundamentals — ONE shared wtlog routine for each, all hand-rolled last-get / last-get-post scans unified

Now:
DONE

Ordered by gritzko 2026-07-19. Two facts define a worktree: its TRACK (the recentmost get row's tracked ref, DIS-074/worktree.mkd) and its BASE (the recentmost get/post row's sha). shared/wtlog.js holds partial truth (attachedBranch(), curTip()), yet callers still hand-roll the same reverse row scans — post.js trackRow() mirrors attachedBranch because attachedBranch HIDES the row's authority. Give wtlog one track() and one base() returning the full fact (row incl. authority/uri/branch/sha/ts), and route every case through them; no last-get/last-get-post row scan may live outside shared/wtlog.js.

Input

Context

  • shared/wtlog.js today: attachedBranch() (:161, DIS-057 — "the SINGLE source of truth" for attach, but drops the row/authority), curTip() (latest get/post sha-tip), baselineTip(), refOf() (:47, the one row→ref codec).
  • verbs/post/post.js:419 trackRow() — a hand-rolled reverse scan, its own comment admitting "the row selection mirrors wtlog.attachedBranch, which hides the row's authority".
  • views/work/work.js resolveTrack (fresh WORK-007 post 82ef082f) is the newest track consumer; core/resolve_hash.js:257 takes base via curTip() (the good pattern).
  • Tail-ts scans (verbs/patch/patch.js:436, post.js:995) and get/head intakes each finger wtl.rows directly to varying degrees.

Goals

  • wtlog.track() → the recentmost get row as a full fact: { row, uri, authority, branch, sha, ts, detached } — attachedBranch()'s verdict WITH the row; attachedBranch() becomes a thin wrapper or absorbs it.
  • wtlog.base() → the recentmost get/post row's sha + ts (curTip's fact, row included) — the ONE base extractor.
  • Migrate ALL callers: post.js trackRow deleted in favor of track(); work.js resolveTrack, get/head/patch/put row scans, any view fingering wtl.rows for track/base — routed through the pair.
  • Gate: grep -rn 'rows\[' verbs views core shows no remaining last-get/last-get-post selection outside shared/wtlog.js.

Constraints

  • Behavior-preserving refactor: no verb/view output change; the full test suite stays at baseline — no test edits beyond NEW units for track()/base().
  • Row→ref decoding stays in refOf(); no second codec, no regex/string surgery on URIs; hash resolution stays in core/resolve_hash.js.
  • The store refs log scans (shared/store.js resolveRef/eachTip) are a DIFFERENT substrate — out of scope here; note overlaps, don't touch.
  • Overlaps the unlanded WORK-003 wt in post.js/work.js — build on //WORK/ tip 82ef082f, expect a weave.

WIP

Design decisions

  • track() → { row, uri, authority, branch, sha, ts, detached, uriTrack } (empty fact when no ref-bearing get row); base() → { row, branch, sha, ts, query, rawQuery, br }; attachedBranch() a thin decode over track(), curTip = base()'s alias, baselineTip the same selection widened to patch rows.
  • attachedBranch().base (STATUS-009 fragment-only baseSha) is a DISTINCT concept from base().sha — differs on legacy &-chain rows (unit leg E pins it); kept as attachedBranch's internal, not folded.
