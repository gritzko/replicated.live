DIS-079: read verbs outside a worktree exit 0 in TOTAL silence; the ones that refuse spell a raw JS exception: WTNONE

Now: OPEN

Run a read view from a directory with no .be anchor and ls, cat, grep and log print nothing at all — no stdout, no stderr, exit 0 — while status and diff refuse with JS exception: WTNONE: no .be worktree anchor from '<dir>'. Both halves are wrong: silence-plus-success is indistinguishable from "the tree is empty", and a raw ok64 code behind a JS exception: prefix is not a user-facing error (RULING: errors in plain words, never a bare C code). Found 2026-07-22 diagnosing a CI red in test/bro/universal, which ran against a git checkout (no .be) and failed all 6 assertions opaquely. Method Issues.

Input

Context

Measured in ubuntu:24.04 with the gritzko/jab release 0.0.1, in a copy of the be tree with its .be removed (the CI checkout shape):

  • jab ls, jab cat core/loop.js, jab grep JSQUE, jab log → rc=0, stdout 0 bytes, stderr 0 bytes — indistinguishable from an empty tree.
  • jab status and jab diff → rc=1, JS exception: WTNONE: no .be worktree anchor from '/nowt' — the right verdict, the wrong words.
  • The same tree WITH its .be: jab ls → rc=0 and 288 bytes of rows, so the verbs themselves are healthy.
  • Incident: be-js-bro-universal goes red on GitHub Actions with 6 FAILs (pipe-*-has-output, tty-*-entered-pager) and every *-exit0 ok — the empty-and-successful shape, misread for months as a pager flake.

Goals

  • A read verb with no resolvable worktree refuses loudly and uniformly: non-zero exit, one plain-words line on stderr, no bare WTNONE, no JS exception: prefix.
  • ls/cat/grep/log stop exiting 0 — they take the same gate status/diff already reach.
  • A genuinely EMPTY worktree stays distinct from a MISSING one: empty is still exit 0 with no rows.

Constraints

  • The anchor lookup itself is not in question — it keeps going through core/discover.js + core/resolve_hash.js (URI); this ticket is about what the caller does with a failed lookup.
  • No new error code: WTNONE is the right condition; the defect is its PRESENTATION plus the call sites that never consult it.

WIP

Design decisions

  • Undecided: one gate in the shared view/loop entry versus per-verb guards. The single gate is preferable — the split behaviour above is exactly what per-verb guards produce.
