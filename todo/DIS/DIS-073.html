DIS-073: bare be get fast-forwards the worktree to the TRUNK tip while recording the current branch

Now
DONE

inRepoSeed's D3' arm resolves the tip from the RAW query, not from the branch it is about to record: branch = query is "" for a bare get (also for ! and ?), so tip = k.resolveRef(branch || "") returns the TRUNK tip (store.js:420-442 keys "" to the trunk and has no "current branch" key), while wantBranch = branch || curBranch — and the appended row is get ?<curBranch>#<trunk-tip> (get.js:514-520). On any non-trunk worktree a bare be get therefore checks out the TRUNK and mislabels the base as the branch's, silently: post then takes its parent from that base (post.js:581), status computes divergence against it, and the classifier reads it as the ours baseline (classify.js:226). The comment two lines above states the intended behavior ("an empty/absent query folds to the current branch", get.js:511-513) and worktree:44-48 + GET:32 agree ("bare: FF the wt to cur's branch tip") — a plain defect, not a spec gap. Invisible on a trunk wt (curBranch "" → the trunk IS correct), which is why the test set misses it.

Input

Context

The resolve reads branch, the record writes wantBranch; the two differ exactly when the worktree is not on the trunk.

  • get.js:514-517 resolves resolveRef(branch) but records wantBranch = branch || curBranch — and the curSha fallback only fires when the trunk ref is ABSENT.
  • store.js:423-435: resolveRef("") matches the empty-query row = the trunk; there is no key meaning "whatever cur tracks".
  • get.js:520 records ?<wantBranch>#<tip> — track says the branch, base is the trunk's tip; every later reader trusts the pair.
  • ? (an explicit trunk switch) and a bare be get are INDISTINGUISHABLE: get.js:465 u.query || "" collapses the URI-009 absent-vs-empty slot the comment at get.js:459-462 relies on.
  • DIS-039 (DONE) settled the NATIVE bare-get story (status vs FF, GET-026/STATUS-001); this is the be/ JS D3' arm, a different defect on a different path.
  • Under DIS-071 the resolve target becomes the TRACK URI; this ticket is the minimal today's-terms fix and must not block on it.

Goals

Resolve what you are about to record; keep ? an explicit trunk switch.

  • Bare get and ! resolve the tip from the tracked branch (resolveRef(wantBranch) in today's terms; the track URI once DIS-071 lands).
  • Preserve the absent-vs-empty query distinction (URI-009) so bare get and ? stay separable without href string matching.
  • Repro: a wt on ?feature behind the trunk; bare be get FFs to feature's tip, and the record's track and base agree.

Constraints

Minimal fix, D3' only — this arm is load-bearing for every other verb's baseline.

  • Touch the D3' arm only (get.js:509-522); leave D1 (?br#sha), D2 (?<sha>), D3 (#~N) and D4 (restore) alone — minimal fix, end-to-end verify.
  • URI-009 slot semantics via the URI class; no href === "?" string matching (the shape the old code carried).
  • Repro-first; a fixture seeds with jab get file:<path> (the working wt-clone form).
