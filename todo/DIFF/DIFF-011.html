DIFF-011: diff:<sub>/<file> renders the file WHOLLY-ADDED — the single-file (scoped) diff branch isn't submodule-mount-aware

Now:
DONE

be diff:<sub>/<file> (a wt-vs-base or range diff of a file UNDER a mounted submodule) reads the from/baseline side from the PARENT's baseline tree, where <sub> is a 160000 gitlink. blobAtTree walks the path segments via readTree and at the gitlink it cannot descend the commit-sha → returns undefined → an EMPTY from-side → diffFile's f.length === 0 "Addition" branch fires, so the file renders WHOLLY-ADDED (@@ -1,0 +1,N @@, every line +) instead of the real wt-vs-base inline diff. The whole-tree wt path (diffWtTree) and the range path already recurse mounts via recurseSubPins/recurse.isMount (open the sub's shard, read the sub's own tree), but the single-file SCOPED branches (views/diff/diff.js:437-441 range+path, 449-451 wt+path) have NO mount awareness — they walk the parent tree straight through the gitlink. PRE-EXISTING (diff.js byte-identical to trunk; independent of the DIS-058 sub-recursion work), surfaced by be-js-diff-14-sub-file-baseline. Scope be/ JS. See Store, Submodules; method Issues.

Input

Context

  • Repro: be-js-diff-14-sub-file-baseline — diff:chsub/c.txt (chsub a mounted sub, c.txt dirtied in-place). Oracle be …--plain emits a real inline diff (@@ -1,4 +1,4 @@ with +/- lines); jab emits wholly-added (@@ -1,0 +1,4 @@, baseline empty).
  • Site: views/diff/diff.js — wt+path branch (449-451, blobAtTree(k, baseTree, spec.path)) and range+path branch (437-441, fromTree/toTree). blobAtTree descends segments via k.readTree; at the chsub gitlink (kind "s") it can't readTree the commit-sha → undefined.
  • The NON-scoped paths already handle this: diffWtTree (:237) + recurseSubPins (:280, gated on recurse.isMount :285) open the sub via be.find/store.open and read the sub's pin-range tree. The scoped single-file branch is the ONLY diff path missing mount awareness.
  • Read Store (flat shard layout, be.find/store.open for the sub's sibling shard) and Submodules (the mount: <wt>/<path>/.be anchor + the sub's OWN baseline tree) to mirror how the recursive paths resolve the sub.

Goals

  • diff:<sub>/<file> (wt-vs-base AND range) renders the real inline diff against the SUB's baseline blob — byte-parity with native be …--plain (the be-js-diff-14 oracle).
  • A path NOT under a mount is unchanged; a path under a declared-but-unmounted sub degrades sanely (not a false wholly-added).

Constraints

  • be/ JS only; REUSE the mount resolution the recursive paths use (recurse.isMount + be.find/store.open) — do NOT re-roll. Keep the friendly string throws.
  • Repro-first (CLAUDE §17): make be-js-diff-14-sub-file-baseline pass (un-xfail if it is marked); keep the other diff/sub cases green.

WIP

Design decisions

  • In the wt+path and range+path branches, before blobAtTree, split spec.path at the deepest mount prefix (recurse.isMount/the subs set). If under a mount: open the sub's store (be.find(join(repo.wt, subPath)) + store.open) and read the from-side blob from the SUB's baseline tree at the in-sub remainder; the to-side stays the wt file (wt+path) or the sub's to-pin tree (range). Mirror recurseSubPins.
  • Single resolution path shared with the recursive diff so the two can't drift.
