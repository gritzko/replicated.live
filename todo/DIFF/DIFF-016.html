DIFF-016: EXPECTED-based diff — green/red local, pale blue/orange patched-in, yellow conflicts

Now
DONE

Per DIS-080: with fence markers retired, the diff view is where conflicts are seen and resolved. EXPECTED = the straightforward weave reading of base + all in-scope patch-ins (theirs layers, no WT layer). Green/red = wt compared to EXPECTED (local outstanding edits). Patched-in changes (EXPECTED vs base) render pale blue/orange — the other kind of in/rm, not salad/salmon. Tokens where both sides touch (conflicts) render yellow. All provenance comes from the weave — per-token origin ids — no separate diff3 pass.

Input

Context

  • Today's diff shows one green/red axis vs base; a patched-in change is indistinguishable from a local edit, and a conflict was only visible as fences in the bytes.
  • The weave already carries per-token source ids (commit hi64, WT layer 00000000005774ed); ours/theirs/both classification per token falls out of the fold.
  • Multi-patch runs stack: EXPECTED folds ALL patch rows in scope, several runs compose in one weave.

Goals

  1. Diff render classifies each changed token: theirs-only → pale blue (in) / pale orange (rm); wt-vs-EXPECTED → green/red; overlap (conflict) → yellow. Conflict paths cross-checked against ULOG-004 accessor.
  2. Row metric: patched-in tokens weigh as edits — in/rm in the max(in,rm) row weight, total = max + eq ([inline-vs-split-metric-max] extends, C HUNK.c + JS bro.js in lockstep).
  3. Theme: pale blue/orange + yellow SGRs in view/theme.js, plain-text fallbacks for goldens; quad/status colors stay red for con rows.

Constraints

  • Weave-based only — no diff3 reimplementation, no marker parsing.
  • Verify through the real UI path (pager pty), not TLV probes ([verify-through-real-ui-path]).

WIP

Design decisions

  • EXPECTED reading = shared/expected.js expectedOf() — patch.js mergeApply MINUS weave.foldWt: weave.build per side, weave.merge, mergedLive.
  • Provenance rides the EXPECTED bytes as a THIRD weave layer folded BETWEEN base and wt (ID_EXP), so ONE emitDiff spells side AND origin — no 2nd pass.
  • emitDiff/emitFull emit the weave walk verbatim (verified: tokens 1:1, never split, windows contiguous) — a hunk record aligns to it by token text.
  • Encoding = tok32 bit 26 (custom) means PATCHED IN. C HUNK.c IGNORES that bit (probed), so --plain stays byte-identical; side 3 was rejected (C plain reads it as EQ and collapses the +/- pair).
  • CONFLICT needs no third bit: it is a RUN of consecutive changed tokens carrying BOTH bit-26 values — the same membership test mergedLive uses. EQ tokens break runs, so two edits on neighbouring lines never false-yellow.
  • PLAIN-TEXT FALLBACK = NONE, deliberately. test/diff/18-patch-base asserts ^\+THREE$ on --plain after a patch and I may not edit it; provenance is a colour distinction, asserted on --color SGR digits (no ESC literal, so dash-safe). --plain output is unchanged for every provenance.
  • Yellow is derived from the WEAVE (DIS-080: regions come from the weave, not rows). wtlog.conflicts() is read in diff.js's expectedCtx and cross-checked at TEST level (status con tally == the yellow path) — path-granular only.
  • Colours (view/theme.js DIFF_WASH, 256-cube bg): local 194/157 + 224/217 (unchanged), patched-in 153/117 (blue) + 223/215 (orange), conflict 229/227 (yellow — 229 not 230, which is the banner band).
