A real merge conflict renders as a plain 2-wash local diff: DIFF-020's patched-in washes (155/192, 215/222) never appear, in the pager or in --color. The con row, the EXPECTED fold and the emitted del+ins rows are all CORRECT — the loss is in markRecord (views/diff/diff.js:220), the text zip that copies provenance onto the record's toks. It assumes emitDiff and the DIS-082 cursor walk yield the identical token sequence (diff.js:189); a dead token SPLIT breaks that in exactly the overlap case.

Input

Context

  • Live repro: work/CI-004 after a get merged BRO-043's pager.js into the wt (con row base 05e4d3b3, theirs 41331e79). TLV probe: 1276 changed toks, 0 with bit 26. Probes attached: provprobe.js (fold+zip replay, run jab provprobe.js in the con wt; regenerate its diff.tlv input via jab diff --tlv <path> > diff.tlv and fix the two absolute paths at the top), tlvprobe.js (bit-26 counter).
  • The three-layer fold itself flags 589 theirs + 684 ours tokens — the weave and expected.js are healthy; only the last-mile copy fails.
  • At the overlap seam the weave stores the dead old comment opener as ONE atom // (cursor: off 72205, text "//"), but emitDiff emits it as TWO / toks — record 33999 toks vs provenance list 33997.
  • The rendered rows are RIGHT (ours' prefix in, old prefix rm, tail eq); only the provenance class is lost.

Goals

  • A conflicted file's diff shows the 4 DIFF-020 washes: ours in/rm salad /salmon, theirs in/rm lime/orange — in the pager AND in --color.
  • A token-granularity disagreement between the two weave readouts must not discard provenance for the whole record.

Constraints

  • DIS-080: provenance falls out of the ONE fold, no second diff pass.
  • markRecord's fail-safe direction stays: never wrong-colour a token; degrade to unmarked only for what truly cannot be attributed.
  • Whether emit (splits the dead atom) or the cursor (coalesces it) is canonical is a DIS-082 cursor-contract ruling — gritzko decides.

WIP

Design decisions

  • Candidate A: align by BYTE OFFSETS, not token text — both readouts agree the dead // covers off 72205..72207; splits become harmless.
  • Candidate B: derive provenance in the same emit pass that produces the record, so there is one sequence and nothing to zip.
  • Secondary defect either way: the stamped toks ride only the out.feed copy (diff.js:256-258); renderRecord paints the unmarked original (diff.js:263), so --color drops provenance even when the zip works.
