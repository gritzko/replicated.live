The diff view must show the whole change, and a born or dying file IS the change: wholly-new files never render (confirmed), and gritzko reports deleted files missing as well (the exact arm still needs pinning — the plain-path deletion repro DOES render, see Context). A file absent from the diff reads as "no change" — the same lie DIFF-008/DIFF-009/DIFF-015 fought at the truncation level, here it is by design.

Input

Context

Reported by gritzko 12Aug26. The new-file skip is explicit in the wt arm; the deleted-file miss did not reproduce on the plain path, so its trigger is narrower.

  • be/views/diff/diff.js:480 (wt arm, DIFF-012 classifier sourcing): if (fsha === undefined) continue; // no base side → wholly-new, skip — kills new AND staged put rows of new files.
  • Repro 12Aug26, wt clone: untracked brand-new-repro.txt → jab diff | cat mentions it 0 times.
  • Same session: mv API.md away → jab diff | cat renders the deletion (2 rows) — the plain no-arg path DOES show base-only files (diff.js:484 BASE_ONLY arm).
  • So the deleted-file miss needs its repro pinned: suspects are the pager view (BRO-027 alt screen), a staged delete row (del bucket, onDisk/inBase variants), or the rev-arg tree-vs-tree arm; per DIFF-016 conventions any fix must be verified through the real UI path, not TLV.

Goals

  • A wholly-new file renders as all-green (empty vs wt), a deleted one as all-red (base vs empty) — in the no-arg wt diff, dir-scoped, and rev-arg arms alike.
  • Staged rows (put of a new file, staged deletes) render the same as their unstaged twins.
  • Pin the deleted-file repro gritzko hit; add both repros as tests that flip with the fix.

Constraints

  • The classifier stays the one source of truth for the dirty set (DIFF-012) — no bespoke wt walk.
  • weave.js policy still applies to the new side: binary or over-cap new files show a header/BLOB row (DIFF-015's err-as-BLOB precedent), never silence.
  • No change to tree-vs-tree output where both sides already render (diff.js:367-385).
