SUBS-042: jab post commits an unstaged submodule in selective mode (recurses + commits the sub in commit-all)

Now
DONE

In the parent worktree in EXPLICIT-STAGE (selective) mode — at least one be put/ be delete since the last get/post — jab post commits a mounted submodule that had NOTHING staged: it recurses a post into the sub, the sub (no staged rows of its own) runs in COMMIT-ALL mode and rewrites its dirty files, and the parent gitlink is bumped to the new sub commit. Selective mode must commit only what is explicitly staged, so a sub with nothing staged must be left untouched (pin unchanged). The parent's selective intent does not propagate into postSubs's recursion. be/ JS (reported by user, 2026-06-30). JS-side twin of the native SUBS-029 phantom-sub-put fix; parent DIS-058; spec Submodules / Dirty; method Issues.

Input

Context

  • User repro (shape): parent in selective mode (be put <parentfile>), a mounted sub with a dirty-but-UNSTAGED file, then jab post — the sub is committed and the parent gitlink advanced, despite nothing staged in the sub.
  • post.js::postTree (post.js:280) calls postSubs (post.js:282, unless --nosub) BEFORE postOne; postSubs (post.js:290) enumerates mounted gitlinks (subs.enumerate) and recurses postTree(subInfo, ctx, {uri: subWt}) into EVERY mounted sub (post.js:314) — no selective-mode gate, no "does the sub have staged changes?" check.
  • The recursive sub post computes the SUB's OWN selective/commit-all from the SUB's wtlog: decideM.decide → m.anyPd (fold-decide.js:109). With no in-scope sub put/delete anyPd is false → COMMIT-ALL → a modified sub file is rewritten (fold-decide.js:160 if (anyPd) keep; else rewrite), so an unstaged-dirty sub is committed.
  • The parent gitlink is then bumped for any sub whose tip moved (post.js:328-335, the synthesised put <subpath>#<newtip>), recording the spurious sub commit.
  • Spec: Dirty selective = ≥1 explicit put/delete since the last post → commit ONLY staged paths; Submodules POST recursion is post-order but must respect the staging intent. Native SUBS-029 added a tip-vs-pin + PUTNONE-tolerant gate to avoid phantom no-op sub commits; the be/ JS port lacks the selective gate.

Goals

  • In selective (explicit-stage) mode, be post must NOT commit or advance a submodule that has nothing explicitly staged (no in-scope sub put/delete, no staged parent gitlink bump for it) — the sub's pin stays unchanged.
  • In commit-all (implicit) mode, keep descending into + committing dirty subs as today (recursion is the default per Submodules).
  • A sub ALREADY advanced out-of-band (pin ⊏ sub tip) still bumps (SUBS-026), but a clean/unstaged sub is never spuriously committed.

Constraints

  • be/ JS only. REUSE decide's anyPd, subs.enumerate, and the existing gitlink-bump primitive; do not re-roll the recursion.
  • Do NOT regress: post-order sub recursion, the advanced-sub bump (SUBS-026), detached/attached sub commit (SUBS-035/SUBS-036), or --nosub.
  • Repro-first (CLAUDE §17): a parent in selective mode + a mounted sub with a dirty-but-unstaged file → assert be post leaves the sub tip AND the parent gitlink UNCHANGED; a commit-all parent still commits the dirty sub.

WIP

Design decisions

  • Gate postSubs on the parent's mode: in selective mode recurse into a sub ONLY when it has in-scope staged changes (its own anyPd) OR an explicit parent gitlink-bump targets it; skip clean/unstaged subs. In commit-all mode descend into every dirty sub as now.
  • Equivalently / additionally, propagate the parent's selective intent into the recursive sub post so the sub does not silently commit-all when the parent is selective — pick the cleaner of the two, do not double-gate.
  • Mirror the intent of native SUBS-029 (tip-vs-pin + PUTNONE-tolerant bump) so a no-op sub neither commits nor bumps.
