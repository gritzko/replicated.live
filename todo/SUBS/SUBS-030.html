SUBS-030: be status renders an advanced-submodule mod <sub> row with no timestamp

Now:
DONE

A submodule whose tip advanced past the parent gitlink pin reads mod <sub> in be status (correct per SUBS-027), but the row is emitted WITHOUT a timestamp (blank ts column, unlike every file mod row) and as a bare mod that doesn't distinguish "advanced — gitlink bump pending" from a content change. Method: Issues.

Input

Context

  • Live repro: in ~/beagle-journal (the beagle submodule advanced 6 commits 5b11dad9→9e80e5f0 past the journal's gitlink pin), be status shows:
         19:27  mod README.mkd
            mod beagle          <- NO timestamp

    Every file mod row carries a ts; the gitlink-advance row is blank.

  • The classification is CORRECT (SUBS-027: R4 tip descends R1 pin → Advanced → mod). The RENDER is the defect: (a) no timestamp, (b) bare mod conflates an advanced gitlink (needs be put <sub> && be post) with a content modification.
  • Render site: sniff/SNIFF.exe.c ~232–248 — the CLASS_BASE_ONLY + RON_s gitlink arm runs SUBSDirty and emits the mod row without stamping a ts.

Goals

  • The advanced-submodule row carries a sensible timestamp (e.g. the sub tip's commit ts) consistent with file rows. Consider a distinct marker for "advanced" (gitlink bump pending) vs content mod — cf. the DIS-048 disapplied-marker semantics discussion (a wrong verb is worse than none).

Constraints

  • Fix in the status gitlink-row emit (sniff/SNIFF.exe.c RON_s arm). Do NOT regress SUBS-027's advanced / stale / health classification. Repro-first.
