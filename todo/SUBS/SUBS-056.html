SUBS-056: mounting a sub re-mints its wtlog, discarding local rows (append-only bypassed)

Now: OPEN Sev: HIGH

Every parent tip move REWRITES each mounted sub's .be from scratch, so any row local to the sub — an in-scope patch, a put/delete, a post — is silently gone along with the work it names. shared/submount.js:337 and :386 call ulog.write(anchorPath, [redirect, track]) UNCONDITIONALLY, and ulog.write (shared/ulog.js:171-176) builds a fresh log at <path>.tmp.<rand> and renames it over the anchor. The root never does this: verbs/get/get.js:446 picks writeWtlog only when fresh = !exists(bePath) (:416), else appendWtlog. So Worktree's append-only wtlog holds at the root and is bypassed at every mount.

Input

Context

  • Live incident (gritzko, 2026-07-29, //BRO-041/be): patch ?2c927d8a absorbed into the test sub at 13:05; a parent update at 13:54 left the sub clean, the patched bytes gone.
  • Proof by stamps: the PARENT log was APPENDED (anchor still 26729AMt08 from the clone, new row 26729Drw7H), the SUB log was REPLACED (a NEW anchor 26729Drw7y + 26729Drw7z, both minted at one instant; the old 26729Cor0U/26729Cor0V + patch 26729D5A74 are gone).
  • The absorbed content itself survived only because it came from a commit (2c927d8a); a put row or hand-staged state has no such backstop.
  • Both call sites sit in the mount path, so this fires on EVERY parent get that materialises a sub, not just a diverged one.
  • Related: PATCH-024 (base tree is the last get/post) and PUT-016 came out of the same session; this one is the data-loss half.

Goals

  • A mounted sub's .be is APPENDED to when it already exists — the same rule the root follows.
  • An in-scope patch/put/delete row in a sub survives a parent tip move, or the move REFUSES in plain words (Errors) before touching anything.
  • A genuinely fresh mount (no .be yet) still gets the two-row anchor as today.
  • ulog.write keeps its replace semantics; the fix is at the call site, not in the primitive.

Constraints

  • The track row must still land with its ASSIGNED ts — submount.js restamps checked-out files from asg[1] (PUT-012 parity); an append must return the same information.
  • Do not change ulog.write's contract; other callers (fresh clone seeding, get.js:215,280,446) depend on replace-on-fresh.
  • Decide and state ONE policy for a sub carrying uncommitted work when the pin moves: preserve-and-append, or refuse. Ask gritzko before implementing the refusal wording.
  • JS ///be/ only.

WIP

Design decisions

  • The root's fresh = !exists(bePath) gate is the model to copy into both mount call sites.
