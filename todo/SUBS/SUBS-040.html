WIP

Design decisions

  • SURVIVES the rescope — branch is GET-owned (Worktree): only get sets cur's branch; a bare get FFs the tip but KEEPS it; post/put/delete advance the tip and NEVER switch branch. URI-016 decision 10 adopts this verbatim and generalises it to the row patterns (post #hash = a local commit advancing the BASE; a parent-written ///path#pin = the TRACKED pin).
  • REPLACED 2026-07-14: "POST advances the dot-branch ref in the sub shard" dies with the dot-branch. The post-side duty is now to refresh the sub's wtlog pin row (URI-016 decision 8) — and only when the sub is on-pin (below).
  • NEW (URI-016 decision 11): an OFF-pin sub is left alone — the parent does not recurse get/patch into it ("you know better") and reports adv from gitlink != base. This replaces I3's "measure against the dot-branch": no ref is consulted.
  • Post-rescope invariant after a clean cascade post: gitlink pin == sub HEAD == the sub's wtlog base, with the tracked row refreshed to the same pin.
