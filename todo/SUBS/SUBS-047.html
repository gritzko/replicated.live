SUBS-047: same-source sub fetch broken (ssh:////), worktree sources unserved, nested fallback empty

Now
OPEN
Sev
HIGH

jab get ssh://localhost/src/beagle died SUBFETCH cannot fetch sub dog/abc (abc) from ssh:////localhost/src/beagle?/abc — child unreachable. Three compounding defects in the be/ JS GET sub-mount path: (A) submount.sameSourceUri hand-concatenated "//" + u.authority where the URI binding's u.authority already carries the // (the known URI-013 latent bug), so every authority-bearing same-source URI was ssh:////host/… and never reached the peer; (B) a git source WITH a worktree (path not ending .git) serves each sub's own checkout at <path>/<subpath>, but no such same-source form existed — only the beagle ?/<proj> swap; (C) a NESTED sub (dog/abc) is declared in dog/.gitmodules as abc, yet mount read only the ROOT .gitmodules with the full subpath, so the official-url fallback (and the Title) came up empty and the whole mount threw. Spec: same source first, official .gitmodules url only as fallback (Submodules §1, Title retrieval preference).

Input

Context

  • User repro: jab get ssh://localhost/src/beagle (a git repo WITH a worktree; subs dog → libdog, nested dog/abc → libabc all checked out at the source) — parent fetched, sub mount threw SUBFETCH; error showed the ssh://// URI and NO or <url> fallback part (the nested url lookup returned "").
  • The update path surfaced three more GET defects, fixed under this ticket: a dir→gitlink type change mounted the sub FIRST and the queued delete leaves then clobbered the fresh checkout (FIFO order); a removed MOUNTED sub was never unmounted (io.unlink on a dir is EISDIR, swallowed); deletes left empty dirs behind (del-sweep was a no-op — and the DELSWEEP fold row dispatches BEFORE the fan-out's delete leaves, so a queue-time sweep sees nothing).
  • Goal set by the user: iterate till jab get ssh://localhost/src/beagle works smoothly and updates the beagle wt to HEAD (removal of js/, dog/ becoming a submodule, nested dog/abc cloned).

Goals

  • Same-source first: beagle store source → ?/<title> project swap; git worktree source → <path>/<subpath>; bare .git → no same-source; official .gitmodules url only as fallback.
  • URIs composed via URI.make ONLY — no string concatenation (house rule).
  • Nested subs resolve their official url + Title via the NEAREST enclosing .gitmodules.
  • The old-state→HEAD update transitions land clean: dir→gitlink, gitlink→absent (unmount), tracked-file deletes collapse emptied dirs.

Constraints

  • be/ JS only (shared/submount.js, verbs/get/get.js); no native edits, no other tests edited.
  • An unmounted stale gitlink dir may hold user files — never rm -rf it; only a REAL mount (.be anchor present) is swept on gitlink→absent.

WIP

Design decisions

  • sameSourceUri(source, title) → sameSourceUris(source, title, subpath) returning an ordered candidate list, built with URI.make; consumed by BOTH the local-reuse branch and the wire branch of mount.
  • declaredUrl(wt, subpath) walks the subpath segments to the nearest enclosing .gitmodules; feeds both the fallback fetch and titleFromUrl (nested dog/abc titles libabc, not abc).
  • dir→gitlink: reconcile tags the mount leaf with oldDirTree; the leaf sweeps the old dir's TRACKED files synchronously (sweepOldTree) BEFORE mounting — queued delete leaves would fire after the mount.
  • gitlink→absent: delete leaf of kind s unmounts via io.rmdir(full, true) (io.rmdir exists since GET-039; the "JS has no rmdir" notes were stale) — gated on the .be anchor existing.
  • del-sweep: delete leaves mark parent dirs (markDelDir); finalizeGet (after the queue drains) rmdirs them deepest-first and walks each chain up; plain rmdir so untracked content keeps a dir alive.
