PATCH-022: harness crash-passes-as-conflict — PATCH_EXPECT=conflict accepts any non-zero exit

Now: OPEN

Input

Context

be/test/lib/patchcase.sh _run_patch has a binary exit gate: PATCH_EXPECT=conflict requires only "non-zero", so a segfault, ASAN abort or any unrelated JS exception satisfies every conflict case (test/patch/conflict, dirty-overlap, same-anchor-conflict). Only test/patch/stampband defends itself by additionally grepping PATCHCONFLICT on stderr. A regression that turns the loud conflict exit into a crash would keep the whole conflict family green.

Goals

Harden the gate in _run_patch (one place, all conflict cases inherit): expected-conflict requires the PATCHCONFLICT message on stderr AND rejects signal exits (rc >= 128); the default arm keeps requiring rc 0. A deliberate-crash self-test proves the hardened gate goes RED.

Constraints

  • Harness-only change (patchcase.sh, and patchspec.sh if it grows the same idiom); the conflict cases themselves stay untouched.
  • The self-test must not depend on producing a real segfault — a stub that exits 139 / prints no PATCHCONFLICT is enough.
