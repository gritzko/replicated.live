PATCH-017: patch refusal paths mostly unasserted — 3 of ~12 PATCHFAIL/PATCHFETCH errors have tests

Now
OPEN

Input

Context

test/patch/tree-uri probes three refusals (bogus scheme, file:+query store form, dead wire PATCHFETCH); the rest of the refusal surface has no test: empty-arg "a patch URI is required" (be/verbs/patch/patch.js:368), unresolvable cherry ref (be/shared/patchscope.js:220), cherry-pick of a root commit (patchscope.js:222), unresolvable ?branch (patchscope.js:235), no cur tip in ours (patchscope.js:100), //WT source tip absent from the local store (patch.js:318), file:<wt> with no worktree / no cur tip (patch.js:328,331). The harness gate is binary non-zero, so a crash currently passes as a refusal.

Goals

One patchspec.sh probe per refusal: non-zero exit, the exact message grepped on stderr, and proof of zero side effects — wt bytes untouched, no patch wtlog row.

Constraints

  • If any message gets reworded while testing, the standing ruling applies: user-facing errors in plain words, never bare C codes.
  • Tests only; refusal probes must be hermetic (no network for the wire-shaped ones beyond a dead address).
