PATCH-003: be patch '<x>!' patch-from broken — false-noop+mutation (local) and dead source (remote)

The ! patch-from operator misbehaves two ways, both seen reconciling the ~/todo/JS-053 worktree against landed ?6a0ce1b7 (URI-006 St.2): a LOCAL ?! reports "nothing absorbed" yet mutates the worktree, and a REMOTE <uri>! absorbs nothing at all while a pinned ?<sha>! absorbs 41. Net: be patch '!' cannot be trusted to reconcile, and when it claims a noop it may still have written. Method: Issues.

Input

Context

  • be patch '?!' → noop=11 … (nothing absorbed — no patch row staged) BUT then

    get abc?40cf6df6 + mod abc/FILE.c + mod abc/FILE.h — fetched abc and edited two files while reporting it did nothing.

  • be patch 'be://localhost/beagle-journal?/beagle!' → same `noop=11 … nothing

    absorbed, though be head be://…?/beagle then reports 1 ahead, 1 behind, 100 changed`. The remote patch-source resolved to nothing.

  • Contrast (works): be patch '?6a0ce1b7!' → `noop=163 take-theirs=41 merged=1

    added=2 deleted=2`, applied St.2's files cleanly. Only the pinned-sha form worked.

Goals

  • be patch '?!' and be patch '<remote-uri>!' resolve the SAME patch source a pinned

    ?<sha>! does, and absorb the real divergence (or report honestly why not).

  • A noop/"nothing absorbed" result means ZERO worktree mutation — never a silent

    get/mod of files after the noop banner.

Constraints

  • Don't regress the working ?<sha>! form. Repro-first (CLAUDE §17).
  • Route via the URI resolver, never hand-rolled handling (ABC).
