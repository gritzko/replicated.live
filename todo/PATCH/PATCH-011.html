Context

The wt→orig merge is blocked when the two trees do NOT share a store: work/ABC-008/abc anchors file:/home/gritzko/.be/?/libabc, the orig journal/libdog/abc anchors file:/home/gritzko/src/libdog/.be/?/libabc — the wt's tip commit does not exist in the orig's shard, so even a fixed tree-URI source (PATCH-010) cannot resolve theirs.

  • RULING 2026-07-10 (gritzko): patch should DOWNLOAD the objects first when it has the remote leg; then everything is present locally.
  • get already owns the transfer machinery (wire/ingest/keeper fetch) — patch reuses that leg, it does not grow its own.

Goals

  • patch <transport-uri> (file:/store?/proj, be://host/…, ssh:/http(s):) fetches the source's objects/refs into the LOCAL shard first (the get leg, no wt touch), then runs the PATCH-010 all-local triple resolve + absorb.
  • a fetch failure refuses loudly BEFORE any wt mutation; the absorb itself stays the ordinary local patch.

Constraints

  • reuse the existing get/wire/ingest transfer path — no second fetch implementation; URI class only.
  • repro test first (two stores, diverged shards, fixture-built); existing tests untouched.
  • depends on PATCH-010 (tree/transport source addressing) — land in that order.
