Port be's PATCH (PATCH) to bee: absorb a branch, a commit or another worktree into the WORKING COPY — no staging, no commit, a dirty tree is fine. RULING (gritzko 2026-09-19): no git merge; bee works the full tree on its own with the cfold weave merge, and records provenance plus the per-file conflict status in .git/be/patch.log. The cycle is patch → test → post (POST-040: post 'msg' commits).

Input

Context

  • git merge --no-commit --autostash (probed, git 2.52) stages the result AND parks dirty edits in MERGE_AUTOSTASH till the commit.
  • index/weave.js:139:KB weave3 is the cfold 3-way merge, conflicts markerless (PATCH-025); null = binary or over 4 MB.
  • index/dag.js:53:~c mergeBase finds the LCA in the index; index/read.js:73:ll entryAt, index/weave.js:186:KB blobOf read the ODB.
  • <gitdir>/be/ is bee's own dir already (index/index.js:14:Wt); the quickjab runtime carries the ULOG container be's wtlog rides.
  • BE-010 is the lesson: ours is the worktree's CURRENT bytes, never the commit tree — that twin clobbered dirty edits.
  • be's verbs/patch/patch.js and shared/checkout.js (~900 lines) are the reference walker and writer; port FROM them.
  • be's model: get, post and patch move COMMITS; uncommitted state is a pseudo-commit preserved where it sits, never transported.

Goals

  • patch <ref>, bare = the configured upstream @{u}: absorb the whole missing line, base = LCA(HEAD, theirs).
  • A target behind or equal to HEAD is "nothing to do", exit 0.
  • patch <sha> cherry-picks ONE commit, base = its first parent; the log row says picked, never a parent.
  • RULING (gritzko 2026-09-21): patch <worktree> (//name or a path) absorbs the commit that tree is ON (GET-065).
  • Theirs is COMMITTED state only, a worktree source too; its staged and unstaged edits stay there, ours are kept by the weave.
  • A dirty source tree gets one stderr warning line, "source tree is dirty, N files not carried"; the exit status is unchanged.
  • Reentrant: a re-run after theirs gained commits weaves just the new delta — HEAD has not moved, so the base holds.
  • A re-run never stacks provenance: the latest head row per source wins, post names one parent per source.
  • Walk base, HEAD and theirs trees in tandem, Merkle-pruned; a path theirs did not touch is never read or written.
  • Per file: a theirs-only change on clean bytes overlays, both sides changed run weave3 on the worktree bytes; no index write.
  • New, deleted, exec-bit and symlink entries are materialised; delete-vs-edit is a conflict, the file kept.
  • .git/be/patch.log: one head row per run (kind parent/picked, the ref, theirs sha), then one row per touched path.
  • Per-file log status in be's words: applied, merged, mod (ours only, kept), conflict.
  • RULING (gritzko 2026-09-21): the printed report is the status QUAD summary (view/status.js:363:vX), same as get and post.
  • The log's conflict rows feed the quad model's con list (view/quad.js:36:3B), so a conflicted path cannot be missed.
  • Any conflict row: stderr says so and the exit is non-zero, so an unattended patch && commit stops.
  • A second patch over a patched tree composes: the prior output is just ours (PATCH weave merge).
  • RULING (gritzko 2026-09-19): recurses into submodules by default — a moved gitlink patches the live sub, theirs' pin the target.
  • patch <path> <ref> scopes the absorption to the path and records NO provenance head row.

Constraints

  • RULING (gritzko 2026-09-19): never write git's upstream or any other git setting, that is intrusive; @{u} is only READ.
  • No git merge, cherry-pick, stash, apply; git only reads here (rev-parse, ODB) — every write is bee's own file write.
  • A source worktree is only READ, by plumbing (rev-parse, diff-index, ls-files -z); nothing is written or stashed there.
  • Files land atomically (temp + rename), modes kept; nothing outside the worktree, nothing under .git but be/patch.log.
  • A weave3 null never picks a side silently: the git merge-file fallback of merge.js:55:sQ (LITE-014:30:Kz), its conflicts logged.
  • RED first over a fixture repo: clean, dirty, conflicting, cherry, patch-on-patch, new/deleted/exec/symlink; no existing case edited.
  • RULING (gritzko 2026-09-21): the verb lives in its OWN file verb/patch.js; verb/ is the writers, view/ the read-only views.
  • Shared helpers (sync.js, stage.js, the shapeOf arg pick of verb/get.js) are required, never copied or forked.
  • RULING (gritzko 2026-09-21): worked in the MAIN tree, in sequence GET → POST → PATCH; no commit (work).
  • Comments per comment, PATCH-026 on the change.

WIP

Design decisions

  • RULED (gritzko 2026-09-19): commits made by bee post check patch.log for the state of the merge; the log is the one record.
  • HOW is the implementer's: the mint and index commit hooks must still run, and no git state outlives the one post call.
  • RULED: a conflict row is informative ("this file is suspicious") and blocks nothing; posting after testing means it is OK.
  • RULED: post commits all added and changed-tracked files, so patched files ride along; the files patch CREATED are untracked — post adds the log's new-file rows first, else the merge commit drops theirs' new files (POST-040).
  • RULED: patch! foster is a TODO for later, out of this ticket; picked stays a log row, how a commit cites it rides with foster.
  • RULED: the merge git itself calls — the three-file driver (merge.js:99:sQ, LITE-014) — is NOT touched.
  • The log's scope ends at the next commit, as be's wtlog has it (any post ends the patch scope).
