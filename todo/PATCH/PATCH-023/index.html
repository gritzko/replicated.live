PATCH-023: port merge scenarios mined from git's test suite as patch tests

Now
OPEN

Input

Context

git's t6xxx/t35xx merge corpus is a decades-old catalog of topologies that break merge engines. A wholesale lift is impossible (harness-coupled, and git's snapshot-3-way answers are the WRONG oracle for a full-history weave), so the corpus was mined for topologies instead: 4 workers read 22k lines of `/tmp/git/t` merge tests and distilled ~40 scenarios into mined-scenarios(mined-scenarios.mkd), grouped A-G, each with git's answer vs the predicted patch answer (SAME / DIFFERS / RULING). Highest-signal: criss-cross cases where the weave beats recursive's virtual-ancestor artifacts (A1-A3), the dirty-wt-as-ours model divergences (B), type/mode/binary classifier collisions (C), and no-rename-detection hazard pins (D).

Goals

Port the catalog as patchspec.sh cases, priority H→L: the SAME/DIFFERS entries become tests directly; each RULING entry gets gritzko's verdict first, then a test pinning it. DIFFERS cases double as the differential showcase (weave answers where git punts).

Constraints

  • Rulings gate their tests — never pick a behavior to make a case green; batch the ruling requests (binary C1, type collisions C2/C4/C5/F1, modes C7, no-base fence A5, sub recording F2, delete-intent D5, silent-pick-notice E3).
  • Overlap discipline: root-cherry refusal lives in PATCH-017, add/add arms in PATCH-018, con-row/rerun legs in PATCH-020/PATCH-021, binary overflow arm in PATCH-016 — link, do not duplicate.
  • Tests only; any wrong observed behavior becomes its own ticket, linked both ways. ~/tmp/git is scratch reference, not a dependency of the tests.

WIP

Design decisions

  • Mod/del policy is impl-known (content side wins, modl, patch.js:147,152) — the rename family (D) pins duplication/stranding, not byte loss.
