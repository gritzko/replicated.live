PATCH-006: whole-tree be patch fails a sub with PATCHCFLCT where a DIRECT sub merge is a clean no-op (ours-ahead gitlink)

Now
DONE

After PATCH-005, be patch be://spot/journal?main! merges the journal level and the be sub cleanly, then reports failed beagle / PATCHCFLCT (content-conflict=0, failed=1) and aborts the whole merge (BEDOGEXIT). But running the SAME beagle merge DIRECTLY — cd beagle && be patch be://spot/journal/beagle?main! — exits 0 with "nothing absorbed — no patch row staged" (a clean no-op; ours beagle 7f9163dd already contains spot's pinned ~8a1f8413, and it recurses abc fine). So the parent's gitlink-diff sub-recursion (BEActSubsPatch) raises a SPURIOUS conflict for a sub that has nothing to absorb (ours is ahead of / equal to theirs), and the whole-tree merge dies on it. The beagle worktree stays clean (1333 ok) — no markers written; the sub just rolls back to ours and the parent aborts. Method Issues.

Context

  • Repro (live 2026-06-26, treadmill): in a be get be://localhost/journal clone, be patch be://spot/journal?main! → applied be, failed beagle, summary noop=203 take-theirs=5 merged=1 added=4 ... content-conflict=0 ... failed=1, PATCHCFLCT / BEDOGEXIT.
  • Direct: cd beagle && be patch be://spot/journal/beagle?main! → rc=0, noop=86 ... failed=0 (nothing absorbed — no patch row staged), recurses abc. So there is NO real beagle conflict — ours ⊇ theirs.
  • beagle sub be status after the failed whole-tree merge: ?7f9163dd… 1333 ok (clean, unchanged) — the parent recursion didn't write conflict markers, it just failed the sub and aborted.
  • So the gitlink-diff recursion mishandles an ours-AHEAD (or nothing-to-absorb) sub pin: it should be a clean take-ours no-op (keep ours, stage no patch row), not PATCHCFLCT. Distinct from PATCH-005 (sub-source resolution, fixed).

Goals

  • The whole-tree merge's sub-recursion treats an ours-ahead / nothing-to-absorb sub gitlink as a clean no-op (keep ours), never PATCHCFLCT; be patch be://spot/journal?main! completes the whole tree.
  • A sub that genuinely DOES conflict still reports loudly (don't suppress real conflicts) — only the no-op/ahead case is reclassified.

Design decisions

The spurious PATCHCFLCT is the parent classifying that no-op as a failure.
