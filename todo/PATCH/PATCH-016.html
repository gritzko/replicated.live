Now
OPEN

Input

Context

be patch emits an internal failed status on four distinct arms, none of which any test under be/test/patch/ reaches: both weave sides empty (be/verbs/patch/patch.js:193), markup-buffer overflow on a token-dense/binary file (patch.js:206-208 — the "out full" catch, no grow-retry unlike the get weave fixed in /todo/PATCH/PATCH-012), unlink throw on a theirs-delete (patch.js:146), and writeLeaf given null bytes (patch.js:234). No patch test feeds a binary file at all. failed is also absent from the /wiki/PATCH reporting word set — it is a code-only word.

Goals

A patchspec.sh case per arm proving the outcome: file counted failed, patch exits loud or clean per ruling, sibling clean files still absorb, wt not corrupted. Plus a spec ruling: does failed join the /wiki/PATCH status set or get renamed/re-routed.

Constraints

  • Binary fixture must be small (a few KiB of dense tokens is enough to overflow the fixed markup cap).
  • The unlink arm likely needs a read-only parent dir trick; keep it hermetic and restore perms in cleanup.
  • Tests only; any behavior change is a separate ticket.
