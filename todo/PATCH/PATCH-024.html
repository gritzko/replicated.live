PATCH-024: an absorbed patch must not move the base — kill baselineTip as a base tree

Now: OPEN Sev: HIGH

An in-scope patch row silently becomes the BASE for several views, so patched-in content goes invisible exactly where it must show. wtlog.baselineTip() resolves "the latest get/post/PATCH sha-row" (shared/wtlog.js:17,249) and consumers then read that sha's tree as the base: diff renders wt-vs-patch (byte-identical → EMPTY output, exit 0) and classifyDir buckets a file that the real base commit tracks as unk. RULING (gritzko, 2026-07-29): patch must NOT affect the base commit; the patched stuff must show in diff and status. Status already says so — base is "the recentmost get/post row" and the patched-in lines are a SEPARATE column "since the base". The correct baseline is curTip(), as classify and status already do.

Input

Context

  • Live incident (gritzko, 2026-07-29, //BRO-041/be/test): after be patch ?2c927d8a, be status correctly shows ..vv diff/13-color-word-wash/run.sh (patch + wt columns lit) while be diff and be diff <path> print NOTHING, exit 0.
  • Cause: views/diff/diff.js:467 takes baselineTip().sha as the from-side, which after the patch row IS the patched sha, so the per-file sha-skip at views/diff/diff.js:287 drops every path.
  • Second symptom, same root: be ls:post/sub-dirty-parent calls the file unk though the base commit 4dd6f80f tracks it — classifyDir reads its base tree from baselineTip() (shared/classify.js:553).
  • Corroboration: be diff ?4dd6f80f (explicit range against the real base) renders the change fine — only the implicit wt-vs-base path is blind.
  • The correct precedent is in-tree: shared/classify.js:249-254 uses curTip and its comment already explains why ("baselineTip folds a patch row's THEIRS sha into the baseline … pat never appeared"); views/status/status.js:341 does the same.
  • wiki/Sniff.mkd (whose line "SNIFFAtBaseline resolves the baseline get/post/patch row" seeded this reading) was DELETED by gritzko on 2026-07-29 — do not restore it, and do not cite it.

Goals

  • The base tree for every wt-relative view is curTip() (recentmost get/post); an absorbed patch never moves it.
  • be diff after a patch renders the patched-in content as a real wt-vs-base diff, matching what status already reports.
  • be ls/list bucket a file tracked by the base commit as tracked, never unk, with a patch row in scope.
  • Every remaining baselineTip() call site is reviewed one by one and either converted or justified in the ticket.

Constraints

  • Do NOT change status's quad semantics — the 4 columns of Status are correct today and are the oracle for this fix.
  • Do NOT delete baselineTip() blindly: some call sites may genuinely want "the latest row of any kind" (e.g. views/refs/refs.js:23 prints it as a baseline: field). Convert what means "base tree", justify the rest.
  • Sub baselines count: views/diff/diff.js:307,556,639 resolve a MOUNTED sub's baseline the same way and must move together with the parent.
  • JS ///be/ only; no C twin in scope.

WIP

Design decisions

  • This is a semantics fix, not a new feature: Status already defines base = get/post row, patch = its own column.
