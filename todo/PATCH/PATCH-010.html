PATCH-010: patch cannot address a tree as its source — tree URIs fall into the cherry-ref slot

Now
DONE

Input

Context

From journal/libdog/abc (the orig tree), every tree-addressed source spelling died in the NAMED-cherry resolver:

  • jab patch file:../../work/ABC-008/abc → PATCHFAIL: cannot resolve cherry ref '../../work/ABC-008/abc'
  • jab patch be://localhost/src/journal/work/ABC-008/abc → same, the be:// AUTHORITY silently dropped, only the path reached the resolver.
  • shared/patchscope.js parseShape knows ?br / ?br! / #sha / bare-ref ONLY; any other URI's path lands in frag → resolveCherry.

Goals

  • patch <tree-uri> (a file:/be://///WT worktree address) resolves that tree's CUR TIP as theirs (the wt's .be cur row / its shard's ref), fork = LCA — the whole-stack absorb of another worktree.
  • a scheme'd/authority-carrying arg patchscope cannot serve refuses LOUDLY naming the arg and the supported forms, never misread as a cherry ref.
  • same-STORE case first (the hive: wt and orig share the shard); the cross-store fetch leg is PATCH-011 (ruling: download first, then all-local).

Constraints

  • URI handling via the URI class only, no regex/manual parsing; resolve fs paths via resolve(context, arg) — the verb resolves, never the pager.
  • repro test first; existing tests untouched; minimal diff (shared/patchscope.js + verbs/patch/patch.js).

WIP

Design decisions

  • accepted source forms: ?<br> | ?<br>! | #<sha> | bare ref | file:<path> (no query/frag/host) | scheme-less //WT[/sub]; anything else → ONE line PATCHFAIL: cannot patch from '<arg>' — supported: … (covers be://, ssh:, and file:…?query store forms — the PATCH-011 seam).
  • TREE absorbs as scope WHOLE (provenance row stays the ?<sha>! grammar POST reads); theirs = the addressed wt's cur tip via wtlog; cross-store gate = object presence (reader.getObject(tip)), refusal names PATCH-011.
