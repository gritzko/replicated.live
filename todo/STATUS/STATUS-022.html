Input

Context

The sweep and why it never shrinks (STATUS-021 Context has the profile): 93 stale work/* clones carry pre-stamp-era organic mtimes; GET-059/POST-037 (landed 04 Aug) stamp only what get/post touch, and no get/post ever runs in a parked wt.

  • Plumbing that already exists: classifyMerge opts.wantConfirmed (POST-037) returns confirmed = exactly the paths whose clean verdict COST a wtEqBase read+sha; stamp-set hits are excluded by construction (classify.js:377-383, provenance per PUT.mkd:27).
  • post.js:997 loops io.setMtime(wtpath(wt,p), rowTs) over that list — the loop to extract, not to duplicate.
  • WHY the stamp cannot live inside classify on a bool arg: post's stamp value is the ASSIGNED post row ts, known only AFTER the ulog append (POST-029 append-returns-assigned, same-ms bumps); status!'s value (the latest get/post row, curTip) is known before. So classify stays a reader and the helper takes the ts from the caller.
  • The bang already routes: verb! → be.force + --force (core/loop.js:379-385, the get! sugar); status.js currently ignores force.
  • STATUS-001's C-era status! (extended branch/remote rows) was never ported to JS status — no semantic collision today; noted, not in scope.

Goals

  • stampConfirmed(repo, paths, ts) — THE one setMtime loop (symlinks skipped: setMtime follows links, get.js:1099 precedent); post.js swaps its inline loop for it, byte-identical post behavior.
  • status!: run the normal classify with wantConfirmed, then stamp the confirmed paths to the wt's latest get/post row ts — the exact value has() accepts; NEVER the DIS-057 ceil-1/2ms band slots; no wtlog row appended; no row → silent no-op.
  • Subs: recurse as status already does, each sub stamping to ITS OWN latest row ts (closes PUT-012's practical gap on this path).
  • Proof: in a wt with N touched-but-clean files, every status run hashes N; after ONE status! the next status/todo hashes 0 there and the mtimes equal the row ts; a second status! restamps nothing (idempotent).
  • Plain status and todo/diff output BYTE-IDENTICAL before/after, both engines; status! prints what status prints (the restamp is silent).

Constraints

  • classify stays a pure reader; wantConfirmed stays opt-gated; buckets/counts/rows untouched.
  • Only wtEqBase-confirmed paths are ever stamped — never a stamp-set hit, never a dirty/patched row.
  • post's stamps keep the assigned row ts discipline unchanged — the helper is a pure refactor on that side.
  • be/ JS only: shared/classify.js (helper), verbs/post/post.js (swap), views/status/status.js (the force leg). No C, no engine, no view redesign.
  • The sweep over the real work/* trees is NOT this ticket — gritzko orders it separately once this lands.

WIP

Design decisions

  • Helper lives in classify.js (it already has wtpath + the confirmed semantics); ulog.js acceptable if import cycles bite — worker's call, noted here.
  • status! stamp ts = wtlogReader.boundaries().pd row's ts (the latest get/post row) — the same floor classify already reads; absent → skip.
  • BUILT (2026-08-11): classify.stampConfirmed(be, paths, ts) — reads be.wt (the classifyMerge house shape), so post passes its info and status its repo; skips symlinks; tolerates a null ts / empty list (silent no-op); returns the count.
  • post.js:997's 3-line inline loop → one classify.stampConfirmed(info, dres.confirmed, rowTs) call, in place, same position relative to the ulog.append — same paths, same assigned ts, same order.
  • status.js force leg: ambient.force() → opts.wantConfirmed on the quadOf call, then stampConfirmed(repo, model.confirmed, log.boundaries().pd) INSIDE gatherInto — so each recursed sub stamps with its OWN log and its OWN row ts, no threading.
  • gatherRepo's STATUS-019 memo is BYPASSED under force: a memo hit would skip the classify, and status! must stamp exactly what a real classify run hashed. Plain reads keep the memo untouched.

Design deviations (reported, not asked for)

  • shared/quad.js +7/-2, OUTSIDE the named 3-file scope. status does not call classifyMerge — quadlib.quadOf does — and quadOf built its own opts literal, dropping anything status passed. The alternative (status running a SECOND whole-tree classifyMerge just for the list) doubles every content read on the force path. So quadOf forwards wantConfirmed and hangs m.confirmed on the model; undefined for every other reader, which is why the byte-identity captures come out clean.
  • SYMLINK finding: the ruling's premise ("io.setMtime FOLLOWS the link", get.js:1099) is STALE for the JS io binding. Probed on both engines: io.setMtime(<symlink>) moves the LINK's own mtime and leaves the target's untouched (lutimes semantics). The skip is implemented AS RULED anyway (a link's clean verdict is about its target PATH, not about bytes); the code comment states that reason instead of the stale one. Consequence: a tracked symlink stays off the stamp-set and is re-readlink'ed by every status — cheap, and unchanged from today.
  • That skip is the ONE post-side behavior delta: pre-refactor post stamped a content-confirmed symlink's own mtime, now it does not. Whole suite green either way; test/status/restamp pins the skip (removing the guard turns it RED with FALSESTAMP link.lnk).
