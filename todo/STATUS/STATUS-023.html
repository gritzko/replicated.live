~/src/quickjab-DOG-047 carries 14 changed files: pack.c in the parent, 10 inside the dog submodule, 3 inside test (git status --short: M pack.c, m dog, m test). All three status surfaces — the HTML view, the TUI pager and the CLI, one shared emitter (view/status.js) — show ONE row, pack.c, and no submodule at all. Yet the bee wts board row says [ i 14 ]: the BEE-040 tally descends the mounts (view/wtstat.js:111:4I) and counts every file, so the tally and the listing disagree about the same tree. Submodule changes must show, and in HTML/pager the rows must be clickable.

Input

Context

  • Suspected cause: view/status.js:110:wtSha — a gitlink answers with the submodule's OWN HEAD sha, so only an ADVANCED sub (new commits, glyph v) ever differs from the recorded sha; uncommitted edits inside the sub never move its head, so a content-dirty sub compares clean and wtOf emits nothing.
  • view/wtstat.js already solves the descent for the tally: depth-first over index/subs.js mounts(), one status read per live mount, an unreadable sub tallies nothing (STATUS-019 replay) — the listing needs the same walk, not a new one.
  • Captured HTML body (2026-08-24): one hunk, rows ... ↑ pack.c and DOG-047...main 1 wt.
  • BONUS EVIDENCE, possibly the same emit path: that one row's href reads /quickjab-DOG-047/dog/pack.c — a submodule prefix on a ROOT file (pack.c sits at the repo root), a dead link in both the file arrow and the name. If the cause proves unrelated, split it out as its own ticket.

Goals

  • A content-dirty submodule SHOWS on all three surfaces: a row per changed file inside the sub, the path mount-qualified (dog/WHIFF.h, test/repack.js), nested mounts recursing (dog/abc).
  • HTML and pager rows are CLICKABLE and the hrefs resolve: /quickjab-DOG-047/dog/WHIFF.h, and the parent-root pack.c row links to /quickjab-DOG-047/pack.c.
  • The advanced-sub v row stays as it is (Status glyphs); dirty-content and advanced states can coexist on one sub.
  • The listing agrees with the bee wts tally: same walk, same count.
  • A repro test pinning: parent file + dirty sub file + nested sub file all listed, hrefs correct.

Constraints

  • BEE-040 semantics stay: an uninitialised sub reads unchanged, an unreadable sub emits nothing and never errors the view.
  • A skipped optional sub (BEE-059) stays silent.
  • No flooding: untracked scanning inside a sub rides the same igno chain discipline as the parent (view/status.js ignoStack).
  • One emitter: the fix lands in the shared view, not per-surface forks.

WIP

Design decisions

  • The "bonus evidence" href was NO BUG: /quickjab-DOG-047/dog/pack.c is /<repo>/<verb>/<path> and dog is the BEE-046 VERB (http.js:88:gw route table), not a submodule prefix; test/substat/href.js pins both spellings. No split ticket.
  • The mounts' rows splice in at PAINT time, not into model.rows: BEE-040's contract (a repo's model is its OWN rows, foldSubs adds the mounts on top) stays, and test/subfold keeps passing unedited.
