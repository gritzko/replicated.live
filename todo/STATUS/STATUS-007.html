STATUS-007: a declared sub with a live gitlink but no anchor buckets as ok — an unmounted sub is invisible

Now
OPEN
Sev
HIGH

Input

Context

Found 2026-07-14 on journal/be: jab status printed 91 ok and no status test hunk while be/test had lost its .be anchor (SUBS-053). A whole submodule had silently dropped out of the status view and the summary still read all-clean.

  • views/status/status.js:308-322 — const mounted = isMount(repo.wt, gl.path); an unmounted gitlink takes the else and lands in res.counts.ok++, indistinguishable from a clean file.
  • views/status/status.js:432 — the recursion gate if (!s || !s.mounted) continue; drops the sub's own hunk, so nothing else hints at the loss.
  • Net effect: a declared sub whose mount is gone reads EXACTLY like a healthy one — jab status test even answers 1 ok.
  • A sub declared in .gitmodules WITH a live 160000 gitlink but NO anchor is a broken tree state, not an ok one.
  • Confirmed end-to-end: deleting only test/.be in a clean clone reproduces the exact symptom (91 ok, no sub hunk); restoring the anchor brings the hunk back.
  • The isMount gate itself is correct (SUBS-049 shape, status.js:480-488) — the bug is the BUCKET an unmounted sub falls into, not the detection.
  • Native parity: check what C be status reports for a declared-but-unmounted sub before picking the verb.

Goals

  • A declared sub with a live gitlink and no anchor emits a LOUD row (e.g. a mis-class verb), never a silent ok tally.
  • The summary line reflects the broken sub so a bare jab status can't read all-clean over a lost mount.
  • A clean unmounted-by-design case (if any exists) stays distinguishable from a LOST mount.

Constraints

  • Repro test first (work); fix in beagle-ext (JS), no C changes.
  • Do not change the isMount detection shape (SUBS-049).
  • Keep status byte-parity with native for every case that is NOT a broken sub; confirm the native verb first.
  • Minimal diff; no edits to unrelated tests.

WIP

Design decisions

  • Sketch: in the else at status.js:310-311, split "declared + gitlink + no anchor" out of the ok bucket into its own row + counter; keep the recursion skip (there is no shard to recurse into).
  • Verb choice is open — mis reads naturally (the mount is missing) but must be checked against native be status and the todo bucket table first.
