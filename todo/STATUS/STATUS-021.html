Post-BE-065 profile (2026-08-11, pty first frame, journal tree): the classify content sweep is the crawl's heaviest term. todo content-reads 16,639 files per COLD first frame — 14,478 of them working files inside 93 stale work/* clones whose organic (pre-stamp-era) mtimes miss the STATUS-011 stamp set forever. Each hashed file pays TWO io.buf allocations and TWO copies (wtBlobSha read buf, then frameSha's header+content re-copy) — the 1.03 M minor faults and most of musl's 43.5% of quickjab's wall. Goal: ONE grow-only per-run scratch, header encoded in place, sha over the read bytes — zero per-file buffer allocs, one copy (the read itself).

Input

Context

Measured on the BE-065 tree (jab 2.29 s / quickjab 4.98 s first frame medians; strace + SIGPROF module rollup, ~/tmp/BE065/).

  • Native profile, quickjab binary samples: sha1dc family 20.3% (sha1_compression_states 12.4 + ubc_check 6.2 + rest), all under the sweep; musl (mallocng+memcpy) is 43.5% of WALL, jab's musl 23.5%.
  • Content reads per cold todo frame: 16,639 O_RDONLY opens; 15,403 under work/ (93 worktrees, 600-850 each), 1.2k in the main tree. Piped runs read none — this is the tty crawl arming the repo caches.
  • WHY the stamp fast path misses: old clones (e.g. work/DOG-016, 10 Jul, file:/~/src/libdog/.be era) carry organic ns mtimes — never stamped; no get/post will ever run there to stamp them (DIS-023: status is a reader, never a re-stamper). A FRESH clone (work/BE-065) is fully ms-stamped and skips its wt files.
  • Per-file cost today (classify.js wtBlobSha + util/sha.js frameSha): io.buf(size+16) + readAll + data(), then frameSha does utf8.Encode(header) + a SECOND io.buf(hdr+size) + feed(hdr) + feed(content) + sha1. Two allocs, two copies, per file, 14.5k times.
  • buf (jab/buf.cpp Buf class) already supports the cure: reset() reuse, feedStr utf8-encodes into IDLE in place, data() is a no-copy subarray view; sha1 (codec) takes any u8 view.

Goals

  • Zero per-file buffer allocations on the sweep: ONE module-level grow-only scratch buf, reset() per file; grow only when a file exceeds it.
  • One copy per file: feedStr the "blob <size>\0" header into the scratch, readAll the content in AFTER it, sha1 over data() — the frameSha double-copy dies on this path.
  • Output BYTE-IDENTICAL (todo, status, diff, pty+piped, both engines); be suite green, no test edits.
  • Before/after: first-frame medians (jab + quickjab), minflt, and the mmap/munmap pair count; target >= 10% on quickjab's first frame.

Constraints

  • frameSha(type, content) keeps its contract for the other callers (keeper, wire, dag ...) — add a scratch-backed variant or fuse inside wtBlobSha; do NOT change frameSha's signature.
  • No io.mmap on the sweep (the JS-side mapping leak — classify.js:148 comment — stands); the fd read stays.
  • classify semantics untouched: same files hashed, same stamp-set shortcut, same buckets. This ticket is allocation shape ONLY.
  • Scope: be/ JS (shared/classify.js, shared/util/sha.js); no C, no engine, no view changes.

WIP

Design decisions

  • Scratch lifetime: module-level in sha.js (or classify.js), grow-only doubling; readAll must land into the scratch's IDLE after the header — verify jab's io.readAll(fd, buf, n) appends at IDLE (buf.cpp flow) on BOTH engines before relying on it.
  • A file larger than the scratch grows it once (size+header, rounded up); no shrink, no per-file free.
  • RULING 2026-08-12 (gritzko): grow-only io.buf doubling is out — ONE io.ram scratch (anonymous mmap, io.cpp:708, pages fault lazily) sized 256 MiB virtual, created on first use, never grown; a file over the cap falls back to the old one-shot io.buf + frameSha path.

readAll-at-IDLE probe 2026-08-11

~/tmp/STATUS021/probe.js, both engines, same answers: feedStr("blob 11\0") writes 8 bytes (NUL is one byte, 98,108,111,98,32,49,49,0); io.readAll(fd, buf) lands the file bytes at the buf's IDLE cursor right after them (buf.size 8 -> 19, bytes = header ++ "hello world"), sha 95d09f2b... = git's blob sha and = the current two-buffer path's answer. Notes on the binding (jab/buf.cpp): io.readAll(fd, buf, n) IGNORES the 3rd arg — it fills to room, so today's io.buf(st.size+16) is what bounds the read, not st.size; a big shared scratch would read to EOF instead. Hence the fix reads into a BOUNDED b.idle().subarray(0, size) (the bare-u8 readAll leaf), which also saves the trailing 0-byte read(2) the Buf leaf does.

Blockers and bummers

Parked for gritzko — the sweep's EXISTENCE, not its allocation shape (this ticket only fixes the latter):

  • 93 stale work/* clones are re-hashed EVERY cold frame; nothing will ever stamp them. Options needing a ruling: a persistent per-wt tally record with a cold-start witness (STATUS-019 territory), lazy/deferred wt classify in the todo view, or plain housekeeping (rm -rf merged wts, work.mkd already allows).
  • wtEqBase compares against a KNOWN sha — collision detection buys nothing there; a plain-sha1 (non-DC) leaf would ~halve hash CPU but means a C/binding change (jab is read-only for agents).

Outcome

Staged (put only, NO post) in //STATUS-021, base //BE-065/#621309f8: shared/util/sha.js (+31/-1), shared/classify.js (+6/-5).

  • sha.js gains blobShaOfFd(fd, size) over ONE module-level io.ram(1<<28) scratch (anonymous mmap, lazy fault-in, created on first use, never grown, never freed): reset(), feedStr("blob <size>\0"), io.readAll the content into IDLE behind it, hex.encode(sha1(b.data())) over the no-copy view. Zero per-file buffer allocs, one copy — the read; a >256 MiB file falls back to the old one-shot io.buf + frameSha path.
  • Reworked 2026-08-12 per gritzko's ruling (was: grow-only io.buf doubling); re-verified: growprobe 11 sizes + short-read parity both engines, ident.sh 28/28 captures cmp-equal vs pre-ticket code (piped+pty x jab+quickjab x todo/status/diff), ctest 375/375.
  • frameSha(type, content) is untouched: same signature, same body, still what keeper/wire/dag/expected call, and still what the symlink + empty-file + EXPECTED branches of classify call.
  • classify.js wtBlobSha regular-file branch returns blobShaOfFd(fd, st.size) instead of building io.buf(st.size+16) -> data() -> frameSha. Same lstat, same kinds, same undefined on every failure, same stamp-set shortcut, same buckets — allocation shape only.
  • Design deviation, one: the read is BOUNDED to size (b.idle().subarray(0, size)) rather than handed the whole scratch. io.readAll(fd, buf, n) ignores its 3rd arg and fills to room, so an unbounded read into a big shared scratch would read past size on a file growing under us and mis-frame it; the bound also drops the trailing 0-byte read(2). A short read (file shrank) falls back to frameSha over the bytes actually read — exactly what the old code's content.length header did.
  • Suggested commit: STATUS-021: one grow-only scratch for the content sweep
