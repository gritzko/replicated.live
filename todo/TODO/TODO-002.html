TODO-002: board rows show TODO-list progress badges — KEY [7/10] title

Now
OPEN

Every ticket carries a ### TODOs checkbox list (/meta/todo: -[ ] open, [v] done, [-] blocked, [x] wontfix/moot, nesting allowed). The board and topic lists can surface that as a short per-row progress badge, so todo reads as a progress dashboard, not just a title index.

Input

Context

views/todo/todo.js list rows render KEY [MARK]: title off the header line only; the TODO tally inside the page is invisible until the page is opened.

  • The mark vocabulary is grown open (JS/UMBRELLA precedent) — a badge is display chrome, NOT a new header mark; the header line stays untouched.
  • Cost: counting requires the ticket BODY — open tickets only (~250 files, 2-8 KB each), and the board already opens each file; this supersedes the TODO-001 bounded-head bullet (amended there, full-but-single read).

Goals

List rows for OPEN tickets carry [done/total] for the live TODO items; a ticket with no TODO list shows no badge.

  • Count scope: the ### TODOs section ONLY (Input/Context may quote checkbox lines as evidence); nested items count as items.
  • Tally: [v] = done; [ ] and [-] = open; [x] moot drops from the denominator. [7/10] reads "7 of 10 live items resolved".
  • [0/0] never renders (all-moot list = no badge); an all-done [n/n] on a still-open ticket is a nudge to close it, worth showing.
  • Placement: after the KEY, before the title rest, both board and todo TOPIC lists; plain and pager alike (content, not chrome).

Constraints

  • Checkbox scan is a per-line char scan (- [ + one state char + ]) — no regex engine growth, tolerant of indentation; malformed lines don't count.
  • One read per file: title AND tally come off the same bytes (no second open); TODO-001's memo/probe fixes compose, don't conflict.
  • Existing todo tests keep passing modulo the added badge; the repro test pins the tally rules above.
