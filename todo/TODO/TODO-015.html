Input

Context

The todo board re-derives per-file facts on every paint: every ticket file is mmap'd and parsed for its head, read whole and SHA-1'd for the dirty check, and every ticket worktree gets a full status walk (profile 2026-08-21, ~0.45s warm / 1.34s cold for 975 rows). Each fact is a pure function of file bytes that rarely change. be/ already solved this shape in TODO-006 (structured per-block cache, per-dir rev witnesses, resident-only memo); bee needs the same, but PERSISTENT, since the CLI is one-shot and cache.js rules "no watcher, no memo" for in-memory revs.

Goals

One caching discipline the three sub-tickets share — TODO-016 (blob-sha stat cache), TODO-017 (ticket heads in the lane), TODO-018 (worktree status): derived values accumulate in the repo's own <gitdir>/be/ lane (where all derived data lives, INDEXES.mkd), and staleness is answered at the DIR grain, not the repo grain.

Constraints

Ruling (gritzko 2026-08-21): per-repo drop is too coarse — one ticket edit must not void a thousand entries. The DROP unit is the directory, matching what index/cache.js already attributes: its rev tree is per-dir ("an event stamps its own dir AND every ancestor"), so a resident process drops exactly the touched dir's bucket. The STORAGE unit stays per-repo (one lane per gitdir); buckets subdivide it by dir. A one-shot run has no watcher, so every entry also carries its own (size, mtime) witness — git's stat-cache discipline — and cold validation is a stat, never a read.

WIP

Design decisions

  • Two-tier freshness: resident = rev(dir) gates the bucket (one compare skips every stat below it); one-shot = per-entry stat witness.
  • Entries are mutable cells, kv-style: a re-put overwrites, nothing is deleted; rm -rf <gitdir>/be rebuilds everything (INDEXES.mkd).
  • Sub-tickets: TODO-016 (Sub), TODO-017 (Sub), TODO-018 (Sub).
