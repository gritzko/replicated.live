Input

Context

Profiled jab todo 2026-07-24 (786 tickets on disk, warm cache): 4403 syscalls — 888 opens, 854 stat + 757 lstat, 1535 reads.

  • views/todo/todo.js listTopic: readdir yields KEY.mkd / KEY/, then pageFile(dir, key) re-probes up to 6 paths (3 exts thin + 3 fat) — ~800 avoidable stats per board.
  • readBytes reads min(st.size, 1 MiB) — the WHOLE file — but pageTitle uses bytes up to the first \n only.
  • views/work/work.js is a second payer: ticketTitle/ticketLink per wt row call todo.boardDir() (a stat) + pageFile probes + a full pageTitle read, 93 rows, zero memoization.

Goals

No path is probed twice: a name readdir returned, or a file already found this run, is never re-discovered.

  • listTopic derives the page file straight from the readdir entry (KEY.<ext> file, or KEY/ dir → README probe only then); pageFile stays for direct todo KEY addressing.
  • work.js memoizes boardDir + per-key title/link per render run (or todo.js exposes a memoizing lookup for consumers).
  • strace acceptance: the 800 pageFile re-probe stats are gone from jab todo; jab work's todo-side stats drop 3x.
  • OUT OF SCOPE (narrowed): pageTitle read size — the full-read-serves-/todo/TODO/TODO-002 plan moves with that ticket.

Constraints

  • Rendering stays byte-identical (existing todo/work tests are the harness); todo KEY direct addressing keeps working for closed tickets and fat layouts.
  • No caching across runs in this ticket — the wt-level title index is a separate discussion (deliberately out of scope here).
  • The 1 MiB CAP stays for emitPage (full page render still reads the file).
