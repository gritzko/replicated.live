The BRO-043 ruling stands as written — bucket plus ancestors, revs only under a live watcher, arming lazy on the query. What is over-eager is what counts as an event. shared/cache.js parses each fsw record and then THROWS THE NAME AWAY (cache.js:126-127, "for revs the dir is all we need"): every write in an armed dir bumps that dir and all its ancestors, whether the name is a ticket, a *.o, a .swp or a rename artifact. The ignore rules are applied to the arming WALK's directories (cache.js:161-163) and to nothing else, so the very names the project's own .gitignore files under # editor junk are the ones that drop the caches. Measured on a real board in a resident process (probes in the TODO-012 worktree, test/todo/junkev/): opening a ticket in vim and quitting WITHOUT saving costs TWO full board-rowset rebuilds; a gitignored *.o under a worktree costs that worktree a full classifyMerge and repaints byte-identical rows.

MEASURED NEGATIVES — suspicions ruled out, so nobody re-chases them:

  • *No self-inflicted loop.* A quiet board render opens ZERO files for write. jab status / jab diff, run repeatedly, leave <wt>/.be and <wt>/..be.idx byte- and mtime-identical. The store lives at ~/.be/<project>/, OUTSIDE the watched tree, so metaidx and keeper writes fire no events at all.
  • *The fsw mask carries no ACCESS/OPEN.* Probed directly on a bare fsw watcher: io.read of a watched file, io.lstat and io.readdir each produce 0 events (creates give 2, a write 2, a rename 2, mkdir 1, io.setMtime 0). A view cannot invalidate itself by reading.
  • *The per-block witnesses hold.* A junk event under one worktree drops that worktree's blocks only — touch=0, other rows byte-identical — and one ticket edit in todo/BUG re-lists BUG only, never TIC (traced: wtWalk←arm←rev←openTickets and listTopic←openTickets on BUG alone). The TODO-006 r3 split is doing its job; the leak is upstream of it.

WHAT IT COSTS ON THE REAL TREE (/home/gritzko/src/journal, 901 tickets, 58 topic dirs):

  • The arming re-walk of todo/ — paid on EVERY miss of that spot, i.e. once per junk event — is 109 ms warm, 3.2 s cold, 976 names.

Goals

An event that cannot change what a view read must not drop what that view cached. Nothing about the BRO-043 ruling changes: bucket plus ancestors, live-watcher-only, lazy arming, R drops all.

  • poll() reads the record's name and asks the ignore rules whether that path could matter before bumping. The matcher is already loaded per armed spot in arm() (cache.js:158); today it is thrown away after the walk.
  • The filter is a PURE OPTIMIZATION: on kqueue name is "" (rescan), and that must bump exactly as it does today. With the filter disabled every view behaves byte for byte as it does now — the BRO-043 constraint, unchanged.
  • .be stays re-admitted (its wtlog rows are a status input) but ..be.idx and *.keeper.idx are not: they are gitignored sidecars no view reads.
  • One drain round bumps a dir at most ONCE. Only the final rev is ever compared, so this is free semantically and makes the drops counter honest (400 files = 400 bumps today, 1200 recorded).
  • A burst poisons ONE render, not N: after an OVERFLOW the queue is drained to empty before the query is answered, instead of leaving the tail behind the 1024-round guard.

Constraints

  • Pure performance, again: with the name filter off, every view renders identically. The rowcache and status/cache tests are the byte-parity nets.
  • fsw.unwatch cannot remove a kernel watch (ABC-013), so the fix can never be "stop watching the junk dir" — it has to be a decision taken at drain time.
  • name is a BARE basename; the ignore matcher wants a path relative to the ignore root. Reconstruct it from the wd's dir, which S.dirOf already holds (cache.js:128) — do NOT re-derive roots by hand.
  • Reuse shared/util/ignore.js load/match (the same instance arm builds) — no second matcher, no hand-rolled name rules (reuse-libdog).
  • The rev tree stores no view values and learns no view semantics beyond "is this path ignored" without gritzko's word: see the Blockers on the ticket-name question.

Blockers and bummers

  • A scratch file in a topic dir that is NOT gitignored (todo/TIC/notes.txt) is invisible to the BOARD but is a real untracked file for status — so the right filter differs per SPOT: ignore rules for a worktree spot, "is this a ticket file" for a board spot. Teaching the rev tree a per-spot name predicate is a design step beyond the ignore filter and needs gritzko's call; the ignore filter alone already covers .swp, *.o, *.log, *.lock, *~ and every build*/ artifact.
  • kqueue reports no name, so macOS keeps today's behaviour exactly — the win is Linux-only, and the tests must not assume the filter fires.
  • The 1024-round guard and the 64 KB drain Buf (cache.js:74, cache.js:115) are the mechanism behind the multi-render poisoning; raising either without a bound is how the burst path grows unbounded latency instead.
  • The probes live in the TODO-012 worktree at test/todo/junkev/ (fixture.sh + probe.js, probe2.js, probe3.js, probe4.js, probe5.js, ptyprobe.py), UNSTAGED and never posted — they are evidence, not a fix, and PROBE=<file> sh fixture.sh reruns any of them.
  • A jab todo --tlv on the real journal tree took 12 m wall for 7 s of user time while other jab processes were running — store-lock contention, not board cost; do not read that number as a board profile.
