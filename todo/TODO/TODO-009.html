shared/metaidx.js hand-rolls the meta-pair key as KEYRE [A-Z][a-z][a-z]: — but the DOG-026 grammar (the truth) is:

meta = (upper lower (lower|dig) ':' @mt_run) sp @mt_set ;

The 3rd key char may be a DIGIT: relation keys On1:, On2: … Key+colon IS the quad, the gap is content — mt_set fires on the gap, so Due:x stays a paragraph. metaidx must mirror this.

Input

Context

  • KEYRE rejects On1:/On2:, which todo registers; the TODO-003 index never sees them.
  • metaBlock stops at the first non-pair line — correct per the grammar (the block is consecutive pairs) — but the wrong KEYRE makes an On1: line END the block, so every pair BELOW it is silently dropped from the index.
  • TODO-008 repro'd the loss: an Ask: gritzko under an On1: line is invisible to todo Ask:*. ABC-023, BE-063 and TODO-009 itself all carry that shape today.

Goals

  • metaidx key class == the grammar, exactly: upper lower (lower|dig) ':' followed by the sp gap; no wider, no narrower.
  • Pairs below a relation key index again; todo On1:* works.
  • Red-first repro: fixture ticket with Ask: under On1: — todo Ask:* misses it today, finds it after.

Constraints

  • The gap rule holds: Due:x (no sp after the colon) is NOT a pair — verify the JS verdicts against the real tokenizer (probe via jab; ///jab/dog is the dog reference) on the edge forms: gapless, empty value, digit key.
  • Already-indexed tickets carry the truncated rows — check the TODO-003 index invalidation and force a reindex (format version bump or equivalent), or stale answers persist.
  • No change to the registered-keys list or ticket format; todo and wiki stay as written.
