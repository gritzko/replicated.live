PUT-004 MED: be put bare-walk + in-process submodule recursion (be/ JS)

Bare be put (no path args) is unimplemented in the be/ JS port: the handler THROWS PUT_BARE_DEFER and be-js-put-bare is xfail in be/test/CMakeLists.txt. PUT also never descends into submodules (gitlink subtrees are skipped). This ticket lands two things: (1) BARE-WALK staging sourced from the NON-recursive classifier + the wtlog's already-staged put/delete rows, auto-pairing mis+unk moves by content sha; (2) IN-PROCESS submodule recursion (mirroring GET's mountGitlink/recurseSubMounts, NOT the job log) so a staged path crossing a mounted-sub root delegates into the sub. Prereq: consolidate the THREE copied .gitmodules parsers into one shared/gitmodules.js. Scope be/ JS. Parent DIS-058; the <sub>/<path> delegation primitive is SUBS-039; depth-cap pattern SUBS-041; one-hunk-per-invocation is PUT-003. Spec Submodules / PUT / Dirty. Method Issues.

Input

Context

  • Bare be put THROWS PUT_BARE_DEFER — the seededRowCount===0 arm of the

    be/verbs/put/put.js handler; no tracked-dirty walk, no move auto-pair.

  • be-js-put-bare is parked in _BE_WILL_FAIL (be/test/CMakeLists.txt:24);

    its case be/test/put/bare/run.sh already covers move-pair + tracked-dirty + skipped-untracked + restamp.

  • shared/stage.js already has a bareWalk()/detectMoves() (a native mirror),

    UNUSED — the chosen source is the per-repo classifier instead (shared/classify.js::classifyMerge, which folds base⊕wt⊕wtlog-put/del).

  • PUT skips gitlink subtrees (stage.js:149 baseOrder kind==="s"; stage.js:261

    expandDir), so be put <sub>/file and a dirty sub are silently dropped.

  • GET recurses subs IN-PROCESS: leaf() kind "s" → mountGitlink →

    submount.mount + recurseSubMounts (get.js:687/736/756), depth-capped MAX_SUBMODULE_DEPTH=8; the job queue carries only single-repo rows.

  • THREE .gitmodules parsers exist: core/recurse.js::gitmodulesOrder,

    views/status/status.js::gitmodulesOrder, shared/submount.js::gitmodulesUrl.

  • User-reported 2026-07-02 (JS): bare jab put (no path args) does not descend

    into mounted submodules at all — the concrete symptom this ticket's in-process sub-recursion deliverable closes; the oracle is native be put.

Goals

  • Bare be put stages every tracked-and-dirty (mod) file as one put row each,

    auto-pairs mis+unk same-content-sha paths as silent mov rows (PUTAMBIG if not strictly 1:1), restamps clean files, and NEVER stages untracked (unk) — per PUT "Bare be put".

  • The list comes from the per-repo NON-recursive classifier; paths already staged

    (wtlog put/delete since the last get/post boundary) are not re-staged.

  • A staged path crossing a MOUNTED sub root delegates into the sub:

    be.find(<wt>/<sub>) → run PUT in-process on the remaining subpath (pre-order, depth-first, cap 8); --nosub opts out; recursion is default-on.

  • ONE put: hunk PER repo (parent + each sub emits its own), not a merged or

    path-prefixed banner.

  • ONE shared shared/gitmodules.js (parse / paths / urlOf) replaces the

    three copies, byte-parity preserved.

Constraints

  • be/ JS only; libabc+libdog. REUSE GET's in-process recursion shape +

    core/recurse.js (isMount/joinPrefix) + be.find/store; do NOT route sub recursion through the job log (ctx.repo is pinned per run).

  • Parent wtlog is NOT written on descent — the gitlink pin bump stays POST's job

    (post.js::postSubs, SUBS-019/DIS-058 D7).

  • Repro-first (CLAUDE §17): a bare-put case (tracked-dirty + move-pair +

    skipped-untracked + restamp) and a <sub>/file + dirty-sub bare case.

  • Do NOT regress named file/dir/move/ref forms, the manual be put <sub>#<sha>

    bump (SUBS-019), or DIS-058 get/post recursion.

WIP

Design decisions

  • Factor put.js into putRepo(repo, ctx) shared by the per-arg leaf and the bare

    path; bare is a one-shot fold (like delete.js _delDone), not per-arg fan-out.

  • Source the bare dirty list from classify.js (non-recursive) + wtlog put/del;

    auto-pair mis+unk by content sha (keep a sha→path map — the mis baseline blob sha vs the unk on-disk hash).

  • Submodule recursion is IN-PROCESS (mirror GET), NOT the job log (the ruling);

    depth cap 8, --nosub opt-out, hunk per repo.

  • Consolidate .gitmodules parsing into shared/gitmodules.js FIRST; rewire

    recurse.js / status.js / submount.js onto it (reuses the SUBS-039 read spine).

  • Coordinate the <sub>/<path> split with SUBS-039 (the general delegation

    routine) so PUT does not fork a parallel walk.
