PUT-006 MED: be put <dir>/ re-stages every UNCHANGED file (status says ok)

jab put test/ on a store-backed worktree stages ALL 214 already-committed files under the test/ submodule mount as fresh put rows, even though jab status calls the SAME tree 214 ok (clean, no changes). Only genuinely new / modified files should stage; an unchanged tracked file must emit NO row. The gate stage.js::expandDir uses (w.ts != null && wtlogReader.has(w.ts) — mtime stamp-set membership, NOT a content-sha compare) disagrees with what classify/status call clean, so the whole subtree re-stages. Reflog noise, and a following post would commit a spurious whole-subtree re-add. Method: Issues.

Input

  • Repro on a CLEAN store-backed get (jab get file:/$HOME/.be/?/beagle-ext

    into an empty dir): jab status = 214 ok under ?/beagle-ext-tests.

  • jab put test/ → exit 0, then jab status shows all 214 files as

    HH:MM put test/<path> — every unchanged already-committed file re-staged.

  • Live evidence tree: /home/gritzko/JS-072 (do NOT mutate — kept as the repro;

  • put <dir>/ and status AGREE: a tree status calls all-ok yields an

    empty put (a second put dir/ already emits nothing — idempotence).
