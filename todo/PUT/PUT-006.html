PUT-006: be put <dir>/ re-stages every UNCHANGED file (status says ok)

Now
DONE

jab put test/ on a store-backed worktree stages ALL 214 already-committed files under the test/ submodule mount as fresh put rows, even though jab status calls the SAME tree 214 ok (clean, no changes). Only genuinely new / modified files should stage; an unchanged tracked file must emit NO row. The gate stage.js::expandDir uses (w.ts != null && wtlogReader.has(w.ts) — mtime stamp-set membership, NOT a content-sha compare) disagrees with what classify/status call clean, so the whole subtree re-stages. Reflog noise, and a following post would commit a spurious whole-subtree re-add. Method: Issues.

  • jab put test/ → exit 0, then jab status shows all 214 files as HH:MM put test/<path> — every unchanged already-committed file re-staged.
  • Live evidence tree: /home/gritzko/JS-072 (do NOT mutate — kept as the repro; its test/ shows the same all-put state from a user :put test/).

Goals

  • be put <dir>/ (incl. a submodule mount) stages ONLY content-changed / new files; an unchanged tracked file (wt sha == base sha) emits no put row.
  • put <dir>/ and status AGREE: a tree status calls all-ok yields an empty put (a second put dir/ already emits nothing — idempotence).

Constraints

  • Scope to the staging engine (shared/stage.js expandDir) + whatever content-sha compare it needs; do not regress bare be put (PUT-004), the explicit-move, or the named-single-file paths.

  • Keep idempotence keyed on the full get/post/put stamp-set.
