PUT-013: a STAGED file modified again is invisible — bare put skips it, status shows the stale stamp

Now
OPEN
Sev
HIGH

RULING (gritzko, chat 2026-07-20): jab put must stage ALL changed files, submodules included. Today the bare form stages a dirty file exactly once: modify it again AFTER it is staged and bare jab put silently stages nothing, while jab status keeps showing the staged marker and the OLD timestamp — so the working copy silently diverges from what would be committed. jab diff DOES see the change, so status and put disagree with diff. PUT-009's fold (mod→put, unk→skip) is right; the CLASSIFICATION is wrong — an already-staged file that changes again is no longer recognised as mod.

Input

Context

  • Repro 2026-07-20 in work/BRO-040 (pristine ///be/ clone, root tree + the mounted test sub), each step verified:
    1. modify shared/spell.js (root) and test/CMakeLists.txt (sub) → jab status shows ...v in BOTH trees.
    2. bare jab put → stages BOTH, prints put shared/spell.js / put test/CMakeLists.txt, markers go ...V. Submodule recursion is CORRECT here.
    3. modify BOTH files AGAIN → jab status still shows ...V with the ORIGINAL 12:46 stamp; no dirty marker, no hint the file changed.
    4. bare jab put → prints only the tree headers (?, test) and stages NOTHING, silently, exit 0.
    5. jab diff shared/spell.js DOES show both probe lines pending → working ≠ staged, the change is real and detectable.
    6. explicit jab put shared/spell.js → re-stages, stamp advances to 12:47. The manual form is the only escape.
  • Live hit that surfaced it: the JS-120 comment-trim pass re-edited six ALREADY-STAGED files; bare jab put staged none of them and status showed the stale stamp — the worker only noticed because it named every path explicitly. A commit there would have carried the PRE-trim bytes.
  • Sibling, different cause: PUT-012 (sub-mount checkout skips the GET-049 restamp) also ends in "status and put disagree"; PUT-005 is the same family of staging-display drift. PUT-008 (bare put ignores the cwd/nav context) is orthogonal — do not fold.
  • PUT-009 DONE is the governing ruling and STANDS: bare fold is mod→put, mis↔unk→mv auto-pair, ok→restamp, unk→skip, deletions are delete's job. Nothing here reopens the unk question.

Goals

  • Bare jab put stages a staged-then-modified file, in the root tree AND inside every mounted sub — "all changed files, submods included".
  • jab status must never show a staged-and-since-modified file as settled: it carries a dirty marker and a current stamp, so status agrees with jab diff.
  • The staged bytes always equal the working bytes after a bare put, or the file is reported — never a silent skip with exit 0.

Constraints

  • Do NOT reopen PUT-009: untracked stays manual-only, deletions stay delete's job.
  • Fix the CLASSIFIER (be/shared/classify.js), not the put verb per-case; status, put and diff must read one classification.
  • Rulings in force: errors and states in plain words; resolution via be/core/resolve_hash.js.
  • Repro-first per work: the 6-step dance above is the acceptance test, root tree and sub.
