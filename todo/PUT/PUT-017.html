Beagle has no repo-init interface. The only bootstrap today is the implicit one: seed an empty .be/ dir and the first rw command mints a born-sharded store in place (be/test/lib/repo-setup.sh:22 rs_fresh_wt documents it; be/shared/store.js:211 "the shard a first write mints"). There is no way at all to init a wt anchored on a central store (~/.be): that .be FILE — the row-0 anchor — can only be hand-written. Live case: turning quickjab/, a plain dir nested INSIDE the journal wt, into a repo.

Input

Context

  • Implicit bootstrap only: an empty .be/ dir plus a first write; nothing names the store, the title or the anchor shape.
  • Central-store init is hand-editing: journal's row 0 is 26625HI34e repo file:/home/gritzko/.be/journal/, typed by hand.
  • quickjab/ sits inside the journal wt, so an init driven by context alone would stage into the parent instead.
  • Downstream, the sub-mount flow is already specified: SUBS-009 refusal, SUBS-013 auto-add.

Goals

One command that inits both ways, for the cwd / nav-context tree.

  • be put! <store>/.be/<title> mints the repo anchor for the current tree.
  • be put! .be/quickjab — shard path resolves INSIDE the wt → colocated: mkdir .be/, wtlog at .be/wtlog.
  • be put! ~/.be/quickjab — shard path outside the wt → central: .be created as the wtlog FILE.
  • One rule: the anchor is a dir iff the store lives in the tree.

Constraints

  • No new verb: Verbs "orthogonal basis, not sprawl".
  • One anchor grammar — the /.be/ path split already in be/core/resolve_hash.js:87,109; no second syntax.
  • An EMPTY .be file must keep anchoring NOTHING; the test firewall relies on that.

WIP

Design decisions

  1. Verb: the anchor is a reflog row, and creating a ref from nothing is PUT's mission (PUT "creates ... branches").
  2. GET was considered and rejected: a mint moves no data, and GET is repo→worktree checkout.
  3. The bang: trailing ! is the generic force modifier, shed into --force (be/core/loop.js:379, GET, DIS-055 D6).
  4. PUT ignores the bang today (PUT-002), so put! gains its first real meaning here.
  5. Plain put on a missing store refuses with an actionable message naming put!; put! creates it.
  6. Grammar: the arg is a shard PATH <store>/.be/<title> — the form row-0 readers already parse; no ?/title query form.
  7. repoFromBe/projectFromPath split on /.be/ (be/core/resolve_hash.js:87,109); journal's row 0 is that path form.
  8. Row written: exactly ONE row — repo file:<abs-store>/.be/<title>/ as row 0 of the new wtlog.
  9. Absolutized: a relative row-0 path breaks when the tree is cp'd (cf. be/test/lib/reanchor.js).
  10. Zero reader changes: isAnchorRow already accepts repo rows (be/core/resolve_hash.js:130, POST-027).
  11. repo vs get as row 0 records provenance for free: born here vs cloned.
  12. No new slot, no collision: put's bareword default is already "path", and .be is excluded from trees.
  13. So a path carrying /.be/ can never name a stageable wt file — the segment itself is the mint marker.
  14. The explicit arg keeps the nested case safe: context never decides, or quickjab force-stages into the parent.
  15. Title elision: be put! .be / be put! ~/.be default the title to the wt basename (the GET-060 default).
  16. be/shared/submount.js:290 titles url-less subs the same way, and repo-setup.sh documents the convention.
  17. Downstream untouched: the shard dir itself is minted by the first post (be/shared/store.js:185 shardDir, named project).
  18. be put! .be/quickjab . mints the anchor and stages the tree via put's per-arg fan-out; be post 'first' finishes.
  19. Guard: remote URIs never mint — only local file: and plain paths.
  20. Follow-on: with ~/.be/<title> minted, the sub-mount flow (SUBS-009, SUBS-013) plugs right in.
