PUT-016: bare put must stage patched-in files (pat/mrg/cnf), theirs-adds included

Now
OPEN

RULING (gritzko, 2026-07-29): patched-in files are DIRTY and a bare be put must stage them — including paths the base does not track (a take-theirs ADD). Today verbs/put/put.js:367-373 keeps only the mod/mis/unk/ok buckets, so a patch-derived file stays ..vv after be put and never reaches ..vV; only POST picks it up, by consuming the patch row directly (DIS-057). The row emission compounds it: put.js:425 walks eng.baseTreeSha and emits a row only for a path that walk yields, so a theirs-add (absent from the base tree by construction) can never be emitted from there. Sibling of PATCH-024 (the base tree is the last get/post) and shares its worktree.

Input

Context

  • Live probe (2026-07-29, work/PATCH-024/be): base T0 + ?feat changing keep.txt; after be patch ?feat, status shows ..vv keep.txt and a bare be put emits NO row for it.
  • verbs/put/put.js:365 sources the dirty list from classify.classifyMerge, then :367-373 filters to mod/mis/unk/ok — pat/mrg/cnf fall on the floor.
  • shared/classify.js:417-436 already buckets these correctly, including "a patch-stamped take-theirs ADD (theirs added a path ours lacked)" carrying theirs' sha and mode.

Goals

  • A bare be put with a patch row in scope stages every patch-derived path: pat, mrg, and a take-theirs ADD the base does not track.
  • Staging a patch-derived path flips its wt char to the staged form (..vV), matching Status's staging-provenance rule.
  • A path-scoped be put <path> on a patch-derived file behaves the same as the bare walk.
  • Existing bucket behaviour (mod/mis/unk/ok) is unchanged; post keeps working whether or not the user ran put first.

Constraints

  • Emit theirs-add rows from the CLASSIFIER row (theirs' sha/mode), never from the base-tree walk — the path is absent there by construction.
  • cnf (weave left conflict markers): stage it like the rest; POST's POSTCFLCT pre-scan is the guard that refuses at commit time. If a test says otherwise, STOP and ask — do not amend the test.
  • Same worktree as PATCH-024 (work/PATCH-024/be); its base-tree fix is a prerequisite and must not be reverted.
  • JS ///be/ only.
