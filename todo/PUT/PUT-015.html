PUT-015: retire put old#new — mv is delete+put rows, shipped as a be mv extension

Now
OPEN

Raised by gritzko 2026-07-24: the verb model does not handle mv well. mv is a binary op (src, dst) in a unary URI grammar, so the PUT move form smuggles the dst into #frag, which everywhere else carries a sha pin or a message. Chosen direction (option c of the 2026-07-24 discussion): decompose mv into the primitive delete old + put new rows and ship the user gesture as a be mv extension per Extensions, keeping the verb basis pure and the wtlog free of a third row type.

Input

Context

be put old.c#new.c (PUT §CLI) is the declared move form; bare put's mis↔unk same-sha auto-pair (PUT-009) is the detected one. The declared form is the wart.

  • #frag overload: be put file.c#abc123 — rename to abc123, or pin/reset? 6..40-hex hashlets make the parse genuinely ambiguous.
  • The fragment slot is crowded further by the row-edit shapes: put '#~1' (PUT-014) and the proposed delete file.c#.
  • A move is not a new kind of change: it is a removal plus an addition sharing a sha; the auto-pair already reasons in those terms.

Goals

Replace the URI move form with an extension that composes the existing primitives.

  • be mv <old> <new>: rename(2) on disk, then stage delete old + put new rows sharing the blob sha; refusals in plain words.
  • Retire the #dst parse and the PUTNOSRC/PUTDSTBAD/PUTNODIR family from the PUT verb; amend PUT accordingly (gritzko's edit).
  • Keep the PUT-009 bare-put mis↔unk auto-pair as the no-typing fallback for shell-mv users; PUTAMBIG advice points at be mv.

Constraints

  • Extensions have no store SDK yet (Extensions §SDK): be mv reaches the repo by spawning be delete / be put via io.spawn.
  • No new wtlog row type; POST-side pairing must work from the two primitive rows exactly as it does for the auto-pair path.

WIP

Design decisions

Proposed by the agent, each point awaiting gritzko's verdict.

  • Row shape: plain delete old + put new, no mv row; POST/blame pair them by sha, the same machinery as the PUT-009 auto-pair.
  • Order: rename(2) first, so the tree state is exactly the mis+unk pair; then stage the pair scoped to these two paths only.
  • Open: be delete <mis-path> must stage the delete row — DELETE "already-absent is a no-op" needs to mean untracked, not mis.
  • Open: a dirty src moves fine (put hashes the moved bytes), but then sha-pairing needs the base sha, not the dirty sha — clarify.
