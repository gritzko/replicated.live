When both sides CREATE the same path, the root entry is absent, so no token anywhere carries spine membership and mergedLive sees the whole file as ONE divergent run. Its equal-bytes escape then compares each group's ENTIRE gathered bytes, so any difference at all — even a single one-sided insertion into otherwise identical text — fails allEq and both full copies are emitted back to back. Measured 2026-08-15 in //LITE-031: mark/node.js reads 661 lines (2x 328 + hooks), mark/blocks.js 2046, mark/inlines.js 2173, each the pristine base blob followed by the same file plus 13 marked hook lines. The correct merge is ONE copy: the two sides' tokens are byte-identical except for our pure insertions.

Input

Context

  • Site is be/shared/weave.js:102-106 (mergedLive): gather(i, hi, seen[g]) over the whole run, collapse only when every group spells the same bytes.
  • The rule as WRITTEN at weave.js:56-58 is right — "a conflicting run whose groups spell EQUAL bytes collapses to one copy (content re-absorbed under another birth id — never a conflict)"; only its granularity is wrong.
  • Run extent is set at weave.js:91-92: it spans until the next token whose mask is spine. With no root entry there is no such token, so hi runs to EOF.
  • Repro in hand: the worker vendored commonmark.js itself while LITE-030 landed the same files upstream; jab get then wove two independent whole-file insertions sharing the empty-file anchor.
  • Harm is silent-ish: status marks ...! on the three paths, but the bytes on disk are a doubled file that still RUNS (JS redeclaration lets the second copy win), so tests pass and the garbage is post-ready.
  • Per Dirty this IS a conflict by the anchor rule; the complaint is the RESULT, not the classification.

Goals

  • A two-sided create of near-identical content merges to ONE copy, with conflict spans only on the bytes that genuinely differ.
  • In this case the residue is one-sided insertion only, so the merge is CLEAN — one copy, hooks in, zero spans.
  • The equal-bytes re-absorption fires per matching token, not all-or-nothing over the run.

Constraints

  • No parallel differ: align the groups' token sequences with libdog's own fold (the TXTT retry shape CFOLD-002 cites); a hand-rolled Myers differ was rm -rf-ed once for exactly this.
  • Repro-first: watch a two-sided create double a file before touching mergedLive.
  • Whether the native twin (graf/GET.c, GRAFMerge3Bytes) shares the coarse granularity is UNVERIFIED here — jab/ is read-only for agents.
