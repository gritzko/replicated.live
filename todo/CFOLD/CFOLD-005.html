cfold_fold's token alignment (dog/CFOLD.c:970, BRAMu64s then NEILCleanup/NEILShift) resolves "insert a parameter AND a following line" by pulling the line's own tail ) { into the INS run and marking the original ) { deleted — three tokens needlessly inserted and three needlessly deleted against an alignment that keeps them EQ. The cost is not cosmetic downstream: the segment's '\n' becomes IN-sided, so bee's row walker can never take its inline path and the line splits, its rm row hoisted ABOVE the inserted lines that precede it. Found by gritzko 2026-08-23 in bee dog view/wtstat.js; the plain unified render is unaffected.

Input

Context

  • Minimal repro, two blobs through wv.blobDiff(from, to, "js") + emitDiff:
    • from "function foldSubs(f, root) {\n for (const s of x) {}\n}\n"
    • to "function foldSubs(f, root, seen) {\n if (seen === undefined) { seen = new Set(); }\n for (const s of x) {}\n}\n"
  • Emitted: EQ "function foldSubs(f, root", IN ", seen) {\n if (…) { … }", RM ") {", EQ "\n for (…".
  • Wanted: EQ "function foldSubs(f, root", IN ", seen", EQ ") {", IN "\n if (…) { … }", EQ "\n for (…" — same insert, no deletion at all.
  • The control case is right: inserting ONLY the parameter (no following line) keeps ) { EQ, so the defect needs the second, line-shaped insertion to appear.
  • Downstream symptom in bee dog --color view/wtstat.js: the tty shows -function foldSubs(f, root) { BEFORE the two +// CODE-041: comment lines that precede it in the file, then +function foldSubs(f, root, seen) {. --plain orders them correctly.
  • render/wrap.js:165:aS demands bnd === SIDE_EQ for an inline row, and the segment's '\n' is IN here, so no renderer fix can recover that line — the alignment has to.

Goals

  • An insertion abutting a line end must not annex EQ tokens it could have left alone; the repro above emits zero RM tokens.
  • A dog/test/CFOLD0N.c case pinning the repro's token sides, red before the fix.
  • No regression in the existing CFOLD/WEAVE/merge suites — the same alignment feeds be's three-way merge, not just the diff view.

Constraints

  • Fix in the alignment, not in the emitters: CFOLDEmitDiff/EmitFull faithfully report what the fold recorded.
  • Bisect the three stages before choosing one — raw BRAMu64s output, then NEILCleanup (dog/NEIL.c:107), then NEILShift (dog/NEIL.c:576). NEILShift slides change-region boundaries to a fixed point and is the first suspect, but its idempotence properties are asserted and must survive.
  • dog/ is a submodule of quickjab (libdog); land there, and bump nothing in bee.

WIP

Design decisions

The bisect is unambiguous: BRAMu64s already emits the wanted alignment and NEILShift is innocent. NEILCleanup's kill is what annexes the tail, so the fix is one guard in front of every kill rather than a tweak to any single heuristic.

  • Repro EDL per stage: BRAM =8 +3 =3 +26 =19, after Cleanup =8 +32 -3 =19, Shift a no-op on top of that.
  • Short-circuiting Cleanup makes the repro pass; skipping Shift does not — Shift alone slides the \n INTO the EQ.
  • The ) { EQ dies to the line-fraction kill (NEIL.c:301): 3 raw bytes * 4 < the 34-byte line it spans.
  • A kill rewrites an EQ as DEL+INS, so in a hole flanked only by INS it invents a deletion of live tokens.
  • Guard (NEIL.c:213): refuse a kill when the flanking region lacks DEL or lacks INS; line-snap needs a replace.
  • Sits after the before_bytes == 0 bail, so it covers the line-fraction, whitespace-only and two-tier kills alike.
  • NEILShift untouched — its idempotence proofs and test/NEIL01.c properties 4/5/6 stand unchanged.
  • 57 real revision pairs from ///dog history: 47 identical, 10 improved (EQ up, IN and RM down), none worse.
  • fuzz/NEIL.c could not corroborate: it includes a missing JOIN.h and no CMake target builds it (pre-existing).
