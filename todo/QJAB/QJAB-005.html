QJAB-005: buffer view TOCTOU — attacker JS frees the backing store mid-leaf

A native leaf unwraps a typed array to a raw base pointer (JABCDataOf / JABCIdleOf, arg.c:195:2X) and then RE-ENTERS JavaScript before it is done writing/reading through that pointer. The re-entry is either a number-arg coercion that runs valueOf (arg.c:119:2X JABCu64Of calls JS_ToFloat64), or an explicit progress/scan callback (JS_Call). During the re-entry, untrusted JS calls ArrayBuffer.prototype.transfer (detach+free) or a resizable buffer's .resize() (realloc/move) — both reachable in quickjs-ng — so the leaf's captured pointer now dangles. The C code then writes attacker-controlled bytes into freed/moved heap. JABCViewOf (arg.c:172:2X) reads the base once and never re-validates, so no gate below it can catch this.

Input

Context

  • quickjs-ng exposes ArrayBuffer.prototype.transfer (sets data=NULL, detached) and resizable ArrayBuffer.resize (js_realloc, moves memory).
  • valueOf / Symbol.toPrimitive on an object arg runs arbitrary JS inside JS_ToFloat64 / JS_ToInt32 — the same call the number gates use.
  • The PTR-010 gates (arg.c) validate a value ONCE; they do not model a second entry into JS between capture and use.

Goals

Close the window: after a view is unwrapped, no leaf may touch that pointer once JS could have run. Every affected leaf either gates all scalar args first, or re-validates the view after any re-entry.

  • A crafted valueOf / callback can no longer make a leaf write or read through a freed or moved ArrayBuffer.
  • A regression test per pattern: a valueOf that detaches, and a callback that transfer()s, must throw or no-op — never corrupt heap.

Constraints

  • Keep the leaf-only shape; the fix is ordering + a re-validate helper, not JS-side state.
  • Prefer one shared helper (re-fetch base+len, re-check detached) over per-site ad-hoc code, so the invariant is greppable.

WIP

Design decisions

  • Two fixes compose: (a) coerce EVERY scalar arg before the first JABCDataOf/JABCIdleOf; (b) for the callback leaves, re-fetch the run pointers after each JS_Call (or forbid handle mutation during the scan).
  • Candidate helper JABCViewReget(base,len,ctx,arg) to re-assert a view is still attached and unmoved before a post-re-entry write.
  • LANDED as three composing rules, documented in the arg.c header: 1. JABCScalar — a number arg must be a PRIMITIVE. Every gate starts there, so no JS_ToFloat64/JS_ToInt64Ext in the bindings can run a valueOf. This kills the whole valueOf class at one gate instead of reordering ~40 call sites, and makes reordering a belt-and-braces move. 2. JABCRunsOf — a runs[] array is COLLECTED, then unwrapped; the element getter (or Proxy trap) can no longer free a run already taken. The returned view[] keeps the refs alive (a Proxy hands out fresh arrays, so an early free would dangle the base too). 3. JABCViewSame(ctx, arg, base, len) — THE re-validate, for the one re-entry that cannot be reordered away: a callback. grep JABCViewSame lists those leaves.

TODOs

  • zip.c _inflate/_deflate: outOff is coerced BEFORE the two unwraps; the placement uses the new pre-gated JABCBufFedAt.
  • net.c dgram._send: fd, host and port are all read BEFORE JABCDataOf; the port now goes through JABCu64Of + a 0..65535 bound instead of a raw JS_ToInt32.
  • pack.c JABCpackRepack: every opts read (cap/log0/every/onStep AND opts.index itself) moved above the unwraps; JABCBufOfKeep hands back the bytes view so the watch re-asserts the SAME value (no second getter call), and JABCPackWatch JABCViewSames both regions after each fire — a handler that transfers either one ends the run.
  • index.c SEEKRANGE_LEAF: two-pass runs[], plus a per-run JABCViewSame after every JS_Call. Same two-pass in COMPACT_LEAF, and FINDGE_LEAF now reads the needle before the run.
  • pup.c _pup_*_range: pupslot.busy bars put/commit/drop/close for the length of the scan (the runs are MAPPINGS, not views — nothing to re-validate, so the ticket's "forbid mutation" arm applies).
  • Shared helpers in arg.c + the invariant documented in its header.
  • Test leg: test/qjab005.js (shared test repo), registered in CMakeLists.txt as JABCqjab005, gated like JABCqjab011.

Beyond the listed sites (same bug, found while fixing)

  • hit.c HIT_RUN: the identical runs[]-getter hole; SORT_LEAF read its size after the unwrap.
  • hash.c / heap.c JABCNumOf: a raw JS_ToFloat64 reading the key/value AFTER JABCLaneArr took the lane array's base — now via JABCScalar.
  • arg.c JABCBufOf: _data/_idle are read BEFORE bytes is unwrapped (a cursor getter is JS too).

Blockers and bummers

  • Some leaves genuinely need a number after the view (offset into it); those MUST re-validate rather than reorder — decide per site. Resolved by rule 1: the gate itself can no longer re-enter, so ordering became optional everywhere except the callback leaves.
  • Audited every remaining raw JS_To* in the bindings (io/pol/tty/http/ igno/ulog/codec): none sits after a view unwrap in the same leaf, so they were left alone.

Outcome

  • Landed on main as e5c1319 (also carried qjs -> submodule @0.16.2); repro test/qjab005.js pushed to jab-tests main 918746a.
  • Closed. Five ticket sites plus four more of the same shape; repro'd first under ASAN (clang; gcc's libasan is broken on this musl box), each case a confirmed heap-use-after-free pre-fix, all throwing post-fix.
  • test/qjab005.js pins six patterns: the number gate, zip's outOff, the dgram port, index findge/seekrange/compact (valueOf, element getter, per-hit cb), git.pack's onStep (Buf and opts.index), and abc.index.range vs put/commit/drop/close.
  • Full ctest green (126/126); the old JABCbass 10s-cap timeout is gone — the qjs 0.16.2 bump runs it in ~3.5s, and ASAN is clean (bigint overflow that hit JABCrepack/JABCpupMem on 0.10.1 is fixed upstream).
