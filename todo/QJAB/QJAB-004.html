An HTTP server in lite (LITE-034) has its transport already — net.c is a Node-style async API over the pol loop, net.createServer accepts and streams. What is missing is message parsing: dog/abc/HTTP.h carries the ragel lexer (HTTP.c.rl → HTTP.rl.c) but no JS binding exposes it, and manual parsing in JS would be a second recognizer next to a working ragel one. This ticket adds the binding, leaf-only in the net.c/io.c style: C parses bytes and hands back slices, no JS state held, no protocol logic — keep-alive, routing and body handling stay in the JS bundle.

Input

Context

dog/abc/HTTP.h: HTTPstate carries data, the request line (method, uri, version), the status line (status_code, reason) and headers (a u8cssp name/value pair list); errors are HTTPFAIL/HTTPBAD/HTTPNONE.

  • HTTPutf8Drain(from, http) lexes one message head off a byte slice; HTTPutf8Feed(into, http) spells one back; HTTPfind(value, key, headers) looks a header up.
  • Binding conventions are quickjab/net.c + pol.c: JABC rule #4, C keeps no per-fd JS closures; leaves return bare values, buffers and dispatch live in the embedded JS bundle.
  • Tests for the net layer sit qjs-side (quickjab/test/net.js), driven by the one implicit pol loop.

Goals

JS can parse an HTTP message head from a Uint8Array and compose one, through the ragel lexer only.

  • A parse leaf: bytes in, on success an object with method/uri/version (or status/reason), the header pairs, and the head's byte length so the caller knows where the body starts.
  • A compose leaf over HTTPutf8Feed, so responses are spelled by the same module that parses.
  • Partial input (HTTPNONE) surfaces as "need more bytes", never a throw — mirrors net.c's EAGAIN-as--1 stance.
  • A qjs-side test leg: lexer legs plus one loopback request/response over net + the new leaves.

Constraints

  • Leaf-only: no header-map caching, no keep-alive state, no chunked-body machinery in C; that layers in JS.
  • No second parser: every byte of the head goes through HTTPLexer/HTTPutf8Drain; JS never scans header bytes itself.
  • Follow abc/INDEX.md + dog/INDEX.md before adding anything; update the index if a header is touched.

PROPOSED API — awaiting gritzko's confirmation

  • http._drain(Uint8Array) → null | {method, uri, version, status, reason, headers, length}. null = need more bytes (HTTPNONE); a refused byte throws http: malformed message head. Absent slots are undefined (uri.c's rule), status is a Number (abc u64decdrain), headers is [[name, value], …], length is the head's byte count — the body starts there, JS slices it off its own buffer.
  • http._feed(head) → Uint8Array, the head object above spelled back (CRLF CRLF included). method set → request line, else status set → status line. A drained head re-spells byte-identically.
  • Bounds: 1024 header pairs lexed, 64 KiB spelled; over either throws in plain words. No JS shim object, no keep-alive/chunked/body state in C.

Notes

  • Head length: the lexer's HTTPBody = octet* swallows the body, so data[0] after a whole-message drain is at the buffer end, not the head end. The head is therefore measured as last lexed token end + 4 — the grammar mandates CRLF CRLF right behind the last token (field value, or the request/status line tail; an empty field value still fires). Verified against a C probe over request/response/no-header/empty-value/pipelined inputs.
  • Need-more vs malformed: HTTPLexer returns HTTPBAD for both. They are told apart by where the machine stopped — http.data[0] at the end of input = truncated (→ HTTPNONE → null), short of it = a refused byte.
  • Upstream quirk (dog/abc, NOT worked around here): an obs-folded header value makes the ragel machine fire FieldValue twice (the inner text and the whole fold), so a folded head yields an odd token list and mis-paired headers. Head length stays correct. Folding is forbidden by RFC 7230; worth its own dog ticket if lite ever needs it.
