QJAB-001

Ruling (gritzko 2026-08-13), verbatim. Entry + require are THREE EXCLUSIVE modes, each with exactly ONE require base — the jsrc STACK (multi-dir climb + floor) dies:

  1. bundled js exists → it contains main.js and is the ONLY source; NO jsrc/ climb.
  2. else arguments start with a .js file → execute that; ALL require()s interpret relative to ITS DIR; no climb.
  3. else → climb for jsrc/, execute jsrc/main.js, use THAT jsrc as the base dir for requires, NO FURTHER CLIMB.

Input

Context

Supersedes QJAB-001's require order (bundle FIRST, climbed jsrc AFTER): mode 1 is bundle-ONLY — the extend-through-cwd-jsrc fallback QJAB-001 verified must now FAIL. QJAB-001's entry rules (packed = no argv script probe, --eval intact) stand.

  • Mode 2 plainly read: the script's dir ITSELF is the base — require("view/bro.js") joins <scriptdir>/view/bro.js. It kills the LITE-001 hazard for good: a script's bareword can never wander up to $HOME/jsrc and load a same-named module from another tree.
  • Mode 3: the base is the FIRST jsrc/ found climbing up from cwd (lite/'s jsrc -> . makes lite/ its own base); higher jsrc dirs are INVISIBLE — a name missing in the found base FAILS rather than resolving further up.
  • Absolute-path require() stays legal in every mode (the be/lite test harnesses depend on it: --eval "require('<abs>')").
  • --eval has no script: it takes mode 1 when packed, else mode 3 (cwd climb).
  • Scope is quickjab ONLY; jab (JSC) keeps its stack until ruled otherwise, and jab/ is READ-ONLY regardless.

Goals

require.c (the pin/stack) + whatever main.c/arg.c still choose the entry, per the three modes; then the four verification legs.

  • Mode 1: packed boots the bundle with NO climb at startup at all; QJAB-001's shadow probe still loses; QJAB-001's EXTEND probe (a cwd jsrc file absent from the bundle) now FAILS to resolve.
  • Mode 2: a script at ~/tmp/x/s.js requiring sub/m.js resolves ~/tmp/x/sub/m.js regardless of cwd; a bareword absent beside the script FAILS (no $HOME/jsrc fallback) — assert the failure.
  • Mode 3: cwd lite/ → lite entry, requires from lite/; a nested dir with its OWN jsrc/ that LACKS a name present in a higher jsrc → the require FAILS (no further climb) — assert the failure.
  • Unpacked ctest -R JABC: run it; a case broken BY THE RULING (it tests the old climb/stack semantics, e.g. the requireJsrc/floor harnesses) is REPORTED with its case name and the old semantic it asserts — jab/test is read-only, do NOT bend or gate it silently. A case broken by a BUG in your change is a bug: fix it.
  • lite/test/pager/run.sh PASS under jab, unpacked qjab, packed qjab, refreshed build-lite (its --eval + $WORK/jsrc plant fits modes 1 and 3).

Constraints

  • Edits confined to quickjab/ (+ this ticket). jab/, lite/, be/ untouched; never read beagle/.
  • Dev builds in ~/tmp; only quickjab/build-lite/ refreshed in place (own cache) at the end.
  • No VC ops, no commits. ABC house rules (meta/abc.mkd) for anything beyond a few lines.

WIP

Design decisions

  • The stack collapsed into ONE string. jsrcStack (an array) + pinJsrcStack (bundle push, then the climb loop pushing EVERY jsrc/ up to the ceiling) are gone; in their place requireBase (one frozen path) + pinBase(spec) reading the three modes IN ORDER as one expression: packExtract() || scriptDir || climbJsrc(). Mode exclusivity is the || itself — no if (packed), no flag, no second source anywhere.
  • climbJsrc() keeps the old walk but RETURNS at the first jsrc/ instead of pushing and continuing, and climbs from io.cwd() only (the old per-requiring-module origin died with the stack). Ceiling unchanged: $HOME inclusive, else /.
  • What else died in require.c: packErr and its try/catch (a bundle that cannot unpack is now fatal — mode 1 has nothing to fall back to); resolveJsrc's from parameter (there is no origin left to scan from); __runScript (mode 2 has no jsrc lookup, so a bare/relative .js entry is just a path off the cwd); __rebaseRequire became __pinScript, which now pins scriptDir as THE base as well as rebinding the top-level require.
  • main.c lost the explicit_path fork: /abs, ./rel and foo.js are ONE branch now — __pinScript(__mainSpec) then JABCRunFile. The .js-suffix test stays a SUFFIX test (no stat): a missing script must still die with cannot open <p> (JS-054), so mode 2 is chosen by shape, not by existence.
  • process.argv[1] is the script path AS GIVEN (main.c already put it there). __runScript's abspath patch existed because the spec was resolved ELSEWHERE (in a jsrc); mode 2 takes the path verbatim, so patching it would be invention. The here idiom on a relative entry is a casualty, reported.
  • Only barewords answer to the base. ./x.js, ../x.js and /abs/x.js keep plain CommonJS meaning — relative to the REQUIRING module's own dir — which is what "absolute-path require stays legal in every mode" needs, and what the be/lite --eval "require('<abs>')" door rides on.
