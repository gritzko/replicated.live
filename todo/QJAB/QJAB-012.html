net._send throws Error: Broken pipe on EPIPE (net.c:127) and runs from Socket._flush inside the _poll fd handler (net.c:283), so the throw lands in a pol callback that no application try can reach. pol.c:59:Xm stashes it, the loop stops, and pol.run re-throws out of main (main.c:88) — one abandoned peer takes the whole server down. Node treats a dead peer as an error event plus a close; the embedded socket layer must do the same.

Input

Context

  • Live bee http session, killed right after a 303 redirect chain; the browser followed the 303 on a new connection and dropped the old one.
  • Session log, the last lines before the process exited:
POST /bee/act 303
GET /bee/todo/Now:* 200
GET /bee-CODE-033/status/ 200

JS exception: Error: Broken pipe
gritzko@thinkcentre:~/src/quickjab/build$
  • The 200 was logged first because respond only queues into _wb (http.js:424:3E); the send(2) happens a tick later, past every try.
  • sock.on("error", …) in bee (http.js:794:3E) cannot help: _send throws synchronously instead of emitting error.

Goals

A peer that vanishes mid-response closes that one socket and leaves the loop running.

  • net._send raising EPIPE/ECONNRESET emits "error" on the Socket and closes it, exactly as a pol.ERR revent already does (net.c:269).
  • net._recv gets the same treatment — ECONNRESET throws by the same path.
  • bee http survives a client that resets a connection mid-flush.

Constraints

  • The fix belongs in JABC_NET_JS (net.c:235), not in bee's http.js — every net user has this hole, not just the repo browser.
  • Keep the leaf-only binding style; _send keeps throwing, JS decides.
