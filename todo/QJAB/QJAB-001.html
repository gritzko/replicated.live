Ruling (gritzko 2026-08-13). Entry: 1. built with a bundled js pack → use the bundle's main.js; 2. otherwise climb for jsrc/, use jsrc/main.js. require(): 1. a bundle is present → look in it first; 2. not there → the jsrc found at startup. This makes the packed binary's entry argv-independent — quickjab main.js RENDERS main.js instead of executing it — and stops any paged repo's own jsrc/ from shadowing the product's modules.

Input

Context

Today quickjab mirrors jab: an existing .js argv[1] is taken as THE SCRIPT (decided in C, before any JS — the swallow LITE-003 recorded), and the JAB-035 pack is the stack FLOOR (last resort). Under the ruling both flip for packed builds only.

  • The swallow repro: cwd lite/, quickjab main.js → runs lite's own entry with zero args (usage/empty pager); quickjab view/bro.js executes the lib silently. A .js file can never be DISPLAYED by naming it first.
  • JAB-035 machinery already in-tree: quickjab/jsrcpack.{S,c,js}, require.c owns the stack; the pack extracts to $XDG_CACHE_HOME/jsrcs/<hash>/ — "use main.js there" = that extracted dir's main.js; "look in there first" = that dir FIRST on the stack.
  • Consequence, per the ruling: a user/repo jsrc can EXTEND the packed tree (files the bundle lacks) but NOT override packed modules — the JAB-035 overlay inversion is intended for the product binary.
  • ASSUMPTION (flag to gritzko if wrong): UNPACKED dev builds keep today's behavior VERBATIM, including argv[1]-script exec — ctest's JABC suite runs test/*.js as scripts and must stay green.

Goals

The two-level order above, in quickjab's C (require.c owns the stack; arg/entry selection wherever main.c/arg.c decide the script today).

  • Packed build: NO argv script probe — the extracted bundle dir supplies main.js unconditionally; every CLI word reaches it as an arg. --eval keeps working (debug door).
  • Packed require: bundle dir first on the stack, the startup-climbed jsrc (if any) after it.
  • Unpacked build: byte-for-byte today's behavior — script exec, climb, stack order.
  • Verify: (a) unpacked /tmp build → ctest -R JABC green; (b) packed /tmp build (-DJAB_JSRC=<lite tree> -DQUICKJAB_JSRC_PACK=ON, lite/README recipe) → from cwd lite/: quickjab main.js opens the pager ON main.js (pty), quickjab --plain main.js | cat dumps it, quickjab --plain view/bro.js dumps the lib; from a jsrc-free cwd the floor still boots; a cwd jsrc file ABSENT from the bundle still resolves (extend), a cwd file SHADOWING a bundled name loses (bundle wins).
  • Refresh quickjab/build-lite in place (its existing cache) and rerun LITEJAB=quickjab/build-lite/bin/quickjab sh lite/test/pager/run.sh — must stay green.

Constraints

  • Edits confined to quickjab/ (require.c, arg.c/main.c as needed; PORTING.md's stable-three freeze was the porting phase and yields to this ticket) + a test under quickjab/test/ if one fits the suite's shape.
  • jab/ is READ-ONLY reference; lite/ and be/ untouched; never read beagle/.
  • Dev builds in ~/tmp (never new build dirs inside quickjab/); only build-lite/ is refreshed in place.
  • No VC ops, no commits.

WIP

Design decisions

  • The probe lived in main.c main(): the arg loop's else branch (first non-flag word → script_file, tail = i + 1) plus the .js-suffix branch below it (JABCEndsWithJs + JABCHasScheme → __rebaseRequire /JABCRunFile or __runScript). Packed only skips the CAPTURE: the word stays in the tail (tail = i) and script_file stays NULL, so the existing else if (eval_code == NULL) __main() arm runs untouched. No branch was deleted — an unpacked build walks the very same lines.
  • "Packed" is JABCJsrcPacked() (new, jsrcpack.c, declared in JABC.h): the .incbin span JABC_JSRC_PACK_TAIL > JABC_JSRC_PACK_HEAD, NOT a flag set by the install — main() parses argv BEFORE JABCInstallModules, and a zero-length pack must read as unpacked (the install's own len == 0 gate).
  • Stack order is expressed by MOVE, not by a condition: packExtract() now runs at the TOP of pinJsrcStack and pushes the bundle dir before the climb loop pushes any jsrc/. An unpacked build has no g.jsrcpack, so packExtract returns null and the pinned array is byte-identical to today's — one code path, no if (packed) in the JS.
  • --eval is untouched and is now the ONLY door to a script file in a packed binary: quickjab --eval "require('/abs/x.js')" runs it (verified on lite's own color.js/pty.js legs, 21 + 43 checks).

Blockers and bummers

  • lite/test/pager/run.sh cannot pass under a PACKED runtime, by the very ruling: its colour and pty legs invoke "$RT" <abs>/color.js / pty.js as SCRIPTS, and a packed binary now renders them instead. The plain leg (10 checks) is green; the colour leg reports "did not finish" and the pty leg SKIPs (the ttyprobe.js run prints a hunk, not yes). Both legs pass in full through the sanctioned door — <qjab> --eval "require('<abs>')" — so the cure is one line in lite/ (out of this ticket's edit fence).
  • Same cause, wider: in a packed build the whole jab API suite goes VACUOUS — ctest -R JABC reports 36/40 "passed" in 0.44s because quickjab test/heap.js now DUMPS heap.js and exits 0. Four cases fail outright (JABCargv, JABCrequireJsrc, JABCleakExit — all script-file harnesses; and JABCjsrcFloor, whose SIB step was ALREADY red before this ticket: lite's bundle has no top-level .js sibling of main.js). The API suite is a DEV-BUILD instrument now; the unpacked leg (mandated here) covers it.

Outcome

Four files, all inside quickjab/, +22 lines: main.c (+6, the packed-arg fence), jsrcpack.c (+10, JABCJsrcPacked), JABC.h (+3, its declaration), require.c (+3, the pack lifted to the head of the pin). No file elsewhere was touched and no VC operation was run.

  • UNPACKED ~/tmp/qjab001-plain: ctest -R JABC 40/40 PASS — script exec, the jsrc climb and the stack order are unchanged for dev builds. The same binary also drives lite/test/pager/run.sh to PASS (76 checks).
  • PACKED ~/tmp/qjab001-pack (-DJAB_JSRC=<lite> -DQUICKJAB_JSRC_PACK=ON), cwd lite/: --plain main.js DUMPS main.js (cmp-identical to printf 'hunk main.js\n'; cat main.js), --plain view/bro.js dumps the lib (12251 = 12234 + the banner), and under a pty quickjab main.js opens the PAGER on main.js — alt screen, banner band main.js, painted body, bar main.js#L1 … TOP h: help, q exits 0. From a jsrc-free ~/tmp dir the floor boots and quickjab f.txt renders it.
  • OVERRIDE semantics, packed, in a scratch cwd carrying its own jsrc/: a file the bundle LACKS resolves to the local tree (jsrc/qjab001new.js, and require() loads it) — EXTEND; a local jsrc/view/bro.js (a throwing marker) LOSES to <cache>/jsrcs/<hash>/view/bro.js and the render still works — the bundle wins.
  • quickjab/build-lite refreshed in place via its own cache; the pager suite was RED under it for the harness reason in Blockers (JS legs invoked as scripts). CLOSED by the LITE-004 run.sh amendment (orchestrator, same day): ttyprobe/colour/pty legs go through --eval "require('<abs>')", a $WORK/jsrc -> lite plant serves the cwd-climb pin for unpacked runtimes, and a relative $LITEJAB is absolutized. PASS 76 checks under all four runtimes (jab, unpacked qjab, packed qjab, build-lite).

Require order superseded by QJAB-002 (gritzko's refined ruling, same day): bundle-ONLY when packed (the extend-through-climbed-jsrc verified above is retired), one require base per process in every mode. Entry rules stand.
