QJAB-007: forgeable Number handles — a JS number becomes a C pointer

Now
DONE
Sev
HIGH
Ask
gritzko
Rep
///quickjab
See
QJAB-005

ulog and igno hand JavaScript a native struct pointer as a plain Number and take it back with (T*)(size_t)d after only a d > 0 check, then dereference and even free/munmap it. Untrusted JS can pass ANY positive number as the handle, turning these leaves into an arbitrary-read / arbitrary-write / arbitrary-free primitive — the exact "a JS number must never become a pointer" rule (PTR-010, arg.c:1:2X) violated at the pointer level. It is the documented finalizer-less idiom (JAB-034), and the recycle-list only makes double-CLOSE of a REAL handle safe; it does nothing against a forged one. git.c already shows the fix: an index into a fixed table plus an unguessable generation counter, re-validated on every call (git.c JABCGitOf).

Input

Context

  • JABCulogHandle (ulog.c:279:RI) and JABCignoHandle (igno.c:18:VF) both do (T*)(size_t)d guarded only by d > 0.
  • Every handle leaf then derefs it: _ulog_append/_close (ulog.c:289:RI…) read h->data/h->idx and free/munmap; _igno_match/_close (igno.c:63:VF, igno.c:79:VF) walk box->set.
  • git.c pins are the counter-example: table index + generation, re-checked before any deref — a forged/stale value is rejected, not trusted.

Goals

A handle value carries no dereferenceable address; a bad or stale handle is rejected, never followed.

  • abc._ulog_close(4096) / dog._igno_match(4919,"x") throw "not open", never touch address 4096.
  • A closed-then-recycled handle is not silently accepted against the wrong object.

Constraints

  • Keep the finalizer-less design (JAB-034); the change is the handle ENCODING, not adding GC finalizers.
  • Reuse the git.c table+generation pattern so the codebase has one idiom.

WIP

Design decisions

  • Replace the raw pointer with (slot << k) | generation; keep a fixed boxes[MAX_OPEN]; validate slot < MAX and generation match on entry.
  • Bump the generation on close so a stale handle to a recycled slot fails.
  • The token codec is ONE shared gate in arg.c (the PTR-010 file), not a copy per module: JABCToken / JABCTokenOf / JABCGenNext, k = 24 (JABC_GEN_BITS) so a whole token is 32 bits — exact in a double, and slots < 256. JABCTokenOf NEVER throws (the refusal is the caller's to spell: a bad ulog handle throws, a bad igno close is a no-op), and it takes a Number ONLY, so no valueOf runs inside the gate.
  • Generation is monotonic per table, as JABC_GIT_GEN is — the security property is "a Number carries no address", and guessing a live token only buys JS a handle it could have opened anyway.
  • The tables are static, so a box costs no heap: calloc/free are gone from both leaves and an unclosed handle can no longer leak one.

Blockers and bummers

  • Handle values become opaque tokens (not addresses); confirm no JS code depends on the numeric value beyond passing it back. -> Confirmed: the only JS consumer is bee/view/status.js ignoStack, which tests h for truthiness and passes it back. 0 stays the "absent .gitignore" answer (a live token is always > 0).
  • A fixed table is a CAP where there was none: IGNO_MAX_OPEN 128 (one per level of a .gitignore chain), ULOG_MAX_OPEN 32. A full table throws ("too many open …"), it does not answer 0.

Outcome

  • DONE (uncommitted, branch QJAB-007). A Number handle is now a token — (slot << 24) | gen over a fixed table — so nothing dereferenceable crosses the boundary and forged / stale / recycled-slot values are all refused before any deref, free or munmap.
  • Pre-fix repro: quickjab --eval 'abc._ulog_close(4096)' and dog._igno_match(4919,"x") both SIGSEGV (139). Post-fix both throw and the process survives.
  • ctest -j16: 125/125 pass, including the new JABCqjab007, plus a bundled bee status smoke run over the real ignoStack chain.
