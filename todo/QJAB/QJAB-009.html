QJAB-009: bareword require is not normalized -> escapes the jsrc base

require's bareword branch concatenates base + "/" + spec raw (require.c:133:pI resolveJsrc) and hands it to io.stat/io.mmap, which resolve .. at the OS level. Explicit paths ARE normalized (require.c:139:pI), but a bareword is any spec not starting with /, ./, or ../ — so isExplicit("x/../../../etc/hostname") is false and it is treated as a bareword, never normalized. The result escapes the single require base that QJAB-002 promises ("resolves against THE base, and nowhere else"). Impact is bounded because io.* is already exposed to JS, but it defeats the confinement the comment claims and lets a bareword name a file outside the tree, which load() then mmaps and evaluates as JavaScript.

Input

Context

  • require.c:137:pI resolve: explicit specs go through normalize; barewords go to resolveJsrc unnormalized.
  • require.c:131:pI resolveJsrc: base + "/" + spec (and + ".js"), fed to isFile/load — OS resolves the embedded ...
  • QJAB-002 fixes the require base to one source per process; this hole reaches past it.

Goals

A bareword cannot resolve outside its require base.

  • require("x/../../../../etc/hostname") throws "cannot find", never loads a file above the base.
  • A legitimate bareword ("foo", "sub/bar") still resolves as today.

Constraints

  • Fix in the JS require shim (require.c); no new C leaf.
  • Keep the explicit-path branch behavior unchanged.

WIP

Design decisions

  • Normalize the bareword candidate, then assert it is still under base (prefix check on the normalized absolute path) before isFile.
  • A bareword containing .. that climbs above base is a hard throw, not a silent miss, so misuse is visible.

TODOs

  • require.c resolveJsrc (require.c:131:pI): normalize base + "/" + spec and reject any result not prefixed by base + "/".
  • Decide whether a bareword may contain .. at all, or is rejected outright.
  • Test leg: require("a/../../etc/x") and a ..-laden bareword both throw; normal barewords still load.
  • Confirm the .js suffix candidate is normalized on the same path.

Blockers and bummers

  • normalize semantics must match io.stat's OS resolution (symlinks) — a normalize that does not follow links can still be bypassed by a symlink; note this and keep the prefix check on the post-stat real path if needed.
