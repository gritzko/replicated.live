QJAB-016: io.environ() — list the process environment, so a driver can find GITHEAD_<sha>

io reads the environment only by exact name, io.getenv(name) (quickjab/io.c:787, over libabc/FILE.c:175 FILEGetEnv). A git merge driver has to learn the merge heads from git, and git names them by the variable NAME: one GITHEAD_<full sha>=<label> per head (measured, git 2.52, CFOLD-006) — no MERGE_HEAD exists at driver time. A name lookup cannot find a key it does not know, so bee's driver has HEAD and no way to name theirs. One leaf, io.environ() -> [[name, value], …], the environ(7) listing as pairs, closes that.

Input

Context

  • quickjab/io.c:787 JABCioGetenv: one name in, FILEGetEnv (libabc/FILE.h:529), undefined when unset or empty; registered at io.c:1082.
  • libabc/FILE.c:175 FILEGetEnv wraps getenv(3) as a slice into the environment; there is no listing twin in FILE.h.
  • Measured under git merge feat with a probe driver: the environment carries GITHEAD_c614244…=feat and GIT_REFLOG_ACTION=merge feat; the gitdir holds HEAD ORIG_HEAD index index.lock …, no MERGE_HEAD.
  • bee's driver (bee-CFOLD-006/merge.js) wants every GITHEAD_ key: the sha is in the NAME, the label in the value.
  • io.getpid, io.chdir, io.getenv are the shape to follow: one JABC_FN, one JABC_API_FN(io, …) line, a test/*.js case.

Goals

  • io.environ() -> Array of [name, value] string pairs, the process environment in environ order; an empty environment answers [].
  • A FILE.h twin for the listing if libabc's policy wants the libc call behind a slice API (abc); otherwise environ read in io.c alone.
  • Length-exact values, as io.getenv has since JS-108; a =-less entry is skipped, a value may itself carry =.
  • test/environ.js: set a var through the harness, assert the pair is listed and io.getenv agrees; assert a GITHEAD_-prefixed key can be found by scanning the names.
  • README.mkd's io listing gains the one line.

Constraints

  • No existing test edited; comment budget and links per comment.
  • The unbundled build build-unbundled/ is what bee runs; ninja there, ctest for the suite.

WIP

Design decisions

  • NO FILE.h twin was added: libabc policy puts a libc call behind a slice API (abc), so a FILEEnviron listing twin of FILEGetEnv (FILE.c:175) is what it wants — but this ticket may not edit libabc, so io.c declares extern char **environ itself. Worth a libabc ticket.
  • Each entry is a_cstr over the char*, split by u8csFind(tail, '=') (S.md "Find element"): a_past names the head, u8csUsed1 eats the =, the rest is the value — slices throughout, no pointer arithmetic, and length-exactness is free since neither side is ever NUL-scanned again.
  • README.mkd carries no per-leaf io listing (only "API notes"), so the line landed there, next to tok.link.
  • The test's whole fixture is set_tests_properties(... ENVIRONMENT ...) in CMakeLists.txt:140:D5, the way JABClink passes LSAN_OPTIONS.
