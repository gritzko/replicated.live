meta/link.mkd is the prose spec of links and lists line anchors only. BEE-073 adds four anchors and a hashlet rule. Update the page within the wiki budgets and sweep the pages that restate the syntax. blog/link.mkd is gritzko's own text: propose the edit, do not make it.

Input

Context

  • meta/link.mkd §Syntax gives one example per shape; the :30:Lj line:col slip is fixed in the tree already (:30:24).
  • meta/comment.mkd:14:I~ shows exact links (http.js:18:3E, TICKET-123:45) and is where an agent learns which anchor to write.
  • blog/link.mkd ("Git Links") is the public explainer of permalinks; blog/meta.mkd and blog/wiki.mkd mention them.
  • The header comment of tok/LINK.rl is the grammar of record (DOG-050); the prose follows it, never leads.

Goals

  • §Syntax gains CAPO.c:'Compose URI', CAPO.c:"ok64 o = OK;", GREP.c:/CAPO\w+Grep/, HUNK.c:HUNKu8sMakeURI.
  • A short §Anchors: exactly one per link; only a line is rev-proofed; searches take the first match in the current tree.
  • The hashlet rule in one bullet: it carries a non-digit, so an all-digit second code is a column.
  • The vouching rule: a delimited anchor vouches like a line, a symbol rides a known extension or a ticket code only.
  • The two traps, one bullet each: a regex ending in * inside a C block comment; a double-space gap under HTML collapse.
  • meta/comment.mkd: one clause on choosing the anchor, a symbol or a search where the line would drift, a permalink otherwise.
  • Credit the precedent in a link, not a paragraph: sam addresses and the Plan 9 plumber.

Constraints

  • Wiki format and budgets (wiki): greppable lines, intro 8, section intro 4, bullet 2; no See-also block.
  • Lands after DOG-050, so the page never documents a form the lexer does not fuse.
  • blog/ pages are hand written: list the proposed changes in the Outcome and request gritzko.
