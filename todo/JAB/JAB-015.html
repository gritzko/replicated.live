JAB-015: HASH bindings never enforce the power-of-2 capacity the native probe requires

Now
OPEN
Sev
MED

jab/hash.hpp:4 states "length MUST be a power of 2 … the JS constructor guarantees both", but the constructors (build/bytes/abc.ram/abc.mmap, jab/cont.cpp:407) validate nothing; dog/abc/HASHx.h warns a non-pow2 length silently corrupts the table and may infinite-loop the probe (LMASK = len - 1). abc.ram("HASHu32", 100) hands native code a broken table today. Found in the 2026-07-24 jab/ review.

Input

Context

  • The comment claims a guarantee no code provides; one bad slots arg is silent corruption, not an error.

Goals

  • HASH-family construction rejects (or rounds up) non-pow2 slot counts before any native probe touches the region.

Constraints

  • Repro-first: abc.ram("HASHu32", 100) asserts a throw (or a rounded capacity — pick one, document it).
  • Zeroing on reuse is separate ground (BASS carve rule); don't conflate.
