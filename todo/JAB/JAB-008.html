JAB-008: binding calls C ops raw, skipping call() — BASS scratch never rewinds, the 1GB arena drains, everything dies as "out full?"

Now: OPEN Sev: HIGH

PRO.h's contract (dog/abc/PRO.h:20-40,73-83): a callee's a_carve scratch dies when the CALLER's call()/try() rewinds ABC_BASS; sane() alone rewinds nothing. The jab binding breaks the contract at the C++/C boundary: every JABC_FN (weave.hpp WEAVENext/WEAVEMerge/WEAVEAlive…, pack.hpp, hunk.hpp) invokes the C op RAW — no call() equivalent — and ABC_BASS is mapped ONCE in main.cpp:281 and never rewound for the process lifetime. So every binding invocation leaks its whole carve set into the arena. Probe 2026-07-16 (in work/PATCH-012): fold the SAME 1MB blob from scratch in one process → DIED at iteration 240, weave.fold: failed (out full?) — ~4.3MB/fold (WEAVEFromBlob's a_carve(u32, toks, len+16) ≈4MB + anchors), 1GB/4.3MB ≈ 240. The C op's internal SNOROOM surfaces under the SAME "out full?" message as a dest overflow, so the leak masquerades as PATCH-012's cap bug. Hypothesis credit: gritzko.

Input

Context

One long-lived process + zero rewinds = every C-op invocation is a permanent allocation; hypothesis by gritzko, confirmed by probe.

  • Probe: jab --eval loop, abc.ram("WEAVE",16MB).fold(null, blob1MB, "txt", hash) ×2000 → DIED at iter 240: weave.fold: failed (out full?); a single fold in a fresh process is fine.
  • grep -c 'call(' weave.hpp → 0; same raw-invocation shape across the JABC_FN surface (pack.hpp pidx/scan, hunk.hpp dogenize/render, weave.hpp all ops).
  • Blast radius is EVERY BASS-carving op reachable from JS in a long session: whole-tree get/patch weave-reconstruction (fold per commit LAYER per file — the amplifier), why: blame, diff renders, pack scans — and the jab PAGER, which lives for hours.
  • Probably the REAL cause of the PATCH-012 incident: the silently-reverted files (~35-60KB) were UNDER the old 256KB fold caps; a whole-tree get's accumulated folds draining the arena mid-reconcile fits the multi-file failure far better than per-file caps. Likely also idxmaint: pack.scan: scan (out full? corrupt?) on the big clone (same day, same class).
  • PATCH-012's fix is still correct but now MASKS arena exhaustion as spurious per-file con rows (its residual-"full" catch); once drained, every later BASS op in the process fails too.
  • The binding CAN'T use PRO.h's call() literally (it is a statement macro over __/return); the needed primitive is its BASS bracket: dup u8bDataC(ABC_BASS) heads on entry, restore DATA+IDLE on exit (PRO.h:77-93 shows the exact 4 lines).

Goals

Restore the PRO.h ownership contract at the JS/C boundary: a binding invocation leaks nothing.

  • A RAII BASS guard (or macro) in the binding layer bracketing EVERY C-op invocation that may carve — snapshot heads, invoke, rewind; exception-safe (JABC_THROW paths must rewind too).
  • Sweep the whole JABC_FN surface (weave.hpp, pack.hpp, hunk.hpp, and any other .hpp/.cpp invoking abc/dog ops) — the guard at each boundary, ONE implementation.
  • Repro-first: the 1MB×2000 fold loop as a test — dies at ~240 pre-fix, SURVIVES 2000 post-fix; add a merge/scan variant if cheap.
  • Mind ops with LEGITIMATE BASS-surviving returns (anything handing carved memory back to the caller — e.g. a_cquired slices): the guard must not free live results; audit before bracketing blindly.
  • After landing: revisit whether PATCH-012's incident repro still needs the caps story amended, and whether pack.scan errors clear up.

Constraints

The guard is the binding's job; the C ops and the JS layer stay untouched.

  • No JS-visible API change; no dog/abc changes (their PRO.h discipline is correct — the binding is the caller that skipped its duty).
  • Per-invocation rewind, not periodic reset: a timer/GC-hook "flush" would leave the same class of transient spikes and racy lifetimes.
  • ~/bin/jab is an ASAN build — keep the probe test under the suite timeout; LSan "Suppressions used" trailer on stderr is noise, not a failure.

WIP

Design decisions

  • Guard at the REGISTRATION path, not per call site: JABC.hpp RAII JABCBassGuard (saves/restores ABC_BASS[1]/[2], exception-safe) + a JABCBassGuarded<F> trampoline wired into JABC_API_FN — the single registration macro, so ALL 142 native leaves (io 32, pack 16, ulog 15, weave 12, pol 12, codec 10, net 10, hunk 9, …) and future ones inherit it.
  • Audit found NO leaf returning BASS-resident memory to JS (hunk toks copy out in-call; io ram/mmap own their maps; ulog handles live in file/heap maps; POL queue is heap) — no copy-outs needed.
