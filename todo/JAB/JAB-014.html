JAB-014: net.accept swallows real errors as "not ready" — pol.IN accept loop busy-spins

Now
OPEN
Sev
MED

JABCNetAccept (jab/net.cpp:76) maps every non-OK from TCPAccept to -1, though the ABC op distinguishes NETAGAIN from TCPFAIL (dog/abc/TCP.h:21). A real failure (EMFILE, ECONNABORTED) thus looks like EAGAIN, and the level-triggered pol.IN accept loop spins on it instead of throwing. NET.md promises "Errors throw out of the loop… (other than EAGAIN)" and maps "TCPAccept (EAGAIN → -1)" — the code honors neither. Found in the 2026-07-24 jab/ review.

Input

Context

  • A server that hits its fd cap should die loudly, not eat a core at 100%.

Goals

  • net.accept returns -1 only for NETAGAIN; every other failure throws, matching NET.md.

Constraints

  • Repro-first: drive accept into a distinguishable failure (e.g. fd exhaustion via setrlimit) and assert a throw, not -1.
  • Errors in plain words per the standing ruling.
