JAB-010: require() re-resolves per call — memoize module resolution

The jab module loader resolves every require() by re-running the upward jsrc/ shard scan (require.cpp resolveJsrc) even when the module is already loaded: the cache is keyed by RESOLVED path, so resolution — a stat ladder up the directory tree — runs again on every call before the cache can hit. One jab work stats jsrc/core/resolve_hash.js 271 times and OPENS it once.

Input

Context

Profiled jab work 2026-07-24 (strace, warm cache): 372 stats under jsrc/ for a run that loads each module once.

  • jsrc/core/resolve_hash.js: 271 stats, 1 open — hot-path callers require() it per invocation; each call pays the climb, the module cache hits only after.
  • shared/ingest.js 22 stats, shared/util/path.js 12 — same pattern, milder (top-of-file requires re-evaluated per requirer).
  • The climb itself also re-stats intermediate candidates (sibling .be probes interleave in the trace) — resolution cost is a ladder, not one stat.
  • JS-side twin: core/registry.js verbFile() climbs per verb lookup — same idiom, smaller volume.

Re-profiled 2026-08-04 on be todo (the title's "re-climbs" is now half-stale — GET-041 froze the jsrc stack, but the per-candidate stat stayed).

  • stat("…/jsrc/core/resolve_hash.js") 80,342 times in ONE be --color todo, open once.
  • load() (require.cpp:88) calls resolve() BEFORE cache[abs], so even an EXPLICIT ./x.js spec pays normalize() + one io.stat per call — not just the bareword climb.
  • Microbench under jab: 80,342 repeat require(abs) = 231ms, io.stat alone 190ms.
  • The be/ call sites that make the volume are CODE-028's (in-body requires in per-path loops); this ticket is the loader-side cure and stands on its own.

Goals

Module resolution costs zero syscalls after the first (requirer shard, relpath) resolution.

  • require.cpp: memo (requirer dir or shard root, given relpath) → resolved abs path; the existing module cache then hits with no fs touch.
  • A jab process is short-lived — no invalidation needed within a run; the memo dies with the process (long-lived pager sessions keep today's staleness behavior, no new promises).
  • strace acceptance: jab work jsrc/ stats drop from 372 to #modules (one stat per actually-loaded file).

Constraints

  • Resolution ORDER must not change (nearest-shard-wins, the require.cpp resolveJsrc contract; JS-119's cwd-independence concern is adjacent — do not worsen it, crosslink).
  • C side follows ABC/CLAUDE.md norms; the memo is per-process state in the require machinery, no on-disk cache.
  • Behavior parity: module identity (one instance per resolved path) unchanged.
