JAB-036: qjab — port the jab runtime from JavaScriptCore to quickjs-ng

Now
OPEN
Ask
gritzko
Rep
///jab
See
JAB-035

jab is a thin C shell around its engine: 172 JABC_FN leaves, but the raw JSC calls already funnel through JABC.hpp macros, the arg.cpp gates and the JS-108 string helper. Meanwhile JSC is 90% of the shipped bytes and ALL of the release pain (JAB-035's static job). quickjs-ng is a 1 MB engine with its own compact unicode tables — no ICU, no Intl, builds in seconds. This ticket inventories the actual engine surface and plans the port.

Input

Context

Motivation, measured 2026-08-11 on the JAB-035 static path; engine choice: quickjs-ng (active fork) over Bellard quickjs (maintenance) and MicroQuickJS (mcu-class trims, too restricted for beagle's JS).

  • Static be with JSC = 54.6 MB: 36.5 MB JSC .text + 13 MB slimmed ICU data + ~4 MB rodata; jab+libdog+2 MB be pack ≈ 3 MB.
  • JSC static build (webkitgtk 2.52.5): 2700 objects, 50 min on a 4-core runner; needs an alpine container + actions/cache + RAM-capped ninja; the ICU pitfalls (64-byte stub libicudata.a, SIGABRT without data) are all JSC-forced.
  • quickjs-ng: 1 MB engine, no ICU/Intl, builds in seconds, 1 ms startup vs JSC's tens of ms, few-MB RSS.
  • Cost: interpreter, 5-30x slower than JIT JSC on compute-heavy JS — mitigated by jab's leaf-only-C design: libdog does tokenize/diff/hash/pack, the exposed surface is pager/view JS.
  • MEASURED TRUTH: grep 'Intl\.' be/ --include='*.js' = ZERO hits (and zero Promise/async/await anywhere in be/ or jab's own JS) — the 13 MB ICU rides for nothing be uses.

The JSC C-API surface, counted 2026-08-11 (///jab#, 13 .cpp + 13 dog-binding .hpp):

  • Totals: 1260 JS[A-Z]* tokens, 45 distinct JSC C-API functions, 172 JABC_FN leaves.
  • Dense .cpp: io 207 tokens (35 leaves), main 78, arg 78, pol 50 (12), net 36 (10), codec 33 (10), utf8 32, tty 27 (5), uri 26 (4); fsw 8 (4), jsrcpack 7, zip 2, console 3.
  • Dense .hpp (dog bindings): pack 116 (17 leaves), weave 88 (12), cfold 76 (11), index 57, pup 55 (11), hunk 50 (9), ulog 47 (15), hash 27, hit 25, heap 20, cont 16, tok 2.
  • buf.cpp, require.cpp, ansi.cpp, console.cpp are (near-)pure embedded-JS bundles run via JABCExecute — zero direct JSC calls, they port for free; the dog .hpp leaves speak almost only the funnel dialect (JABC_FN/JABC_THROW/JABCu64Of/JABCDataOf/JABCStrOfSlice/Get-SetProp + JSValueMakeNumber/Undefined).
  • Top call sites: JSValueMakeUndefined 147, JSValueMakeNumber 123, JSStringRelease 69, JSStringCreateWithUTF8CString 43, JSValueToNumber 36, JSBigIntCreateWithUInt64 29, JSValueToUInt64 26, JSStringGetUTF8CString 23, JSValueToStringCopy 22, Set/GetProperty 33, typed-array family ~30, JSObjectCallAsFunction 5, Protect/Unprotect 7, JSEvaluateScript 4.
  • No-copy externally-backed typed arrays, 5 sites: io.cpp _mmap (ro + slotted finalizers JABCMapROFree/JABCMapFree, ABC-020 gen-guard), io.cpp _ram, jsrcpack.cpp rodata pack (NULL dealloc), pup.hpp lane leaves; subview surgery via JSObjectGetTypedArrayBuffer + WithArrayBufferAndOffset in hunk.hpp + hit.hpp.
  • GC pinning (JAB-033): JSReportExtraMemoryCost + JSSynchronousGarbageCollectForDebugging are hand-declared SPI in JABC.hpp (webkitgtk ships no JSBasePrivate.h); JAB-034's ulog handle is still a finalizer-less pointer-as-Number.
  • Strings (JS-108): JABCStrOfSlice transcodes u8 slices to explicit-length UTF-16 (embedded NULs survive, bad bytes → U+FFFD); utf8.encodeInto walks JSStringGetCharactersPtr no-copy UTF-16.
  • Eval: JSEvaluateScript x4 — JABCExecute bundles + JABCRun's (0,eval)(__src) global wrapper; require.cpp compiles modules with new Function — both standard JS, engine-independent.
  • C→JS callbacks: pol's two JSValueProtected router refs (_fd/_timer), io.cpp readdir cb — 5 JSObjectCallAsFunction sites total.

Goals

A qjab that runs the whole be surface — jab suite 115/115, be suite 375/375 — and collapses the static release to a plain ubuntu job.

  • Payoff (JAB-035 static job): no alpine container, no 50-min JSC actions/cache, no ICU slimming/genccode — asset ≈ 4 MB (3 MB jab+libdog+pack + ~1 MB engine) vs today's 54.6 MB, built in seconds.
  • Perf within an accepted factor on the pager path (threshold: gritzko, see Blockers).

Constraints

  • Engine vendored + pinned, no network at build; no ICU, no Intl.
  • The JSC leg stays green through the whole migration (it is the differential oracle); any flip/removal only on gritzko's explicit order.
  • arg.cpp gate semantics (PTR-010) and require/jsrc-stack semantics (GET-041, JAB-035 floor) unchanged to the byte.

WIP

Design decisions

Port shape ORDERED by gritzko 2026-08-11: a separate all-C tree /quickjab (cmake), quickjs-ng v0.10.1 vendored+pinned under quickjab/qjs/; jab/ stays untouched and IS the oracle; gate = jab's own test/*.js suite run unmodified in place by the quickjab binary; goal = lighter in code AND binary. This supersedes the in-tree dual-build shape below (kept for the mapping notes) and settles the "separate binary vs build flavor" blocker: separate binary.

Earlier funnel-in-place sketch: an engine-neutral JABC layer in JABC.hpp/arg.cpp with dual builds, NOT a clean cutover branch.

  • Why: 88 of the 172 leaves (the dog .hpp bindings) already speak only the funnel dialect, so the per-leaf diff is small; dual builds keep the 115+375 suites as a differential oracle at every step; and it leaves the dual-engine question (Blockers) for gritzko instead of preempting it. Cutover REJECTED: forks 26 files in a live repo and forfeits the oracle.
  • THE model gap the funnel must absorb: ownership + exceptions. qjs JSValue is refcounted — JS_FreeValue on every temp (JSC releases only JSStringRefs) — and errors are the JS_EXCEPTION sentinel + JS_GetException, not JSC's *exception out-param. Plan: JABC_FN keeps the out-param signature, the qjs shim materializes it; scope macros whose frees are REAL under qjs, no-ops under JSC; the qjs CI leg runs ASAN + the JS_FreeRuntime leak report so refcount bugs cannot hide under the JSC build.
  • Mechanical mapping: value make/test/convert → JS_New*/JS_Is*/JS_To*; props → JS_Get/SetPropertyStr + JS_DefinePropertyValue — NOTE the attribute INVERSION: kJSPropertyAttributeReadOnly|DontDelete (jsrcpack, process.version) → omit JS_PROP_WRITABLE|JS_PROP_CONFIGURABLE; functions → JS_NewCFunction; calls → JS_Call; arrays → JS_NewArray + JS_DefinePropertyValueUint32; the u64 BigInt pair → JS_NewBigUint64 / JS_ToInt64Ext (takes Number AND BigInt, like JSValueToUInt64); eval → JS_Eval(JS_EVAL_TYPE_GLOBAL) ((0,eval) + new Function need the compiler kept in — never a qjsc-stripped build).
  • No-copy backing → JS_NewArrayBuffer(ptr, len, free_func, opaque, false) + a Uint8Array over it; free_func replaces the JSC deallocator 1:1 (opaque carries the ABC-020 gen scheme unchanged); jsrcpack rodata → free_func NULL; hunk/hit subviews → get the buffer, construct the view at (off, len).
  • JAB-033 pinning: JSReportExtraMemoryCost has no qjs equivalent — but refcounting makes wrapper death DETERMINISTIC (last JS_FreeValue munmaps), so the VMA price mostly evaporates; keep the fd-mark forced collection as public JS_RunGC (both hand-declared SPIs in JABC.hpp die). Cycle-captured views still wait for GC — keep the mark sweep.
  • Strings get SIMPLER: qjs is byte-oriented — JS-108's UTF-16 transcode collapses to JS_NewStringLen (explicit length, NULs survive; VERIFY ng's lossy-byte behavior matches the U+FFFD policy); encodeInto rewrites over JS_ToCStringLen (UTF-8 out, lone surrogates → U+FFFD — same policy, no JSChar walk).
  • Jobs: qjs queues Promise jobs, nothing pumps them — JABCRun/JABCExecute/pol trampolines get a JS_ExecutePendingJob drain after every JS re-entry. Zero Promise/async in be/ or jab's JS today (measured), so future-proofing, not a port blocker.
  • Build: -DJAB_ENGINE=jsc|qjs (default jsc until the flip); quickjs-ng VENDORED as a pinned snapshot under jab/qjs/ — jab is a beagle repo (git submodules do not apply) and a build must not fetch; the engine is small enough to carry.

Blockers and bummers

Open calls for gritzko, plus the known semantic risks.

  • Dual-engine kept (JSC for daily TUI speed, qjs for release) vs full replacement (ONE behavior everywhere)? The funnel supports both; the output-diff oracle lives only while both legs do.
  • Intl absent FOREVER acceptable? Measured: be/*.js has zero Intl. uses today — nothing breaks.
  • Name: qjab as a separate binary vs a jab build flavor?
  • Perf accept/reject threshold on the pager stress — gritzko's number, not ours.
  • Risk: engine error TEXTS differ ("x is not a function" wording) — any test snapshot pinned to JSC phrasing needs normalization, not accommodation in code.
  • Risk: qjs stack cap (JS_SetMaxStackSize) vs deep view recursion, and JABC_MAP_MAX (2 GiB) vs ng's own typed-array limits — probe both in step one, not at the be suite.

Outcome

Landed 2026-08-11 in /quickjab (uncommitted, awaiting gritzko's review; no VC ops run): the all-C port passes jab's whole unmodified suite.

  • VERIFIED by the orchestrator on a clean Release build: ctest 38/38 green in 3.5 s (jab's add_test list minus jabc_test.cpp, a C++/JSC-internal harness with no C twin; JABCzip existence-gated exactly as in jab, proved by probe).
  • Size: quickjab 2.3 MB stripped, engine INSIDE, deps = musl+sodium+z; jab = 2.5 MB binary + 39 MB engine .so (JSC 34.3 + ICU 4.7). Code: 7761 lines C (28 .c + JABC.h) vs jab's 8087 C++ — smaller while absorbing refcount/exception glue.
  • Structure: W1 skeleton (CMake, JABC.h funnel, main/arg/utf8, per-module JABCInstallXxx contract, PORTING.md) + 5 parallel opus porters over disjoint files; quickjs-ng v0.10.1 vendored pinned at quickjab/qjs/.
  • JS bundles byte-identical to jab's except 8 lines in cont's (late name-binding for install order); JS-108 UTF-16 transcode collapsed to JS_NewStringLen as predicted; both JAB-033 hand-declared SPIs died (public JS_RunGC); PTR-010 / GET-041 semantics unchanged.
  • mmapfd teardown crash root-caused to quickjs-ng js_array_buffer_transfer dropping the free_func's opaque on the transferred husk; fixed io-side (heap JABCMapRec owns the base, NULL-opaque husk is a no-op), ABC-020 ABA guard kept exact. Engine never patched. Related latent risk noted: ng's transfer(new_len) reallocs — fatal on mmap memory — unexposed today (cont calls it same-length).
  • jab-side stack smash found by the port: JAB-037 (hunk.hpp 2-vs-4-slot getters); weave.hpp found to be dead text (WEAVE.h gone since DIS-082) — weave.c is a documented no-op install.
  • Not done: jsrcpack CMake leg is OFF by default (packer needs the binary; ON path hand-proved), no ASAN/leak CI leg yet, --version/argv0 still say "jab", pager perf table still open (Blockers).
