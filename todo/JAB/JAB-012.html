JAB-012: ulog._close frees the box but JS keeps the raw pointer — post-close use is UAF

Now: OPEN Sev: HIGH

JABCulogClose (jab/ulog.hpp:337) does ULOGClose(...); free(h); while the handle circulating in JS is the box's address as a Number; JABCulogHandle (ulog.hpp:276) only rejects d <= 0, so a second _ulog_close(h) or any post-close call dereferences freed memory. The "idempotent — nulls handle" comment at ulog.hpp:245 is false — C cannot null the JS-held Number. Found in the 2026-07-24 jab/ review.

Input

Context

  • Double-close is an easy JS-side mistake (finally blocks, error paths); today it is silent heap corruption, not an error.

Goals

  • Post-close use of a ulog handle throws a plain-words error; double-close is a no-op or throws — never UAF.

Constraints

  • Repro-first: open, close, close again / append after close — assert throw, run under ASAN.
  • Keep the handle representation cheap; a generation-checked slot table or a magic field zeroed on close both fit.
