Input

Context

  • Duplication is already done by hand (the copy step); the agent only sorts + deletes. Do NOT treat it as one accidental collision — ALL are dupes.
  • Three submodules (/README): be→beagle-ext (JS scripts), beagle→core C/C++ + JABC bindings, html→site. be <name>/jab runs the be/ shard.
  • beagle/test/CMakeLists.txt GLOBs test/js/{get,post,put,delete}/*/run.sh into be-js-<verb>-<case> ctest targets (if(WITH_JS)) — these drive be/ verb scripts, so they are be-side and their beagle copy must go.

Goals

  • Every test file lives in EXACTLY ONE place after the sort; the duplicate on the wrong side is rm'd.
  • Binding tests → beagle/test/js + beagle/js/test (JABC surface only).
  • be/-script tests → be/test (in the beagle-ext submodule).

Constraints

  • No silent test loss: every case that runs today must still run (same green count) after the sort; deleting a dupe must not delete the only home.
  • Decide ownership per file BEFORE any rm; a wrong delete loses the test.

  • Classify by subject-under-test: a test exercising a JABC C++ leaf → binding, home is beagle; a test exercising a be/{core,shared,verbs,views,view} script → be-script, home is be/test. Keep that copy, rm the other.
  • Likely split of today's beagle/test/js: be-script (→ be/test, rm from beagle) = verb dirs get/put/post/delete/patch, views bro/diff/ls/regex/spot, core units loop/emit/resolve/barrier/store/ulog, parity/, lib/. Binding units already in beagle/js/test stay; ulog.js has a copy on each side — keep the binding one in js/test, the be/shared one in be/test.
  • be/test runner finds the toolchain via env (BE_BIN/JABC) exported by the parent build; the be shard carries no C build.
