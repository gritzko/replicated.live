JS-118: store.shardDir silently adopts a SIBLING shard when the named project is absent — "last non-dotted subdir wins"

Now
OPEN
Sev
HIGH

shared/store.js shardDir() (~lines 144-158): when the named project's shard dir does not exist, an auto-detect scans the store and picks the last non-dotted subdir — so an UNKNOWN project name resolves to a random sibling project with rc=0 and no warning. Found mid-fix on STATUS-010 (2026-07-16): with the context fix landed, a sub anchored to nonexistent project ghost in a 3-shard store ran jab status ///ghost clean and silently read the par shard — the foreign trunk walked as miss ?fd462224#par c0, the own base rendered as a metadata-less post row. The same trap has bitten clones for weeks (a ?/repo typo yields a clean-looking clone of libabc with no dog/) and is the ENABLER that turned STATUS-010's context slip into a confidently-wrong DAG walk instead of a refusal. An unknown project must refuse (SHARDNONE-class error), never adopt a sibling.

Input

Context

The auto-detect was presumably a convenience for single-project stores; in multi-shard stores it is a landmine.

  • shared/store.js shardDir() ~:144-158: named shard absent → scan store root, last non-dotted subdir wins.
  • Live probe (work/STATUS-010, post-fix tree): project ghost in a par/ext/orph store → status reads par, rc=0.
  • Known prior bites: jab get 'file:…/jab.be/.be?/repo' silently cloned libabc (no error, wrong tree, no dog/); a bare ? trunk on that store resolves libabc similarly.
  • Enabler for STATUS-010: the wrong-context ? resolution only became a foreign-tip walk because shardDir handed back a live sibling shard.
  • Blast radius: every store.open caller — get/clone, status, post, patch, views — any typo'd or stale project name reads/writes a WRONG project.

Goals

An unknown project name is an ERROR, everywhere.

  • shardDir() on an absent named project → refuse (SHARDNONE-class, RON60 code per /meta/abc ok64 rules), no auto-detect.
  • Decide the legitimate single-project convenience explicitly (e.g. auto-detect ONLY when no project was named at all) — gritzko to rule.
  • Repro-first: multi-shard store + unknown project → today rc=0 wrong shard; post-fix a refusal naming the missing project and the store.
  • Sweep callers for reliance on the fallback (a legit bare-?-no-project clone flow may exist) before flipping.

Constraints

  • Refusal texts follow the post.js RULING 2026-07-16 style: 1 line, ≤64 chars, plain text.
  • Don't break the documented single-project store flows (test suite + clone recipes) — the sweep decides scope.
