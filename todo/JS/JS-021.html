JS-021: ron time codec — ron.now / ron.of / ron.date

Now
DONE

JSC provides Date (wall-clock), but beagle's ron60 time encoding (ULOG ts fields) and the be log relative-date format aren't reachable from JS. Bind the small leaves + JS sugar on the ron object. Method: Issues.

Input

Context

  • ron.encode/decode (js/codec.cpp) already do ron60↔BigInt, but NOT the time interpretation — you can't read a ULOG ts as a date.
  • Leaves exist: RONNow(), RONOfTime(ron60*, tm, ms), RONToTime(ron60, tm, ms) (abc/RON.h:104/45/48); DOGutf8sFeedDate(into, ts, now) (dog/DOG.h:719) — the 12:34/Tue/01Jan relative formatter.
  • Lets a JS tool read/format be log/be status timestamps as the dogs do.

Goals

  • ron.now() → current ron60 (BigInt).
  • ron.of(x) → ron60 from a JS Date or a ms-epoch int.
  • ron.date(ronval) → relative-date string (DOGutf8sFeedDate).

Constraints

  • MAY implement in JS over thin native leaves (ron._now/_ofMs/_date); extend the existing ron object in codec.cpp (a small JABCExecute bundle like uri.cpp's). ron60 crosses as BigInt; no held refs (rule #4).
  • ron.of coerces Date→getTime(); localtime alignment matches RONNow.
  • ron._date computes now via time(NULL) itself (RONToTime→mktime→secs → DOGutf8sFeedDate). Needs #include "dog/DOG.h" in codec.cpp.

WIP

Design decisions

  • (open) 3 native leaves (_now, _ofMs, _date) + JS now/of/date sugar; now may bind directly. of is the only one needing JS (Date coerce).

Outcome

  • LANDED 78edd840 (2026-06-21): 3 native leaves in codec.cpp — ron._now (RONNow), ron._ofMs (localtime_r+RONOfTime), ron._date (RONToTime→mktime→DOGutf8sFeedDate) + a JABC_RON_JS sugar bundle → ron.now() / ron.of(Date|ms) / ron.date(ron60) (BigInt). ron60 spans 2000–2099 (RONOfTime YY field) — ron.of THROWS outside it (documented, inherent to the encoding).
