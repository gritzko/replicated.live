JS-015 LOW: script args dropped — no process.argv / args global

A JABC script cannot read its own command-line parameters: main() takes the first non-flag token as the script path and breaks, never exposing the trailing argv to JS. Method: Issues.

Input

Context

  • js/main.cpp:120-123 — once argv[i] is taken as script_file, the

    arg loop breaks; every token after it is ignored.

  • No process.argv / scriptArgs / args global is installed, so a

    script has no way to see its parameters (verified: grep argv in js/).

  • Blocks any parameterized utility, e.g. jabc tool.js status ~/repo

    (the surfaced gap from the be status JABC-coverage review).

Goals

  • The argv tail (tokens after the script path) reaches JS as an array.

Constraints

  • Pure main.cpp + glue; no abc change. --eval / --version intact.
  • JS-owned strings; no held refs beyond bootstrap (JABC rule #4).

WIP

Design decisions

  • (open) Collect the tail into a JS array set as a global — args, and

    optionally a Node-ish process.argv = ["jabc", script, …tail].
