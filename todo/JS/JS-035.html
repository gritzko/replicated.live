JS-035: zip.deflate / zip.inflate — raw zlib over dog/git/ZINF

Now:
DONE

Expose ZINFDeflate/ZINFInflate as a zip JS global so JS can (de)compress arbitrary bytes — the missing primitive for a pure-JS git-wire client (REF_DELTA record bodies, loose objects). Reopens JS-018 (no longer MOOT: the wire needs standalone compression, not just pack-internal). Method: Issues.

Input

Context

  • A JS git-wire client must emit/ingest pack records whose bodies are standalone zlib streams; git.pack only (de)compresses WHOLE records, no raw transform. dog/git/ZINF.h (libdog) has ZINFInflate/ZINFDeflate.
  • Prereq for JS-037 (thin-pack REF_DELTA bodies) and the future wire client.

Goals

  • zip.deflate(bytes[, out]) -> Uint8Array | n and zip.inflate(bytes[, out]).
  • No out: fresh sized Uint8Array. out is a Buf: write into IDLE, advance fed, return n (zero-copy), mirroring tok.parse/pack shape.

Constraints

  • Pure marshalling over dog/git/ZINF (libdog, already linked). No new abc, NO dog. Holds no refs (rule #4). Leaf sizes nothing — JS owns the out buffer.

WIP

Design decisions

  • Native leaves _deflate(src,out,outOff)->n / _inflate(src,out,outOff)->n in a new js/zip.cpp (JABCZipInstall, like ansi.cpp); install in main.cpp.
  • JS zip wrapper sizes the out scratch (deflate: len+len>>10+128; inflate: grow-and-retry on NOROOM, like keeper.js readRecord) — sizing is JS's job.
