JS-087 MED: core/ and shared/ depend UPWARD on view/ (relocate shQuote, emit)

The dispatch loop and the git wire client import the rendering layer — an upward dependency that makes view/ un-droppable from a headless or server build and couples the transport to the UI. Worst: wire.js, a git transport client, pulls the POSIX-quoting primitive shQuote from view/render.js. emit.js (the output sink in core/) requires view/render.js + view/theme.js at module top. Method: Issues.

Input

Context

  • wire.js:22 const shq = require("../view/render.js").shQuote;

    — a transport module reaching into the renderer for a shell quoter.

  • view/render.js:32 function shQuote(s){…} — pure POSIX single-

    quote, zero render dependency; exported at render.js:35.

  • emit.js:14-15 require view/render.js + view/theme.js at top

    — core/ depending on view/ for the columniser/theme.

  • loop.js:23 require(_here+"/view/bro.js") — the dispatch loop

    reaches into view/ for the edge renderHunkLog.

Goals

  • Move shQuote to shared/util/shell.js; wire.js + render.js +

    status.js consume it from there (no view/ import in wire.js).

  • Relocate emit.js under view/ (the sink IS a render concern), or

    have core depend only on the injected ctx.out/ctx.sink seam.

  • After: shared/ and the transport import NOTHING from view/.

Constraints

  • Byte-identical banners + wire argv: render.js re-exporting the

    moved shQuote keeps existing render call sites unchanged.

  • No new bindings; pure JS move (libabc only for shell.js).
  • Parity: SUT=loop hunk render path stays byte-for-byte.

WIP

Design decisions

  • shared/util/shell.js::shQuote is the canonical home (a sibling

    of util/path.js + util/sha.js, JSQUE-016 layering); render.js re-exports for back-compat.

  • loop.js's view/bro.js edge is the legit core→view seam IF it is

    the ONLY one; the goal is to make it the single arrow, not many.
