JS-075 HIGH: be get fan-out row URIs break on tree names with ?/# → wrong-path unlink

The GET fan-out builds per-path effect rows by raw string concat — rel + "?" + ne.sha + "#" + oldSha (get.js:290-308) — then the leaf re-parses each with new URI(uri) (get.js:319-323), reading rel=u.path, newSha=u.query, oldSha=u.fragment. A tracked filename containing ? truncates rel and corrupts newSha (wrong file written/skipped). A name containing # makes newSha empty, so the leaf takes the delete branch and io.unlink(join(wt,rel)) (get.js:324,327-328) — a destructive wrong-path delete. Effects stay inside the worktree (correctness/integrity, not traversal). Method: Issues.

Input

Context

  • get.js:290-291,298-299: rows are rel + "?" + ne.sha + "#" + … raw

    concat — rel (the file name) is unescaped.

  • get.js:307-308: the removed-entry row is rel + "?#" + oe.sha — same

    unescaped concat for the delete case.

  • get.js:319-323 leaf: `const u = new URI(uri); rel=u.path;

    newSha=u.query; oldSha=u.fragment — URI splits on the FIRST ?/#`.

  • get.js:324,327-328: full = join(g.wt, rel); `if (!newSha) {

    io.unlink(full); … } — an empty newSha (from a # in the name) DELETES the path the truncated rel` resolves to.

  • A name like a#b → newSha="" → leaf deletes join(wt,"a"); a?b

    → rel="a", newSha="b…" (corrupt) → wrong file written/skipped.

Goals

  • A tracked file named a#b or a?b round-trips through the get fan-out

    and leaf with the correct new bytes and NO spurious deletion.

  • The delete branch fires only for a genuinely removed path, never from a

    #/? in a live name.

Constraints

  • Match the C URI grammar (the path component is percent-encoded there);

    encode the path on row build, decode symmetrically in leaf.

  • Or pass rel/sha as separate structured row fields (avoid the

    parse round-trip entirely) — keep the row verb get and the queue shape.

  • Scope to get.js fan-out + leaf; no change to tree-map building.

WIP

Design decisions

  • Percent-encode rel in every emitted row (:290,298,301,306,308) and

    decode u.path in leaf, OR carry {rel,newSha,oldSha} structurally.

  • Guard the delete branch on "old path existed AND no new sha", not on a

    string-parse artifact.
