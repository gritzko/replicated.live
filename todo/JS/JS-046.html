JS-046: be put/delete/post as pure-JS extensions

Now
DONE

Reproduce the three reflog-WRITE verbs — be put, be delete, be post — as bin/{put,delete,post}.js, output-equivalent to native, the way JS-027 did status and JS-038 did get. PUT/DELETE append intent rows (the wt .be ULOG + the keeper refs ULOG); POST consumes them to build a tree+commit, write a keeper pack-log, and FF-advance the ref. libabc+libdog ONLY — keeper/graf/sniff stay unlinkable, reimplemented in JS. Method: Issues.

Input

Context

  • status/get were READ ports; these are the first WRITE verbs. PUT/DELETE are POST's prerequisite (POST commits their staged set). Native: sniff/PUT.c, sniff/DEL.c, sniff/POST.c; store keeper/REFS.c, format keeper/KEEP.h.
  • Verb semantics: Verbs, PUT, DELETE, POST. Put→post flow is be put ./f && be post '#msg'. Two prior write precedents exist in JS: get.js::writeWtlog/appendWtlog and ingest.js::writeUlog.

Goals

  • bin/put.js/bin/delete.js/bin/post.js byte-equivalent to native on the LOCAL path (rows, file mtimes, REFS, banner); shared bin/lib/* writers.
  • Exactly ONE new native leaf: io.setMtime over a new abc/FILE utimensat wrapper (JS-047). Everything else is pure JS over the bound abc/dog surface.

Constraints

  • libabc+libdog ONLY; NO keeper/graf/sniff binding (reimplement in JS).
  • We do NOT touch PATCH. POST is FF-or-refuse: THROW where native would rebase/merge (non-FF advance, absorbed-patch "theirs" trees, the cascade).
  • Wire push (//remote) deferred; the local path lands first.

WIP

Design decisions

  • Native leaves wrap abc/dog only; ref resolve/advance, pack-log+idx framing, classification, the wire convo all reimplement in JS (the get/status pattern).
  • Non-FF POST → POSTNOFF (refuse); graf rebase is unreachable without a binding (sole future escape: a pure-JS WEAVE rebase over the already-bound dog/WEAVE).
