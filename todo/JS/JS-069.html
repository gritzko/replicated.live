JS-069: diff follows tracked symlinks via io.mmap (info leak)

Now
DONE

be diff's wt-vs-base path reads symlink leaves by dereferencing the link, so a TRACKED symlink to /etc/passwd leaks that file into the wt side of the diff. Symlink leaves wrongly land in the files map and get io.mmap'd. Reachable once an attacker tree is checked out. Masked today by DIFF handler unreachability (JS-071). Method: Issues.

Input

Context

  • views/diff/diff.js:134-135 treeMap routes only kind === "s" to subs; symlink leaves (kind === "l") fall into files.
  • views/diff/diff.js:201-211 per base file: join(repo.wt,p) then readWtFile(wtPath) — no lstat, no symlink kind branch.
  • views/diff/diff.js:216-218 readWtFile does io.mmap(path,"r").data().slice() — FOLLOWS the link, reads target.
  • A tracked symlink link -> /etc/passwd thus emits the TARGET's bytes as the wt-side blob, not the link target string.
  • Read sink is real now; the diff handler is just currently unreachable (see JS-071) so it is not yet exploitable end-to-end.

Goals

  • Diff symlink leaves as the stored link-target blob body, not contents.
  • wt-side symlink read uses lstat+readlink (or O_NOFOLLOW).
  • Repro: tracked symlink to an outside file leaks nothing into diff.

Constraints

  • Keep diffWtTree/diffTreeRefs lex order + sha-skip parity.
  • No new follows in readWtFile; gate by leaf kind upstream.
  • Pairs with JS-071 (reachability) — land together.

WIP

Design decisions

  • Split symlinks out of files into a links map (like subs); diff their target-string blobs, never mmap the wt path.
  • For wt side, io.lstat kind=="lnk" → io.readlink, else mmap.
