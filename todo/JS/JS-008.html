JS-008: number marshalling precision — i64 truncation, NaN/Inf mis-routing, float→int UB

Now
DONE

The convert/rdx number path truncates 64-bit ints through a JS double and mis-routes NaN/Inf; POLAddTime((int)ms) is float→int UB. Convert path is DEAD (rdx unwired) — fix before wiring. Method: Issues.

Input

Context

  • (a) convert.cpp:97 JSValueMakeNumber(ctx, top->i) truncates i64 (RDX.h:204) above 2^53 → must use BigInt.
  • (b) convert.cpp:65-73 number import uses floor(d)!=d, which mis-routes NaN (→ float branch) and ±Inf (→ int branch); must gate on isfinite first.
  • (c) io.cpp:219-222 POLAddTime((int)ms) is float→int UB for NaN/Inf/negative/ >INT_MAX.
  • convert.cpp is the DEAD rdx path (unwired in main.cpp:40-42); io.cpp:219 timer is live. Priority: fix before the rdx path is wired.

Goals

  • 64-bit ints survive the round trip; NaN/Inf route correctly; the timer rejects non-finite / out-of-range delays.

Constraints

  • BigInt for 64-bit ints; isfinite + explicit range guards before any (int) cast.
