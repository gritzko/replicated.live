JS-094: jab diff of a file under a submodule shows it wholly "added"

Now
DONE

jab diff <sub>/<file> (e.g. diff:be/view/bro.js from the journal root) rendered @@ -1,0 +1,N @@ — the WHOLE file as new — while be shows the real @@ -1,M +1,N @@. The baseline of a file UNDER a mounted submodule lives in the SUB's store; jab's parent-tree walk (blobAtTree) hits the gitlink, finds no blob, and diffFile treats the from-side as empty. be recurses the mount.

Input

Context

  • Repro (from ~/journal): jab diff be/view/bro.js → @@ -1,0 +1,663 @@; be diff:be/view/bro.js → @@ -1,291 +1,663 @@. Same-store files (todo/BRO/README.mkd) were already byte-identical — only mount-nested paths broke. Surfaced while dogfooding the BRO-009 diff-colour work.

Goals

  • jab diff:<sub>/<file> byte-matches be (wt-vs-base AND range), the emitted names prefixed under the mount.

Constraints

  • Pure JS; reuse core/recurse.isMount + be.find + the existing prefixingSink; no new binding.

WIP

Design decisions

  • mountSplit(repo, path) finds the longest mounted prefix → {subPath, rest}. The handler opens the sub repo/store, resolves the baseline THERE (wt: the sub's wtlog.baselineTip; range: the gitlink pin at each parent commit via gitlinkAtTree/subTreeAtParent), and diffs rest through a prefixingSink(out, subPath).
