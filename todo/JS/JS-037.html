JS-037 MED: pack feed — base by offset|hash (REF_DELTA emit)

Teach the pack writer to name a delta base by SHA (REF_DELTA), not only by in-log offset (OFS_DELTA). The missing primitive for a pure-JS thin-pack builder: a delta against a base the peer already has (not shipped). Method: Issues.

Input

Context

  • git.pack feed(type, content, prevOff, out) emits raw or OFS_DELTA;

    dog/git/PACK.c::PACKu8sFeedObj "NEVER emits REF_DELTA" by design (a stored-log concern). A thin pack on the wire DOES carry REF_DELTA.

  • Builds on JS-035 (deflate) + JS-036 (delta.encode) conceptually; the

    dog/git writer does both internally, so no JS-API dep, but shares the files.

Goals

  • feed base ref is offset (default → OFS) OR hash (→ REF_DELTA): pass the base

    bytes + its 20-byte sha; the record names the base by sha, body is the delta.

  • Read-back parity: git.pack reader sees ref-delta, _pack_ref == base sha,

    apply(delta, base) == target.

Constraints

  • The REF framing is a dog/git/PACK.c writer (PACKu8sFeedObjRef) — NO manual

    record framing in the binding (CLAUDE.md). Binding is pure marshalling.

WIP

Design decisions

  • C: add PACKu8sFeedObjRef(log,type,content,base,base_sha,cur_off,delta,out?)

    to dog/git/PACK.{c,h} — REF header + 20-byte sha + deflated delta (reuses DELTEncode+ZINFDeflate internally, like the OFS path).

  • Binding: _pack_feed_ref(buf,off,type,content,base,baseSha,delta)->end leaf;

    JS feed dispatches — number base → OFS (today), {hash,base} → REF.
