JS-078 MED: core/job.js — dead crash-resume; crashed runs leak /tmp/.bequeue

job.openOrResume documents a crash-safe RESUME (a surviving queue file is an interrupted run to re-open via its .done offset). But the ONLY caller (core/loop.js cli) PID-KEYS the queue name and unlinks it on clean exit, so a fresh process can NEVER re-open a dead one — fresh is always true and the done-tracking is inert. The net effect inverts the contract. Method: Issues.

Input

Context

  • core/job.js:37-44: openOrResume computes donePath, stats the

    file for fresh, books it — the whole RESUME split.

  • core/job.js:84: const startOff = fresh ? 0 : _readDone(donePath);

    — the resume skip; with fresh always true it is never taken.

  • core/job.js:24-31 _readDone + :106-109 markDone + :88 donePath

    exist only to serve that unreachable resume.

  • core/loop.js:377-380 _tmpQueue: `"/tmp/.bequeue." + USER + "." +

    _pid() + "." + key` — PID-keyed; a new PID is a new path.

  • core/loop.js:295-297: every cli run keys the queue via _queuePath/

    _tmpQueue (PID-keyed) — so two distinct PIDs never share a file.

  • core/loop.js:120: q.close(true) on clean exit unlinks queue +

    .done; a CRASH skips it.

  • Result is the OPPOSITE of the doc: a crash leaves

    /tmp/.bequeue.<deadpid>... (+ its .done) on disk PERMANENTLY, with nothing — no new PID, no sweeper — that will ever re-open or remove them.

Goals

  • Remove the inverted contract: either make resume reachable, OR drop

    the dead split AND stop the permanent stale-file leak.

Constraints

  • Keep the queue PID-keyed for the concurrent-run no-collision property

    (loop.js:289-294) if resume is dropped.

  • Keep openOrResume's grow-on-demand + consume-while-append surface

    (append/next/markDone/close) intact for core/loop.js.

WIP

Design decisions

  • Option A (simplify): drop the resume split — collapse to seed +

    append + consume; delete _readDone/markDone/donePath/fresh. PID-keying makes resume unreachable, so this loses nothing live.

  • Option B (revive): stop PID-keying (key by repo/cwd only) AND add

    stale-PID detection so a dead run's queue is re-opened, not collided.

  • Either option ADD a best-effort startup sweep of stale

    /tmp/.bequeue.* (skip live PIDs) so crashed runs do not accumulate.

  • Prefer A + sweep: PID-keying is load-bearing for concurrency

    (the verb '0' stale-dispatch fix, loop.js:289-294); do not unwind it.
