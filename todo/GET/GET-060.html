GET-041

A dir that already carries an empty .be is NOT a clone destination for seedRemote: be.treeAt calls it an established worktree, so a first-ever clone takes the UPDATE leg. The pack then lands in the store ROOT (.be/0000000001.keeper) instead of .be/<proj>/, the wtlog never gets its file:…/.be/<proj>/ anchor row, no per-sub shard is minted, and the run dies before a single file is checked out. The bytes fetched are FINE — the same store reads clean from a fresh process — so this is a placement/anchor bug, not an ingest or wire bug. mkdir .be is the documented way to start a repo (test/get/be-update/run.sh does exactly that), so the shape is reachable by hand.

Context

  • Terms: the ANCHOR is the wtlog row naming this wt's shard — <ts> get file:…/.be/<proj>/, written first by the green-field clone (get.js:256-258). UNANCHORED = a .be carrying no such row: the empty dir of the repro (no wtlog, no <proj>/, no refs), or the half-built store this bug leaves behind (tip row present, anchor row absent).
  • Repro: mkdir -p w/.be && cd w && be get 'https://github.com/gritzko/beagle.git?main' → dies, no checkout.
  • Control A (PASSES): same command in an empty dir with NO .be → .be/wtlog + .be/beagle/ + .be/beagle-ext-tests/, tree checked out.
  • Control B (PASSES): same command under $HOME/tmp — no .be in cwd, nearest ancestor store is ~/.be — correct layout; the ancestor anchor is properly ignored.
  • The cell: verbs/get/get.js:219-220 — info = be.treeAt(wt), then if (info && info.wt !== wt) info = undefined. The GET-041 guard rejects only an ANCESTOR anchor; an own-but-EMPTY .be passes as established.
  • Consequence 1 — placement: shard = store.shardDir(info.storePath, info.project) (get.js:238); with no project subdir to auto-detect shardDir returns the store root, so git.pack streams the whole pack into .be/ itself.
  • Consequence 2 — anchor: the update leg calls appendGetRow (get.js:274), not writeWtlog (get.js:256), so the file:…/.be/<proj>/ anchor row that names the shard is never written; the wtlog holds the tip row alone.
  • Consequence 3 — subs: no .be/<sub>/ shard is minted, so sub tips have nowhere to live.
  • Run-1 death: TypeError: Invalid argument type in ToBigInt operation — hashlet60FromBytes ← locate ← getObject ← commitTree ← fanoutWholeTree; k.peel(tip) (get.js:269) returned "", and hexDecode("") yields zero bytes, so sha20[0] is undefined. An empty tip must never reach locate — see Goals.
  • Run-2 death (same dir, store now populated): checkout: tip 10e57b7d…c1d2a has no tree (shared/checkout.js:217) — the SUB's tip, which has no shard.

Goals

be get <remote> into a dir whose own .be is empty/unanchored clones properly — never a half-built flat store.

  • RULING (gritzko, 2026-08-06): a store .be/ holds ANY NUMBER of shards, and the shard path is ALWAYS .be/<shard>/*.keeper. There is no flat store; a pack directly under .be/ is out of spec, whatever leg put it there.
  • RULING 2 (gritzko, 2026-08-06, on the measurement below): ANY use of a flat store is a hidden landmine. No flat stores any more — find every place in the code that mints, resolves or tolerates one and remove it as STALE. The 268-case fallout is not an argument to keep it; the WRITERS are what must change.
  • So the pack lands in .be/<proj>/ on EVERY leg: widen the get.js:220 guard from "anchor belongs to another wt" to "anchor is absent" (no anchor row / no shard dir) → the existing clone leg runs and mints .be/<proj>/ + both wtlog rows. [LANDED, staged]
  • The IN-PLACE bootstrap mints a shard too: mkdir .be && jab put a.txt currently writes .be/0000000001.keeper + .be/*.keeper.idx + .be/wtlog with NO shard dir (verified 2026-08-06), via put.js:112 store.createShard(k.shard, …) resolving k.shard to the store root. It must mint .be/<title>/ instead.
  • shared/store.js::shardDir must stop degrading a project-less resolution to the store root (return found || (project ? join(beDir, project) : beDir), store.js:159, and the if (isDir(storePath)) beDir = storePath guess at :138-140) — those encode the flat store the ruling denies.
  • OPEN SUB-QUESTION for gritzko: what NAMES an in-place repo's shard? A clone takes the URL basename (titleFromUrl, "repo" as last resort, GET-042). The wt dir basename is the obvious in-place twin, but a wt can be renamed under a live store. Propose with evidence, flag prominently, do not block the sweep on it.
  • k.peel / commitTree must never be handed an empty sha: a lookup miss is a named error, not a ToBigInt TypeError out of locate.
  • Repro test under test/get/ covering all three shapes: own empty .be (RED today), no .be, ancestor-only .be.

Constraints

  • Do not regress GET-041: an ESTABLISHED worktree is never a clone destination, and a secondary wt's .be redirect FILE must keep resolving to the real shard (minting <wt>/.be/<proj> under a redirect ENOTDIR-crashed the ingest).
  • Ancestor anchors stay ignored (Control B must keep passing).
  • All URI/anchor resolution through the existing helpers — no hand-rolled path guessing.
  • Multi-shard stores stay first-class: .be/ holds any number of shards (.be/beagle/ + .be/beagle-ext-tests/ in the beagle clone), so the shard is NAMED, never "the one subdir" — auto-detect may resolve nothing, but it must never answer the store root.
  • Minimal diff no longer applies after RULING 2: the sweep reaches every writer that mints a store (put/post/store/ingest) and whatever test fixtures and goldens encode the flat shape. Breadth is expected; sloppiness is not.
  • Goldens are evidence, not a nuisance: a golden may only change where the SHARD PATH itself shows in the output, and every changed line must be justified. Never re-bless a golden file wholesale to make a suite green.

WIP

Design decisions

  • The leg question is "does this .be ANCHOR anything", NOT "does this .be exist" — new anchoredWt(info) in get.js, two witnesses, either suffices: (1) its own WTLOG exists (info.bePath; a secondary wt's redirect FILE is that wtlog, so GET-041 keeps its update leg untouched), (2) the store .be dir holds ANY entry at all (a <proj>/ shard, refs, a pack). A mkdir .be bootstrap dir has neither. The GET-041 ancestor test (info.wt !== wt) stays, ORed with the new one.
  • anchoredWt deliberately does NOT ask store.shardDir: under RULING 2 shardDir always ANSWERS a shard path (minted or not), which is the right answer for a WRITE and no answer at all to "is this wt established". Keeping the probe off the resolver also keeps the leg choice independent of the naming rule below.
  • RULING 2 sweep — THE mechanism: shardDir no longer degrades a project-less resolution to .be; it resolves a NAMED shard in three rungs — (1) the DEFAULT-titled shard .be/<title>/ if it exists, (2) the single non-dotted subdir (auto-detect: a renamed wt, a shard titled otherwise), (3) the default-titled path as the shard a first WRITE must mint. Rung 3 is what makes the whole sweep one edit instead of ten: every writer already writes to k.shard, so the in-place bootstrap now mints .be/<title>/ without post/put/delete/head/serve learning a new call. Rung 1 before rung 2 keeps the answer STABLE when a store holds sibling sub shards (the hazard subcase.sh's header names: "the empty-project auto-detect would pick the sub shard").
  • OPEN SUB-QUESTION, ANSWERED WITH EVIDENCE — what NAMES an in-place repo's shard: the WORKTREE DIR BASENAME, repo as last resort. Not invented here: submount.js:290 already titles a url-less sub basename(subpath), test/lib/repo-setup.sh::rs_fresh_wt documents exactly this rule ("the project (Title) defaults to the wt basename, so its refs/packs live in .be/<name>/") and exports RS_SHARD=".be/$_rs_name" for it, and GET-042 gives a title-less CLONE the same repo last resort. The rename hazard gritzko raised is covered by rung 2: a renamed wt finds its old shard by auto-detect. NEEDS CONFIRMATION — and see the durable alternative in the next bullet.
  • PROPOSED, NOT DONE (needs gritzko): make the in-place bootstrap write the wtlog ANCHOR ROW (get file:<wt>/.be/<title>/) the way a clone does, so an in-place repo NAMES its shard instead of leaning on the default title. It is the durable answer to both the rename and the multi-shard-ambiguity corners, and it would make jab refs print project: <title> instead of (unnamed). Deferred because the row can only be written at the bootstrap MOMENT (resolveAnchor reads ROW 0, and an existing wtlog cannot be retro-prefixed) and because it moves observable output — a change of shape, not a sweep.
  • MIGRATION, PROPOSED: a store that is ALREADY flat on disk FAILS BY NAME. shardDir's project-less miss path carries a flatStoreGuard — a loose *.keeper under .be/ throws store: <path>/.be keeps its packs directly in the store dir — that flat layout is retired; move them into a shard: mkdir …/<title> && mv …/*.keeper …/*.keeper.idx …/refs …/<title>/. Verified end to end: the recipe restores a repo (status clean, jab log reads the commit). Silence was the alternative and it is worse — an unresolved flat store reads as an EMPTY repo, i.e. a wiped worktree. No auto-migration: moving a user's packs without being asked is exactly the kind of thing this ticket exists to stop.
  • The ToBigInt death is TWO guards, not one: store.js::locate treats a short/empty sha as a MISS (undefined, the documented getObject contract) instead of crashing in hashlet60FromBytes, and fanoutWholeTree stops handing commitTree an empty oldTip at all (!isFullSha(r.oldTip) → no old tree). A verb-level unresolvable tip still throws the plain-words be get: tip <sha> has no tree.
  • The repro test uses a be:<path>/.be remote, NOT file: — a file: source is rem.local and routes to seedLocal, which never touches the buggy leg. be: host-less is a LOCAL wire leg (seedRemote) and POST-028 spawns THIS jab as the peer (KEEPER_BIN=$JABC), so the case is hermetic, offline, and needs no native keeper.

Suggested commit message:

GET-060: no flat stores — a shard is always .be/<title>/

Two bugs, one shape. be.treeAt calls a bare mkdir .be an established worktree, so the GET-041 guard — which rejects only an ANCESTOR anchor — let the UPDATE leg run on a first-ever clone: the pack landed flat in .be/, the tip row went in without the file:…/.be/<proj>/ anchor row, and the run died in commitTree("") with a raw ToBigInt TypeError before any checkout. And the reason a flat store was reachable at all: shardDir degraded a project-less resolution to the store ROOT, which is also the answer every writer minted through — mkdir .be && jab post built one on purpose.

get now asks whether the .be ANCHORS anything (its own wtlog, or any entry in the store dir) instead of whether it EXISTS; a secondary wt's redirect file IS its wtlog, so GET-041 keeps its leg. shardDir answers a NAMED shard on every path — the default-titled shard, else the single subdir, else the default-titled path a first write mints — so the in-place bootstrap lands .be/<wt name>/ exactly like a clone lands .be/<url basename>/. The GIT-020 flat-store retries in serve/wire, submount's open(shard, "") fallback and serve's shard-as-store-root open go with it; a store that is already flat on disk fails by name with the move that fixes it. An empty sha is a lookup miss in locate, and the baseline tree is only read when there IS a baseline.

RULING 2 (gritzko, 2026-08-06): any use of a flat store is a hidden landmine — no flat stores any more. OPEN: the in-place shard title is the worktree dir name (submount and repo-setup.sh already say so); naming it in a wtlog anchor row at bootstrap is the durable fix and needs a ruling.
