GET-040: non-force get DELETES untracked files — only get! may clean

Now: DONT

A plain (non-force) jab get must MERGE dirty tracked files and LEAVE UNTRACKED files alone; only jab get! may clean the worktree (GET wiki: "be get! resets the worktree to a clean state, all local changes discarded"). It does not: a non-force get that recurses into a submodule RESET the sub and SILENTLY DELETED every UNTRACKED file in it. Verified this session: in a beagle-ext worktree, test/ is the beagle-ext-tests store-backed submodule; a non-force jab get swept 7 dirs of untracked, newly-authored test files (left empty), while tracked files survived — silent data loss. Suspected locus: get's del-sweep / prune (verbs/get/get.js fanoutWholeTree + delSweep) unlinks worktree paths absent from newTree WITHOUT checking they were TRACKED (in oldTree), and/or the submodule recursion does a wholesale clean re-checkout of the sub (should be read-only, DIS-058). JS only (be/, via jab). Evidence: cost the GIT-016 T1–T4 tests. Method: work; siblings JGET-001/DIS-058/JGET-013.

Input

Context

  • Repro-shaped evidence (this session): in a beagle-ext worktree test/ is a SEPARATE store-backed submodule (beagle-ext-tests, own .be). A NON-force jab get (recursing) reset that sub and DELETED all UNTRACKED files under it — 7 test dirs emptied; the 40+ TRACKED test files survived.
  • verbs/get/get.js fanoutWholeTree(ctx, r, wt, force): noPrune = !!force || (sameTip && !r.fresh); a del-sweep BARRIER (DELSWEEP/delSweep) folds delete leaves; if (!force) dirtyOverlapCheck(...) (get.js ~L382). The prune/del-sweep is what removes worktree files during a switch/update.
  • GET wiki: only be get! (force) "resets the worktree to a clean state, all local changes discarded" — so a non-force get must NOT discard untracked (or dirty tracked) content.
  • An UNTRACKED file = a worktree path in NEITHER oldTree NOR newTree. A tracked deletion = a path in oldTree but gone from newTree. Only the latter may be unlinked, and only when not dirty.

Goals

  • A non-force jab get (switch / update / re-get / FF) NEVER deletes an untracked worktree path (in neither tree); it merges dirty tracked files and only removes TRACKED deletions.
  • jab get! keeps its clean-reset (may remove untracked/dirty) — force is the SOLE cleaning path.
  • The invariant holds THROUGH submodule recursion: reconciling / re-getting a sub must not sweep the sub's untracked files (coordinate with DIS-058: sub recursion is read-only).

Constraints

  • JS only, be/, run via jab. Do NOT run native be; do NOT open beagle/.
  • Repro-first (a silent-data-loss bug): make the failing case before the fix; verify untracked files survive a non-force get.
  • ABC/JS norms: ≤2-line GET-040 comments, greppable, ticket-coded ≤64-char commit. No new deps.
  • Do NOT regress get! (still cleans), dirty-tracked merge, tracked-deletion sweep, or the get/dirty/restore buckets.
