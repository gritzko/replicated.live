GET-054: wt→wt clone: reflink (CoW) intact files instead of re-materializing

Now
OPEN
Sev
LOW

Small optimization, requested by gritzko in chat 2026-07-24. When get clones from a local WORKTREE source (the GET-038 scenario) it decodes every checkout file from the store, though the source wt already holds the exact bytes on disk. On a CoW filesystem (btrfs/XFS/bcachefs/ZFS 2.2+/APFS) an intact source file can be reflinked into the new wt: O(metadata) checkout, shared extents until either side edits, rm -rf of ticket clones stays free. Blobs live inside .keeper TLV segments, not one-file-per-blob, so store→wt reflink is impossible — wt→wt is the only file-level CoW spot.

Input

Context

The agent fleet spawns one clone per ticket under work/<TICKET>; each clone re-materializes the same ~16 MB tree. N sibling clones of one base could share one extent set. CoW applies only when source and destination are on the same filesystem (reflinks never cross mounts).

  • Chat design notes 2026-07-24: keeper-segment reflink for full-clone store copies is a separate, bigger win — NOT this ticket.
  • GET-038 covers wt-source clone anchor bugs; this ticket assumes that path works.

Goals

When cloning from a wt source, for each checkout file whose source-wt copy is intact (clean against the rev being materialized), clone it with FICLONE instead of decoding from the store.

  • Fallback chain: FICLONE → plain decode-from-store; failure of the ioctl (EXDEV, EOPNOTSUPP, ext4) is silent and per-file.
  • CoW is a perf layer only, never a correctness dependency; behavior identical on ext4.

Constraints

  • "Intact" must not trust a stamp-false-clean file (GET-052 showed stamps lie): a dirty source file reflinked forward corrupts the clone. Decide: same clean-check diff uses, or hash-verify the source bytes before reflinking.
  • No manual byte copying fallback beyond what checkout already does; no cp -r semantics — track/identity rows are written by get as today.
  • Dev boxes run ext4; tests must pass there via the fallback leg and may skip the reflink-assert leg when the fs lacks FICLONE.
