GET-046: ingest.land append-into-existing-shard is broken for the keeper wire

Now
OPEN
Sev
HIGH

A second get from a be:// source lands the new tip as BYTES but leaves it UNRESOLVABLE (be get: tip <sha> has no tree), and the shard goes index-blind — even the OLD tip then reads unk. The keeper wire re-sends FULL history each fetch (no have-negotiation), so the appended tail duplicates run-1 keys; the pack-log's PACK-header object count is never bumped, so every rebuild path rescans by header count and drops the appended objects. get-git escapes because git negotiates and sends no duplicates. Found under URI-016 while fixing SUBS titleFromUrl; the append branch was previously UNREACHABLE, so this has never run.

Input

Context

be-js-get-be is red. It was red for a DIFFERENT reason (URI-016: titleFromUrl("be://…/.be") returned ".be" as the shard title, so clone wrote <wt>/.be/.be/ while discovery read <wt>/.be/). Fixing that made clone and discovery agree on ONE shard — which routed the second get into ingest.land's append branch for the FIRST TIME.

  • The old code passed get2 BY ACCIDENT: get1/get2 used two DIFFERENT dirs, so it never appended.
  • Proven pre-existing, not a regression: a THREE-get sequence fails IDENTICALLY on the ORIGINAL code (planted repro).
  • A full reindexShard still cannot find the new tip — the rebuild is what drops it.
  • be-js-get-be cannot go green until this is fixed; it is that test's remaining blocker.

Goals

A second/third get from a be:// source must land a resolvable tip and leave the shard index-sane.

  • jab get be://<host>/<path>/.be/<shard> twice into one worktree: tip resolves, files read ok, not unk.
  • The old tip must stay resolvable after the append.
  • get-git (negotiating wire) must not regress.

Constraints

  • Repro first (work 3). Plant jsrc above any scratch repo or it silently runs the INSTALLED code.
  • be get is NOT read-only: it re-checks-out test/ and destroys uncommitted test edits.

WIP

Design decisions

Unsettled — two candidate fixes, not yet chosen.

  • Bump the pack-log's PACK-header object count on append, so rebuilds rescan the whole log.
  • Or de-duplicate the appended tail against existing keys before writing.
  • Or give the keeper wire have-negotiation, so it stops re-sending full history — the root cause, widest blast radius.
