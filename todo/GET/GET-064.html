Input

Context

Incident 2026-08-13 in ///quickjab: a get from //DOG-032-quickjab updated the parent files (pup.c, cont.c) but silently skipped the mounted dog/ sub (attached to ///jab/dog), so dog/DOG.h lacked DOGPupPutMem/DOG_PUP_MEM_PAGES and ninja died on undeclared identifiers — the tree was left inconsistent with zero warning.

  • The skip is currently BY DESIGN: GET-047's SUBS cluster gates recursion on subAttachedElsewhere — "differently-attached subs untouched by normal get, get! overrides".
  • The gate lives around mountGitlink + recurseSubMounts in be's get verb; GET-047 §4.1 deferred "wire+subs recursion (needs ruling)" — this is the ruling.

Goals

RULING 2026-08-13 (gritzko): a bare get ABSOLUTELY MUST recurse into mounted subs. A parent update that leaves a sub stale and says nothing is unacceptable.

  • Default recursion updates each mounted sub from its OWN attach (dog/ -> ///jab/dog), whatever source the parent get used.
  • Open design point: when the parent source is a worktree whose same-path sub is ahead of the attach (//TKT-quickjab/dog/ vs a lagging ///jab/dog), which one wins — wt URIs compose by path (SUBS-047 ground); get a ruling before coding.
  • Every recursed sub shows up in get's report (GET-062's quad, one line per tree); nothing silent.

Constraints

  • get! force semantics and --nosub stay; the SUBS-041 depth cap holds.
  • test/sub* goldens that encode the old skip contradict this ruling; list them and request approval before amending — no unilateral test edits.
