be get must display the quad view of the commits it pulled and the files it updated — the same unified report status and post give (Status: the quad is THE default output of status, GET, POST and PATCH, not a flag). Today get renders quads, but of the WRONG moment: verbs/get/get.js:1424 quadReport() runs quadOf over the POST-get tree, where the track/base divergence the get just consumed is already gone — a clean FF pull prints no commit rows at all, and file rows filter to touched paths whose post-state quads are mostly all-same and omitted. post got this right: it snapshots the quad BEFORE the commit (verbs/post/post.js:925, "the wt-column dirt is what this post absorbs into base, so the PRE state is the report").

Input

Context

The render pipeline is all in place; only the snapshot moment is wrong.

  • shared/quad.js quadOf builds the model; view/quadrender.js commitRow/fileRow render <date7> <quad4> <path> rows — shared by status and post (Status, BRO-030).
  • get.js quadReport (get.js:1430) is a post-run report only, try/catch-downgraded to a warning; GET-058 made get DECIDE by the quad, this ticket is about get REPORTING it.
  • post proves the pattern: pre-commit quadOf snapshot at post.js:925-928, rendered after success — the report shows the state the verb consumed.

Goals

  • After a get, print the commits pulled (the track-ahead rows the get consumed, old tip → new tip) and the files updated, as quad rows — same renderer, same vocabulary as status/post.
  • A no-op get (already current) keeps today's terse output; divergence left behind (conflicts, dirty survivors) still shows, as now.
  • Byte-format parity: rows come from quadrender, plain vs pager tok-tagged exactly as quadReport does today.

Constraints

  • Snapshot, don't recompute history: take the quad (or the tips) BEFORE mutating, like post does; no log re-reading after the fact (no-log-readback, be.now rules stand).
  • GET-058 decision path untouched — this is the report side only; no new mechanism, reuse shared/quad.js + view/quadrender.js.
  • Scope: be/ JS (verbs/get/get.js); no C, no engine changes; suite green, no test edits.

WIP

Design decisions

  • Consumed quad = quadModel({base: oldTip, track: tip}) from the tips already threaded on the get ctx — no pre-get quadOf pass, no log re-read; root === oldTip gates FF-only (GET-053), so a diverged get! reset or rewind keeps today's silent report.
  • Conflict row keeps the track column lit: v..! ("theirs advanced it AND the wt conflicts"), one quad per path (Status) — NOT the later-status ...!. AWAITING RULING (the table-cells test greps the old literal).

Blockers and bummers

3 existing tests contradict the new report BY DESIGN — reported, not edited; gritzko's ruling wanted on each:

  • be-js-get-quad asserts a synced wt's get report goes SILENT (no o... commit row) — the exact behavior this ticket overturns.
  • be-js-get-file is a golden snapshot; gains 6 correct rows, needs GOLDEN_REGEN=1.
  • be-js-get-table-cells greps '...! bin_t_v_w_v.dat'; the row is now v..! — the conflict-row design decision above.
  • Patch column of consumed commits is always . (patches: []): a pulled commit already absorbed by PATCH prints o... not o.o.; a pre-get wtlog snapshot spans ~10 appendGetRow sites — out of scope, follow-up ticket territory.
  • Detached partial pull (get ?#<mid sha>) stays silent (detached ⇒ track = base in quad.tips()); pre-existing, status behaves identically.

Outcome

Staged (put only, NO post) in //GET-062, base ///be/#29166a34: verbs/get/get.js (+49/-3), only file touched.

  • quadReport renders commitRows(pre, post) (what the get LEFT first, then what it CONSUMED, deduped by sha) and fileRows (ONE row per touched path: consumed track/base/patch columns + the POST wt char) through the unchanged quadrender/out.quad* plain-vs-pager split.
  • Clean FF pull now prints the pulled o... ? commit rows + v.../o.../x... file rows; no-op get byte-identical to before; piped and pty captures match across /bin/jab and /bin/quickjab (~/tmp/GET062/).
