GET-030 MED: be get be://host wire fails "keeper: not found" (remote non-interactive PATH)

The be:///ssh: wire spawns the remote keeper via a non-interactive non-login ssh whose PATH lacks the dog bin dir, so be get be://host… fails sh: keeper: not found out of the box. Found creating worktrees for the loop. Method: Issues.

Input

Context

  • Repro: be get be://localhost/beagle-journal?/beagle (also be://localhost?/beagle)

    → sh: keeper: not found / be: remote … is not a beagle or git repository (reachable, but advertised no refs) / WIRENOTRP / BEDOGEXIT.

  • Root cause: the be+ssh wire runs the remote dog via ssh host 'keeper …' — a

    NON-interactive NON-login shell whose PATH is the bare default (/usr/local/sbin:…:/bin); it does NOT source ~/.profile//etc/profile where the dog bin dir (e.g. …/beagle/build/bin) is added. Interactive ssh host (login) finds keeper; the wire's shell does not.

  • Knobs already in the code (keeper/WIRECLI.c): DOG_REMOTE_PATH (line ~334)

    prepends to the remote PATH (PATH='<rpath>':"$PATH" exec keeper … via sh -c) and KEEPER_BIN (line ~151) sets the LOCAL keeper path — but DOG_REMOTE_PATH is test-harness-only and unset by default, so the user-facing be get be:// breaks.

Goals

  • be get be://host resolves the remote keeper with NO manual env/PATH setup:

    auto-carry the remote dog path, OR document DOG_REMOTE_PATH as the supported knob with a clear error that points to it when keeper isn't found.

Constraints

  • Fix in the keeper/WIRECLI.c wire spawn. Don't break the existing

    DOG_REMOTE_PATH / KEEPER_BIN test paths.

WIP

Design decisions

  • (open) the client can't know the remote's layout, but it CAN pass its own

    sibling dir as a hint, or be can require/auto-derive DOG_REMOTE_PATH.
